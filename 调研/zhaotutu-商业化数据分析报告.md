## 〇、重要前提

该产品为独立开发者/小团队产品，**未公开任何运营数据**。本报告无法获取真实的安装、活跃、收入数据，因此采用 PM 标准做法：**区分「已知事实 / 估算假设 ⚠ / 待验证项」**，构建可自下而上推演的商业化模型。所有区间数字均需用真实埋点数据校准。

## 一、产品是什么

**定位**：面向 AI 绘画/视频创作者的 Windows 桌面工具箱，覆盖「打标 → 训练 → 分发」三段工作流。

| 产品线 | 版本/门槛 | 收费模式 | 商业角色 |
|---|---|---|---|
| 提示词反推器（打标器） | v1.2.9 · 需 12GB+ 显存 | 默认模式免费；高级模式接自己的 API | 获客/生态入口 |
| LoRA 训练器 | v1.4.4 · 需 16GB+ 显存 | 官方明确「完全免费，无套路无广告」 | **增长引擎** |
| 视频发布机 | v1.2.7 · Windows | 发布免费；**AI 补全按视频时长消耗积分（唯一明确付费点）** | 变现引擎 |

**商业模式**：免费生产力工具拉新 → 高频分发场景按量付费。积分只覆盖 AI 生成（标题/标签/简介/封面），AI 推理成本可 pass-through 加价，毛利结构类似 API 转售。

**分发渠道**：官网直装包 + 夸克/百度网盘 + Product Hunt（英文版）+ B站/YouTube/TikTok/X/Telegram + RunningHub 工作流社区（带邀请码）+ QQ/微信群。基础设施用 DigitalOcean 新加坡节点（S3 兼容 CDN），个人邮箱/QQ 联系 —— 典型 indie hacker 形态。

## 二、市场规模与触达面（Top-Down）

| 层级 | 估算 | 依据 |
|---|---|---|
| 全球本地 LoRA 训练兴趣人群 | 数十万级 | SD/FLUX 社区（Civitai、liblib、秋叶包用户群）规模外推 |
| 满足 12–16GB 显存门槛的活跃子集 | ⚠ 约 20–40% | RTX 3060 12G/4070+ 为 AI 绘画主流配置；云端训练分流一部分 |
| 该产品可触达（中文内容+分发渠道） | ⚠ 1–5 万潜在用户 | 内容主阵地为 B 站 + RunningHub 中文社区，海外仅 PH/YouTube 轻量布局 |

**判断**：窄而深的垂直工具市场，TAM 天花板在「十万级用户、千万级年收入」量级。靠训练器收费做不大，**空间在于把免费训练器做成入口后，向云端算力分成 / 素材交易 / 发布代运营等高价值环节延伸**。

## 三、安装量估算（Bottom-Up 漏斗）

```
内容触达(B站/YT/RunningHub/PH) → 官网下载页访问 → 下载安装包 → 完成安装 → 完成首次关键动作
```

| 漏斗层 | 月度估算（悲观–乐观） | 转化率假设 |
|---|---|---|
| 内容月触达（视频播放+社区帖浏览） | ⚠ 5,000 – 20,000 | — |
| 官网/下载页 UV | 1,000 – 4,000 | 触达→点击 15–25% |
| 下载安装包 | 500 – 2,000 | UV→下载 40–55% |
| 完成安装（三件套合计） | 300 – 1,400 | 下载→安装 60–70%（10GB 级安装包拉低完成率） |
| 激活（完成首次关键动作） | 180 – 900 | ⚠ 安装→激活 50–65% |

**累计装机量推算**

- 悲观（发布约 9 个月，弱增长）：**≈ 5,000 – 8,000**
- 中性（持续内容运营）：**≈ 15,000 – 25,000**
- 乐观（社区口碑 + 爆款教程）：**≈ 40,000 – 60,000**

> 三件套装机存在重叠（训练器用户大概率同装打标器），去重后「独立用户数」约为装机数的 60–75%。训练器预计贡献最大份额，发布机次之。

## 四、活跃度估算

| 指标 | 估算区间 | 逻辑 |
|---|---|---|
| MAU / 累计装机 | ⚠ 10% – 25% | 桌面工具 + 项目制使用（炼丹时高频、平时闲置），低于 SaaS 留存 |
| MAU 绝对值 | ≈ 800 – 8,000 | 对应上一节累计装机区间 |
| DAU / MAU | ⚠ 15% – 30% | 发布机用户（日更矩阵号）黏性最高；训练器呈脉冲式 |
| 结构性分层 | — | 核心高频：批量打标 + 矩阵号发布者（估计 <15% 用户）贡献大部分 AI 积分消耗 |

**活跃质量的最大风险**：三款工具全部依赖「Windows 本地显存」；发布机通过 UI 自动化操作抖音/视频号等平台，**平台风控升级可能导致高频用户瞬间流失**，活跃数据波动会远大于常规 SaaS。

## 五、收入估算（唯一明确付费点 = AI 积分）

**付费漏斗模型**

```
月付费用户 ≈ MAU × 使用发布机比例(25–40%) × AI补全采用率(20–40%) × 付费转化(60–80%)
```

| 参数 | 假设区间 | 说明 |
|---|---|---|
| ARPPU（月） | ⚠ ¥20 – 60 | 按视频时长扣积分；重度矩阵号更高，轻度用户几元即流失 |
| 月收入（悲观） | ≈ ¥1,000 – 3,000 | 低 MAU × 低采用 × 低 ARPPU |
| 月收入（中性） | ≈ ¥6,000 – 15,000 | MAU 3–4k，付费用户 200–400 人 |
| 月收入（乐观） | ≈ ¥30,000 – 60,000 | MAU 8k + 重度矩阵号占比高 |

**隐性收入（待验证）**：RunningHub 邀请码分成、爱发电/捐赠、打标器高级功能收费、定制/企业服务（论坛帖提到「企业用户私有数据训练」）。

**PM 判断**：中性假设下月收入 ≈ 一名中级工程师薪水的 20–40%，仍难覆盖人力成本。训练器免费是正确的获客武器，但**积分模式天花板低**——按量付费缺乏订阅的现金流可预测性，且 AI 文案补全对用户的感知价值弱（替代品是免费 GPT 网页版）。

## 六、成本结构估算

| 成本项 | 月度估算 | 性质 |
|---|---|---|
| AI 推理成本（视频理解/文案/封面） | 收入的 30–50%（毛利 50–70%）⚠ | 变动成本，随用量线性增长 |
| 云与带宽（DigitalOcean Spaces + CDN） | ⚠ $20 – $150（¥150 – 1,100） | 10GB 级安装包 × 月下载 500–2,000 次，出流量为主要变量 |
| 更新服务器/后端（调度、积分系统） | < ¥300 | 轻量 |
| 人力（1–2 人开发+运营+内容） | **¥20,000 – 60,000（机会成本口径）** | **真实主导成本，占 90%+** |
| 获客成本 | ≈ ¥0 现金 | 内容营销 + 社区自传播，CAC 以创始人时间计价 |

**单位经济（中性情形）**：月收入 ¥10k、变动成本 ¥4k → 毛利 ¥6k/月，远低于人力成本 → **经营性现金流为负**。独立产品早期属正常，但商业化必须在「提高 ARPPU」或「找到规模化付费场景」上突破，不能只靠堆用户。

## 八、机会评估与优化建议（Optimization Backlog）

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 接入数据埋点：安装→激活→首关键动作→付费全漏斗 | 本报告所有数字都需真实数据校准；没有漏斗数据无法判断优化哪一环 |
| **P0** | 积分付费升级为「订阅 + 按量」双层 | 重度矩阵号需要可预测成本，订阅能抬升 ARPPU 与现金流可预测性 |
| P1 | 建立发布机的平台风控预案（官方 API / 降级路径） | UI 自动化是活跃用户留存的最大单点风险 |
| P1 | 训练器向「云端一键训练」延伸（RunningHub 分成模式已有雏形） | 触达无卡用户，把免费入口变成算力分发佣金，打开收入天花板 |
| P1 | 合规加固：生成内容边界、平台协议风险、版权提示 | 社区内容已出现成人向 LoRA 案例；商业主体化后合规敞口放大 |
| P2 | macOS / 云端 Web 版 | 扩大 TAM，但成本高，应排在商业模式验证之后 |

## 九、如何验证本报告（数据需求清单）

1. 下载接口（Spaces 对象存储）请求日志 → 真实下载量，校准漏斗第 3 层
2. 客户端首次启动上报（脱敏 device id）→ 真实装机与激活率
3. 周启动频次分布 → MAU/DAU 与分层黏性
4. 积分售卖流水 → 付费用户数、ARPPU、复购
5. 推理供应商账单 vs 积分收入 → 真实毛利率
6. 各渠道带 UTM 的下载链接 → 渠道 ROI
