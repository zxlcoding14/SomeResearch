## 〇、结论先行（TL;DR）

1. **ShareX 不是「截图工具」，是「截图/录屏 → 处理 → 分发」的可编排流水线。** 真正的产品内核是 **12 种捕获方式 + 22 条后置任务 + 89 个上传目标**这套组合，截图只是入口。功能数量本身不是护城河，**编排能力**才是。
2. **共 36 个内置工具**（官网 5 大类：屏幕与取色 5 / 图像 13 / 视频 6 / 数据与文本 7 / 系统 5），源码 `ShareX.Tools/Tools/` 下 30 个独立工具目录 + 6 个（取色、屏幕取色、美化、编辑器、图像效果、图像查看器）散落在 `ShareX.ImageEditor` 等项目中 —— **两边对得上，数字可信**。
3. **它的"能力"绝大部分不贵**：OCR 直接调 Windows 自带 `Windows.Media.Ocr`（零模型、零成本、精度受系统限制）；抠图是本地 ONNX 分割模型（DirectML 加速、模型需用户自备）；录屏/转码走 FFmpeg；编辑器渲染走 SkiaSharp。**没有一个自研大模型，没有一个付费云依赖** —— 这就是它 18 年不收费还养得起 40k Star 的成本结构。
4. **对复刻者的第一道硬约束不是技术，是许可**：本体 **GPL-3.0**，代码不能进闭源商业产品，只能「读设计、重写实现」。可复用的上游（Avalonia / SkiaSharp / ONNX Runtime / Vortice / ZXing.Net）基本是 MIT，**拆分得很干净**。
5. **最值得抄的三件事**：① 捕获后置任务的**全量可勾选编排**（22 条，用户自选链路）；② **自定义上传器**（任意 HTTP 服务都能接进来，绕开官方适配成本）；③ **36 个工具的"顺手工具箱"定位**（免费、无广告、不设付费墙，把 T4 长尾工具当口碑资产而不是卖点）。

## 一、它是什么 / 口径边界

| 项 | 内容 |
|---|---|
| 一句话定义 | 一键截取/录制屏幕上任意区域，按预设链路自动处理（标注、脱敏、美化、加水印）并投递到 89 个目标之一 |
| 品类货架 | 截图工具 → 实际占据「Windows 效率工具箱 / 工作流自动化」这一格 |
| 最小可用内核 | **热键 → 区域截图 → 复制/上传 → 拿到链接**（删掉其余全部，这一条仍成立） |

| 平台 | Windows 正式支持；`develop` 分支已拆出 Avalonia + SkiaSharp 公共层（跨平台技术准备，**不等于已支持 macOS/Linux**，详见关联文档） |
| 授权 | GPL-3.0（`【实测·API】license.spdx_id = GPL-3.0`） |
| 分发形态 | 安装包 `setup-x64.exe` + 便携版 `portable-x64.zip`，另有 Microsoft Store / Steam 版本 |

## 二、能力全景（四层分层）

| 层 | 能力 | 商业含义 |
|---|---|---|
| **T1 内核**（去掉它产品不成立） | 区域捕获 + 全局热键 + 后置任务链（保存/复制/上传）+ 区域标注与脱敏 | 定价地基；免费产品的"必须有" |
| **T2 增强**（提效可替代） | 录屏/GIF、独立图像编辑器、上传目标矩阵（图床/云存储/FTP）、历史记录、OCR 与扫码后置任务 | 决定口碑，通常不单独收费 |
| **T3 差异化**（只有它有） | ① 22 条后置任务全量可编排 ② 自定义上传器（任意 HTTP 服务）③ 滚动截图 ④ 36 个内置工具矩阵 ⑤ 外部 CLI 动作链 | 卖点来源；但已被"免费 + 开源"自身覆盖 |
| **T4 长尾**（低频/边缘） | 网络监控、显示器测试、无边框窗口、窗口检查器、剪贴板查看器、图标转换、目录索引、远程存储浏览、视频播放/裁剪 | **"看起来很强"的装饰**，是口碑资产，不是付费理由 |

> **PM 提醒**：ShareX 的功能数量（36 工具 / 89 目标 / 60+ 图像效果）是**成本**不是**价值**。它能承受这个成本，是因为边际成本≈0 且不开工资式的客服团队；换成要养人的商业产品，同样清单会直接压垮毛利。

## 七、后置任务与工作流（T3 真正差异点）

### 7.1 捕获后置任务（22 条，全量可勾选）

| 类别 | 任务 |
|---|---|
| 交互 | 显示快速任务菜单、显示"捕获后"窗口、显示"上传前"窗口 |
| 处理 | 美化图像、添加图像效果、在图像编辑器中打开 |
| 输出 | 复制图像到剪贴板、固定到屏幕、打印、保存到文件、另存为、保存缩略图 |
| 派生 | 执行外部动作（`Perform actions`）、分析图像、扫描二维码、**识别文字（OCR）** |
| 分发 | 上传到主机、复制文件到剪贴板、复制文件路径、复制文件夹路径、在资源管理器中显示 |
| 清理 | 本地删除文件 |

### 7.2 编排与触发层

| 能力 | 说明 |
|---|---|
| 全局热键 | 每种捕获方式、每个工具、每个上传动作均可绑独立热键（含冲突检测） |
| 任务设置（Task settings） | 一个动作的完整行为集合：捕获选项 + 后置任务勾选 + 上传目标 + 命名规则 + 动作链，改一处不影响其他热键 |

| 浏览器集成 | `ShareX.NativeMessagingHost` + 官方浏览器扩展，实现网页内右键上传/截图 |

| 多语言 | 29 种语言包（含简/繁中文） |

## 八、能力背后的技术实现一览（复刻最该先看这一节）

| 能力 | 实现路径 | 成本含义 |
|---|---|---|
| 屏幕捕获 | Windows API + **Direct3D11（Vortice）**，`ScreenCaptureLib` 为 `net10.0-windows` | 平台绑定最深的一层，跨平台最难 |
| 录屏 | **FFmpeg** 外挂编码；新增 `ShareX.ScreenRecordingLib` + `Vortice.MediaFoundation` 依赖，显示在向 Windows 原生管线（WGC + MediaFoundation）迁移 `【推断·依据：项目结构与依赖变化】` | 借力 FFmpeg = 0 自研编码成本 |
| 图像渲染/编辑器 | **Avalonia 12 + SkiaSharp 3**，MVVM（CommunityToolkit） | 跨平台底座已铺好，MIT 可商用 |
| OCR | **`Windows.Media.Ocr`**（系统 API，需 10.0.18362+） | **零模型、零调用费**；精度天花板=系统 |
| 抠图 | **ONNX Runtime 1.24.4 + DirectML**，1024 级分割模型，模型需用户自备 | 真正的 AI 能力，但成本转嫁给用户机器 |
| 二维码 | **ZXing.Net 0.16.11** | 成熟轮子 |
| FTP/SFTP | **FluentFTP 55 / SSH.NET 2026** | 成熟轮子 |
| 云存储 | 各家 SDK/HTTP 协议直连，凭据本地存（OAuth 走 `UploadersLib/OAuth`） | 无自建服务端，**零服务器成本** |
| 数据存储 | SQLite 本地历史库 + JSON 配置 | 无账号体系 |

> **结构性结论**：ShareX 的成本结构是「**客户端重、服务端零**」。它没有一条业务逻辑需要自己付云账单——这是它能永久免费、且能白送 89 个上传目标的根本原因。任何要复刻它的 SaaS 化改造（云端历史、团队共享、在线分享页），都会立刻产生它从未有过的边际成本。

## 九、PM 判读：该抄什么 / 别抄什么

### 9.1 该抄（机制层，不是功能层）

| 可迁移机制 | 为什么 |
|---|---|
| **后置任务全量勾选** | 一次实现，覆盖"发群/存档/工单/日志"多种私域流程；用户自建链路 = 免教育 |
| **自定义上传器** | 把"适配长尾服务"的成本转成用户/社区成本，自己只维护协议描述器 |
| **固定到屏幕（Pin）** | 极低实现成本、极高日常价值 —— 典型的"小功能大口碑" |
| **命名规则 + 目录分片** | 决定用户长期使用后的文件可管理性，是留存的隐性因素 |
| **裁剪优先的脱敏文案** | 一句话建立专业感，成本为 0 |

### 9.2 别抄（它是免费产品的合理选择，不是你的）

| 别抄的 | 原因 |
|---|---|
| 36 个工具全量铺开 | T4 工具对商业产品是**成本 + 噪音**，只该挑 3–5 个高频的做深 |
| 89 个上传目标 | 每一个都要跟着对方 API 变更维护；商业产品选 3–5 个主目标 + 自定义器即可 |
| 无账号、无云端 | 这是它的成本优势，也是它做不了订阅的原因（见下） |
| GPL-3.0 代码 | **一行都不能进闭源产品**，只能读设计 |
| "无付费墙" | 用户被免费训练过 18 年，同品类直接收订阅会被立刻对标 |

### 9.3 免费替代威胁对照（L5：谁在吃它）

| 能力 | 已被系统/官方免费覆盖 | 覆盖度 |
|---|---|---|
| 区域截图 + 简易标注 | Windows `Win+Shift+S`（截图工具） | **高（T1 已被吃掉）** |
| OCR | PowerToys `Text Extractor`、系统截图工具自带文字提取 | **高** |
| 录屏 | Xbox Game Bar、PowerToys | 中（长时/多源仍不足） |
| 取色 | PowerToys Color Picker | 高 |
| 窗口置顶 | PowerToys Always on Top | 高（Pin 仍有"钉的是图不是窗口"的差异） |
| 滚动截图 | 系统截图工具已支持 | 中高 |
| **编排 + 上传矩阵 + CLI 动作链** | **无系统替代** | 🟢 **它的真实护城河在这** |

> 结论：**T1 已被 OS 吃掉，T3（编排/分发）没被吃掉。** 谁在这条赛道上做产品，卖点必须落在"编排与分发"，落回"截图清晰/标注好看"就是正面撞系统。

## 附 B、测算过程（与实测分开）

### B.1 复刻工作量估算（全量 vs MVP）

**假设**：以「一个熟悉 C#/Win32 的开发者」为基准单位；工作量按工具复杂度分档，不含设计、测试、本地化。

| 模块 | 依据 | 人日（P50） |
|---|---|---|
| 捕获内核（12 种 + 区域浮层） | 区域捕获浮层是最大单体：形状、命中测试、放大镜、标注 | 25–35 |
| 图像编辑器（22 工具） | 关联文档已确认 Avalonia+SkiaSharp 架构；绘图/历史栈/效果栈 | 30–45 |
| 36 个工具中 34 个低难度工具 | 按 0.5–2 人日/个（标尺、显示器测试 0.5；哈希、图标、拼图 1；元数据、窗口检查 2） | 30–40 |
| 抠图工具 | 模型接入 + DirectML + 掩码合成，**不含模型训练** | 8–12 |
| 上传器（82 个服务） | 按 0.3–0.5 人日/服务（协议直连、OAuth） | 25–40 |
| 工作流/后置任务/热键/命名/历史 | 编排引擎 + SQLite 历史 | 20–30 |
| **合计** | 各档相加 | **138–202 人日 ≈ 7–10 人月** |

**敏感度**：若砍掉编辑器与抠图（T3/T4 里最贵的两项），落到 **100–145 人日 ≈ 5–7 人月**；若上传目标砍到 5 个，再减 **20–35 人日 → 4–5.5 人月**。结论**不翻转**：真正的成本在捕获浮层与编辑器，不在"工具数量"。

**置信度**：中低。推翻条件：若目标平台非 Windows（跨平台捕获难度上升 2–3 倍），或要求中文排版级文字标注。

### B.2 为什么它不做订阅（成本结构反推）

- 边际成本构成：`服务器 0 + 模型调用 0（OCR 走系统、抠图走本地）+ 存储 0（用户本机）`。
- 因此**没有"持续交付成本"可挂订阅**，只能靠捐赠/商店分发；这也解释了它 18 年不设付费墙的必然性。
- 反推：任何把它 SaaS 化的方案，一上线就新增"云端存储 + 带宽 + 账号"三项持续成本 → 必须收费 → 立刻失去"免费对标物"优势。**这是这条路线的天花板，不是执行问题。**
