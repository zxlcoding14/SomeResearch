# PixelSwift — 产品分析报告（PM 视角）

> **分析对象**：PixelSwift（`pixelswift.site`）—— 浏览器端纯本地图片压缩 / 格式转换 / 尺寸调整工具
> **快照时间**：2026-10-10 16:41（实测连续 3 次抓取 + 英文站交叉验证）
> **分析目的**：**学它 + 判它**——回答「这套『本地 WASM + 免费无限 + SEO 截流』打法能不能收得到钱」
> **计数口径**：功能按「用户可感知功能」计；「已处理图片数」为站方自述、口径未披露（见附 C）
> **数据可信度分级**：① 经审计 ② API/页面实测 ③ 官方宣称 ④ 第三方估算 ⑤ 二手转载
> **本分析要回答的 3 个问题**：
> 1. 一个「断网都能用、边际成本为 0」的免费工具，凭什么收 $4/月？
> 2. 它的增长（8 语言 SEO + 竞品截流）是可持续的资产，还是一次性的流量脉冲？
> 3. 如果我要做同类工具，哪些直接抄、哪些必须避？

## 〇、结论先行（TL;DR）

1. **这是一个高质量的个人副业项目，但不是一门生意。** 作者在阮一峰《科技爱好者周刊》Issue #9499（2026-04-02）自荐时明说：「断网都能用，图片不离开本地，所以我也没什么服务器维系成本，**可以说是真正的白嫖且无限制**」【②一手自述】。**「没有服务器成本」这句话，恰好也是「订阅制不成立」的原因**——按 C 端方法论，**无持续交付成本 → 只能买断，硬做订阅必流失**。

2. **核心功能（压缩 / 转换 / 缩放）的免费替代覆盖率约 95%，定价天花板趋近 0。** 三个免费替代就把它压死：**Squoosh**（Google 出品，浏览器本地，**完全免费无限**，26,012★，**Apache-2.0**）、**Pixotter**（免费无限、无单次上限，且与它同为浏览器本地 WASM，几乎同构）、**系统自带**（macOS 预览 / Windows 照片 / 画图）。它自己用的 MozJPEG / OxiPNG 还是开源编解码器——**护城河为负**。

3. **它把唯一的付费理由押在「AI 助手」上，但这个功能存在产品逻辑硬伤。** 全站第一卖点是「**文件永不离开设备**」；而 AI 若要读图就必然上云、与承诺直接冲突；若只解析文字指令输出处理参数（从其预设按钮「推荐增强 / 压缩优化 / 转 WebP / 缩放 800px」推断），**那它就是一个包装成 AI 的预设按钮组，用户很难理解为何值 $4/月**。**这是全报告最关键的否定性结论：AI 助手目前撑不起订阅。**

4. **首页四项「社会证明」数字不可采信。** 实测连续 3 次 + 英文站均稳定为 `58,000+ / 60% / 3分 / 60张`，而搜索引擎快照显示的是 `76,800+ / 90% / 4.8分 / 100张`——**两套数值、且同页另有冲突**（hero 写 60% 压缩率、功能卡写「高达 90%」；hero 写批量 60 张、FAQ 写 100 张）。数字稳定说明是**手工维护的常量而非实时埋点**；「累计处理量」还会变小，逻辑上不成立。**→ 首页社会证明视为营销文案，不作依据。**

5. **它有一处必须立刻修的合规硬伤：隐私政策说「不使用任何广告服务」，页面却挂着 Google AdSense；并自称「GA4 无需 Cookie 同意」——而它恰好覆盖德/法/西/葡语市场。** 前者是**政策与事实不符**，后者在 GDPR / ePrivacy / LGPD 辖区属明确违规。**这是它最脆弱的攻击面，也是同类项目最容易踩的坑。**

6. **真正值得抄的是它的增长引擎，不是它的产品。** 7+ 篇内容**全部是竞品截流型**（「绕过 TinyPNG 的 20 张限制」「TinyPNG 替代方案：突破 500 张限制」「WordPress 不装插件压图」「Shopify 压图」）+ 8 语言 SEO + 阮一峰周刊 & Product Hunt 首发。**「把竞品的配额限制逐条变成自己的标题」是教科书级打法，可直接迁移到任何工具站。**

## 一、定位与口径（L0 + L1）

### 1.1 一句话定义（不贴品类词）

> **PixelSwift 让用户在不上传任何文件的前提下，把一批图片变小、换成别的格式、改到指定尺寸——整个过程发生在自己的浏览器里。**

**关键**：定义里没有「在线工具」这个词。一旦贴上，竞品集合会被锁死成「在线图片工具」；而它真正的对手是 **操作系统自带能力** 和 **免费开源替代**。

### 1.2 主体与项目画像（L0）

| 维度 | 事实 | 来源级别 |
|---|---|---|
| 项目性质 | **个人独立项目**（非公司）——联系页仅一个邮箱且做了防爬混淆（`[email protected]`），**无公司主体、无注册地址、无 VAT 信息** | ②页面实测 |
| 作者 | GitHub 用户 `zsk-coder`（在 `ruanyf/weekly` Issue #9499 自荐） | ②一手 |
| 首发曝光 | **阮一峰《科技爱好者周刊》Issue #9499**（2026-04-02）+ **Product Hunt**（站内 `?ref=producthunt` 参数） | ②实测+一手 |
| 技术栈 | **Nuxt 4** + 部署在 **Cloudflare Pages**；**WebAssembly 把 MozJPEG / OxiPNG 搬到浏览器本地**；Web Worker 分离运算 | ②作者自述+脚本指纹（Cloudflare Insights、@nuxtjs/sitemap v7.6.0） |
| 处理位置 | **100% 浏览器本地**（不上传、断网可用） | ②作者自述 + 隐私政策 |
| 站点语言 | **8 种**：en / zh / es / ja / de / fr / pt-BR / ko-KR | ②sitemap 实测 |
| 路由规模 | **19 条路由/语言**（11 主路由 + 7 博客 + 1 demo） | ②sitemap 实测 |
| 分析类服务 | GA4（gtag）+ Cloudflare Insights + **Google AdSense** | ②脚本指纹实测 |
| 支付通道 | **未发现任何支付 SDK 指纹**（Stripe / Paddle / LemonSqueezy / Creem / Gumroad 全部未命中） | ②实测（**注意：定价页已上线但支付链路无迹可寻，见附 C**） |

> **口径提醒**：本报告的「用户量」只能基于站方自述的处理量，而该自述已被证伪（见结论 4）。因此**本报告不对其绝对用户规模下强结论**，只做区间推算（附 B）。

## 二、功能全景与替代谱系（L1）

### 2.1 功能四层分层

| 层 | 功能 | 商业含义 |
|---|---|---|
| **T1 内核**（去掉不成立） | **图片压缩**（质量滑块 + 三档预设）· **格式转换**（7 种输入 → 4 种输出）· **尺寸调整**（像素/百分比/比例预设 + 旋转翻转） | 定价地基——但这三件事**免费替代覆盖率 95%**（见 §4.2） |
| **T2 增强**（提效可替代） | 批量 100 张 · 单文件 50MB · **压缩前后对比预览** · ZIP 打包下载 · 锁定宽高比 · 移动端适配 | 决定体验口碑；**TinyPNG 免费版每次仅 20 张 / 5MB——这是它主打的对比优势** |
| **T3 差异化**（只有它有） | **AI 助手**：自然语言描述需求 → 自动组合转换/压缩/缩放，构建批处理流水线（NEW） | **唯一可定价段**，但逻辑存疑（见 §5.3） |
| **T4 长尾** | 旋转/翻转 · 1:1 / 4:3 / 16:9 快捷预设 · 证件照尺寸参考 | 装饰性，勿作卖点 |

**格式支持明细**（②实测）：
- **输入**：JPG / PNG / WEBP / BMP / GIF / TIFF / AVIF
- **输出**：JPG / PNG / WEBP / AVIF
- 注：首页 FAQ 只列 JPG/PNG/WebP/AVIF 四种，转换页才暴露完整输入格式清单 → **首页功能表述少于实际能力，属宣传不到位而非虚标**。

### 2.2 替代方案谱系（六类，必须列全）

| 类型 | 具体替代 | 覆盖率 | 对撞后剩余 |
|---|---|---|---|
| ① 手动做 | 用 PS / 看图软件逐张导出 | 低 | 保留（批量省时间） |
| ② **系统内置（头号对手）** | **macOS 预览（导出可调质量/格式）· Windows 照片/画图 · iOS 相册导出即压缩** | **中高** | 只剩「批量 + 多格式 + 跨平台一致」 |
| ③ **免费开源（最强）** | **Squoosh**（Google，浏览器本地，免费无限，**Apache-2.0**，26,012★）· **Caesium**（桌面，GPL-3.0，6,377★）· sharp / libvips（库） | **极高** | **几乎为零** |
| ④ 竞品 | TinyPNG（云端，免费 20张/5MB）· iLoveIMG · Convertio · **Pixotter（浏览器本地，免费无限）** | 高 | 只剩「批量上限更宽 + 中文界面」 |
| ⑤ 外包/找人做 | — | 不适用 | — |
| ⑥ **忍着不做（成本 0）** | 图片大就大着用 / 用原图上传 | 高 | 需求本身是「痒点」而非「痛点」（见 §4.1） |

> **判定**：第 ②③ 类对撞后，**产品能守住的核心仅剩「批量 + 跨平台一致性 + 中文场景词」**——这三项都不足以支撑 $4/月。
> **「开源这一格必须逐条落地」**：Squoosh 的 **Apache-2.0** 是宽松许可，**可直接商用甚至闭源复用**——这意味着**技术上零门槛，任何人在一周内能复刻一个 PixelSwift**。这是本产品最根本的脆弱性。

## 三、用户、场景与频次（L2）

### 3.1 用户分层

| 角色 | 画像 | 付费动机 |
|---|---|---|
| **核心用户** | 前端开发者 / 博主（内容站优化图片） | 低（免费替代够用） |
| **高频用户** | 自媒体运营、电商美工（批量处理商品图） | 中（但这类人更可能买 TinyPNG 的 WordPress 插件或 API） |
| **隐私敏感用户** | 不愿图片上云的人（医疗、法务、个人隐私照片） | **中高——这是它真正的差异化人群** |
| **一次性用户** | 偶尔压一张图发邮件 | 无 |
| **付费者** | 需要 AI 助手做批处理流水线的人 | **存疑（见 §5.3）** |

### 3.2 JTBD 与频次

**JTBD 句式**：
> 「当**我手上有一批图太大、格式不对、尺寸不合，而且我不想把它们传到别人服务器上**的时候，我想要**一个打开就能批量处理的工具**，这样我就能**在不牺牲隐私的前提下立刻拿到可用的图**。」

| 频次维度 | 判断 | 商业含义 |
|---|---|---|
| **使用频次** | **低频、脉冲式**——写文章时、上架商品时、发邮件时才用 | ⚠️ **低频需求收不了订阅**（方法论铁律） |
| **单次时长** | 极短（秒级处理，即用即走） | 跳出率高——**第三方数据显示 TinyPNG 跳出率 65.28%**，本类产品结构相同 |
| **付费触发** | 几乎不存在「必须付费才能完成」的时刻 | **它的付费墙不挡路，所以没人翻**（见 §5.2） |

> **核心洞察**：这**不是一个高频工具**。用户一年可能只是偶尔来几次，每次几十秒。**这种频次结构下，任何订阅制都建立在「用户忘记取消」而非「持续获得价值」上**——这是收入质量最差的一类订阅。

### 3.3 频次 × 心理价位

| 频次 | 价位锚点 | 本产品匹配度 |
|---|---|---|
| 日频 / 周频 | 对标「每天省 N 分钟」 | ❌ 不符合 |
| 月频 | 对标「一次打车」 | ⚠️ 勉强 |
| **一次性 / 偶发** | 对标「一次外包报价」 | ✅ **实际属此档 → 只能买断或按次** |

> **判定**：**$4/月 的月付订阅与其「偶发使用」的频次结构严重错配。** 若必须变现，**买断制（如 $9 终身）或按量计费（如 $5 / 500 张）**在心理上更成立。**这是本报告对定价的核心建议。**

## 四、价值主张与需求硬度（L3）

### 4.1 痛点 / 痒点 / 爽点判定

| 需求点 | 类型 | 强度（P0–P5） | 依据 |
|---|---|---|---|
| 图片太大导致网页变慢 | **优化点** | P2 | 站长在意，但「不做也不会出事」 |
| TinyPNG 的配额限制恶心人 | 痒点（情绪驱动） | P2 | 作者自述的创业动机就是「被限制弹窗搞烦了」——**这是「替代品更爽」，不是「没有就活不了」** |
| 图片不能上传（隐私/合规） | **痛点** | **P3** | 医疗、法务、涉密行业真实存在；**这是唯一有硬度的一条** |
| 批量 100 张一次搞定 | 爽点 | P2 | 提效，可被替代 |

> **判定**：**没有 P4 以上的强痛点。** 它的立命之本是「**别人有限制，我没有**」——这是**替代品优势**，不是**需求硬度的证明**。方法论提醒：**「用户吐槽多」≠「痛点强」**；TinyPNG 被吐槽了十年，照样做到月访问 256 万。

### 4.2 卖点对撞免费替代（逐条）

| 卖点 | 免费替代能否覆盖 | 覆盖率 | 可定价部分 |
|---|---|---|---|
| 图片压缩 | Squoosh（免费无限）、系统预览 | **95%** | ≈ 0 |
| 格式转换（含 AVIF） | Squoosh（支持更多编解码器）、Caesium | **95%** | ≈ 0 |
| 尺寸调整 | 系统预览、Squoosh（也有 resize） | **90%** | ≈ 0 |
| 批量 100 张 | Pixotter（免费无限、**无单次上限**，比它还宽） | **95%** | ≈ 0 |
| 单文件 50MB | Pixotter（**无文件大小限制**） | **100%** | ≈ 0 |
| **文件不上传** | Squoosh / Pixotter / Caesium **同样是本地处理** | **90%** | ⚠️ **它主打的「隐私」并非独占** |
| **AI 助手** | 无免费等效品 | **10%** | ✅ **唯一可定价段** |

> **关键打击**：它最自豪的两个卖点——「**文件不上传**」和「**无限制批量**」——**Squoosh 和 Pixotter 都已经免费提供了，且做得更彻底**（Squoosh 支持的编解码器更多，Pixotter 没有单次张数上限）。**它不是「唯一做本地处理的」，只是「中文 SEO 做得最好的那个」。**

## 五、商业模式与付费墙（L4）

### 5.1 定价结构（②实测 pricing 页）

| 方案 | 价格 | 内容 |
|---|---|---|
| **Free** | **$0 / 永久免费** | 压缩无限次 · 转换无限次 · 缩放无限次 · 批量最多 100 张 · 单文件 50MB · **AI 助手 3 次体验** · 无优先支持 |
| **Pro**（标注 MOST POPULAR） | **$4 / 月** | Free 全部功能 + **AI 助手 100 次/月** + 自然语言驱动 AI 处理 + AI 自动构建处理流水线 + 优先邮件技术支持 |

**附加变现**：Google AdSense 展示广告（`ca-pub-7567205058563091`）
**退款政策**（②实测）：购买起 **7 天内**可全额退款，**每账户仅一次**

### 5.2 付费墙位置与有效性判定

| 判定项 | 判断 |
|---|---|
| 墙型 | **用量墙**（AI 助手 3 次 → 100 次/月） |
| 墙的位置 | **建在 AI 上，而非建在核心功能上** |
| **能不能挡路？** | ❌ **完全挡不住**——核心功能（压缩/转换/缩放）**无限免费**，用户根本不经过付费墙就能完成 95% 的任务 |
| 持续交付成本 | ⚠️ **核心功能无成本**（WASM 本地，零边际成本）；**仅 AI 有成本** |
| **订阅是否成立** | ❌ **按方法论判定：无持续交付成本 → 订阅不成立**。整个订阅建立在最薄的那一层（AI）上 |

> **这是本产品商业模式的根本矛盾**：它把「无限免费」当作获客卖点（因为它确实没成本），又想在同一个产品里收订阅（但订阅需要持续成本的理由）。**「零边际成本」既是它的武器，也是它收不到钱的根因。**
> **方法论原文**：「**没有 → 订阅不成立，只能买断。**」

### 5.3 「完全免费」与「$4/月」的公开冲突（重要）

**首页 hero 区**（②实测原文）：
> 「完全免费——图片压缩、格式转换与尺寸调整均可免费使用，**无水印、无限次使用、无需注册**」
> FAQ：「PixelSwift 真的免费吗？有隐藏费用吗？——**是的**，…没有隐藏费用、没有水印、**没有使用限制**，无需注册即可使用。」

**但**：导航栏有「定价」，页脚有「退款政策」，pricing 页有 $4/月 Pro。

**证据链（可复现）**：
1. 作者 2026-04-02 的自荐帖**完全没提付费**，只说「绝对隐私和免费…真正的白嫖且无限制」【②一手】
2. 隐私政策最后更新 **2026-03-20**，退款政策 **2026-04-29**——**退款政策晚于自荐帖**，说明 Pro 是**首发曝光之后追加的**
3. 结论：**首页 hero 文案停留在「免费版」时代，未随 Pro 上线同步更新** → 用户从「完全免费」的 hero 跳到「$4/月」的定价页，会产生被欺骗感

> **PM 判断**：这是**典型的「增长在前、商业化在后」导致的话术断裂**。修复成本极低（改一句 hero 文案），但**不修会持续损耗转化与信任**。

### 5.4 AI 助手的产品逻辑硬伤（本报告最关键判断）

从实测页面推断其实现方式：

| 证据 | 推论 |
|---|---|
| 入口文案：「上传视觉素材并**描述你的优化需求**」 | 输入是**文字描述** |
| 预设按钮：「推荐增强 / 压缩优化 / 转换为 WebP / 缩放至 800px」 | 输出是**处理参数组合** |
| 全站第一承诺：「文件始终留在你的设备上，**不会上传到任何地方**」 | 与「AI 需要读图」互斥 |

**两种可能，两种结局**：

| 若 AI 的实现是… | 后果 |
|---|---|
| **A. 只解析文字 → 输出处理参数**（不上传图片） | ✅ 与隐私承诺一致，**但功能价值极低**——本质是「把 4 个预设按钮换成一句话」，**用户看不出为何值 $4/月** |
| **B. 上传图片给视觉模型分析** | ❌ **与全站核心承诺直接冲突**——「文件永不上传」变成假话，构成**虚假宣传风险** |

> **结论（否定性）**：**AI 助手目前撑不起 $4/月订阅。** 若是 A 方案，它需要**显著加深**（如：自动识别图片类型与用途、给出可解释的优化建议、按平台要求一键产出全套尺寸）；若是 B 方案，**必须立刻修改隐私承诺的措辞**，否则是比「收不到钱」严重得多的风险。
> **给作者的直接建议**：AI 助手的价值必须建立在「**读图**」之上（识别是截图/商品图/人像/文档，再给差异化方案）——但那要求它**诚实地重写隐私政策**，明确说明「核心处理本地完成，AI 分析需要上传」。

## 六、盈利模型与生存线（L4.5 + 测算）

### 6.1 成本结构（这是它最大的优势）

| 成本项 | 金额 | 说明 |
|---|---|---|
| 服务器 / 算力 | **≈ $0** | WASM 在用户浏览器跑，**算力由用户承担**——这是方法论里点名的「把边际成本压到 ≈0」的路径 |
| 带宽 | **≈ $0**（静态资源走 Cloudflare Pages 免费额度） | 无需上传下载图片 |
| 域名 + CDN | **≈ $10–15/年** | 主要固定成本 |
| **AI 助手调用成本** | **仅此项有变动成本** | 见下 |
| 时间机会成本 | **未取得**（个人副业，难以折算） | — |

> **结论**：**除了域名和 AI 调用，它几乎没有成本。** 这意味着它**不会死**（可无限期免费运营），但也意味着**它没有「必须收到钱」的压力**——这解释了为什么它的商业化如此敷衍。

### 6.2 AI 助手的边际成本红线

**公式**：`定价 > 单次调用成本 × 每人月均调用次数 × 安全倍数`

| 变量 | 取值 | 依据 |
|---|---|---|
| Pro 定价 | $4/月 | ②实测 |
| 含 AI 额度 | 100 次/月 | ②实测 |
| **单次可承受成本** | **$0.04 / 次** | `$4 ÷ 100` |
| 实际 LLM 成本（若纯文本解析） | **≈ $0.0002–0.002 / 次** | 短文本 + 结构化输出，用轻量模型即可【推算·类比当前 API 价目】 |
| 实际成本（若需视觉分析） | **≈ $0.003–0.02 / 次** | 视觉模型输入图片，成本高一个数量级 |

**推算结果**：
- 若为**纯文本解析**：单次成本约为定价的 **0.5%–5%** → **毛利极高，安全**
- 若为**视觉分析**：单次成本达定价的 **7.5%–50%** → **仍在安全线内，但重度用户（用满 100 次）可能接近盈亏平衡**
- **敏感度**：若用户平均只用 20 次/月（而非 100 次上限），成本进一步降至 `$0.004–0.4/月` → **无论哪种实现都安全**

> **判定**：**边际成本不构成否决项。** 真正的否决项是**需求**（用户为什么要为它付费），不是成本。

### 6.3 收入推算（方法：自述处理量反推）

> ⚠️ **前置声明**：本测算的输入（「58,000+ 已处理图片」）**已被证伪为不可信常量**（见结论 4）。因此**以下推算置信度低，仅作数量级参考**，不作为结论依据。

- **推算**：`2,900 ÷ 7 ≈ 414` 次处理会话/月

**⚠️ 与曝光渠道的冲突**：它在**阮一峰周刊 + Product Hunt** 上过首页/推荐位，理论上单次曝光可带来数千 UV。若按「脉冲式流量」修正，峰值月份可能是上述数字的 **5–10 倍**，但**脉冲后回落**。→ **真实形态更可能是「曝光月 ¥2,000–3,000、平峰月 ¥300–500」的剧烈波动曲线。**

> **判定**：**这是典型的「副业级」收入（月均数百至数千元）**，与「商业产品」相距甚远。**印证结论 1。**

### 8.3 开源替代专项实测（覆盖度五级判定）

| 项目 | Stars【②API 实测·采集日 2026-10-10】 | 许可 | pushed_at | 覆盖度等级 | 结论 |
|---|---|---|---|---|---|
| **Squoosh**（GoogleChromeLabs） | **26,012** | **Apache-2.0** | 2026-10-07（活跃） | **L3 活跃成品 + L4（官方免费）** | ⛔ **最强打击**：Google 出品、浏览器本地、完全免费、**宽松许可可直接复用** |
| **Caesium** | 6,377 | **GPL-3.0** | 2026-10-05（活跃） | L3 活跃成品 | 🔴 桌面端免费替代；**GPL 传染 → 不可闭源复用** |
| sharp / libvips / mozjpeg / oxipng | 【未取得】 | 多为 Apache-2.0 / MIT | — | **L1 有库无产品** | ✅ **这才是可复用底座**（PixelSwift 正是这么做的） |

> **关键区分（方法论要求）**：
> - **Squoosh 与 Caesium 是「开源竞品」** → 抢它用户，结论是**威胁**
> - **mozjpeg / oxipng / wasm 编解码器是「开源底座」** → 替它省成本，结论是**杠杆**
> - **两者结论相反**。PixelSwift 正确地用了「底座」（MozJPEG/OxiPNG），却无法摆脱「竞品」（Squoosh）。
> **踩坑警告**：若自研同类产品，**绝不能复用 Caesium（GPL-3.0，传染）**；若要用 Squoosh 的代码，**Apache-2.0 允许闭源商用，但需保留版权声明**。

### 8.4 定价天花板公式

```
定价天花板 ≈ min(竞品价格, 人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)
```

| 能力段 | 免费替代覆盖率 | 天花板 |
|---|---|---|
| 压缩 / 转换 / 缩放 | **95%** | ≈ 5% × $4 ≈ **$0.2/月**（趋近 0） |
| 批量 + 大文件 | **95%**（Squoosh/Pixotter 均无限制） | ≈ **$0** |
| **隐私保护（不上传）** | **90%**（Squoosh/Pixotter 同样本地） | ≈ **$0.4/月** |
| **AI 助手** | **10%** | ✅ **可定价空间最干净** |
| **WordPress 自动化**（它没做） | 0%（TinyPNG 独有） | ✅ **未被覆盖，但它没做** |

> **结论**：**「免费无限 + 本地处理」这个组合本身，已经被证明是「不值钱」的**——因为 Squoosh 免费给了。**唯一的定价地基是 AI，第二块空着的地（WordPress 自动化）它没去占。**

## 附 B、测算过程与敏感度（与实测分开排版）

### B.1 月收入推算（方法 B：自述处理量反推）

- **假设 1**：累计处理图片 58,000 张【③站方自述，**已被证伪为常量**】
- **假设 2**：每次会话平均处理 20 张【推算·按批量使用场景】
- **推算**：`58,000 ÷ 20 = 2,900` 次累计会话
- **假设 3**：运营 7 个月（2026-03 至 2026-10）
- **推算**：`2,900 ÷ 7 ≈ 414` 会话/月
- **假设 4**：会话 / UV = 0.6
- **推算**：`414 ÷ 0.6 ≈ 690` UV/月
- **假设 5**：转化率 0.3%（P50）【推算·类比免费工具站】
- **推算**：`690 × 0.3% ≈ 2 人/月` → 累计付费用户 ≈ 15 人（假设 7 个月累计、月流失 10%）
- **结果**：`15 × $4 = $60/月` + AdSense `690 × $4/1000 = $2.8` ≈ **$63/月（¥450）**
- **区间**：**$21 ~ $104（¥150 ~ ¥750）**
- **置信度：低**（输入数据不可信 + 多层假设）
- **推翻条件**：作者公开真实 UV / 付费数；或第三方流量平台数据

### B.2 脉冲流量修正

- 若阮一峰周刊 + Product Hunt 各带来 **3,000–8,000 UV** 的脉冲
- 按 0.3% 转化 → 单次脉冲新增 **9–24 付费用户**
- 但 SaaS 类工具站的 12 个月留存通常 **30%–50%** → **脉冲用户大量流失**
- **修正结论**：收入曲线呈「**尖峰 + 快速回落**」，**不适合用线性年化**

### B.3 AI 助手边际成本

- **公式**：`可承受单次成本 = 定价 ÷ 额度 = $4 ÷ 100 = $0.04/次`
- 纯文本解析：$0.0002–0.002/次 → **占定价 0.5%–5%（安全）**
- 视觉分析：$0.003–0.02/次 → **占定价 7.5%–50%（仍安全）**
- 若实际月均仅用 20 次：成本降至 **$0.004–0.4/月**
- **结论**：**边际成本不是否决项；需求才是。**
