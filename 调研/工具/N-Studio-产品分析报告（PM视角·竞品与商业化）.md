## 〇、结论先行（TL;DR）

1. **这是一次「用 27,750★ 免费开源项目养出信任资产，再用闭源产品收钱」的完整转轨 —— 但结构正确、增量不足。** N-Studio 不是新产品，是 **ScreenToGif 的官方继任者**（同一位作者、官网明写"the successor of ScreenToGif"），闭源、上微软商店、免费版 $0 + 专业版 **$36 买断 / $3 月**、企业版 **$6 / 人 / 月**。作者自述"This is a one developer endeavor"。

2. **【否定性结论 · 最硬的一条】它最大的威胁不是竞品，是它自己的前身。** Windows 11 已经把「录屏 → 剪辑」这条链免费打通（Snipping Tool 录屏 `Win+Shift+R` → **一键 Edit in Clipchamp**）；ScreenToGif 免费开源、功能高度重叠且仍在更新；ShareX（39,925★）与 OBS（77,128★）免费覆盖录制与多轨剪辑。按功能逐条对撞，**免费替代覆盖率推算 ≈ 75%–85%**（附 B）。而 N-Studio 的免费版把「录制 + 音频 + 基础调整」整层送掉，且明确「无限制 / 无水印 / 无广告」——**三种最有效的付费墙被主动放弃，只剩功能墙一层**。

3. **分发侧的差距是量级性的，不是百分比的。** ScreenToGif 单个版本（2.43.2，2026-07-28）仅 x64 安装包一个通道就 **187,134 次下载**【二手】；N-Studio 最新 1.7.3 的 MSIX + 便携包合计 **5,908 次**【二手转述官网计数】；微软商店 US / BR / CN 三地条目**均为 0 条评价**【实测】。按 6 个月约 8 个版本推算，N-Studio 直链累计下载 P50 ≈ **3.3 万次**，对应年营收 P10–P90 ≈ **$0.8 万 – $4.5 万**（【推算·方法 B2】，置信度低）。**这个体量能养活一个巴西的独立开发者，但不构成一门可扩张的生意。**

4. **唯一有真实空位的能力是 Region Share（区域投放），但空位很窄。** Zoom 自带「Portion of Screen」（免费）；Meet / Teams 无原生区域分享 —— 这是真实空位，且作者把它做成了「共享一个镜像窗口」的通用解法（任何会议软件都能用）。但市面上已有 **Partial Screen**（freemium，未授权 4 分钟限制）与 **Conjuly**（付费）两家专做这件事。**空位窗口估计 < 18 个月。**

5. **对「我要不要进这个方向」的回答是：不进。** 用 C 端加固版 12 维打分卡（满分 135）评「桌面录屏 + 轻剪辑」这一方向，得 **66 分 ≈ 48.9%**，低于「直接杀」的 50% 阈值；同时触发**一票否决第 3 条（依赖单一 OS 平台，一个系统版本更新即可被内置）**。**可迁移的不是「做录屏工具」，而是三条机制**：① 开源前身 → 闭源商业化的**用户池继承路径**；② 买断 / 订阅双轨的**定价结构**（$36 一次性 vs $3/月 → 12 个月回收期）；③ 「共享镜像窗口」这种**绕过平台限制的窄能力识别法**。

## 二、是什么（L1）

### 2.1 一句话定义（**不贴品类词**）

> **它让一个人在不离开同一个窗口的前提下，把屏幕上的操作过程变成一段可以直接发出去的成品视频 —— 包括把屏幕上的一小块区域实时「投」进任何会议软件。**

### 2.2 品类归属与内核

| 项 | 判定 |
|---|---|
| 陌生用户会把它放进哪个货架 | 录屏工具（screen recorder）；**次级货架：轻量视频编辑器**；**它自己争的货架是「一体化的捕获—编辑—分享」** |
| 最小可用内核（删掉所有包装后用户为什么装它） | **「录屏 → 剪辑 → 导出」不用换软件**（官网原话：Record… Then refine everything in a full editor） |
| 真正的差异化内核 | **Region Share**：选屏幕一块区域 → 生成一个可被任何会议软件共享的镜像窗口（含光标、点击、按键、跟随光标） |
| Non-scope（它明确不做什么） | 不做直播推流（无 RTMP/推流场景）；不做云存储与在线协作（无云服务层）；不做会议录制（不接会议 SDK）；不做移动端 / 浏览器端；**不做多平台**（MS Store 与下载页只有 Windows） |
| 交付形态 | Windows 桌面原生应用；`msix`（商店 / 侧载）、`msi`（安装器）、`portable zip`（便携）三种部署 × x64 / arm64 两种架构 × Free / Pro / Light 三种变体（**前端产物枚举实测**） |
| 授权与后端 | 闭源；账号体系 + 订阅授权 + 多租户管理后台；支付走 **Paddle**（`paddleToken: live_7478…`，24 种货币，含 USD/EUR/BRL/CNY/JPY/TWD）|

### 2.3 产品线关系（本文最重要的一张背景表）

| | **ScreenToGif**（前身 / 并存） | **N-Studio**（本报告对象） |
|---|---|---|
| 上线 | 2016-08-02（GitHub 建仓） | 2026-04-09 发布，2026-04-28 上架微软商店 |
| 授权 | **MS-PL（开源）** | **闭源商业** |
| 价格 | **¥0**（含赞助 / 捐赠） | $0 免费版 + $36 买断 / $3 月 / 企业 $6 人月 |
| Stars | **27,750**（2026-10-08 实测） | 无公开仓库 |
| 最后提交 | 2026-07-28 🟢（**未死**） | 1.7.3（2026-09-01） |
| 包体 | 71.7 MiB（MSI）| 296.5 MB（商店）/ 221.73 MiB（appx）/ 79.5 MiB（MSIX 直链）|
| 定位关系 | 官网首页挂横幅："N-Studio, the new screen recording experience, is now live!" | 官网首页："the successor of ScreenToGif, made by the same developer :)" |
| 下载（对照口径） | 单版本单通道 187,134 次（2.43.2 x64 安装包）| 单版本双通道 5,908 次（1.7.3）|

> **读法**：这不是「新产品 vs 老产品」，是**同一个人的两代产品并存**。老的一代免费、开源、27.7K★、仍在更新；新的一代闭源、收费、6 个月、0 评价。**这条并存关系决定了 N-Studio 的全部商业难题**（详见 §五、§九）。

### 2.4 功能全景（T1–T4 四层分层）

| 层 | 定义 | N-Studio 的能力 | 商业含义 |
|---|---|---|---|
| **T1 内核** | 去掉它产品不成立 | 屏幕录制（区域 / 窗口 / 全屏）· 帧率控制（常规 1–60fps / 手动 F7 / 用户交互触发）· 捕获光标、点击、滚轮 · 捕获按键 · 麦克风 / 系统音频采集 | **定价的地基**——但这层**已被 Windows 11 内置 100% 覆盖**（见 §九）|
| **T2 增强** | 提效但可替代 | 声音录制（**多麦克风 + 多输出同时采集**）· 快速调整（trim / crop / resize / 换轨 / 改帧率 / 改速度）· 多格式导出（APNG/GIF/WEBP/MP4/MKV/MOV/WEBM/MP3/WAV/FLAC/ALAC/OGG/PSD/NSM/STG/JPG/PNG/BMP/AIF/HEIC）| 决定体验口碑；**这一层也被免费送掉了** |
| **T3 差异化** | 只有它有 / 少有人做 | **Region Share（区域投放，1.1 版新增）** · 多轨时间线编辑器（图层 / 媒体 / 文本 / 形状 / 手绘 / 马赛克 / 进度指示条）| **卖点来源**——但只有 Region Share 通得过免费替代对撞（编辑器那半被 Clipchamp + ScreenToGif 覆盖）|
| **T4 长尾** | 低频 / 边缘 | 亮度补偿 · 10-bit SDR gamma 校正（针对 AMD 核显）· BitBlt vs DesktopDuplication 采集方式切换 · 内存缓存 / 压缩强度 / 强制内存回收等工程参数 · 捕获频率自定义 | 典型的「看起来很强」的装饰——**这层全是坑，不是卖点** |

**付费墙切在哪一层（这是关键判读）**：切在 **T3**。
- 免费（Starter）拿到：T1 全部 + T2 全部（含隐藏光标、系统音频开关、框选边框——**这三样恰恰没被塞进付费墙，Windows Central 的评测专门称赞了这点**）+ 无水印 / 无广告 / 无限制
- 专业（Professional）拿到：额外捕获频率、**timelapse / long timelapse**、改动画帧率、改播放速度、**完整多轨编辑器（插入图层 / 效果 / 分割片段）**

> **PM 判读**：墙的位置选得**有品味但在商业上偏软**。它把最容易被免费替代的一层（T1 录制）免费送出去换口碑，把最难被免费替代的一层（T3 编辑）拿来收费——这个方向是对的；但它同时放弃了水印墙、用量墙、时间墙三种墙型，**只剩一层功能墙**，而 ScreenToGif（免费）恰恰有多轨编辑器。**等于用「免费替代已经免费给过的东西」去收费。**

## 四、用户、场景与频次（L2）

### 4.1 用户分层（谁用 / 谁付）

| 层 | 是谁 | 他们真正要什么 | 会不会付钱 |
|---|---|---|---|
| **核心用户** | 做教程 / 产品演示 / 远程培训 / 技术支持视频的人（**官网自己点的场景**）；开发者提 issue 录复现步骤 | 一条能直接发出去的成品视频，过程可见（点击 / 按键 / 光标）| **大概率不付**——T1 已被免费覆盖 |
| **边缘用户** | 教师 / 学生 / 自媒体 / 远程参会者 | 快速录一段 + 简单剪 | 不付 |
| **付费方（3 种）** | ① 被时间成本逼的人（不想 OBS 录完再进剪辑软件再转码）② 需要「点击/按键可见」做教学的人 ③ **企业 IT / 培训部门（按席位买）** | 省流程；或者 **可交代的批量授权** | ③ 最可能付 |

### 4.2 触发场景（JTBD 句式）

> **当我在 ___ 的时候，我想要 ___，这样我就能 ___**：
- 当我**要给同事讲清一个 bug 是怎么复现的**时，我想要**录一段带点击高亮和按键显示的短片**，这样我就能**不用反复文字解释**。
- 当我**在做产品演示 / 培训，要共享一块区域而不是整屏**时，我想要**只把这块区域投进会议**，这样我就能**不暴露通知和其他窗口**。
- 当我**要交一份 30 分钟的教程**时，我想要**录完直接在多轨里剪、加字幕和标注、再导出**，这样我就能**不装三个软件**。

### 4.3 频次判定（决定能否收订阅）

| 场景 | 频次 | 模式含义 |
|---|---|---|
| 提 issue 级录屏 | **一次性 / 偶发** | 只能免费，硬收订阅必流失 |
| 教程 / 演示 / 培训录制 | **周频（做内容的人）/ 月频（一般职场）** | 订阅勉强成立，需强价值 |
| 区域投放到会议 | **日频–周频**（高频开会的人） | **唯一撑得起订阅的场景**，但 Zoom 免费自带 |
| 企业内部培训视频 | **项目制（季度级）** | 偏买断 / 席位授权 |

> **结论**：整体是**「周频 + 一次性的混合需求」**，不是高频。**这样的频次里，$3/月的订阅结构比 $36 买断更脆弱**——而官网把订阅标成了「most popular」。这是设计意图（现金流稳定）与需求现实（低频）的错配。

### 4.4 切换成本

| 从谁切过来 | 成本 | 判断 |
|---|---|---|
| Windows 内置 Snipping Tool | **0**（学习成本为负）| 极难抢 |
| OBS | 中（场景/来源配置、编码参数）| **这才是 OBS 的真实护城河：配置成本**，而 N-Studio 的「简单」正好打这里 |

## 七、盈利模型与生存线（L4.5）

### 7.1 三个公式（代入附 B 的推算）

```
年营收 = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利 = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本
```

**代入（口径见附 B，全部为推算）**：

| 项 | 值 | 来源 |
|---|---|---|

| 免费→付费转化率 | P50 = 2%（区间 1%–3%）| 【推算·方法 C，类比同类桌面工具】|
| 付费用户（6 个月累计新增）| P50 ≈ 660（区间 350–1,650）| 计算 |

| 支付费率 | 5% + $0.5/笔（Paddle 常见档）| 【推算·方法 D，需回官方页重核】|

| **时间机会成本**（最容易被漏掉的一项） | 一个人 6 个月全职 → 按巴西中高级工程师年薪 $25–40K 折半计，**≈ $12.5–20K** | 【推算·方法 D】|

> **盈亏平衡判读**：以**现金成本**算，$2.2 万年营收 **早已越过 $700 的固定成本线** —— 它"活着"；以**时间机会成本**算，$2.2 万 vs $1.25–2 万的机会成本，**刚刚擦线或略亏**。
> **这就是本产品最真实的状态：它不是亏损项目，也不是生意，是一份「按市场价被低估的打工」。** 唯一能救它的变量是 B 端席位（$6/人/月，边际交付成本仍 ≈ 0，但需要销售与合规背书）。

### 7.2 客单价 × 分发难度匹配（方法论关键表）

| 客单价档 | 所需用户量级 | 对分发能力的要求 | N-Studio 实际能力 |
|---|---|---|---|
| **$3–36 / 单用户**（本产品所在档）| **需要海量** | **必须有规模化渠道** | ❌ 只有微软商店自然流量 + 前身项目导流 + 媒体一篇测评 |

> **核心诊断**：**它把客单价定在了「需要海量分发」的档位，却只有「几个自然渠道」。** 解法只有两条——**要么把客单价提上去（做 B 端席位 / 专业版），要么把分发做起来（内容复利 / 插件市场 / 前身项目内导流）**。它现在两条都在半途。

### 9.4 系统内置威胁（**本题必答**）

| 问题 | 判定 |
|---|---|
| 如果 OS 把它做成系统功能，它还活吗？ | ⚠️ **T1 已经发生**：Windows 11 Snipping Tool 内置录屏（`Win+Shift+R`）+ 麦克风 + MP4 + 一键 Edit in Clipchamp → **「录屏 + 剪辑」这条链已被官方免费打通，这正是 N-Studio 的核心价值主张** |
| 有没有还活着的部分？ | ✅ 有三个：① Region Share（OS 不做）② 事件可视化（点击/按键，OS 不做）③ 多音源与精细帧率控制（OS 不做）|
| **开源覆盖度五级判定（L4 检查）** | 屏幕录制 = **L4（OS + 开源双覆盖）→ ⛔ 按方法论应「直接砍」**；但产品整体不等于单能力，故**判为「T1 已被砍，靠 T3 续命」** |
| 「它会被什么吃掉」 | ① **Windows 下一个大版本给 Snipping Tool 加系统音频 / 光标特效 / 简易多轨** ② Clipchamp 加录制入口 ③ 前身 ScreenToGif 免费更新覆盖 ④ 免费开源项目补上 Region Share（**这是一个小功能，社区一周能做出来**）|

### 9.5 定价天花板（方法论公式）

```
定价天花板 ≈ min(竞品价格, 人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)
```
| 变量 | 取值 | 说明 |
|---|---|---|
| 竞品价格 | $39/年（Snagit）| 三口径取最小 |
| 人力替代成本 | 高（外包剪 1 条 ¥100–500，但录屏本身几乎无替代人力）| 实际不构成约束 |
| 损失规避金额 | 低–中（Region Share 的隐私风险规避，仅对合规敏感组织成立）| |
| 免费替代覆盖率 | **75%–85%**（附 B）| |
| **天花板** | **≈ $39 × 0.2 ≈ $8/年**（若覆盖 80%）| ⚠️ 公式是**方向性诊断，不是精算** |

> **PM 判读（重要）**：这个公式给出 $8/年，而实际定价 $36 买断 / $30/年——**高出 4 倍左右**。但**不要据此说"它定价错了"**。真实结论是：**$36 这个价位锚得很准（压在 Snagit $39 年费下），但它需要「免费替代覆盖率 < 50%」才支撑得住。** 覆盖率与定价之间出现了 30 个百分点的落差 —— **这个落差就是它转化率低的机制性原因**，也是本项目最值得记住的一条。

### 11.4 若仍要进场：唯一的窄切口与最小验证

**唯一的窄切口**：**「录制 → 结构化交付」这一段**（不是「录制」）。
- 为什么：T1/T2 已死（L4），T3 里编辑层是 L3，**只有「录完之后自动变成可直接交付的东西」这一段尚无人做**——自动章节切分、要点摘要、点击热点总结、可搜索的文字稿、按步骤拆好的 GIF/短视频、可嵌入知识库的结构化包。
- 为什么这段能挂订阅：**它需要真实持续交付成本**（转录 / 模型调用 / 存储 / 索引），订阅结构自洽；且它天然落在 B 端（培训 / 客户支持 / 内部知识库），付费理由是「可交代」而不是「省时间」。
- 但它已经不是「mini-tool」，而是「工作流 + 内容管线」——**超出个人开发者「窄而深」的最优形态**，需要重新评估客体匹配度。

**最小验证（写死，不许临时放宽）**

| 步骤 | 动作 | 通过门槛 |
|---|---|---|
| 1 | 在 2 个真实社群（例如某 SaaS 的客户成功团队 / 某高校教发中心）**人肉代做** 5 条「录屏 → 结构化视频」，收 ¥300/条 | **≥3 人付款**（收钱才是强信号）|
| 2 | 观察他们是否**第二次**来找你做 | ≥2 人复购 |
| 3 | 只有同时满足 1+2，才进入原型 | 任一不满足 → **杀掉** |

### 11.5 一句话总回答

> **N-Studio 是一份质量很高、定位很准、定价很对，但「免费替代覆盖率高出定价承受力 30 个百分点、且分发量为零」的产品。**
> 它最值得学的不是产品，是**一个人如何用十年开源积累换一次商业化机会**；
> 它最值得警惕的是——**当你的前身免费且更成功时，你的付费产品必须先回答「比免费少了什么」这个问题，而不是先回答「比竞品多了什么」。**

## 附 B、测算过程（**与实测分开排版**）

> 纪律：每条预估写成 **假设 → 依据 → 推算 → 结果**，附 **置信度** 与 **敏感度**。

### B1 免费替代覆盖率（**本报告最核心的一条推算**）

- **假设**：把产品拆成 12 个「用户可感知的最小能力单元」，按 ① 是否被免费替代完整覆盖 ② 该能力在用户决策中的权重（高 3 / 中 2 / 低 1）加权。
- **依据**：见 §三 / §5.2 的逐条对撞表；免费替代清单来自 §A.4（微软官方页 + 开源实测）。
- **推算**：

| 能力单元 | 权重 | 是否被免费完整覆盖 | 加权覆盖分 |
|---|---|---|---|
| 屏幕录制（区域/窗口/全屏）| 3 | ✅ Snipping Tool | 3 |
| 帧率控制 1–60fps | 2 | ⚠️ Snipping Tool 不定帧，OBS 可 | 1.6 |
| 光标 / 点击捕获 | 2 | ✅ ScreenToGif / ShareX | 2 |
| 按键捕获 | 2 | ✅ ScreenToGif | 2 |
| 麦克风音频 | 3 | ✅ Snipping Tool / OBS | 3 |
| 系统音频 | 2 | ✅ OBS | 2 |
| 多音源同采 | 1 | ✅ OBS 多音轨 | 0.8 |
| 快速调整（trim/crop/resize/速度）| 3 | ✅ Clipchamp / ScreenToGif | 2.4 |
| 多轨编辑器（图层/文本/形状/手绘/马赛克）| 3 | ✅ ScreenToGif（同源免费）/ OBS | 2.4 |
| 20 种格式导出 | 1 | ✅ ffmpeg / ScreenToGif | 1 |
| **Region Share 区域投放** | **3** | ⚠️ 部分（Zoom 仅本体、第三方受限）| **0.9** |
| 17 语言本地化 | 1 | ✅ OS 级本地化 / 开源多语言 | 1 |
| **合计** | **26** | | **22.1** |

- **结果**：覆盖率 = 22.1 ÷ 26 = **85.0%**（基准）。
- **置信度**：**中**（权重分配带主观性；覆盖事实本身为实测）。
- **敏感度**：若把「多轨编辑器」判为**未**被完整覆盖（用户认为 ScreenToGif 编辑体验差）且权重降到 2，则覆盖率降至 **80.4%**；若把 Region Share 判为**完全未**覆盖（权重 3、覆盖分 0），覆盖率降至 **79.2%**。
  → **区间结论：75%–85%。** 无论取哪一端，都在「免费替代覆盖率 > 75%」这一档，结论不翻转。

### B2 N-Studio 累计下载量与营收

- **假设 A**：各版本下载呈「首发高、后续衰减」分布，后发补丁版本累计下载约为首发版本的 0.7 倍。
- **依据 A**：ScreenToGif 的通道结构显示主通道（MSI）占三通道累计的 82%（169,094 ÷ 205,060），说明**渠道集中、下载主要来自单一入口**；N-Studio 仅有 MSIX + 便携两通道（无 MSI 直链披露），故单版本量级应低于 ScreenToGif 同结构口径。
- **推算 A**：已知 1.7.3（发布 5.2 周）= 5,908。可考版本约 8 个（1.0→1.1→1.4→1.7→1.7.3，中间小版本未逐一披露，按 8 计）。
  `累计 ≈ 5,908 × 8 × 0.7 = 33,085` → **P50 ≈ 3.3 万**
  区间：乐观（每版本均按 5,908 且补丁不减）= 5,908 × 8 = 47,264；保守（按 5 个可考版本 × 0.7）= 20,678
  → **P10–P90 = 2.0 万 – 4.7 万**（含微软商店安装量未知）
- **假设 B**：免费→付费转化率 P50 = 2%（区间 1%–3%）。
- **依据 B**：**类比推算**。桌面工具类免费增值产品的公开转化率常见区间为 1%–5%，考虑本产品免费版极宽（三免）+ 免费替代覆盖率 85%，下调至 **1%–3%**。
- **推算 B**：
  - 付费用户 = 33,000 × 2% = **660 人**（区间 330 – 990）
  - 客单结构：60% 订阅（$30/年）+ 40% 买断（$36 一次性）
  - 首年营收 = 660×0.6×$30 + 660×0.4×$36 = $11,880 + $9,504 = **$21,384 ≈ $2.1 万**
  - 区间：低（20,000×1%）= $6,480；高（47,000×3%）= $45,700 → **P10–P90 = $0.6 万 – $4.6 万**
- **结果**：**首年营收 P50 ≈ $2.1 万（区间 $0.6 万 – $4.6 万）**。
- **置信度**：**低**（两个乘数均为类比/结构推算，且缺少商店安装量这一关键项）。
- **敏感度表**：

| 变量 | 悲观（−50%）| 基准 | 乐观（+50%）| 结论是否翻转 |
|---|---|---|---|---|
| 累计下载量 | 1.65 万 | 3.3 万 | 4.95 万 | 否 |
| 转化率 | 1% | 2% | 3% | 否 |
| 客单价 | $18 | $36/$3 | $54 | 否 |
| **两者同时 −50%** | 营收 **≈ $0.52 万** | $2.1 万 | **≈ $8.6 万** | **是**（从"明显不够"到"接近独立开发者体面收入"）|

> **敏感度结论**：单变量变动不翻转结论；**下载量 × 转化率同时下调 50% 时，结论翻转为「明显不足」**。因此本报告对该体量的判断应表述为**「$0.5 万 – $4.6 万年营收区间，且结论不稳」**，而不是给出一个点值。

### B3 回本周期与生存线（对照方法论公式）

```
盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单
回本周期(单用户)   = 单用户获取成本 ÷ 月毛利/单     ← 必须 < 12 个月
```
- 月固定成本 ≈ $700/年 ÷ 12 ≈ **$58**；月毛利/单 ≈ $30/12 ≈ **$2.5**
- **盈亏平衡付费用户数 ≈ 23 人** → 现金层面极易越过
- **回本周期**：CAC ≈ 0（**无付费投放，靠商店自然流量与前身导流**）→ 回本周期 ≈ 0
- **判读**：**现金模型健康，但它没算进「一人 6 个月的机会成本（≈ $1.25–2 万）」。** 把机会成本计入后，$2.1 万年营收**刚刚擦线**。这是本报告"不是亏损、也不是生意"判断的算数依据。
