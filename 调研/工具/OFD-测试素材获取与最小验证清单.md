# OFD 测试素材获取与最小验证清单

> 配套文档：`Windows-PDF阅读器-横向对比与商业化模式分析（PM视角）.md` 附 E（OFD 支持情况）
> 目的：回答「想验证某个阅读器是否真的支持 OFD，素材从哪来、要测哪几件事」
> 更新：2026-10-20

---

## 〇、结论先行

**不要只找一个「OFD 样例」就下结论。** 要验的东西是三层，三层需要不同来源的素材，任何一层的结论都不能推到另一层：

| 层次 | 要验什么 | 素材来源 | 大多数产品的实际结果 |
|---|---|---|---|
| L1 能解 | 容器/页面能否解析、版式是否跑偏 | 开源样例、13 件符合性测试集 | 多数「宣称支持」的产品卡在这一层之后 |
| L2 能显 | 字体/图形/语义树/附件是否正确 | 真实公文、电子营业执照、双层 OFD | 缺仿宋_GB2312 就白屏 |
| L3 能验 | 签章是否真验、篡改是否报错 | 电子营业执照、ofdrw-gm 生成件 | **这一层挂掉的最多** |

**素材来源优先级（按「权威性 × 可得性」排）**：

1. **财政部会计司的电子凭证工具包** —— 唯一官方指定给「接收端」做适配与验签的工具+样例，验签口径最权威；
2. **开源测试集 + 自造件（ofdrw / 13 件测试集）** —— 唯一能可控构造「篡改件、加密件、大文件」的来源；
3. **真实业务件（电子营业执照、数电票、银行回单）** —— 唯一含真实国密签章与真实公文字体的来源。

## 二、最小可测集：4 个文件、20 分钟出结论

| # | 素材 | 验什么 | 判定标准 |
|---|---|---|---|
| 1 | 一个普通多页文本 OFD（ofdrw 样例 或 13 件之一） | 能否打开、版式/分页是否正确 | 打开即白屏或跑版 → 直接判不支持 |
| 2 | 一个带**国密签章**的 OFD（电子营业执照 或 ofdrw-gm 生成） | 签章是否显示、验签是否通过 | 有章但点「验证」无反应 → 只画章，不验签 |
| 3 | 一个**口令加密**的 OFD（电子营业执照导出件） | 是否提示输密码、能否正确解密 | 直接报错/绕过密码显示 → 安全能力缺失 |
| 4 | **签章后篡改一字节**的 OFD（ofdrw 生成后手改内容流） | 是否报「签章无效」 | **不报错 → 该产品不具备可信阅读能力** |

补充一件：**500 页 / 100MB 大文件**，测首屏时间与内存峰值（公文动辄上百页，分页加载是硬指标）。

**这张表的用法**：能过 1、2 只说明「能读」；**能过 4 才说明「能验」**。绝大多数的「支持 OFD」宣称会在第 4 条上失效——因为它们做的是渲染，没做完整性校验。

## 三、测试用例矩阵（要覆盖的维度）

| 维度 | 必测用例 | 为什么必须 |
|---|---|---|
| **容器** | 全 STORE / 全 DEFLATE / 混合压缩、非法路径、缺 entry | 解析器容错；13 件测试集正对此设计 |
| **渲染** | 嵌入字体子集、**非嵌入字体（仿宋_GB2312）**、少数民族文字、竖排 | 公文必踩；「白屏 / 乱码」八成是缺字体 |
| **图形** | 矢量路径、渐变、透明、扫描图（JPEG/JBIG2） | 公章与扫描件 |
| **结构** | 多页 / 横竖混排 / 旋转页、大纲书签、**语义树**、图层、附件、注释 | 语义树是 OFD 独有，PDF 无对应物——这是「真 OFD 支持」与「PDF 套壳」的分水岭 |
| **签章** | 单章 / 骑缝章 / 多章、SM2 与 RSA、证书链、时间戳、过期证书、**篡改件** | 唯一真门槛 |
| **安全** | 口令加密、权限控制、密标、隐写溯源 | 政企采购的硬性评分项 |
| **性能** | 500 页 / 100MB、首屏 < 1s、内存峰值 | 见上 |
| **双层** | 扫描图 + OCR 文字层的「双层 OFD」 | 档案与票据场景；不能用一个的结论推另一个 |

## 四、自造素材的三条路

**A. ofdrw（推荐，可脚本化）**
`OFDDoc` 生成 → `ofdrw-sign` 签名（RSA）/ `ofdrw-gm` 签名（国密）→ 手动改 XML 造篡改件。最适合做**批量回归集**：一晚上能产出「10 页 / 100 页 / 带附件 / 带语义树 / 已签名 / 已篡改」的完整矩阵。

**B. 办公软件导出**
福昕 PDF 编辑器（PDF→OFD）、WPS（另存 OFD）。优点是零门槛，缺点是产出基本是「简单件」，**覆盖不到语义树、密标、国密签章**。

**C. 手工拆包改结构（造异常件最快）**
OFD 本质是 ZIP + XML：把 `.ofd` 改名 `.zip` 解压，进 `Doc_0/Pages/` 与 `Res/` 就能直接改内容与资源。这也是造「结构损坏」「签章失效」用例最直接的办法——顺带说明一件事：**OFD 的防篡改不靠扩展名，只靠签章**，所以「文件后缀是 .ofd」不代表内容可信。

## 五、实测前必读的坑

1. **验签失败经常不是软件问题**：系统时间偏差超 30 分钟，验签直接失败。
2. **缺字体 → 白屏；缺 VC++ 运行库 → 启动即崩**。测之前先确认环境干净。
3. **「双层 OFD」不是普通 OFD**，测试结论不能互推。
4. **浏览器内置预览会给出假阳性**：360 / QQ 浏览器 / 微信里的 OFD 预览走的是数科的技术支持，用它测「某产品是否支持 OFD」等于在测数科。
5. **别把真实发票、营业执照上传到公共在线预览或转换站**——这些文件含真实主体信息与签章，属于不可撤回的泄露。
6. **13 件测试集只覆盖容器层**，不含签章；用它得出「支持/不支持 OFD」是不完整的。

## 六、缺口声明

| 拿不到 | 原因 | 替代方案 |
|---|---|---|
| 中国电子技术标准化研究院的正式符合性测试集 | 仅对送测厂商开放 | 用 13 件二手测试集近似，结论降级为「参考」 |
| 银行 / 税务的真实生产件全集 | 受控分发 | 自取单张（脱敏）+ ofdrw 自造 |
| 财政部工具包内是否逐类附样例文件 | **未下载解压确认** | 需实际下载后核对包内 `sample` 目录，本清单对此标注为「待确认」 |
| 数科 / 福昕 / 点聚 的官方样例下载页 | 厂商普遍不公开 | 在线预览自测 + 开源样例对照 |
