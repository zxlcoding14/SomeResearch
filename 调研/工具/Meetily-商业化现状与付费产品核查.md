# Meetily 商业化现状核查：到底有没有真在卖的商业产品

> **核查对象**：Meetily（`github.com/Zackriya-Solutions/meetily` 开源社区版 + 商业版 Pro / Enterprise）
> **商业主体**：Zackriya Solutions（印度）
> **采集日**：2026-10-15
> **本文回答**：① 有没有实际的商业化产品；② 卖什么、卖多少钱、怎么收钱；③ 有没有可验证的成交证据；④ 数据可信度如何
> **姊妹文档**：技术构建与依赖见《Meetily-本地构建与环境依赖分析.md》；模型与依赖的许可/商用核查见《Meetily-自动下载资产的许可与商用核查.md》
>
> **核查原则**：本报告区分「**产品存在**」与「**成交存在**」。两者证据强度完全不同，下文分开陈述。

|---|---|---|

**一句话**：**产品层面成立，成交层面未证实。** 你能买到它，但你找不到"谁买过"。

## 1. 商业化结构总览

| 层级 | 产品 | 价格 | 交付形态 | 目标客群 |
|---|---|---|---|---|
| 免费 | **Community Edition** | 免费，MIT 开源 | 桌面应用（Win/macOS；Linux 源码构建） | 个人、隐私敏感用户、开源社区 |
| 付费（主力） | **Meetily Pro** | **$10/用户/月（¥71/用户/月）**，按年计费 = **$120/用户/年（¥852/用户/年）**；原价 $25/月（¥177.5/月），现 **60% off** | 桌面应用（Windows / macOS；Linux 开发中） | 个人专业用户、小团队（按席位买） |
| 付费（高客单） | **Meetily Enterprise** | **全部 Custom 报价**，三档：Standard（100–500 用户）/ Premium（500+）/ Ultimate（无限用户） | **自托管**（客户自己的 on-prem 或 AWS/Azure/GCP，可选 EU 数据中心） | 受监管行业大客户（医疗/法律/金融/政府） |

**三层漏斗的逻辑非常清楚（典型 open-core）**：
MIT 社区版做流量池与信任背书 → Pro 用「$10 一个席位」收个人与小队 → Enterprise 用「自托管 + 合规 + SLA」收大客户。

## 3. Meetily Enterprise 深度核查

### 3.1 产品与定价

| 档位 | 用户规模 | 内容 | 价格 |
|---|---|---|---|
| Enterprise Standard | 100–500 用户 | 托管合规团队、GDPR/HIPAA 处理、优先支持、审计追踪 | **Custom（Contact Sales）** |
| Enterprise Premium（标 MOST POPULAR） | 500+ 用户 | 专属合规经理、自定义合规框架、白手套部署、24/7 支持 | **Custom** |
| Enterprise Ultimate | 无限用户 | 合规外包、专属合规团队、托管基础设施选项 | **Custom** |

**无任何公开价格。** 官方唯一给的量化承诺是「**一个工作日内出报价**」。

### 3.2 部署与合规主张

| 维度 | 官方主张 |
|---|---|
| 部署 | 自托管：客户 on-prem、或客户自己的 AWS / Azure / GCP、或德国/法国/荷兰数据中心（Hetzner / OVH / LeaseWeb） |
| 管理 | 管理后台、LDAP/AD 集成、RBAC、用户供给、审计日志（谁在什么时间用什么设备录了什么）、使用分析 |
| 合规框架 | GDPR（第 25/30/32/44 条）、DSGVO、RGPD、NIS2、MiFID II、HIPAA + BAA、ISO 27001 / SOC 2 Type II 框架 |
| 支持 | 24/7 优先支持、专属客户经理、白手套部署、合同约定 SLA（明确表示不公开统一 SLA） |
| 加密 | AES-256 静态与传输加密、可空隔离部署（air-gapped） |

### 3.3 ⚠️ 最重要的两处"自我否定"

**① 官方主动声明没有独立认证**（这是诚实，也是硬伤）：

> "Meetily is GDPR and HIPAA compliant by design (architecture-level). **We do not claim independent SOC 2, GDPR, or HIPAA certification** - those are organizational designations the deploying enterprise holds."

即：**没有任何第三方审计认证**。企业采购通常需要的 SOC 2 Type II 报告、ISO 27001 证书，这里一个都没有，只有「架构层面符合」。

**② 客户证据为零**。Enterprise 页标题写「Trusted by European Regulated Industries」、结尾写「Join European healthcare providers, legal firms, financial institutions and government agencies」，但通篇：

| 应有的证据 | 实际情况 |
|---|---|
| 客户 logo 墙 | ❌ 无 |
| 具名客户 | ❌ 无 |
| 案例研究 / 客户故事 | ❌ 无（官网博客 25 篇里没有一篇客户案例） |
| 客户引语 | ❌ 无 |
| 部署数量 / 客户数 | ❌ 无 |

**全部是行业泛称（"German hospitals"、"French clinics"、"European banks"）**。这是典型的**未成交或不便公开的营销写法**。

> 补充：第三方企业目录站 everydev 把 **Saviynt** 列为 Zackriya 的 "Notable Customers"，但检索 Saviynt 官网**找不到任何与 Meetily 的关联**（返回的是 Saviynt 自家的 IGA 案例）。**该条不可采信**【实测反驳】。

## 5. 变现逻辑还原

### 5.1 官方自述（唯一的一手变现说明）

官网博客《Where Does Your Meeting Data Actually Go?》原文：

> "Community 是开源项目，**不赚钱**。Zackriya Solutions 的收入来自 **Meetily Pro（$10/用户/月，按年计费）** 和 **Enterprise 部署**（自托管、SSO、管理控制与支持）。**免费层由付费层补贴**。"

### 5.2 结构性判断

| 判断 | 依据 |
|---|---|
| 采用**开放核心（open-core）**模式 | 社区版 MIT 引流 → Pro 席位收个人/小队 → Enterprise 自托管收大客户 |
| 免费层是**成本极低的流量入口** | 转写在用户本地跑，用户越多官方边际成本几乎不增（官方自己也这么说）—— 这是本地优先架构带来的独特商业优势 |
| 付费点的选择**刻意** | 锁的三个功能（说话人分离、高级导出、MCP/CLI 集成）都是**「个人用户忍得了、专业用户忍不了」**的位置；再往上的企业能力（SSO/AD、审计、SLA）只能靠 Enterprise |
| 地缘定位明确 | Enterprise 页几乎整篇针对 **EU 合规市场**（GDPR/DSGVO/NIS2/MiFID II + 德国/法国/荷兰机房）—— 这是有意的差异化：美国云工具在 EU 受监管行业的合规摩擦就是它的机会 |
| 价格带落在行业下沿 | Pro $10/月，对标 Otter $8.33–16.99/月、Fireflies $10–18/月、Granola $18/月、Fathom $15–19/月 —— **不便宜，但差在"数据不出本机"** |

## 7. 数据可信度专章：官方用户量口径为何不可采信

同一个产品，官方与第三方给出至少 6 个互不相容的数字：

| 数字 | 出处 | 采集/声称时点 |
|---|---|---|
| **599K+ downloads** | 官方 Pro 页 | 2026-10 |
| **252K+ users** | 官方 open-source 页 | 2026-10 |
| **475K+ downloads / 29.6K+ stars** | rightaichoice（第三方） | 2026-09 |
| **440,000 downloads / 29,000 stars** | thetruestack（第三方） | 2026 年内 |
| **88,000+ 用户** | toolguide（第三方） | 2026-03 前后 |
| **12,000 users 里程碑** | everydev 转引官方里程碑 | **2026-03** |
| **31,094+ developers** | 官方博客 | **2025-11** |
| **10,000 GitHub stars** | 官方博客 | **2026-02** |
| 23.9K stars | 中文评测 | 2026 年内 |

**问题所在**：
1. **"users"与"downloads"被混用**（599K downloads ≠ 599K users，但页面语境暗示同一件事）。
2. **时间线不单调**：2025-11 有 31K+ developers，2026-03 却只有 12,000 users —— 数字倒挂。
3. **官方自身页面之间就不一致**：同一时间点，Pro 页写 599K、open-source 页写 252K、legal 页写 31K+。

**结论**：**所有基于这些数字的规模推断都不成立。** 需要真实规模数据时，唯一可行方向是看 GitHub Release 资产的下载计数（单一、可观察），本文未取得【未取得】。
