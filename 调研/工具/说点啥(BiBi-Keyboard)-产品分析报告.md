# 说点啥（BiBi-Keyboard）— 产品分析报告（PM 视角）

> **分析对象**：`BryceWG/BiBi-Keyboard`（产品名「说点啥」/ BiBi Keyboard），Android 端 LLM+ASR 语音输入法键盘
> **仓库**：https://github.com/BryceWG/BiBi-Keyboard ｜ **官网**：https://bibi.brycewg.com ｜ **文档**：https://bibidocs.brycewg.com ｜ **Pro 上架**：Google Play（`com.brycewg.asrkb.pro`）
> **快照时间**：2026-10-10（版本 v4.5.1 / Release 发布于 2026-10-07）
> **分析目的**：**学它 + 判它 + 抄它的结构**。不是投它，也不是打它。
> **分析粒度**：单品（免费开源版 + Pro 付费版视作一个产品的两层）
> **计数口径**：功能按「用户可感知功能」计数（不按代码能力单元）；用户量按「安装量」而非注册量
> **数据可信度分级**：① 经审计（无）② API/页面实测 ③ 官方宣称 ④ 第三方估算 ⑤ 二手转载 —— 逐条在附 A 标注
> **方法论叠加顺序**：产品分析框架（七层提问法）→ 开源竞品与可复用能力（先判死再省钱）→ C 端方向切片 + 个人开发者方向切片（这一刀怎么切）→ 本报告
>
> **本分析要回答的 3 个问题**
> 1. 它靠什么结构和位置活下来？这个结构能不能被复制？
> 2. 它的天花板在哪，为什么「跑得通但不养人」？
> 3. 它的哪一段可以直接迁到 Windows/Mac 桌面端？

## 〇、结论先行（TL;DR）

1. **【判断】它不是「语音输入法」，是「ASR 中立的输入层」。** 它真正做的事是把「语音识别引擎」与「输入体验」解耦——18 个 ASR 供应商（12 云 + 6 本地）任选、14 家 LLM 做后处理、悬浮球绕开输入法本身直接上屏。**这个位置正是巨头结构性不做的**：搜狗/百度/讯飞不会让你用别人家的 ASR。这是它唯一站得住的差异化，也是全部价值的来源。（依据：功能全景 §二 + 竞品盲区 §七.4）

2. **【否定性结论】它的核心能力「中文语音转文字」已被免费三方夹击，本身零定价权。** 系统内置（Gboard）+ 三巨头免费语音输入（市占合计 76.2%）+ 开源免费同类（Transcribro 756★ / Sayboard 583★ / FUTO / HeliBoard）三面覆盖。**它收得到钱的那一段只有「引擎可切换 + AI 后处理 + 跨输入法上屏 + 本地离线」这四件巨头不做的事**，而其中前三件都是软件工程，**代码 Apache-2.0 全开 = 任何人都能抄走**。（依据：§四 + §七.2/§七.5）

3. **【结构性发现，最值钱的一条】它唯一成立的原因是「BYO API Key + 端侧推理」，把边际成本压到 ≈ 0。** 免费版与 Pro 版都没有服务端：云端走用户自己的火山引擎/硅基流动 Key，本地走用户手机算力。**做一个对照就清楚了**：若改成开发者代付，火山流式语音 1.0 元/小时，一个每天用 1 小时的重度用户 = ¥30/月，**直接超过 ¥36 的买断价 → 立刻触发「边际成本 ≥ 定价」一票否决**。所以 BYO Key 不是产品选择，是这个价位的**唯一活路**。（依据：附 B-3，火山引擎官方价目页）

4. **【量化结论】年营收量级 ≈ ¥1 万–¥3 万，是「热爱可支撑、不能养人」的副业级项目。** 实测 GitHub Releases 11 个版本合计 6,910 次下载（86 天，≈80 次/天）→ 年新增安装推算 1.76 万–3.08 万；按开源工具典型转化率 0.5%–3%、买断 ¥36 推算，**年营收 P50 ≈ ¥1.3 万（P10 ¥0.3 万 / P90 ¥3.3 万）**。要进「主业」量级（¥30 万/年）需转化率 ≥12% 或客单价 ≥¥300 或下载量 ≥30 万/年——**三个都不在现有结构里**。（依据：附 B-1 / B-2 + 敏感性表）

5. **【风险】它有三条高危线，但无硬否决。** ① **分发与收款双通道都在墙外**（Pro 唯一官方通道是 Google Play，国内不可达；国内走「个人收款码 + 邮件发激活码 + Play 兑换码」— 履约手工化、有 Play 兑换码配额与区域限制、不合规风险）；② **支持面宽到一个人扛不住**（18 ASR × 14 LLM × 6 本地模型 × LSPosed 模块 × 无障碍权限，已积压 15 个开放 issue）；③ **买断 ¥36 + 零持续交付成本 → 只能是买断 → 买断低价必须靠海量分发 → 与个人分发能力天然冲突**。12 维打分卡 **80/135 = 59.3%**，落在「只做最低成本补充采集、不投实验资源」区间。（依据：§六 / §九）

6. **【可迁移，最值得带走的一条】它验证了一条能横移到桌面端的结构。** 「ASR 中立层 + BYO Key + 端侧兜底」直接可搬到 Windows/Mac 语音输入，而桌面端付费意愿（Wispr Flow 类订阅制工具）比 Android 端的 ¥36 买断高出**一个数量级**——正好落在「客单价 × 分发难度」表里的 **¥299 档 = 个人开发者最优区间**。它踩过的坑（支持面过宽、手工履约）也可以直接避开。（依据：§十）

## 二、功能全景（四层分层表）

> 判据：T1 去掉它产品不成立 · T2 提效但可替代 · T3 只有它有 · T4 低频/边缘（警惕拿它当卖点）

| 层 | 功能 | 商业含义 |
|---|---|---|
| **T1 内核** | 长按/点按/摇一摇录音 · 智能判停（静音自动停）· 极速识别（松手即传）· **18 个 ASR 供应商可切换**（12 云 + 6 本地）· 本地离线模型（SenseVoice / FunASR Nano / Qwen3-ASR / Parakeet / FireRedASR V2 / X-ASR）· 流式识别 · 文字上屏 | 定价地基。**注意：其中「语音转文字」本身不是它的（是 ASR 供应商的）**，它的内核其实是「调度 + 上屏」 |
| **T2 增强** | AI 文本后处理（LLM 纠错/加标点/口语转书面）· 悬浮球跨输入法输入 · 备用引擎与本地兜底 · 剪贴板同步（SyncClipboard/WebDAV）· 自定义键盘布局 · 键盘高度/振动/多语言界面 · 识别后自动回车 · 配置导入导出 | 决定口碑，**通常不该单独收费——而它把其中一批做成了 Pro**（见 §五） |
| **T3 差异化** | ① **ASR 引擎中立可切换**（含 BYO Key）② **悬浮球绕开输入法直接上屏**（任何输入法都能用）③ **IME Bridge 模块**（LSPosed/LSPatch，在任意第三方输入法内录音+上屏+剪贴板同步）④ **外部语音输入接口**（第三方 App 经 SpeechRecognizer/AIDL 调用）⑤ **多家庭本地模型 + 主备兜底** | 卖点来源。**但必须验证是否已被免费替代覆盖**——经对撞：①②未被海外开源覆盖（海外方案基本英语优先），③④⑤属小众技术位 |
| **T4 长尾** | 应用专属 Prompt · 正则后处理 · 离线繁体转换（含台湾/香港用词）· 全向光标滑动 · AMOLED/Monet/Key color 取色 · 热词分组与自动学习 · 畅说模式（VAD 自动起停）· AI 助手唤醒词 · WebDAV 定时备份 | 「看起来很强」的装饰区。**其中大部分正是 Pro 的付费点——这是本节最关键的结论：Pro 卖的是 T4 长尾，不是 T1 内核**（见 §五.3） |

**⚠️ 本节最该记住的一句话**：**它的 T1 依赖外部（ASR 供应商），T3 是工程位（可被抄），Pro 卖的是 T4。** 一个产品的价值锚点全部落在最容易丢的三层上。

## 三、用户、场景与频次（L2）

### 3.1 五角色模型（B 端分离，C 端折叠）

| 角色 | 本产品情形 |
|---|---|
| **使用者** | Android 用户本人（C 端，角色折叠为一人） |
| **付费者** | 同一个人。**无预算科目、无决策链**——这既简化了转化，也封死了客单价上限 |
| **决策者 / 影响者 / 阻挠者** | 不存在（或等于「他愿不愿意放弃用了十年的讯飞」） |
| **真正被折叠掉的第四方** | **ASR 供应商与 LLM 供应商**——他们不付钱也不用产品，但**他们的定价、ToS、限流随时能杀死体验**。这是 C 端罕见的「隐形第四方」，必须单列进风险 |

### 3.2 JTBD 句式（真实场景，取自官方文档 + 一手社区帖）

- 「**当**我在走路/开车/懒得打字**的时候，我想要**说一句话就把微信回完**，这样我就能**腾出手/省下三分钟**。」（聊天场景，官方列为首要场景）
- 「**当**我要给 AI 助手发一大段长指令**的时候，我想要**口述三十秒而不是敲三分钟**，这样我就能**把长 prompt 变成常态**。」（一手社区帖明确点出，原文：「用它给 AI 助手发长指令尤其爽」）
- 「**当**我要写长文/会议速记**的时候，我想要**先口述出草稿再改**，这样我就能**跳过从零敲字**。」
- 「**当**我在用第三方输入法（小企鹅/同文/小小/小狐狸）**的时候，我想要**不换输入法也能语音输入**，这样我就能**保住我的词库和习惯**。」（这是它独有的场景，因为它提供外部接口）
- 「**当**我处理敏感信息**的时候，我想要**音频不出手机**，这样我就能**不把声纹交给云」。（隐私场景）

### 3.3 频次 × 心理价位（决定模式）

| 维度 | 本产品事实 | 结论 |
|---|---|---|
| **使用频次** | **日频、多次**——输入法是全手机最底层入口（赛道基准：头部输入法日均使用时长 >3 小时） | 高频 → **理论上可订阅** |
| **但持续交付成本** | **≈ 0**（无服务端、用户自带 Key / 端侧算力） | **无持续交付成本 → 订阅不成立，只能买断** |
| 实际选择的模式 | **买断 $5.49 / ¥36，绑定 Google 账户，永久使用** | ✅ **模式选择正确**：高频 + 零持续成本 = 买断（若硬收订阅必然流失） |
| 心理价位对标 | 对标「一次打车 / 一杯咖啡×2」——而非「每天省下的时薪」 | 定价锚在**低档**。这是天花板低的直接原因（见 §六） |

### 3.4 切换成本（C 端最高发的一格，它反而占了便宜）

| 切换成本项 | 高低 | 说明 |
|---|---|---|
| 学习成本 | **低** | 长按麦克风即用，无需学键位 |
| 数据迁移 | **低** | 不接管词库，不接管打字；**它不要求你放弃原输入法** |
| 习惯改变 | **低（悬浮球模式）/ 高（作为主输入法）** | 悬浮球模式是它最聪明的设计——**把切换成本降到「装个 App」** |
| 集成改造 | 中 | 第三方输入法联动需 LSPosed/LSPatch（受众极小）或对方主动适配 |

> **判断**：**「悬浮球 + 不抢输入法」是它能从巨头嘴里吃到一小块肉的关键**。它主动放弃了「成为主输入法」这件事，从而把自己从「与讯飞抢装机」变成「与讯飞共存」。这是一个**降低切换成本换生存空间**的经典打法，值得抄。

## 四、价值主张与需求硬度（L3）

### 4.1 五类问题定性（用你的问题识别方法论判定）

| 类型 | 本产品的哪些点 | 判定 |
|---|---|---|
| **痛点** | 开车/走路无法打字时回消息（P3）· 长 prompt 手打三分钟（P3）· **敏感内容不能交云（P5 合规级，对特定人群）** | 只有第 3 条是**真痛点**（损失性质 = 风险/合规，不满足就不敢用） |
| **痒点** | AI 后处理让口语变书面（P1–P2）· 畅说模式省点击（P1）· 热词提升专名准确率（P2） | 大幅拉新/留存主力，**但难单独定价** |
| **爽点** | 「说完自动回车直接发出去」的一气呵成感 | 放大器，不构成定价理由 |
| **优化点** | 键盘高度、取色、光标滑动、正则后处理 | **边际摩擦，单卖不收钱——事实也正是靠 Pro 打包收钱** |
| **机会点（用户永远提不出来）** | **「ASR 中立层」这个位置本身**：当云端模型每月都在换、本地模型每季度都在出新的时代，**用户需要的是一个不绑定引擎的入口**。这是新能力激活出的位置，不是用户抱怨出来的 | ✅ **本产品唯一的机会点型价值** |

### 4.2 卖点对撞「免费替代」（覆盖率量化）

| 它自称的卖点 | 免费替代 | 对撞后剩余 |
|---|---|---|
| 语音转文字准 | 系统内置 Gboard / 讯飞 / 搜狗 / 百度（全免费）+ Sayboard/Transcribro（开源免费） | **≈ 0** |
| 快 | 同上 | **≈ 0** |
| 离线可用 | FUTO Keyboard（Play 可装）· Transcribro · HeliBoard（全免费离线） | **≈ 0**（海外已覆盖；**中文场景仍有空位**） |
| 隐私不出网 | 同上 | **≈ 0** |
| **多引擎可切换 + 自带 Key** | **无免费替代**（巨头不给、开源不做） | **100% 保留** ✅ |
| **AI 后处理（LLM 润色/纠错/口语转书面）** | 部分：Gboard/百度/讯飞已内置 AI 润色（免费） | 约 40% 保留（自定义 Prompt/应用专属 Prompt 是其独有） |
| **悬浮球跨输入法上屏** | 无免费替代（Gboard 不行、FUTO 不行） | **100% 保留** ✅ |
| **第三方输入法联动（外部 AIDL 接口）** | 无免费替代 | **100% 保留** ✅ |

**免费替代覆盖率（按功能项计）**：八项卖点中 4 项被覆盖 ≈ 50%；**但被覆盖的是「钱袋子项」（识别准/快/离线/隐私），未被覆盖的是「工程位」**。
→ **这与你的方法论第 3 条完全同构**：单一能力型产品的开源层已备好且免费，能收费的只剩开源不做的那一段。

### 4.3 刚需还是可选 —— 一句话判死

> **没有它，用户的损失是什么？** 对 **95% 的用户**：**只是「更方便」**（有至少 4 个免费替代随时可用，且系统内置）。对 **≤5% 的用户**（隐私/合规敏感 + 需要专名准确率 + 需要本地离线 + 已重度使用第三方输入法）：**是损失风险**。
> **结论：这是一个「窄人群 × 真痛点」的产品，不是「宽人群 × 弱痛点」的产品。窄人群意味着它必须靠单价或深挖来赚钱，而不是靠量——而它选的是 ¥36 的低价走量路线，与人群结构矛盾。**

### 4.4 天花板（TAM/SAM/SOM 粗算，标口径）

| 口径 | 数值 | 来源级别 |
|---|---|---|
| **TAM** 中国第三方输入法月活大盘 | 约 10 亿+（搜狗 6.98 亿 + 百度 4.96 亿，QuestMobile 2026-06） | ④ 第三方估算 |
| **SAM** 语音输入高频使用者 | ≈ 大盘 × 40.9%（AI 语音输入功能使用率，居所有 AI 功能首位）→ **≈ 4 亿** | ④ 第三方估算 |
| **SOM** 可实际触达 | 品牌无认知、无预装、无投放 → 只能抓「主动搜索 + 开源圈 + 输入法极客圈」。**按实测年下载 2.93 万次、Top 10% 留存估算 → SOM ≈ 1 万–3 万活跃** | ② 实测 + ③ 推算 |

> **三个口径差 4 个数量级**——这正是你方法论里「三口径常差 2–3 倍」的极端案例。**TAM 好看，SOM 才是命。** 任何拿 TAM 讲这个故事的人，都在掩盖 SOM 只有大盘的 0.005%。

### 5.2 付费墙位置判定

| 墙型 | 是否使用 | 判断 |
|---|---|---|
| **功能墙** | ✅ **主墙** | Pro 锁 13 项功能——**工具型商业的标准墙** |

> **关键判断**：**功能墙 + 零边际成本 = 可以无限慷慨地免费，但也意味着「免费版永不出血」，付费转化只能靠「想要更多」而非「不够用了」。** 这是转化率被压在 1% 量级的机制性原因——对比「用量墙」模式（免费额度用尽必须付费），后者的转化率通常高一个数量级。

### 5.3 付费墙卡在哪一层（本节最重要的发现）

把 Pro 的 13 项功能对回 §二 的四层分层：

| 被锁功能 | 所属层 | 判定 |
|---|---|---|
| 热词管理 / 识别后近音替换 / 从纠正中学习热词 | T4 长尾 | 专业用户才用 |
| 畅说模式（VAD 自动起停） | T4 长尾 | 小众体验 |
| 输入框上下文辅助 | T2 增强 | 提效 |
| 离线繁体转换 | T4 长尾 | 垂直人群 |
| 正则后处理 / 应用专属 Prompt | T4 长尾 | 极客 |
| AI 助手（唤醒词指令） | T4 长尾 | 炫技 |
| 个性化 UI 取色 / 全向光标滑动 | T4 长尾 | 装饰 |
| WebDAV 自动备份 | T4 长尾 | 便利 |

> **结论：13 项付费功能中，约 11 项属 T4 长尾。** 这意味着——
> ① 免费版拿到的是**完整 T1 内核**（能干活）；
> ② **Pro 卖的是「专业用户的省事」，不是「不做就用不了」**；
> ③ 因此 **付费转化率的天花板由「T4 需求人群占比」决定，而不是由「日频使用」决定**。日频使用带来的是留存，不是付费。
>
> **这是「高频使用 ≠ 高付费率」的一个教科书样本。**

### 5.4 续费理由

**买断制，无需续费**——✅ 正确的模式选择。但代价是：**没有 MRR（月度经常性收入）**，收入完全靠新增。对个人开发者而言，这意味着**每月必须重新卖一遍**，无法形成复利。

### 6.2 生存线

```
月毛利/单 = 客单价 − 单用户变动成本 = ¥36 − ¥5.4(Play 抽成) ≈ ¥30.6
月固定成本 ≈ ¥30
→ 盈亏平衡付费用户数（纯现金口径） = 30 ÷ 30.6 ≈ 1 单/月   ← 极易达成

含时间机会成本口径（副业投入 20 h/月，时薪 ¥100 → ¥2,000/月）：
→ 需 2,000 ÷ 30.6 ≈ 66 单/月 ≈ 792 单/年
```

| 口径 | 生存线 | 对照附 B-2 的营收推算 | 结论 |
|---|---|---|---|
| 纯现金 | 1 单/月 | 中位 30 单/月（360/年） | **36 倍于生存线 → 现金上安全** |
| **含时间机会成本** | **66 单/月** | 中位 30 单/月 | **仅覆盖 45% → 缺口 55%** |

> **这就是它「跑得通但不养人」的精确表述**：**它的现金账早就转正了，但一个人的时间账没转正。** 判断一个独立开发者产品该不该继续做，看的是第二行，不是第一行。

### 6.3 边际成本红线（AI 类头号杀手）

| 方案 | 边际成本 | 结论 |
|---|---|---|
| **本产品实际：BYO Key + 端侧推理** | **≈ ¥0**（算力/API 费由用户承担） | ✅ **唯一成立解** |
| 对照 A：开发者代理云端 ASR | 火山流式 1.0 元/小时 × 重度用户 30 h/月 = **¥30/月** | ❌ **¥30/月 > ¥36 一次性** → 立刻触发否决 |
| 对照 B：开发者自建 LLM 后处理 | 豆包 6 元/百万 input + 30 元/百万 output × 每句 200 token → 单用户日 30 句 ≈ ¥0.2/月 | ⚠️ 后处理本身便宜，但 **ASR 才是红线** |
| 对照 C：本地模型全内置 | ¥0（用户承担）+ 包体膨胀 + 低端机不可用 | ⚠️ 可行但牺牲覆盖 |

> **可复算算式**：`边际成本/月 = 单价(元/小时) × 单人月均语音小时数`。**只要分母 > 0 且分子 ≥ ¥36，就否决。** 本产品把分子按结构钉死在 0。
> **供应商涨价 30% 后它还赚钱吗？** ✅ 赚钱——**因为它不承担这个成本，涨价打的是用户，不是它**。这是 BYO Key 模式的隐性优势，也是它的隐性风险：**当用户自己算账发现「火山一年要花 ¥50」时，他会重新评估 ¥36 到底值不值**。

### 9.3 一条方法论意义上最重要的「结构矛盾」（打分卡抓不到的）

> **买断 ¥36 + 零持续交付成本 → 只能是买断 → 买断低价必须靠海量分发 → 与个人分发能力天然冲突。**
>
> 这不是打分项，是**结构级死结**：
> - 想提价到 ¥199（进入「客单价 × 分发难度」表里的可行档）→ 但免费版已含完整 T1，**T4 长尾撑不起 ¥199**
> - 想收订阅 → **无持续交付成本，订阅无正当性**
> - 想放量 → 巨头免费 + 无预装 + 无投放
>
> **结论：这个产品形态在结构上无法长大。它可以活得很久（成本极低），但长不大（客单价 × 转化率 × 分发量三个乘数都被钉住）。** 这也是它真正的、不可修复的天花板。

### 10.3 机会点：这套结构可以横移到桌面端（本报告最值得带走的一条）

> **它的结构 = 「ASR 中立层 + BYO Key + 端侧兜底 + 不抢宿主」**。这套结构**与平台无关**，而**桌面端的付费意愿比 Android 端高一个数量级**。

| 维度 | Android 端（本产品） | 桌面端（可迁移） | 机会含义 |
|---|---|---|---|
| 客单价 | ¥36 买断 | 对标 Wispr Flow 类：**订阅制 $10–15/月**；superwhisper 类买断 ¥300+ | ✅ **进入 ¥299 档 = 「客单价 × 分发难度」表里的个人开发者最优区间** |
| 巨头覆盖 | 🔴 三巨头免费语音 + 系统内置 Gboard | 🟠 **Windows 无原生高质量语音输入**；macOS 有系统听写但弱 | ✅ **桌面端的「系统内置」这一格更空** |
| 持续交付成本 | ≈0（BYO Key） | ≈0（同结构） | ✅ 结构可直接复用 |
| 分发 | Play（国内不可达，致命） | **官网 + 开源 + 开发者社区 + 直接收款**（无平台墙） | ✅ **绕开它最大的死穴** |
| 支持面 | 18 ASR × 14 LLM × 6 本地 × LSPosed × 无障碍 | **可主动收窄**（如只做 3–5 个引擎 + 1 个本地模型） | ✅ **可以把它的最大风险直接避开** |
| 竞争 | 巨头 + 开源 + 系统三面夹击 | **中文优先的桌面语音输入仍是空位** | ✅ 位置仍空 |

> **最小验证（写死门槛，参照个人开发者方法论 §9 证据阶梯）**
> 1. **先做付费实验，不做产品**：一个 landing page + 一段 90 秒 demo（BYO Key + 中文 + 桌面悬浮），**只留「预售 ¥199 早鸟」按钮**——按证据阶梯，只有「直接收钱」是强信号，留邮箱是弱信号。
> 2. **门槛**：30 天内 ≥3 个真实付费信号（含定金）→ 立项；有使用无付费 → 2 周内无改善则杀。
> 3. **必须前置回答**（否则不许开工）：① 收款主体与通道（个人 → 建议 MoR 类，如 Paddle/Lemon Squeezy，由平台代扣税）② 支持面收窄到几个引擎 ③ 中文桌面语音的「为什么是现在」。
> 4. **一票否决自查**：边际成本 ≈ 0 ✅ / 分发可得（桌面开发者社区 + 中文 AI 工具圈）✅ / 不依赖单一平台 ✅ → **三道闸门全过，可进入证伪实验**。

### B-3 单用户边际成本核算（本报告最关键的一条测算）

| 段 | 内容 |
|---|---|
| **假设** | 边际成本/月 = ASR 单价 × 单人月均语音小时数 + LLM 后处理成本 |
| **依据** | ① 架构实测：无服务端，云端走用户自带 Key，本地走用户端算力【② + ③】② 火山流式语音 **1.0 元/小时**、录音文件 **0.8 元/小时**【③ 官方价目页】③ 豆包 LLM 输入 6 元/百万 token、输出 30 元/百万 token【③】④ 重度用户语音输入时长按 **30 小时/月** 估（每日 1 小时） |
| **推算** | **本产品实际**：¥1.0 × 0 + ¥0 × 0 = **≈ ¥0**（开发者侧）<br>**对照·开发者代理 ASR**：¥1.0/小时 × 30 小时 = **¥30/月/重度用户** → 年 ¥360<br>**对照·LLM 后处理自建**：30 句/日 × 200 token × 30 日 = 0.18 M output + 0.18 M input → ≈ ¥6.5/月 |
| **结果** | **本产品开发者侧边际成本 ≈ ¥0；若改为代付 ASR，重度用户即产生 ¥30/月成本。** 对照**一次性 ¥36 定价**：代付模式下一个重度用户**首月即吃掉 83% 的收入，第二个月开始净亏** → **立刻触发「边际成本 ≥ 定价」一票否决** |
| **敏感度** | 使用者人均语音时长 ±50%（15 / 45 小时/月）：代付模式成本 ¥15–¥45/月 → **无论哪一档，代付模式都不成立**；本产品实际模式**恒为 ¥0，不随用量变化** |
| **结果的意义** | **BYO Key 不是产品偏好，是这个价位的唯一活路。** 任何「帮用户代付 API 以降低门槛」的改法，都会把它从「稳赚」变成「必亏」 |
| **置信度** | **高**（结构性推论 + 官方价目） |
| **推翻条件** | 若开发者实际承担了代理成本（如内置 SiliconFlow 引擎是否由作者代付 → **附 C 应查未查项**），需重新核算 |

### B-4 生存线与回本

| 段 | 内容 |
|---|---|
| **假设** | 月毛利/单 = 客单价 − 单用户变动成本；盈亏平衡 = 月固定成本 ÷ 月毛利/单 |
| **依据** | ① 客单价 ¥36；变动成本 = Play 抽成 15% ≈ ¥5.4 → **月毛利/单 ≈ ¥30.6** ② 月固定成本：无服务器、无 API 月费、文档站可免费托管 → **≈ ¥30/月**（域名+杂项）③ 时间机会成本：副业投入 20 h/月 × 时薪 ¥100 = **¥2,000/月** ④ 客服隐性成本：300 付费用户 × 0.3 次/月 × 15 分钟 = **22.5 h/月 ≈ ¥2,250/月** |
| **推算** | 纯现金口径：30 ÷ 30.6 ≈ **1 单/月**<br>含时间机会成本：2,000 ÷ 30.6 ≈ **66 单/月**<br>含时间 + 客服折算：(2,000 + 2,250) ÷ 30.6 ≈ **139 单/月** |
| **结果** | **纯现金口径 1 单/月即转正**（月固定成本极低）→ 对应附 B-2 中位 30 单/月 = **30 倍于生存线 → 现金上非常安全**<br>**含时间机会成本口径需 66 单/月，中位仅 30 单/月 → 覆盖 45%，缺口 55%**<br>**含客服折算口径需 139 单/月 → 覆盖 22%，缺口 78%** |
| **敏感度** | 时薪 ±50%（¥50/¥150）：门槛 33–99 单/月 → **中位 30 单在乐观端（时薪 ¥50）勉强打平，在保守端（¥150）明显不足 → 结论对「时薪假设」敏感** |
| **结论** | **「跑得通但不养人」的精确量化表述：现金账早就正了，时间账没正。判断是否继续做，看第二/三行。** |
| **置信度** | **中**（固定成本低是结构性事实；时薪与客服频次为经验值） |
| **推翻条件** | 若实际月固定成本远高于 ¥30（如自建代理服务），或客单价上调至 ¥99+ |
