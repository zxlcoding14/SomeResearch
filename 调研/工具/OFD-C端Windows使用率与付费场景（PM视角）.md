## TL;DR

**"C 端 Windows 用户使用 OFD 的比例"必须先拆成三个不同的问题，否则答案会差十倍。**

| 口径 | 定义 | 比例 | 绝对人数 | 置信度 |
|---|---|---|---|---|
| **A. 年度接触率** | 12 个月内至少在电脑/手机上收到过一个 `.ofd` 文件 | **6%–11%** | 2,000–3,500 万人 | 低–中 |
| **B. 年度打开率** | 12 个月内**在 Windows 上**真正打开过 `.ofd` | **3.5%–6%** | 1,200–2,000 万人 | 低 |
| **C. 独立装机率** | 电脑上装着一个独立的 OFD 阅读器（非 WPS/非浏览器） | **1.5%–2.7%** | 500–900 万台 | 低–中 |
| （参考）月活 | 每月至少打开一次 | **< 0.5%** | < 150 万人 | 低 |

**结论：OFD 在 C 端是一个"年度个位数百分比、月度千分之几"的长尾格式。它不构成一个产品品类，只构成一个流程环节。**

三条支撑判断：

1. **供给量的天花板已经被官方数字钉死。** 铁路电子发票 2024-11-01 全国上线，**28 天开出 524.5 万张**，日均从 6 万涨到 28 万张（年化约 1 亿张）。而 2025 年全国铁路发送旅客 **46.01 亿人次**——即**开票率只有 2%–5%**。报销行为本身就是一个少数派动作。
2. **接触 ≠ 打开。** 需求方是"公司财务"，不是"本人"。大量 OFD 在流转中被报销系统自动抓取、被转发给财务、或在手机上看掉，根本没有落到 Windows 桌面。
3. **微信不支持直接查看 OFD**（多地税务局公开答复），这是 C 端 OFD 起不来最硬的结构性原因——**它被切断了中国最主要的一条文件分发链**。

**付费：C 端几乎没有。** 有付费的三类人全在"小微 B"边上：个体户/小微企业主（批量发票打印归档）、代账会计、文印打印店。C 端 OFD 直接付费市场约 **¥0.5–1.5 亿/年（$704–2,113 万）**，碎片化、无复购、被免费品全覆盖。

## 一、先把口径拆开：三个"使用率"不是一回事

行业里说"OFD 使用率"经常偷换概念，导致数字从 0.4% 到 30% 都有人讲。必须先分层：

| 层级 | 问的是什么 | 观测方式 | 本文取值 |
|---|---|---|---|
| L0 认知 | 知不知道 OFD 是什么 | 问卷 | 不做（无可靠数据） |
| **L1 接触** | 有没有收到过 `.ofd` 文件 | 开票量 × 格式占比 | 6%–11% |
| **L2 打开** | 有没有打开成功 | 装机 × 使用频次 | 3.5%–6% |
| **L3 深度使用** | 验签、批注、转换、归档 | 功能调用 | < 1% |
| **L4 付费** | 为 OFD 能力单独付过钱 | 付费记录 | < 0.1% |

> ⚠️ **口径陷阱 1**：把"财务人群的 OFD 接触率"当成"全体用户使用率"。合思×财科院绿皮书测得电子凭证格式中 **OFD 占 30.18%**（多选），但样本里财务相关岗位占 34.39%、10 年以上工作年限占 57.89%——**这是财务视角，不是大众视角**。同一份调研里 PDF 占 94.62%、XML 占 18.01%。
>
> ⚠️ **口径陷阱 2**：把"数电票占比 91%"当成"OFD 使用率 91%"。数电票是**票种**，不是**格式**；它的法律载体是 XML，PDF/OFD 只是人眼可读的渲染件。二者不是一回事。

## 三、分子：五条供给管道逐条量化

OFD 不会自己出现在用户桌面上，它必须由某条管道"发"出来。逐条算：

### 3.1 管道一：铁路电子发票（最强、最刚性）

| 环节 | 数值 | 依据 |
|---|---|---|
| 2025 年全国铁路旅客发送量 | **46.01 亿人次** | 【实测·国家统计局】 |
| 电子发票上线 28 天开具量 | **524.5 万张** | 【官方宣称·12306，2024-11-29】 |
| 日均开具量（当时） | 6 万 → **28 万张** | 同上 |
| 年化（按 28 万/日） | **≈ 1.02 亿张** | 【推算·方法】 |
| 2026 年预估（全面推广 + 认知提升） | **1.5–2.5 亿张** | 【预估·依据】 |
| 隐含开票率 | **3.3%–5.4%** | 1.5–2.5 亿 ÷ 46 亿 |
| 开票人年均张数（假设） | 8–15 张 | 【假设】 |
| **开票人数** | **1,000–3,000 万人** | 1.5–2.5 亿 ÷ 8–15 |

**关键细节（决定 OFD 份额）**：12306 下载时同时提供 **PDF 与 OFD**——PDF 供预览打印，**OFD 才是支持电子签名验证与税务查验的归档件**。所以：
- 只为"看一下/打一张"的人 → 选 PDF（多数）
- 需要"合规归档/抵扣"的人 → 被财务要求选 OFD

**OFD 选择率假设 25%–50%**（依企业财务规范程度）→ 铁路侧 OFD 接触人群 **600–1,500 万人**。

> 反直觉点：**2024 年 11 月上线时，铁路电子发票最初只能开 OFD，后来才补上 PDF**（当年 11 月 29 日"好消息：电子发票可以开具为 PDF 格式了"是作为便利化改进发布的）。也就是说，**OFD 是被"减负"掉的那一个**——每加一条 PDF 通道，OFD 的必要性就掉一截。

### 3.2 管道二：航空电子行程单（OFD 属性最强）

| 环节 | 数值 | 依据 |
|---|---|---|
| 2025 年民航客运量 | **7.70 亿人次** | 【实测·国家统计局】 |
| 航空人口 | 5 亿人 | 【官方宣称·交通运输部】 |
| 纸质行程单停用 | 2025-10-01 | 【官方】 |
| 需报销比例（假设） | 40%–50% | 商务出行为主 |
| 年度电子行程单 | **3.1–3.9 亿张** | 【推算·方法】 |
| 与铁路人群重叠 | 50%–60% | 【假设】 |
| **增量接触人数** | **600–1,200 万人** | 【推算·方法】 |

**格式证据**：按财会〔2025〕9 号配套标准体系，**航空运输电子客票行程单、铁路电子客票的合规载体是"内嵌 XBRL 的 OFD"**（同时也可开 XML）。这是 OFD 在 C 端**唯一由政策强制赋予不可替代性**的位置。

### 3.3 管道三：电商与消费发票（最容易高估）

| 项 | 判断 | 依据 |
|---|---|---|
| 淘宝/天猫发票格式 | **PDF 与 OFD 并存**，平台两格式都接收 | 【实测·天猫商家服务大厅】 |
| 二手资料称"淘宝发票大部分是 OFD" | **不采信**：来源为 AI 生成的百科页与厂商营销页，无版本/时间口径 | 判定为二手失真 |
| 个人消费开票量（估算） | 数电票 190 亿份中 B2C 约 10%–15% | 【推算·方法】 |
| 其中个人亲自下载 OFD 并打开 | **< 3%** | 【预估·依据】 |
| **贡献接触人数** | **300–800 万人** | 低置信 |

> 这条管道最容易被"淘宝发票都是 OFD"的旧认知放大。实际情况是：**开票主体是商家，下载动作多数由公司财务完成，个人只是转发**。

### 3.4 管道四：财政电子票据（重要的"排除项"）

这是最容易被误算的一条，方向**相反**：

| 项 | 事实 |
|---|---|
| 格式 | **内嵌 XML 的 PDF**，不是 OFD（财会〔2025〕9 号标准体系明文） |
| 规模 | 极大。仅湖北一省 2025 年就开出 **3.3 亿份**，医疗机构覆盖率 98.4%（【实测·湖北省财政厅】） |
| 场景 | 看病、交学费、交通罚款、不动产登记——**C 端最高频的民生票据** |
| 结论 | **完全不产生 OFD** |

**这条决定了 C 端 OFD 的天花板**：中国人一年接触最多的"电子票据"（医疗、教育、罚没）全部是 PDF，与 OFD 无关。

### 3.5 管道五：电子证照与政企公文

| 场景 | 规模 | OFD 可能性 | 年度人数 |
|---|---|---|---|
| 电子营业执照（可导出 PDF/OFD，带国密签章、口令加密） | 1.37 亿经营主体存量 | 部分选 OFD | 300–600 万（新设+变更） |
| 电子公文（党政机关/国企内部流转） | 信创 PC 存量约 2,200 万台 | 高（OFD 是公文标准格式） | 400–800 万 |
| 电子合同/电子保单/学历证书 | 多为 PDF | 低 | < 200 万 |

### 3.6 汇总

| 管道 | 接触人数（万人） | 在 Windows 上打开的比例 | 打开人数（万人） |
|---|---|---|---|
| 铁路电子发票 | 600–1,500 | 45%–60% | 300–900 |
| 航空电子行程单 | 600–1,200（增量） | 45%–60% | 270–720 |
| 电商/消费发票 | 300–800 | 15%–25% | 45–200 |
| 证照 + 政企公文 | 700–1,400 | 35%–50% | 250–700 |
| **去重合计** | **2,000–3,500** | — | **1,200–2,000** |

**推算比例**（分母 3.3 亿）：
- 接触率 = 2,000–3,500 万 ÷ 3.3 亿 = **6%–11%**
- Windows 打开率 = 1,200–2,000 万 ÷ 3.3 亿 = **3.5%–6%**

## 四、交叉验证：三条独立线索都指向"低"

### 4.1 装机侧：独立阅读器的下载/装机量级很小

| 产品 | 量级 | 口径 | 标签 |
|---|---|---|---|
| 数科 OFD 阅读器（移动端） | 应用宝 6.1 万下载；360 助手 14 万人 | 单渠道 | 【实测·平台】 |
| 数科 OFD 阅读器（PC，天极单镜像） | 4.11 万次 | 单镜像站 | 【实测·平台】 |
| 浙舟 OFD 阅读器 | 53.3 万次下载 | 官网计数器 | 【官方宣称】 |
| 福昕 OFD 版式办公套件 | **100 万+ 用户装机量** | 信创/党政为主 | 【官方宣称】 |

**如果把"3,000 万人需要 OFD"和"头部产品装机百万级"放在一起，唯一的解释是：需求被 WPS 内置、政企预装、在线预览消化掉了，用户根本不需要装独立阅读器。** 这也解释了为什么"独立 OFD 阅读器"从来不是一个能赚钱的品类。

### 4.2 历史侧：OFD 在发票里的占比曾经只有 0.4%

每刻报销平台 2022 年数据：平台流通的增值税发票中，**OFD 格式仅占 0.4%**（PDF 为主）。这是"电子专票 OFD 时代"的真实比例。

对比合思绿皮书（财务人群，多选）的 **30.18%**——两者差 75 倍，**差异全部来自"人群"和"多选/单选"口径**。这正说明：**OFD 只在一个非常窄的职业人群里有存在感。**

### 4.3 分发侧：微信是断链点

多地税务局公开答复：**"微信暂不支持 OFD 格式文件查阅"**，必须"点右上角用浏览器打开再下载到电脑"。

这一句话的杀伤力被严重低估：**中国 C 端文件流转的主干道是微信**。主干道不支持 → 文件必须绕道 → 绕道过程中 90% 的需求被"让对方发个 PDF"化解掉。**这不是产品体验问题，是渠道结构问题，任何阅读器都改不了。**

## 六、付费场景：C 端收不到钱，但三个"小微 B"口子存在

### 6.1 C 端（个人）直接付费：接近零

| 形态 | 实际定价 | 现状判断 |
|---|---|---|
| iOS「OFD阅读器」App 会员 | **¥68/年、¥28/月** | 存在，但规模极小；功能可被免费品替代 |
| 在线 OFD→PDF 转换站 | 免费 / 限页免费 | 流量生意，广告变现，非订阅 |
| 福昕会员（含 OFD 互转） | **¥238/年**（个人版，含 PDF 编辑、转 Word 等） | 卖的是"PDF 全能"，不是 OFD |
| WPS 会员（内置 OFD） | ¥89–¥179/年区间 | 同上，OFD 只是附带能力 |
| 数科 OFD 阅读器 | **免费**（签名、验签、票据助手全免费） | 免费品直接把 C 端价格打到 0 |
| OFD 转换 API（云市场） | ¥0.01/页；2 元/1,000 次 | 这是 B 端 API 价，不是 C 端 |

**C 端 OFD 直接付费市场规模推算**：
3,000 万接触人群 × 付费率 0.2%–0.5% × ¥68/年 = **¥408 万–1,020 万/年（$57–144 万）**。

> 这个数字的意义不是"小"，而是**它连一个两人团队的销售成本都盖不住**。

### 6.2 有付费的三类人（都在小微 B 侧）

| 人群 | 规模 | 需求 | 可承受价格 | 市场量级 |
|---|---|---|---|---|
| **代账会计 / 小微企业财务** | 代账机构 13.68 万家，从业会计 2,000 万+ | 批量打印凭证、批量转 PDF、数据导出 Excel 进 ERP | ¥200–800/套/年 | **¥0.6–1.6 亿/年** |
| **个体户 / 小微企业主** | 1.37 亿经营主体 | 收票后转 PDF 发客户、打印归档 | ¥98–298/年 | **¥0.3–0.8 亿/年**（付费率 <1%） |
| **文印店 / 打印店** | 数十万家 | 客户拿 OFD 来打印，需快速排版出票 | ¥300–1,000/套 | **¥0.1–0.3 亿/年** |

合计 **¥1.0–2.7 亿/年（$1,408–3,803 万）**，与 OFD 整体可统计年收入 **¥3–5 亿** 的量级吻合（见 `OFD-付费场景与商业化可行性（PM视角）.md`）。

### 6.3 三个"看起来能收钱、实际收不到"的伪场景

| 伪场景 | 为什么收不到 |
|---|---|
| **"更好用的 OFD 阅读器"会员** | 数科免费、WPS 内置、政务终端预装，三重免费把价格锁死；用户一年用 3 次，订阅制没有立足点 |

## 七、为什么 C 端就是收不到钱：三个结构性原因

**1. 需求是"任务触发"，不是"持续使用"。**
一个人一年打开 OFD 的次数是 3–15 次，且高度集中在报销季。**订阅制需要一个"每月都回来"的理由，OFD 没有。** 这是订阅模式在 C 端失效的根本原因，不是定价问题。

**2. 付费主体错位：用的人不付钱，付钱的人不打开文件。**
报销人被迫用 OFD，但**采购决策在公司**；公司买的是"报销系统/档案系统"，不是"阅读器"。C 端用户在这个链条里是**零预算节点**。

**3. 免费替代卡在分发链上，不在产品里。**
WPS 预装（覆盖 6 亿+ 月活）、信创整机预装（2,200 万台）、政务终端预装、在线预览、个税票夹——**五个免费入口全部位于"用户还没产生安装念头"之前**。这不是"做得更好就能赢"的竞争，是渠道已被占满。

**4. 附加：微信不支持 OFD。**
这一条单独列，因为它是唯一一个"如果变了，格局会变"的变量。见第八章证伪条件。

---

## 八、证伪条件：什么情况下这个结论会翻

| 变量 | 现状 | 若发生变化 | 对结论的影响 |
|---|---|---|---|
| **微信支持 OFD 直接预览** | 不支持 | 若支持 | **接触率翻倍**，C 端可能出现"轻阅读"需求，但仍难付费 |
| 铁路/航空取消 PDF 通道，只留 OFD | 双格式并存 | 若只留 OFD | 打开率从 3.5–6% 升到 6–9%，**唯一能显著改变分子的杠杆** |
| 财政电子票据改为 OFD | 现为内嵌 XML 的 PDF | 若改 OFD | **分子量级翻 5–10 倍**（医疗/教育是最高频民生场景） |
| 银行回单 C 端化（个人可自助下载 OFD 回单） | 目前以 B 端为主 | 若开放个人 | 增量 500–1,000 万人，但无付费 |
| WPS 把 OFD 能力收进付费墙 | 基础阅读免费 | 若收费 | 可能催生"廉价 OFD 阅读器"需求，**唯一对独立产品有利的变量** |

**我的判断：后四条中任何一条单独发生，都不足以把 C 端 OFD 变成一门生意；只有"财政票据改 OFD + 微信支持"同时发生，量级才会变。这个组合概率我估 <10%。**

---

## 九、结论与建议

1. **不要做 C 端 OFD 阅读器。** 3.5%–6% 的年度打开率、<0.5% 的月活、接近零的付费率，撑不起任何产品形态。
2. **也不要做"C 端 OFD 工具 + 会员"。** 免费替代（数科/WPS/在线）已经把价格打到 0，且分发链（微信）不站在你这边。
3. **如果一定要碰 OFD，只做"流程里的一个动作"，且卖给流程的所有者**：
   - 报销系统的"OFD 归档与验签"组件（卖给费控/档案厂商）
   - 银行回单的结构化抽取（卖给财务共享/RPA，见另一份报告）
   - 代账工具的"批量票据处理"（卖给代账 SaaS）
4. **C 端唯一还值得观察的，是"打印店"这个场景**：它是 C 端里唯一同时具备"必须 Windows + 高频 + 当场付钱"三个条件的地方，但天花板在 ¥0.1–0.3 亿/年。

## 附 B｜测算过程与敏感度

### B1 核心公式

```
接触人数 = Σ(各管道文件量 ÷ 人均张数)
打开人数 = Σ(接触人数 × Windows 打开比例)
比例     = 人数 ÷ 3.3 亿
```
