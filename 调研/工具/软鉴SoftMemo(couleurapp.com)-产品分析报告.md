# 软鉴 SoftMemo（couleurapp.com）— 产品分析报告

> **分析对象**：软鉴 SoftMemo 站点（域名 `couleurapp.com`），含公开目录、清单广场，以及其管理员后台能力
> **快照时间**：2026-10-10（GMT+8）｜**版本**：公开上线 2026-07-24（首帖），距今 78 天
> **分析目的**：**学它 + 判它**——这套"结构化软件档案库"值不值得做、怎么变现、从哪进场
> **计数口径**：条目 = 可独立访问的 `/software/{id}` 详情页（官网自报"371 款"与 sitemap 实测 371 条一致）
> **数据来源分级**：①【审计】无 ②【实测·页面结构】本站 sitemap / 原始 HTML / 路由直取（Python urllib，非渲染代理）③【实测·API】GitHub REST ④【官方宣称】作者在小众软件论坛自述 ⑤【二手转载】论坛回帖、导航站收录 ⑥【第三方估算】SimilarWeb / Semrush（用于同类对标，非本站）
> **本文要回答的 3 个问题**：① 它到底替谁解决了什么 ② 这个品类能不能收到钱 ③ 若我要做，该做哪一段
> **⚠️ 口径提示**：本站**无用户系统、无公开 API 文档、无定价页**，因此"用户量 / 留存 / 收入"在结构上不可得——本文按 `产品分析框架` §4.5 给出**有依据的推算 + 敏感度**，并在附 C 列明获取路径。文中所有推算与实测在版面上分开。

## 〇、结论先行（TL;DR）

1. **【否定性 · 最重要】这不是一门生意，是一个"个人工具被顺手公开"的产物。** 作者在首发帖里把后台的真实用途说得很清楚：那是给他自己用的**软件订阅台账**（买了哪些软件、激活码记录）+ **更新推送**（某软件更新后把 AI 总结的更新日志推到他手机上）+ **每日 GitHub 仓库巡检**（删库/归档第一时间通知他）。公开的那个"软件知识库"只是这套自用系统的外壳。**理解这一点，才能解释后面所有"不合商业逻辑"的地方。**

2. **【否定性】这个品类的天花板被"公共品属性"钉死，且这不是它的锅——龙头已经证明了。** 对标站 **AlternativeTo**（2009 年至今、15 万条应用、200 万条用户评价）公开的唯一价格是**一次性 $5 的"加急审核费"，且官方明文"付费不改变排名、不影响展示"**。**这个品类的世界第一，做了 17 年，没有跑通面向读者的收费。** 原因很硬：内容一旦公开，**给第 N 个读者看一页的边际成本 ≈ 0**，读者没有付费理由。

3. **【否定性】它的内容生产方式本身，就是"护城河不存在"的证明。** 作者自述管线是 `Tavily · Jina · AnySearch 三路检索 + 大模型生成`，并靠这套管线批量产出 371 条档案。这意味着**任何人都能复现同一管线**——它把成本压到近 0 的同时，也把对手的成本压到近 0（与上一个标的 ImgIng 同一结构）。更关键的是作者**自己承认**："AI 总结的还是太宽泛了……感觉这些还是要靠真人体验发掘"——**最该收费的那一层（真人体验），恰恰是他最缺的**。

4. **【肯定性】真正值得抄的只有一块：版本动态 + 停更 / 删库 / 归档 / 安全警示。** 这一层数据来自 GitHub 与官方发布页，**可验证、可自动化、AI 编不出来也编不错**，且有真实的每日持续成本。它是全站唯一"AI 替代不了且用户能感知"的资产。**抄它，别抄那 371 篇 AI 摘要。**

5. **最硬的风险不是商业，是合规。** 收录条目里含大量在中国大陆属高风险类目的工具（第三方 IM 补丁与防撤回、自托管代理面板、影视资源采集与 VIP 解析、网盘增强等），站点自己都给部分条目打了"**已失效**"。作为**个人技术笔记**它一直存在；作为**商业产品**，这一层必须先处理掉——这是本文唯一"碰到了就必须重做"的风险项。

6. **打分卡 63 / 135 = 46.7%**（≤50% 区间），并**实质触发两条一票否决**（合规红线、收款路径不成立）→ **作为独立 C 端商业方向：否。作为"可迁移的编辑格式 + 数据结构"：是**（详见 §十）。

## 一、它到底是什么（L0 + L1）

### 1.1 一句话定义（不贴品类词）

> **把"一款软件是什么、优缺点在哪、现在还活着吗、替代是谁"整理成一份固定结构的档案，并让用户能把成组清单直接分享出去。**

**刻意不用"AI 工具站"开头**——因为"AI"是它的生产方式，不是它的价值。它的货架位置是**软件目录 / 资源导航站（Directory）**，国际同类是 AlternativeTo，中文同类是小众软件、异次元软件世界、果核剥壳、大眼仔旭这一批。

### 1.2 最小可用内核（删掉所有包装后，用户为什么来）

| 问题 | 答案 | 判断 |
|---|---|---|
| 用户为**哪一件事**来？ | 想知道"这款和我现在用的那款，到底差在哪" | 作者原话印证见 §3.3 |
| 删掉 AI 生成还剩什么？ | 一份人工筛选过的软件清单 + **GitHub 版本跟踪** | ⚠️ 前半段无壁垒，后半段有 |
| 删掉清单还剩什么？ | 单条档案 | 单条档案撑不起独立产品 |

### 1.5 内容模型（这是全站最有价值的部分）

每条档案是一份**固定七段结构**（用 `/software/300` 与 `/software/514` 两条实测校验）：

| 段 | 内容 | 字段实测 |
|---|---|---|
| ① 头部元信息 | 分类 / 平台 / **版本（含"今天更新"）** / **星标（实时）** / **安全警示条数** / **"整理于"日期 + 用的哪个模型名** | 例：`v1.0.156 · 今天更新 · 星标 31.8k · 2 条安全警示 · Claude Opus 5 整理于 2026/07/30` |
| ② 一句话定位 | 一句话说清是什么 | — |
| ③ 适合谁 | 列具体人群，不是"所有人" | 例："用 Claude Code、Cursor 批量产出报告和 PPT 的人" |
| ④ 亮点 | 3–4 条 | — |
| ⑤ 功能说明 | 分组详述 | — |
| ⑥ 适合场景 | 列具体场景 | — |
| ⑦ **取舍** | **三栏：「选它的理由」/「先想清楚」（何时别用）/「安全警示」** | **这是全站最值钱的设计** |
| ⑧ 来源存档 + 免责 | 每条结论附来源 URL；页脚"基于公开资料与 AI 分析整理，仅供参考，请自行核实。" | 来源示例：`mkzn.org` 等原始出处，标注"来源记录于 2026-10-09" |

**两个必须记下来的细节**：

- **"整理于"暴露了模型与时间双信息**：`/software/300` 显示 `Claude Opus 5 整理于 2026/07/30`，`/software/514` 显示 `GPT-6.1 Sol 整理于 2026/10/09`。→ **① 用的是多个模型；② 档案有"保质期"概念**（0710 的档案会标注生成日），这是同类站点几乎都没做的**数据新鲜度声明**。
- **"先想清楚 / 安全警示"是反向信息**：多数目录站只写优点（因为要拿佣金），它主动写"什么时候别用"。`/software/300` 甚至写了两条供应链级警告（安装脚本会写入所有 AI 编程工具配置目录、curl 拉远程 SKILL.md 的信任链过长）。**这是它区别于"软文站"的唯一信誉来源。**

## 二、功能分层（T1–T4）

| 层 | 定义 | 本站对应 | 商业含义 |
|---|---|---|---|
| **T1 内核** | 去掉它产品不成立 | **结构化档案**（定位/亮点/功能/适合/取舍/风险）+ **版本与星标实时跟踪** | 定价地基。但注意：内核里"AI 摘要"部分**可被免费替代**，只有"版本跟踪"不可 |
| **T2 增强** | 提效但可替代 | 29 分类、站内搜索、分区浏览 | 不该收费 |
| **T3 差异化** | 只有它有 | **① 三路交叉验证 + 来源存档**（Tavily·Jina·AnySearch，AnySearch 另查 Reddit）**② 安全警示 / 先想清楚（反向信息）** **③ 停更·删库·归档告警** **④ 清单作为可分享产物** | 卖点来源，但需对撞免费替代（§4.1） |
| **T4 长尾** | 低频 / 装饰 | AI 编程技能（仅 2 条）、部分低频分类 | ⚠️ 警惕拿它当卖点 |

**功能全景外的关键缺项（这才是诊断重点）**：

| 缺什么 | 后果 |
|---|---|
| **无用户系统** | → 无留存数据、无推送触点、无复访度量。**这是它最致命的产品缺陷**，也是"订阅"无从谈起的技术根源 |
| **无评价 / 投票** | → 内容质量无外部裁决机制，全靠作者一人；对比 AlternativeTo 的 200 万条评价，这是**代差** |
| **无"个人使用体验"字段** | → 作者自己承认的缺口（论坛原话见 §4.3） |
| **无浏览器扩展** | → 用户提过"打开软件官网时弹出评分"，作者答"真没从这个角度考虑"，说明**触点缺口已被用户点出但未补** |

## 三、用户、场景与频次（L2）

### 3.1 用户分层（作者自己划的 + 实测推断）

| 层 | 是谁 | 证据 |
|---|---|---|
| **核心用户 = 作者本人** | 收藏党 / 工具爱好者 / 一人管着一堆软件订阅 | 后台自用功能（台账 + 激活码 + 更新推送）是**第一用户就是他自己** |
| **第二类：安利者** | 在群里/帖子里给人推荐软件、被问"这跟我用的那个差在哪" | 作者原话："我做这个，还有一个主要用途，就是在安利别人软件时，能让对方迅速了解这款软件，比直接给他们发官网来的直接" |
| **第三类：选型者** | 要换工具、要对比、要避坑（含怕用到停更/有安全问题的） | 站点主打"停更风险""安全争议会明确标出" |
| **明确非用户** | 只想下载的人、要破解的人（它不给下载）、手机用户（它承认没覆盖） | — |

### 3.2 JTBD 句式

> **当** 我要装一个新工具 / 被朋友问"你推荐的这个跟我用的有什么不同" **的时候，**
> **我想要** 一眼看清它的优缺点、还活着吗、替代是谁，并且能把这份对比**直接发出去**，
> **这样我就能** 快速做决定、并且说服对方。

### 3.3 频次 —— **这是全篇的判决点**

| 问题 | 答案 |
|---|---|
| 使用频次？ | **事件驱动，低频**。找软件不是日常动作。 |
| 作者自己多久用一次？ | 每次"安利"时用 → 周级或更低 |
| 频次 × 心理价位（C 端方法论对照） | 月频 → 对标"一次打车"；一次性 → **只能买断/按次，硬收订阅必流失** |
| **致命推论** | **低频 + 用户侧无持续获益 → 订阅不成立**（详见 §5.3） |

### 3.5 切换成本

| 项 | 值 |
|---|---|
| 数据迁移 | 0（无需注册、无数据） |
| 学习成本 | ≈0 |

### 4.1 卖点对撞免费替代（逐条，不许写"有但不够好"）

### 5.1 变现信号穷举（七类全查，结论：**全空**）

| 支付 SDK（Stripe / 支付宝 / 微信支付） | ❌ 无 |

**唯一"看起来像变现"的东西**：站点 meta 与页脚反复出现"**订阅权益**"四个字（`og:description`："AI 整理软件资料、版本动态、更新通知、**订阅权益**与对比分析"）。

### 5.2 对标 AlternativeTo 的变现天花板（本报告最硬的一条行业证据）

| 项 | AlternativeTo |
|---|---|
| 成立 | **2009 年**（至今 17 年） |
| 规模 | **15 万+ 应用 / 200 万+ 用户评价与投票** |
| 流量 | 【第三方估算】Semrush 有机流量 **≈26.6 万/月**（月环比 +11%）；SimilarWeb 口径 ≈250 万/月（两口径差近 10 倍，**已标注冲突**） |
| 对读者收费 | **免费** |
| 对软件方收费 | 收录免费；**唯一公开价格 = 一次性 $5 加急审核费**（把排队从"数月"缩到 1–2 天） |
| 官方明文 | "付费**不改变排名、点赞与展示位置**，只买更快的人工审核"；"没有付费排名、没有 PPC 广告位、没有按席位订阅" |
| 其他收入 | 有"Official Partners"合作，但**条款不公开**（rfp.wiki 标注为 Unknown） |

> **结论（本报告最重要的一条推论）**：**这个品类的世界第一，拿了 15 万条内容、200 万条评价、17 年时间，最终公开的商业模式是"几乎不收费"。** 这不是 AlternativeTo 无能，而是**品类的结构**：目录的价值在"信息可得性"，而信息一旦公开就无法排他。
>
> **推论**：软鉴拿 371 条内容去挑战一个"17 年、400 倍内容量、且已证明收不上钱"的龙头——**问题不在它做得不够好，在这条路上没有钱。**

### 5.3 若它要收费：四条路的逐一判决

| 路 | 做法 | 判决 | 依据 |
|---|---|---|---|
| ① **广告** | 接 Adsterra / AdSense | ⚠️ 技术上可行，**但量级不够**（§6.4 测算：月 UV 2,000 → 月广告收入 ¥36–180） | 需月 UV 10 万才够吃饭；且**中文工具站用户对广告极度敏感**，会毁掉"干净"这个唯一口碑优势 |
| ② **联盟 / CPS** | 挂软件推广链接 | ❌ **结构性不成立**：站内条目**大量是免费/开源软件**（首页 24 条中 15 条标"开源"），无佣金可拿 | 可佣金条目估算占比 ≈20%（§6.5） |
| ③ **付费收录 / 置顶** | 向软件方收排名费 | ❌ 与它的**唯一信誉资产（"先想清楚/安全警示"的中立性）直接冲突**；且龙头明文"不卖排名" | 一旦卖排名，内容可信度归零，等于自杀 |
| ④ **订阅** | 向读者收月费 | ❌ **频率不成立**（§3.3）：用户低频访问 + 内容已公开免费 + 无排他性 | C 端方法论：**低频 + 无持续交付成本 → 只能买断；此处更差——低频 + 内容公开** |

### 5.4 唯一说得通的一条（也是它的机会）

**把作者"自用的那套后台"产品化，而不是把目录拿去收费。**

| 为什么这条不同 | 说明 |
|---|---|
| 它解决的是**高频 + 有真实持续成本**的问题 | "我买过哪些软件、激活码在哪、哪个更新了"——**这是持续发生的**，不是一次性查目录 |
| 有**天然排他性** | 台账与推送是**用户私有数据 + 主动推送**，可 gating；公开目录不可 gating |
| 有**付费先例** | 会买一堆软件、且愿意为管理付费的人，正是"软件订阅党"——付费意愿已被证明（他们本来就在为软件付钱） |
| 但它**天花板小** | 目标人群是"买了很多软件的人"，且这个需求可被"1Password 存激活码 + 邮件订阅 release note"免费凑合（§10.3） |

> **判断**：这条路是**唯一自洽的**，但它把产品从"内容站"变成"工具"，是**另一个产品**，不是现有站的变现。

## 六、盈利模型与生存线（L4.5）

> **本节全部为推算**，与 §一～§三 的实测分开排版。所有推算按 `产品分析框架` §4.5 写成 **假设 → 依据 → 推算 → 结果 + 置信度**。

### 6.1 成本侧 —— 与上一个标的（ImgIng）最大的区别：**它有真实的持续成本**

| 成本项 | 数值 | 假设 → 依据 → 推算 | 置信度 |
|---|---|---|---|
| **① 内容生成（一次性）** | **$56–111**（P50 ≈ $80 ≈ ¥570） | 假设：每条 = 3 路检索 × 4 次查询 + 2,500–4,000 字生成。依据：Tavily 类检索 API 约 $0.008/次起（公开价目页），LLM 输出约 $5/M token。推算：检索 $0.10 + 生成 $0.05–0.20 = $0.15–0.30/条 × 371 条 | **中低**（实际用量未取得） |
| **② 每日巡检 + 更新通知（持续）** | **$1–2/日 ≈ $30–60/月 ≈ ¥215–430/月** | 假设：371 条中约 60% 有 GitHub 仓库 ≈ 220 个（有 token 时 GitHub API 免费）；每日 5–20 个仓库有 release 需 AI 总结（约 1,500 token/条）；网页类软件需抓取对比。依据：作者自述"每日会自动巡检"+"更新日志经过 AI 总结"。推算：$0.05–0.40 + $0.5–1.5 ≈ $1–2/日 | **低—中** |
| **③ 固定（服务器/域名）** | **¥60–130/月** | Next.js SSR 需 Node 运行环境 → 轻量云 ¥50–120/月；`.com` ≈¥70/年；Cloudflare 免费层 = ¥0 | **中** |
| **④ 时间机会成本（最大项）** | **¥2,200–4,300/月** | 假设：每周 5–10 小时（收录建议、校对、迭代、合规自查）。依据：C 端方法论"全成本清单"要求把时间折算成钱；作者自述"一个人维护"。推算：22–43 小时/月 × ¥100/h | **中**（工时未取得） |

| **合计（含时间）** | **≈ ¥2,500–4,850/月** | 全部相加 | 中 |

> **这一节的价值**：**它证明"软件目录站"不是零成本生意**（与"静态站边际成本≈0"的直觉相反）——**AI 巡检与更新总结是每天都要花的钱**。这条成本是它**唯一可以拿去换钱的筹码**（§5.4）。

### 6.2 收入侧与生存线

| 情景 | 需多少付费用户才打平 |
|---|---|
| **现金口径**（¥300–550/月），定价 ¥15/月 | **20–37 个订阅者** |
| **现金口径**，定价 ¥299/年 | **13–23 个年费用户** |
| **含时间成本**（¥2,500–4,850/月），定价 ¥15/月 | **167–323 个订阅者** |
| **含时间成本**，定价 ¥299/年 | **100–195 个年费用户** |

> **读法与上一个标的一致**：**现金口径极易打平（十几单即转正），含时间成本则很难**。这类项目典型的"**热爱可支撑、不能养人**"结构。

### 6.3 流量推算（最关键、也最不确定的数）

> 【未取得】真实流量。以下为**有依据的推算**，置信度**低**，获取路径见附 C。

| 推算方法 | 假设 → 依据 → 推算 | 结果 |
|---|---|---|
| **自下而上（渠道反推）** | 假设：主要外部流量来自 appinn 论坛首发帖 + Telegram 转发。依据：同类案例（同批次 appinn 首发帖）论坛帖首周点击量级 2,000–5,000；论坛引流**首周衰减 80%+**。推算：首发脉冲 ≈1,500–4,000 次，78 天摊薄后**自然访问主要靠搜索** | 月 UV **P50 ≈ 2,000** |
| **SEO 反推** | 假设：371 页、上线 78 天、新域名无外链 → 绝大多数页无排名。依据：新站收录到排名的典型周期 3–6 个月。推算：仅长尾词偶发曝光 | 与上一法一致 |
| **区间** | P10 **500** / P50 **2,000** / P90 **8,000** | — |

### 6.4 广告路径测算

假设：月 UV = 2,000，人均 3 PV → 月 6,000 PV → 展示位 ×2 ≈ 12,000 impressions。依据：中文工具站 RPM 约 **¥3–15/千次展示**（行业常见区间，采集日 2026-10-08，需按平台重核）。

→ **月广告收入 ≈ ¥36–180**。

**敏感度**：UV 放大 5 倍（到 1 万）→ ¥180–900/月；放大 50 倍（到 10 万）→ **才到 ¥1,800–9,000/月**。

→ **结论：广告要能养活自己，需要月 UV 十万级，即当前规模的 50 倍。**（此结论对 RPM ±50% 不翻转。）

### 6.5 联盟/CPS 路径测算

假设：371 条中可挂佣金链接的（免费增值/买断类）≈20% = 74 条。推算：月 UV 2,000 × 30% 会点外链 = 600 次 → 其中 20% 落在可佣金条目 = 120 次 → 购买转化 0.5% = **0.6 单/月** × 客单价 ¥150 × 佣金率 30% ≈ **¥27/月**。

→ **可忽略。** 敏感度：UV ×10 → ¥270/月。（对 UV 与转化率 ±50% 均不翻转。）

| 路径 | 月收入（P50） | 能否覆盖现金成本 | 能否覆盖含时间成本 |
|---|---|---|---|
| 广告 | ¥36–180 | ❌ 否 | ❌ 否 |
| 联盟 | ≈¥27 | ❌ 否 | ❌ 否 |
| 付费收录 | — | **技术上能，但会摧毁唯一信誉资产** | — |
| 订阅（读者） | 结构上不成立（§5.3） | — | — |
| **后台工具化（§5.4）** | **唯一有空间的一条**，但天花板小 | 可能 | 需 100–195 年费用户 |

### 8.5 开源维度（转换口径：它不是开源项目，但技术全在开源侧）

`开源竞品与可复用能力` 的五级判定**不直接适用**（被收录对象是开源软件，本站不是）。但按能力域拆开看，"**复用替代估算法**"结论很干脆：

| 能力域 | 现成方案 | 自建成本 | 结论 |
|---|---|---|---|
| Web 框架 / SSR | **Next.js（MIT）** | — | 不可行（无意义自建） |
| 样式 | Tailwind（MIT） | — | 同上 |
| CDN / 防护 / 免费统计 | Cloudflare（免费层） | — | 同上 |
| **AI 检索 + 生成** | Tavily / Jina / AnySearch / 各 LLM（**商业 API，按量付费**） | 不适用 | **这是唯一"要花钱"的能力域，也是唯一有壁垒可能的地方** |
| **版本 / 停更 / 归档信号** | **GitHub REST API（免费）** | 不适用 | ✅ **免费可得，且是这个产品最值钱的一层** |

> **关键推论**：**它最值钱的能力（版本/停更信号）来自免费 API，最花钱的能力（AI 生成）恰好最不值钱。** 这是一条可以直接指导"该做什么"的结构性结论——**把预算从"生成内容"挪到"监控与告警"。**

### 8.6 定价天花板公式

```
定价天花板 ≈ min(竞品价格, 人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)
```

- 竞品价格 = AlternativeTo **$0**（读者侧）
- 人力替代成本 = 自己记 Notion ≈ ¥0
- 损失规避金额 = "重搜一次"，以分钟计
- 免费替代覆盖率 ≈ **80%（按首问计）** ～ **100%（按"查工具好评"这一功能计）**

→ **天花板 ≈ 0。** 这就是"零变现"的数学原因，与作者是否勤勉无关。

### 10.6 最小验证门槛（写死，不许临场放宽）

| 结论 | 条件 |

### 10.7 三条硬结论

1. **它是一个"好习惯"（记录与整理工具），不是一个"好生意"**——作者自己都在用它做私事（管激活码、收更新推送），公开目录是副产品。
2. **它唯一值钱的资产（停更/归档/安全告警）来自免费 API，唯一花钱的能力（AI 生成）恰好最不值钱**——所以正确的做法是**把预算从"生成"挪到"监控与推送"**。
3. **它长在一条会缩水的河里**：内容获取方式正在从"搜索→点站"变成"提问→得答"，AI 目录与 AI 直答同时挤压它。**要进场，就做 AI 做不到的那一段：真人实测、企业责任、私有数据。**

## 附 B、测算过程与敏感度（**预估与实测分开排版**）

### B1 【推算】内容生成一次性成本

- **假设**：每条档案 = 3 路检索 × 平均 4 次查询 = 12 次检索调用；生成正文 2,500–4,000 中文字 ≈ 5,000–8,000 输出 token。
- **依据**：Tavily 类检索 API 公开起价 ≈ $0.008/次；LLM 输出 ≈ $5/M token（公开价目页）。
- **推算**：
  - 检索：12 × $0.008 = **$0.10/条**
  - 生成：8,000 × $5/M ≈ $0.04 + 输入/多轮 ≈ **$0.05–0.20/条**
  - 合计 **$0.15–0.30/条**
- **结果**：371 条 × $0.15–0.30 = **$56–111**（P50 ≈ **$80 ≈ ¥570**）
- **置信度**：**中低**（实际用量与单价未取得）
- **推翻条件**：若实际使用更贵的推理档或多次重跑，可能上浮 2–3 倍（仍为百美元级，不改变量级）

### B2 【推算】每日巡检 + 更新通知（持续成本）

- **假设**：371 条中约 60% 有 GitHub 仓库 ≈ 220 个；每日 5–20 个仓库有新 release 需 AI 总结（约 1,500 token/条）；另有网页类软件需抓取比对。
- **依据**：作者自述"每日自动巡检""更新日志经过 AI 总结"；GitHub API 有 token 时免费（5,000 次/小时，220 次/日远低于限流）。
- **推算**：AI 部分 $0.05–0.40/日；网页抓取与比对 $0.5–1.5/日 → **$0.55–1.90/日**
- **结果**：**≈ $1–2/日 ≈ $30–60/月 ≈ ¥215–430/月**
- **置信度**：**低—中**（调用量未取得）
- **敏感度**：日调用量 ±50% → ¥110–650/月，**不改变"现金口径极易打平"的结论**
