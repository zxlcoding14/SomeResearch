## 一、执行摘要

白描是一款以 OCR 图片转文字为入口，向文件扫描、表格识别、翻译和 PDF 转换延伸的效率工具。它解决的核心问题不是“能否拍照”，而是如何把纸张或图片中的信息转换成可以编辑、查找、复用和交付的内容。

从产品经理视角，其价值链可以表达为：

**拍摄或导入 → 识别或扫描 → 校对编辑 → 翻译或格式转换 → 导出分享。**

主要结论：

- **已确认：** 官网展示 iOS、Android、Windows、Mac、小程序和网页版，并宣传“一个会员全平台通用”。[S1]
- **已确认：** Apple 中国区接口显示约 4.25 万个评分、约 4.86/5 的评分，首次发布日期为 2017-06-20，查询时版本为 3.5.6。[S2]
- **分析判断：** 白描的差异化更偏向轻量交互、批量操作、结果校对和完整处理流程，而非仅提供一个 OCR 入口。
- **尚不明确：** 累计用户、安装量、DAU、MAU、付费会员数、收入、利润和续费率，本次材料均不能证实。
- **商业化边界：** 存在会员机制可以确认，但具体价格、订阅周期、是否自动续费、免费额度及付费权益未核实。不能直接把“会员”等同于“自动续费订阅”。
- **战略建议：** 优先提升任务完成质量与重复使用，而不是立即扩展成重型企业文档平台；企业服务应作为独立验证方向。

## 二、产品定位与发展逻辑

### 2.1 一句话定位

面向学习、办公和日常办事用户的轻量化文字识别与文档数字化工具。

用户购买的不是 OCR 技术本身，而是省去手工录入、反复裁剪、重新排版和跨软件转换的时间。

### 2.2 产品起点与扩展路径

App Store 描述称，开发初衷是为女朋友制作方便读书做笔记的轻量 OCR 工具，随后加入批量识别、翻译和扫描功能。[S2]

可归纳出以下产品演进逻辑，注意这不是经过完整版本史核实的时间线：

1. 单张图片取字，验证基础需求。
2. 批量识别与校对，服务更重度的资料整理。
3. 文档扫描与 PDF，覆盖正式材料交付。
4. 表格与格式转换，提高结果的可编辑性。
5. 多端入口，覆盖手机采集与电脑处理场景。

### 2.3 产品边界

| 层级 | 已披露内容 | 需要避免的误读 |
|---|---|---|
| 核心产品 | OCR、扫描、翻译、批量处理 | 有功能介绍不等于已验证准确率 |
| 多端入口 | 手机、桌面、小程序、网页 | 会员通用不等于文件自动同步 |
| PDF 扩展 | 官网推荐白描 PDF 在线转换工具 | 不应默认所有端功能与会员权益一致 |
| 关联产品 | 白描证件照、方弗相机 | 不应合并计算白描 OCR 的用户和收入 |

## 三、用户与核心痛点

以下人群划分及付费意愿属于产品分析假设，不是白描后台用户画像。

| 用户群体 | 典型任务 | 原有痛点 | 产品价值 | 付费意愿假设 |
|---|---|---|---|---|
| 学生、考研用户 | 整理教材、课件、习题 | 手打耗时、资料多、格式乱 | 批量取字和校对 | 中，价格敏感且有季节性 |
| 职场人员 | 扫描合同、会议材料、证件 | 无扫描仪、材料提交急 | 清晰扫描件与 PDF | 中高，取决于使用频率 |
| 教师 | 整理试卷和教学材料 | 多页录入、分享流程繁琐 | 批量扫描与导出 | 中高 |
| 研究与知识工作者 | 摘录书籍、档案和论文 | 多栏、竖排、外文难处理 | 识别、校对、翻译 | 中高，重视可信度 |
| 留学生 | 处理外语教材与课堂内容 | 识别和翻译需反复切换 | OCR 与翻译衔接 | 中高 |
| 财务、行政、个体商户 | 录入图片表格、整理清单 | 手工录入易出错 | 图片转 Excel | 高价值场景，准确性要求高 |
| 普通办事用户 | 身份证扫描、证件提交 | 不会裁剪拼接和加水印 | A4 证件扫描件 | 低频，更可能接受单次付费 |
| 视障用户 | 了解图片和环境文字 | 内容不可访问 | VoiceOver 与识别配合 | 需求重要，付费水平待研究 |

### 3.1 六类关键痛点

1. **信息不可编辑：** 图片和纸张无法直接复制到笔记、邮件或文档。
2. **扫描质量不足：** 普通拍照包含杂乱背景、倾斜和光照问题，不能直接用于正式提交。
3. **重复操作成本高：** 多张图片逐一识别、复制、合并，流程冗长。
4. **表格结构丢失：** 即使提取出文字，也可能需要重新建立行列结构。
5. **跨工具切换多：** OCR 后还需翻译、编辑、格式转换与导出。
6. **结果缺乏信任：** 用户必须校对数字、专有名词、证件字段，错误可能带来实际损失。

### 3.2 需求优先级判断

“单张取几个字”容易被系统功能替代；“几十页资料整理成可交付结果”更可能产生付费价值。

因此，建议按任务复杂度而不是仅按人群判断机会：

- 低复杂度：单图复制文字，强调速度与低门槛。
- 中复杂度：多页 OCR、扫描成 PDF，强调批量与稳定性。
- 高复杂度：表格、复杂版式、跨格式转换，强调准确性与可校对性。

## 四、产品功能与使用闭环

### 4.1 功能清单

| 模块 | 公开材料披露的能力 | 主要价值 | 来源与限制 |
|---|---|---|---|
| 基础 OCR | 图片转文字、横排与竖排、手写、多语言 | 减少手工录入 | S1、S2；准确率未实测 |
| 复杂图片 | 长图、多栏图片识别 | 适应资料类图片 | S2 |
| 批量识别 | 一次识别 50 张图片、批量校对 | 减少重复操作 | S2；不应推广为所有端限制 |
| 校对编辑 | 原图对照、分块选择、编辑复制、自动分段 | 提高结果可用性 | S1、S2 |
| 历史记录 | 识别结果自动保存、检索 | 方便再次使用 | S2；跨端同步未确认 |
| 表格识别 | 图片表格转 Excel | 保留结构、减少录入 | S1、S2 |
| 文档扫描 | 自动识别边界、自动拍摄、连续扫描 | 替代部分扫描仪任务 | S1、S2 |
| 图像处理 | 彩色、黑白、灰阶、增强模式 | 提高扫描件清晰度 | S1 |
| PDF | 扫描件合成 PDF；官网展示 PDF 转 Word/Excel/PPT/Markdown | 归档与格式转换 | S1、S2；存在独立 PDF 工具入口 |
| 翻译 | 识别结果翻译、多语言互译、系统分享菜单入口 | 减少切换 | S1、S2；各端支持范围待核实 |
| 身份证 | 正反面 A4 扫描件、水印、分享打印 | 规范提交材料 | S1、S2；S2 称该功能免费 |
| 系统集成 | 相册插件、iPad 多任务与拖放 | 降低使用路径成本 | S2；主要为 Apple 端描述 |
| 无障碍 | VoiceOver 支持 | 改善文字可访问性 | S2，未进行无障碍测试 |

### 4.2 三条核心用户旅程

**旅程 A：图片取字**

选择图片或拍照 → 识别 → 查看结果 → 对照校对 → 复制或分享。

关键成功标准：用户能在较少步骤内获得可用文字，而不是仅收到“识别成功”。

**旅程 B：纸质资料交付**

扫描多页 → 检查裁剪与清晰度 → 确认页面顺序 → 合成 PDF → 提交或分享。

关键成功标准：页码完整、顺序正确、文件可打开、文字清晰。

**旅程 C：表格数字化**

导入表格图片 → 识别行列 → 检查数字和单元格 → 导出 Excel → 继续处理。

关键成功标准：单元格关系正确、数字无关键错误、导出文件可编辑。流程中的逐单元格检查是应关注的需求，不代表已确认存在专门的单元格编辑功能。

## 五、产品需求拆解

本节是从现有产品反推的需求框架，不是厂商内部 PRD。

### 5.1 产品目标

- 减少从原始图片到可用文本或文件的耗时。
- 降低校对与重新排版成本。
- 提高多页任务一次完成率。
- 在不明显增加操作负担的情况下实现合理收费。
- 对证件、合同和个人资料提供清晰的隐私说明与控制。

### 5.2 用户故事与验收方向

| 用户故事 | 验收方向 |
|---|---|
| 我希望拍教材后快速复制文字 | 能处理常见印刷体，保留合理段落，便于复制 |
| 我希望批量整理几十张图片 | 任务进度可见、失败项可定位、结果顺序正确 |
| 我希望合同变成规范 PDF | 边界准确、页面完整、清晰可读、顺序可调整 |
| 我希望表格变成 Excel | 行列结构保留，数字与合并单元格可检查 |
| 我希望知道敏感资料如何处理 | 上传范围、保存期限、删除方式和第三方处理方明确 |
| 我希望购买后清楚能使用什么 | 权益、额度、适用平台、有效期和续费规则透明 |

### 5.3 功能优先级建议

- **P0：核心任务可靠完成。** OCR、扫描、校对、导出、错误提示、隐私告知。
- **P1：重度使用效率。** 批量任务、表格识别、失败重试、长图多栏、结果检索。
- **P2：经过验证后扩展。** 云同步、文档库、团队权限、企业 API、AI 理解。

云同步、团队权限、API 等为建议方向，未在本次资料中证实为现有能力。

### 5.4 非功能需求

- 性能：记录不同图片大小、页数与网络条件下的 P50/P95 耗时。
- 稳定性：避免批量任务整体失败，支持单项重试与中断恢复。
- 安全：明确传输、存储、删除及权限策略，不能只依靠“加密处理”宣传。
- 兼容：保证 PDF、Excel 等导出结果能被主流软件正确打开。
- 可访问性：识别、校对、购买和导出流程均应支持辅助技术。
- 成本：不同识别与转换任务具有独立成本统计，避免高成本功能无限透支。

## 六、体验与差异化分析

### 6.1 值得肯定的产品设计

1. **从识别到结果交付。** 复制、校对、翻译与导出让 OCR 更接近真实任务。
2. **批量处理解决重度需求。** 对资料整理用户，节省时间可能比单张识别更有价值。
3. **原图对照降低纠错负担。** 准确率不可能永远完美，校对效率本身也是竞争力。
4. **多入口降低使用成本。** 手机拍摄、电脑截屏、网页与小程序覆盖不同触发场景。
5. **无烦人广告的产品承诺。** App Store 描述强调这一点，有利于简洁定位；并不等于已审计全部端完全无广告。[S2]

### 6.2 需要警惕的体验断点

- 注册或付费是否在用户看到结果前打断任务。
- 识别结果是否需要大量重新分段与清理空格。
- 多端会员规则与 PDF 工具权益是否容易理解。
- 批量处理出现部分失败时是否能保留成功项。
- 文档自动裁剪错误是否容易手动修正。
- 导出前是否存在页数、格式或水印限制。

以上是待实测检查项，不是已发现的缺陷。

## 七、用户规模与活跃度

### 7.1 可以确认的数据

| 指标 | 调研结果 | 解释 |
|---|---|---|
| Apple 中国区评分数量 | 约 4.25 万 | 两次接口返回 42,453 和 42,456，属于查询快照差异 |
| 平均评分 | 约 4.86/5 | 不能替代代表性满意度调查 |
| 首次发布 | 2017-06-20 | Apple 接口字段，不代表其他端上线时间 |
| 查询时版本 | 3.5.6 | Apple 端版本 |
| 最近更新时间 | 2026-09-18T23:52:40Z | UTC；北京时间为 2026-09-19 07:52:40 |
| 下载价格 | 免费 | 不代表所有功能免费 |
| 累计独立用户/安装量 | 未获得可靠数据 | 不能把评分数量当用户量 |
| DAU/MAU/留存 | 未获得可靠数据 | 无法量化活跃度 |

### 7.2 对上一轮规模推算的修正

上一轮将约 42,453 个评分除以假设评分率 0.5%～2%，得出约 212 万～849 万的数字区间。

这个算式在数学上成立，但**评分率没有经白描数据或可靠行业样本校准，评分口径也不能直接映射安装与去重用户，因此不能把该区间写成真实安装量估计，更不能据此认定“用户大概率百万级”。**

正确使用方式仅是敏感性示例：

| 任意假设的累计评分率 | 算式结果 | 可否用作用户量结论 |
|---|---:|---|
| 2% | 约 212 万 | 不可以 |
| 1% | 约 425 万 | 不可以 |
| 0.5% | 约 849 万 | 不可以 |

本报告的实际结论是：白描拥有多年经营记录与一定公开评价积累，但用户量级仍待可靠数据验证。

### 7.3 活跃度应如何判断

工具产品可能长期安装但低频打开。低 DAU/MAU 不一定意味着价值低，因为身份证或合同处理常由事件触发。

建议分群观察：

- 学习用户：学期和考试周期内的任务频率与回访。
- 办公用户：月度有效任务数与连续月份复用。
- 办事用户：在下一次同类需求发生时是否再次选择白描。
- 重度用户：批量页数、处理时间节省、续费和替代工具使用情况。

没有行为日志时，不应给出虚构的日活、月活或留存率。

### 8.2 合理的商业模式假设

**免费增值：** 基础任务降低使用门槛，复杂任务或更高额度收费。适合建立口碑，但需要验证免费边界不会透支成本。

**会员模式：** 以批量、复杂转换或多端权益提高价值。具体是定期会员、买断还是订阅，必须查看实际购买页。

**按量或短期使用包：** 适合偶发但有明确交付需求的用户，如一次处理数百页材料。属于可评估建议，不是已确认模式。

**企业业务：** 可探索行政、财务和档案整理，但涉及权限、审计、服务保障和数据治理，应与消费级产品单独核算。

**广告：** 与轻量和无烦人广告定位存在张力，不宜仅为短期收入破坏核心体验。现有材料不能量化广告收入。

### 8.3 定价应围绕什么

- 用户节省的时间，而不是单纯展示技术能力。
- 单次、低频与高频用户的不同需求。
- 处理页数、复杂度和成本差异。
- 各端权益的一致性与可解释性。
- 清楚展示有效期、限额、退款及续费规则。

不应将基本导出或用户已生成的结果突然锁住，造成被迫付费感。

### 8.4 收入测算示例——不是白描经营数据

公式：**月度会员收入示意 = 当月付费人数 × 每人当月平均贡献金额。**

| 假设场景 | 假设人数 | 假设每人月均贡献 | 算术结果 |
|---|---:|---:|---:|
| A | 10,000 | 20 元 | 20 万元/月 |
| B | 50,000 | 25 元 | 125 万元/月 |
| C | 200,000 | 30 元 | 600 万元/月 |

以上人数与价格均没有白描证据支撑，仅保留为经营模型示例，不能被引用为白描收入范围或预测。

实际核算还必须区分：

- 支付流水与按服务期间确认的收入。
- 年费预收与当月收入。
- 含税金额、渠道分成、退款后的净收入。
- 一次性买断收入与经常性订阅收入。

### 8.5 单位经济性

建议按任务追踪 OCR、复杂版式、表格、翻译和 PDF 转换的单位成本，再按用户计算贡献毛利。

**用户贡献毛利 = 用户净收入 − 识别/转换/存储等可变成本 − 可归属服务成本。**

主要风险是重度用户消耗大量资源，而低价或永久权益不足以覆盖长期成本。白描的实际引擎供应商、成本结构及毛利未披露，本报告不作认定。

## 九、竞争格局与风险

以下为定位层面的对照，未进行各竞品同版本实测。

| 竞争类别 | 用户为何选择它 | 白描需要证明的价值 |
|---|---|---|
| 系统自带 OCR | 免费、无需安装、操作短 | 批量、复杂版式与校对效率 |
| 扫描全能王等专业扫描产品 | 扫描与文档能力丰富、品牌成熟 | 轻量、少打扰、明确的场景优势 |
| WPS、网盘与办公平台 | 已在现有工作流中 | 更快完成采集与转换，并方便导回办公工具 |
| 翻译与笔记产品 | 下游处理和保存便利 | 识别质量与输出结构更好 |
| 通用多模态 AI | 可识别、总结和问答 | 忠实还原、可校对、批量稳定与隐私透明 |

主要风险：

1. **基础功能被系统替代。** 单图取字差异缩小。
2. **低频需求难支撑订阅。** 用户认可产品，但未必愿意持续付费。
3. **成本与权益错配。** 无限额度或长期低价可能侵蚀利润。
4. **隐私信任风险。** 身份证、合同、财务资料具有较高敏感性。
5. **多端维护成本。** 不同端功能和权益不一致可能引发投诉。
6. **范围扩张风险。** 云盘、知识库、协作、企业服务可能破坏轻量定位。
7. **组织能力不确定。** 产品描述使用独立开发者叙事，但不能据此推断当前团队人数和资源。

## 十、产品指标体系

### 10.1 北极星指标建议

**每周完成有效文档处理任务的去重用户数。**

有效任务应具有识别或扫描结果，并出现复制、导出、分享或明确保存行为；仅打开应用或触发接口不算成功。

低频人群另看月度成功用户与跨月复用，避免只追求日活。

### 10.2 漏斗指标

访问或安装 → 开始导入 → 处理成功 → 结果采用 → 再次使用 → 查看权益 → 购买 → 续费或再次购买。

| 指标 | 推荐定义 | 注意事项 |
|---|---|---|
| 首次激活率 | 新用户中完成首个有效任务的比例 | 明确激活时间窗 |
| 任务成功率 | 成功得到可用结果的任务/发起任务 | 接口成功不等于用户成功 |
| 结果采用率 | 复制、导出、分享或有效保存任务/成功任务 | 去除重复点击 |
| 批量完成率 | 全部页面成功的批量任务/批量任务 | 同时追踪部分失败 |
| 7 日复用率 | 激活用户中 7 日内再完成任务的比例 | 按首用场景分组 |
| 月度付费转化 | 指定用户群内当月首次付费人数占比 | 不能混用累计注册分母 |
| 到期续费率 | 到期可续费用户中实际续费比例 | 买断用户不纳入 |
| 多端使用率 | 在两个及以上端完成任务的用户比例 | 需合规去重身份 |

### 10.3 质量与护栏指标

- 字符错误率及不同语言、字体、拍摄条件的分组表现。
- 表格单元格与结构正确率。
- 用户校对时间和修改比例。
- P50/P95 处理耗时、失败率与崩溃率。
- 导出可打开率和格式兼容性。
- 退款率、投诉率、隐私删除请求处理时长。
- 单任务成本与付费用户贡献毛利。

## 十一、产品优化与路线图

### 11.1 第一阶段：先保障结果质量

- 拍摄时提示模糊、反光、边缘缺失。
- 优化原图与文字联动校对。
- 对数字、日期、专有名词提供重点核对入口。
- 支持批量任务部分失败重试。
- 清晰展示文件处理和删除规则。

验证方式：固定测试集、用户任务测试、任务完成时间及结果采用率比较。不得把建议写成现有产品缺陷。

### 11.2 第二阶段：提高重复使用

- 改善历史记录检索与分类。
- 支持常用导出设置与场景模板。
- 针对学生、办公和表格用户优化默认流程。
- 验证是否确实需要跨端文件接续，再决定建设同步能力。

验证方式：看分群复用、重复任务耗时与付费转化，而不是单看页面访问量。

### 11.3 第三阶段：探索高价值增量

可测试 OCR 后摘要、结构化字段提取、文档问答和多文档对比。但必须：

- 将原文忠实提取与 AI 推断清楚区分。
- 保留原图或原文定位，便于核验。
- 不让模型“纠正”合同金额、姓名和证件号码而无提示。
- 单独核算 AI 成本，并明确相关数据处理规则。

企业版应先通过少量客户验证付费需求，再投入组织管理、审计、API 或私有化能力。

### 11.4 优先级原则

优先投入“高频出现、损失明确、可量化验证”的问题。复杂企业协作不是天然的下一步，先证明其收益能覆盖研发与服务成本。

| 待核实事项 | 建议证据 | 决策影响 |
|---|---|---|
| 实际会员价格与购买类型 | 各端购买页、服务协议、订单样本 | 商业模式与价格分析 |

## 十三、结论

白描的价值在于将 OCR、扫描、校对和转换组合成较短的文档处理流程。多端入口与公开评分积累说明它并非刚起步的概念产品，但不能据此推出具体用户量、活跃度或收入。

产品策略上，应优先巩固复杂和批量任务的完成质量，以可信输出和低操作成本对抗系统自带功能，再通过明确的权益与成本控制实现商业化。

**最终判断：白描是一款具有明确使用价值、已有会员机制的文档效率工具；商业规模与增长质量仍需后台数据和真实使用测试验证。**
