# Visual Studio Code（VS Code）— 产品经理视角分析报告

> **分析对象**：Visual Studio Code（官方发行版 1.142.0 / 2026-10-14）+ Code-OSS 开源仓库 `microsoft/vscode`
> **分析目的**：**学它**（开源换分发的结构怎么设计）+ **判断位势**（AI 时代它会不会被吃掉）
> **快照时间**：2026-10-23（GitHub 数据为当日 API 实测；调查数据为 2026-10-06 发布的 SO 2026）
> **计数口径**：星标/issue 为仓库累计快照；使用率为 Stack Overflow 多选题内占比（**多选，合计 >100%，不可当市场份额**）；用户数为微软官方口径（**VS + VS Code 合计**，非单品）
> **数据可信度分级**：① 经审计 ② API/一手调查实测 ③ 官方宣称 ④ 第三方估算 ⑤ 二手转载。逐条标注见附 A。

---

## 〇、结论先行（TL;DR）

1. **VS Code 不是"编辑器生意"，是"开发者入口生意"。** 编辑器本体 ARPU = 0（无 Pro 版、无订阅），钱全部落在它身后的三层：GitHub Copilot（付费 470 万、估算 ARR $20 亿 / ¥142 亿）、Azure 消费、企业 GitHub 席位。**5,000 万 MAU 是流量池，不是收入池。**

2. **"VS Code 是开源的"是本产品被误读最深的一点，而这个误读正是它的商业模式。** MIT 只覆盖 Code-OSS；微软官方发行的二进制是**专有免费软件**（Microsoft Software License）；Marketplace 服务条款（2025-09 版）**明确禁止任何 fork 接入**；微软自家的 C/C++、Pylance、Remote、C# 扩展**只授权给 VS 系产品**。四层结构 = **开放内核 → 封闭分发 → 封闭市场 → 封闭 AI**，是"开源获客、闭源收钱"的教科书样本。

3. **真正的护城河是扩展生态 + 切换成本 + 企业分发，不是代码。** Cursor、Windsurf（现 Devin Desktop）、Trae、Kiro、VSCodium 全部 fork 自 Code-OSS，**代码 100% 可复制**；但没人复制得了 10 万+ 扩展、微软专有扩展授权、以及"公司 IT 已经默认装好"的分发位。

4. **2026 年出现十年来第一次结构性松动，但松动不在"编辑器"这一层。** SO 使用率 **75.9%（2025）→ 70.9%（2026），-5.0pct**；agent 类目里 **Claude Code 65.5% 反超 Copilot 58.7%**。VS Code 的应对不是防守编辑器，而是**把编辑器改造成 agent 宿主**（Agent HQ / 多 agent 并行 / Agent Host Protocol），把自己从"编辑器"重定义为"agent 的操作系统"——这是本轮最值得学的一步。

5. **对个人/小团队的可迁移结论：不要做"更好的编辑器"（L4，被官方免费 + 开源双覆盖），要做它结构性不做的那一段。** 三个可验证空位：① 扩展与配置治理（22,049 个未关 issue、40+ 扩展即 1.5–2GB 内存）；② 隐私/合规分发（VSCodium 已占 7.7%，约等于每 13 个 VS Code 用户有 1 个在逃离遥测）；③ agent 会话与成本审计（企业侧，非个人侧）。

## 一、定位与口径（L0 + L1）

### 1.1 一句话定义（不贴品类标签）

> **它替开发者完成的任务是：「在一个窗口里，把『写代码』这件事所需的编辑、理解、运行、调试、提交全部接上，并且允许任何人给它加装能力。」**

品类归属：**代码编辑器（Code Editor）**，但因为扩展生态，实际货架位置是「开发工作台 / IDE 平台」。这个货架决定了它的竞品不只是编辑器，还包括 IDE（JetBrains、Visual Studio）与 agent 工具（Claude Code、Codex）。

### 1.2 最小可用内核

删掉所有包装后，用户为**一件事**安装它：**打开一个项目文件夹，获得「语法高亮 + 智能补全 + 跳转 + 调试 + Git」的开箱组合，且跨三大平台一致。**

Non-scope（它明确不做）：
- 不做重型 IDE 的深度重构/建模（让给 Visual Studio、JetBrains）；
- 不做语言运行时与编译器（让给 SDK）；
- **不做编辑器收费**（明确不做 Pro 版）；
- 不做封闭的 AI 模型（只做模型的路由与宿主， Claude / Codex / GPT 都可接）。

### 1.3 口径陷阱（本产品必须先拆清，否则所有数字都错）

| 陷阱 | 常见错法 | 正确口径 |
|---|---|---|
| **用户数** | "VS Code 有 5,000 万用户" | 官方原话是 **Visual Studio + VS Code 合计 5,000 万 MAU**（微软 CVP Amanda Silver，2025-05）。单品未披露。 |
| **开源程度** | "MIT 开源，谁都能用" | 仓库 MIT；**官方二进制是专有许可**；Marketplace 与微软扩展另有条款。三者不是一回事。 |
| **使用率** | "VS Code 占 70.9% 市场" | SO 是**多选题内占比**（n=13,193，可选多个），**不是市场份额**，不能与 JetBrains 财报份额直接比。 |
| **Copilot 用户** | "5,000 万人在用 Copilot" | 5,000 万是 **Copilot 累计用户**（2026-07），其中**付费 470 万**（2026-01）。两者差 10.6 倍。 |
| **版本** | 引用博客里的 "1.96 LTS" | 实际稳定版 **1.142.0（2026-10-14）**，月更节奏。中文技术博客的版本号多为编造。 |

## 二、功能全景（四层分层）

| 层 | 内容 | 商业含义 |
|---|---|---|
| **T1 内核**（删掉就不是它） | Monaco 编辑器内核、LSP 语言智能、DAP 调试协议、Git 集成、**扩展宿主模型**、Remote（SSH / WSL / Dev Container / Codespaces）、Win/mac/Linux/Web 四端一致 | 获客地基，**永久免费**，也是所有 fork 的复制对象 |
| **T2 增强** | 集成终端、任务系统、Jupyter Notebook、Settings Sync、Profiles、Workspace Trust、Live Share、内置浏览器（2026 新增 agent 可驱动） | 留存层，与竞品重合度最高 |
| **T3 差异化**（2026 的主战场） | **Agent HQ**：Agent Sessions View 统一管理本地/后台/云端会话；**多 agent 并行**（Copilot + Claude + Codex，同一 Copilot 订阅）；**子 agent 并行**（上下文隔离）；Plan Agent（先出计划再改码）；**Agent Host Protocol（AHP）** 跨窗口/跨应用续接会话；MCP Apps；Autopilot；1M 上下文；模型选择器 | 卖点层，也是**唯一能收订阅的一层** |
| **T4 工程与合规** | 遥测、自动更新、扩展更新延迟 2 小时（供应链缓冲）、托管设置（Windows/macOS MDM + JSON 文件）、Marketplace 审核/下架/黑名单、Workspace Trust | 用户看不见，但**企业采购看这一层**；也是"开源但不自由"的落点 |

**关键读法**：T1 全部被 MIT 开源（fork 可复制），T3 全部是闭源（Copilot 服务端 + 微软扩展），T4 里的 Marketplace 是**条款护城河**而不是技术护城河。**开放的那一层刚好是不赚钱的那一层。**

## 三、用户与场景（L2）

### 3.1 用户分层

| 角色 | 是谁 | 规模/特征 | 付费关系 |
|---|---|---|---|
| **核心使用者** | 全栈/前端/脚本/数据/运维/学生 | SO 2026：**70.9%** 的受访开发者过去一年用过 | 用编辑器不付费 |
| **付费者** | 个人专业开发者 | Copilot Pro **$10/月**、Pro+ **$39/月** | 付费买 AI，不买编辑器 |
| **付费者（真正的钱）** | 企业 IT / 工程效能部门 | Copilot Business **$19/席/月**、Enterprise **$39/席/月**；约 90% Fortune 100 部署 | 席位制，走采购 |
| **影响者 / 阻挠者** | 安全合规、法务 | 遥测默认开启、扩展供应链、Marketplace 条款 | 决定"能不能装" |

### 3.2 触发场景（JTBD）

- **日常主力**："今天要在这个仓库里写一天代码" → 打开即用，配置已同步；
- **临时查看**："快速改一个配置文件 / 看一个 PR" → 启动快、不需完整 IDE；
- **远程/容器**："代码在服务器/容器里，但我要本地体验" → Remote 是它最硬的独占场景之一；
- **交给 agent**（2026 新增）："这个重构交给 agent，我去开另一个会话" → Agent Sessions View。

### 3.3 使用频次与替代谱系（必须列全 6 类）

频次：**日频、每日数小时**——这是它能把免费用户转成订阅的结构前提（高频才有续费）。

| 替代类型 | 具体对象 | 覆盖度/证据 | 判定 |
|---|---|---|---|
| 什么都不做 | 记事本 / nano / cat | 极低频场景仍存在 | 不构成威胁 |
| 系统/平台内置 | GitHub 网页编辑器、DevTools Snippets | 只能改单文件 | L0，弱 |
| **免费开源** | **VSCodium 7.7%**、Neovim 14.7%、Vim 27.2%、Notepad++ 27.8%、Zed 11.4%（开源） | SO 2026 实测 | **最强的一档**：VSCodium 就是"去掉遥测的 VS Code" |
| 直接竞品 | Cursor 14.9%、Windsurf/Devin 3.2%、Kiro 2.8%、Trae 0.7%、JetBrains IDEA 24.3% | SO 2026 实测 | 真实分流，但**多数是并用不是替换** |
| 间接竞品 | Visual Studio 27.6%、JetBrains 全家桶 | 重型 IDE，场景不同 | 长期共存 |
| **新一层：CLI agent** | **Claude Code 65.5%（agent 类目第一）**、Codex 29.5% | SO 2026 实测 | **这一层绕过了编辑器**，是唯一可能"降维"的对手 |
| 自己动手 | dotfiles、自写扩展、自建 LSP | 极客行为 | 生态的养分，不是威胁 |

> **口径声明**：以上百分比均为多选题内占比，受访者可同时选多个，合计远超 100%。**"Cursor 14.9%" 与 "VS Code 70.9%" 不是"此消彼长"关系**——大量开发者是"VS Code 主力 + Cursor 试用 + Claude Code 辅助"三开。

### 3.4 切换成本（护城河的真正来源）

| 成本项 | 强度 | 说明 |
|---|---|---|
| 配置迁移 | 中 | settings.json / keybindings / snippets 可导出，但插件组合难复刻 |
| **扩展可用性** | **高** | fork 只能用 Open VSX；微软 C/C++、Pylance、Remote、C# **法律上不可装** |
| 团队统一 | 高 | `.vscode/` 目录、推荐扩展、devcontainer.json 已进代码库 |
| 企业合规 | 高 | MDM 托管设置、Workspace Trust、扩展白名单 |
| 肌肉记忆 | 中 | 快捷键可迁移，但"命令面板"心智难改 |

## 四、价值主张与需求硬度（L3）

| 判断项 | 结论 | 依据 |
|---|---|---|
| 痛点 / 痒点 / 爽点 | **痒点为主**（效率与顺手），**痛点只在两处**：远程开发、团队统一 | 不用它也能写代码（Vim/Notepad++ 27%+），但"换掉它"的成本高于"忍着" |
| 卖点真伪 | T1 的卖点已被免费替代覆盖（编辑器本身）；**T3 的 agent 编排是当下唯一未被覆盖的卖点** | Cursor/Zed 已复制 T1；Claude Code 已覆盖"单 agent"，但**没有一个产品做好"多 agent 编排 + 会话管理"** |
| 可感知的 10 倍 | 不是"快 10 倍"，是"**少切 10 次窗口**"（Agent Sessions 把 3 个 chat + 2 个 CLI 会话收进一个面板） | 官方 1.109 发布说明的原始动机 |
| 刚需还是可选 | **对专业开发者是刚需**（默认答案），对学生/偶发编码者是可选 | SO 使用率 70.9% + Codespaces 6.6% |
| 天花板 | 开发者总量 × 编辑器渗透已接近饱和 | MAU 5,000 万（VS+VS Code），GitHub 注册开发者 1.5 亿+，付费渗透仅 3.1% |

**需求硬度的真实位置**：VS Code 的价值不在"编辑"，而在**"默认"**——它是新机器上第一个被装的工具、教程里第一个被提到的工具、团队 onboarding 文档里写死的工具。**"默认"本身就是最强的需求，也是最难被功能打败的需求。**

## 五、商业模式与付费墙（L4）

### 5.1 收入结构（编辑器本体 = 0）

| 收入层 | 计费 | 价格 | 规模 | 备注 |
|---|---|---|---|---|
| **编辑器** | 免费 | $0 | — | **无 Pro 版，永不变现** |
| **GitHub Copilot 个人** | 订阅 | Free（2,000 补全 + 50 chat/月）/ Pro **$10/月** / Pro+ **$39/月** | 付费 470 万（2026-01，+75% YoY） | 2026-06-01 起叠加 **usage-based AI Credits（$0.01/credit）** |
| **Copilot 企业** | 席位 | Business **$19/席/月** / Enterprise **$39/席/月** | 约 90% Fortune 100 部署 | 真正的收入主体 |
| **Azure / GitHub / Codespaces** | 用量/席位 | 按服务 | 未披露 | 编辑器是入口，不是收入 |
| **Marketplace** | 不向用户收费 | 扩展免费为主 | 10 万+ 扩展 | 收的是**生态位**，不是钱 |

### 5.2 付费墙位置（本产品很特殊）

| 墙型 | 是否存在 | 位置 |
|---|---|---|
| 功能墙 | ✅ | agent 能力、模型选择、1M 上下文、Pro+ 专属（Claude/Codex 云端 agent） |
| **用量墙** | ✅ **2026 年新增** | AI Credits 按 token 计量 —— 这是本轮最重要的商业变化 |
| 时间墙 | ❌ | 无试用期概念 |
| 体验墙 | ❌ | 无广告、无功能阉割 |
| **编辑器墙** | ❌ **不存在** | **编辑器功能 100% 免费** |

> **判定**：这是"**免费工具 + 付费服务**"的干净分层，不是"免费阉割 + 付费解锁"。它遵守了本方法论反复验证的一条铁律——**没有持续交付成本的部分不收费，有持续成本的部分（模型推理）才收费**。

### 5.3 为什么 2026-06 必须转用量计费（本轮最硬的商业信号）

- 官方口径：转用量计费后 **Copilot 收入环比增长 >60%**；
- 真实原因写在产品动作里：**agent 模式单次任务的 token 消耗是补全的几十到上百倍**，flat-rate 订阅在 agent 场景下是负毛利结构。
- **这不是涨价，是商业模型修正**：把"不可预测的推理成本"转嫁给"不可预测的使用量"。

### 5.4 单位经济（ARPU 断层，本方法论的核心指标）

| 口径 | 计算 | 结果 |
|---|---|---|
| **编辑器 ARPU** | $0 ÷ 用户 | **$0** |
| Copilot 付费渗透（分母= Copilot 用户） | 470 万 ÷ 5,000 万 | **9.4%** |
| Copilot ARPPU（年化，含企业混合） | $20 亿 ÷ 470 万 | **≈$425/年（≈¥3,018/年）** |
| Copilot ARPPU（按最低估值 $9 亿） | $9 亿 ÷ 470 万 | ≈$191/年（≈¥1,356/年） |
| **同产品内 ARPU 断层** | $0 → $425 | **无穷倍**（0 到正数） |

> **读法**：这是本方法论里见过的**最极端的 ARPU 断层**——同一产品内，一层的 ARPU 结构性为 0，另一层是 ¥3,000/年。**断层的位置不在功能，在"有没有持续交付成本"。**

## 六、竞争位势与免费替代（L5）

### 6.1 竞争四层 + 新第五层

| 层 | 对象 | 2026 位置 | 威胁等级 |
|---|---|---|---|
| **直接竞品** | Cursor 14.9%（$40 亿 ARR / ¥284 亿，被 SpaceX 以 $600 亿 / ¥4,260 亿收购，2026-08-14 交割）、Zed 11.4%（1.0 于 2026-04-29）、Devin Desktop 3.2%、Kiro 2.8%、Trae 0.7% | AI-first 编辑器 | ★★★（抢高价值用户，不抢大盘） |
| **间接竞品** | JetBrains（IDEA 24.3%、PyCharm 13.5%）、Visual Studio 27.6% | 重型 IDE | ★★（场景分层，长期共存） |
| **免费替代（开源）** | VSCodium **7.7%**、Neovim 14.7%、Vim 27.2%、Notepad++ 27.8% | **VSCodium 是同一份代码的去遥测版** | ★★★（唯一"零成本同体验"替代） |
| **免费替代（系统/平台）** | vscode.dev、GitHub 网页编辑、Codespaces 免费额度 | 弱 | ★ |
| **新第五层：CLI agent** | **Claude Code（agent 类目 65.5%，ARR $25 亿 / ¥177.5 亿）**、Codex 29.5% | **不装编辑器也能干活** | ★★★★（**唯一可能降维的一层**） |
| 用户自己动手 | dotfiles、自写扩展 | 生态养分 | ★ |

### 6.2 开源覆盖度五级判定（本层必做）

| 对象 | 等级 | 判定依据 |
|---|---|---|
| Code-OSS（VS Code 内核） | **L4（被官方免费覆盖）** | 微软自己开源，任何人可 fork，**不存在"做一个更好的开源编辑器"的位置** |
| AI-first 编辑器（Cursor 类） | **L3（有活跃成品）** | $40 亿 ARR、14.9% 使用率，且已被巨头收购 |
| 多 agent 编排 / 会话管理 | **L1–L2（有库无成熟独立产品）** | VS Code 自己在做（Agent HQ），Conductor 类工具年轻且单薄 → **独立产品位极窄** |
| **扩展/配置治理（体检、瘦身、冲突检测）** | **L1（有空位）** | 有零散脚本与 issue，无成熟 GUI 成品 → **唯一像样的空位**（待一手核实，见附 C） |
| **去遥测/企业合规定制** | **L2–L3** | VSCodium（免费、社区维护）+ 企业自建；**商业化成品的空位在"合规打包 + MDM + SBOM"** |

### 6.3 差异层级与竞品盲区

| 竞品 | 它明确不做 / 做不了 | 留下的空位 |
|---|---|---|
| **Cursor** | 不做自有扩展市场（只能用 Open VSX）；不做完整企业合规套件；**每月的 rebase 税**（跟随上游 1.1xx 节奏合并） | 企业合规、微软专有扩展场景 |
| **Claude Code** | 不做 GUI 编辑器；不做团队会话管理；不做本地扩展生态 | "agent 的可视化宿主"（VS Code 正在吃） |
| **Zed** | 不做 Codespaces 等价物；无企业 SSO/合规；扩展生态小（WASM 扩展待完善） | 企业级 remote + 合规 |
| **JetBrains** | 不做免费跨平台轻量编辑器；订阅价高 | 学生、脚本、偶发编码 |
| **VSCodium** | 不做商业化；不提供支持；扩展生态不完整 | **企业级"去遥测 + 合规"付费包** |

### 6.4 它最危险的地方（不是 Cursor）

> **Cursor 抢的是"愿意为 AI 多付 $20 的人"，这群人本来就付得起，VS Code 用 Copilot 就能接住。**
> **真正危险的是 Claude Code 这一层：它把"写代码"从"在编辑器里操作文件"变成"在终端里下任务"，编辑器的存在必要性被绕过了。**
> VS Code 的应对（Agent Host Protocol + 跨应用续接会话 + 外部 agent session 导入）**正是在把这一层的入口抢回自己**——官方 1.135 已支持"在 VS Code 里继续你在别的应用里开的 Claude/Copilot 会话"。这是本轮最聪明的一步。

## 七、持续性与风险（L6）

### 7.1 护城河与时间窗

| 护城河 | 强度 | 还能守多久 | 依据 |
|---|---|---|---|
| **扩展生态（10 万+）** | ★★★★★ | 3–5 年 | 网络效应：扩展作者只投最大市场；fork 只能用 Open VSX |
| **切换成本（团队 + 配置 + 合规）** | ★★★★ | 3 年+ | `.vscode/` 进代码库、MDM 托管设置 |
| **企业分发（90% Fortune 100 用 GitHub）** | ★★★★★ | 5 年+ | 采购惯性，非产品力 |
| **品牌 = "默认答案"** | ★★★★ | 2–3 年 | SO desired 40.6% 仍第一 |
| **技术（Electron/Monaco）** | ★★ | **已无** | Electron 是债不是壁垒；Zed 原生架构已证明可超越 |

**综合时间窗判断：12–24 个月**是"编辑器形态"的关键窗口。依据：Cursor 从 0 到 14.9% 使用率只用了 3 年；Claude Code 从 0 到 $25 亿 ARR 只用了约 15 个月。

### 7.2 风险清单

| 风险 | 证据 | 影响 |
|---|---|---|
| **性能债（Electron）** | 第三方实测：Zed 冷启动 0.12s vs VS Code 1.2s；内存 3–16 倍差；40+ 扩展 = 1.5–2GB RAM | 高端用户流失到 Zed |
| **遥测/隐私分流** | 遥测默认开启（opt-out）；**VSCodium 已占 7.7%** | 约每 13 个用户有 1 个在逃离 |
| **AI 成本倒挂** | 2026-06 强转 usage-based，收入 +60% QoQ | 说明 flat-rate 在 agent 场景不可持续 |
| **扩展供应链安全** | Marketplace 审核 + 自动下架 + 2 小时更新延迟（都是补丁） | 一次恶性扩展事件即品牌危机 |
| **issue 积压** | **22,049 个未关 issue**（2026-10-23 实测） | 社区参与是"倾倒"不是"共建"；也是治理工具的需求证据 |
| **fork 反向蚕食** | 所有 AI 编辑器都 fork 自它；Open VSX 已成型 | 开源红利被对手吃掉 |
| **满意度下滑** | Copilot "most loved" 从约 30% 降至 9%（第三方分析）；SO：仅 6.6% 高度信任 AI 输出 | "用但不喜欢"= 替换窗口 |

### 7.3 生命周期位置

**成熟期，但形态在迁移**：编辑器层的增长已停滞（使用率首次下降），agent 宿主层仍在高速增长（Copilot 收入 +60% QoQ）。**它不是衰退，是"换壳"——把产品定义从"编辑器"换成"agent 的运行界面"。**

## 八、可迁移结论与机会点（L7）

### 8.1 能抄什么（机制层，可直接复用）

| # | 机制 | 具体做法 | 为什么有效 |
|---|---|---|---|
| 1 | **四层开源结构** | 内核 MIT 开源换分发 → 官方二进制专有 → 市场条款封闭 → AI 服务收费 | 既拿到"开源"的信任与生态，又保住变现 |
| 2 | **市场即护城河** | 不做功能壁垒，做"扩展作者只来我这里"的网络效应 | 功能会被抄，生态不会 |
| 3 | **把新范式收编，不对抗** | 不禁止 Claude/Codex，反而让它们在 VS Code 里跑，并统一计费 | 把对手变成自己的流量 |
| 4 | **免费层做渗透，用量墙做变现** | Free 给 2,000 补全；agent 用量按 credit 计 | 免费层不阉割体验，收费层有真实成本 |
| 5 | **企业合规是 C 端工具收 B 端钱的通道** | MDM 托管设置、Workspace Trust、扩展白名单 | 个人不付的钱，IT 部门会付 |

### 8.2 别做什么（反面清单）

| ❌ 不要做 | 原因 |
|---|---|
| 通用编辑器 / IDE | L4：官方免费 + 开源 + 10 万扩展，三重封锁 |
| "更快的 VS Code fork" | rebase 税（月更上游）+ Open VSX 生态不足 + 微软专有扩展法律不可用 |
| 通用 AI 补全插件 | Copilot Free（2,000 次/月）+ Claude Code + Cursor 已覆盖 |
| 通用多 agent 编排器 | VS Code 自己下场（Agent HQ / AHP），且 Conductor 类已拥挤 |
| 靠"开源"做差异化 | 代码可复制，护城河在市场与分发，不在代码 |

### 8.3 三个可验证空位（个人/小团队，按可行性排序）

| # | 空位 | 需求证据 | 付费逻辑 | 初判 |
|---|---|---|---|---|
| **1** | **VS Code 扩展/配置治理工具**（体检 → 启动耗时归因 → 冲突检测 → 一键瘦身 → 配置快照） | 22,049 未关 issue；40+ 扩展 = 1.5–2GB；Zed 对比 3–16x 内存；"extension hell"是社区高频抱怨 | 买断 ¥68–99（无持续成本，**不许做订阅**）；也可做成团队版（`.vscode/` 基线审计） | **可做，但需先核开源覆盖**（见附 C）。生死变量是分发，不是技术 |
| **2** | **企业级"合规 VS Code"打包**（去遥测 + 预置扩展 + MDM 策略 + SBOM + 更新通道） | VSCodium 7.7% 证明需求真实；企业不敢用社区版（无支持、扩展不全） | B 端年费/席位（有持续成本：安全更新、扩展兼容、合规文档） | **价值最高但门槛最高**：需要企业渠道与合规能力，个人难独立起量 |
| **3** | **agent 会话/成本审计（团队侧）** | Copilot 转 credit 计费后，"每个会话花了多少"成为管理问题；官方只做到"看总量" | B 端订阅 | **谨慎**：LiteLLM/Langfuse 已覆盖通用 LLM 成本；本空位只在"VS Code 会话级"这一窄缝，**易被官方吃掉** |

> **诚实结论**：VS Code 这个标的**对个人开发者几乎没有"做产品"的机会**，它的价值在**方法论**——四层开源结构、市场即护城河、把对手收编成流量。三个空位里只有第 1 个过得了个人开发者的四道闸门（收得到钱 / 扛得住成本 / 送得到人 / 算得过账），且必须先验证分发。

## 附 B、测算过程（假设 → 依据 → 推算 → 结果 + 敏感度）

> 本节全部为**推算**，与附 A 的实测/官方数据分列。禁止混读。

### B1. VS Code 单品 MAU 推算

- **假设**：VS Code 占 VS + VS Code 合计 MAU 的 **85%**（P50），区间 80%–90%。
- **依据**：① 官方只给合计 5,000 万；② VS 是付费/Windows 限定 IDE，历史口径中 VS 订阅量级约 200 万+（二手，不作为硬依据）；③ SO 使用率 VS Code 70.9% vs Visual Studio 27.6%，比值 2.57:1，但使用率非装机量，需按"VS 用户几乎都同时用 VS Code"修正。
- **推算**：5,000 万 × 85% = **4,250 万**；区间 4,000 万–4,500 万。
- **结果**：VS Code 单品 MAU **约 4,250 万（P50）**，置信度**中**。
- **推翻条件**：微软公布单品 MAU，或 VS 订阅数被审计披露。

### B2. Copilot 在 VS Code 用户中的付费渗透

- **口径 A（分母 = Copilot 用户）**：470 万 ÷ 5,000 万 = **9.4%**。这是"用 Copilot 的人里有多少付钱"，**不是**"VS Code 用户付费率"。
- **口径 B（分母 = VS Code MAU 推算值）**：470 万 ÷ 4,250 万 = **11.1%**（上限，因部分付费者不用 VS Code，如 JetBrains 用户）。
- **结论**：付费渗透 **9.4%–11.1%**，置信度**中低**（分子分母时点差 6 个月）。
- **敏感度**：若 MAU 取 4,000 万，渗透升至 11.8%；若取 4,500 万，降至 10.4%。**结论不翻转**（量级稳定在 1 成左右）。

### B3. Copilot ARPPU

- **公式**：ARPPU = 年化收入 ÷ 付费用户数。
- **高值**：$20 亿 ÷ 470 万 = **$425.5/年 ≈ ¥3,021/年**（企业混合占比高，接近 Business/Enterprise 档）。
- **低值**：$9 亿 ÷ 470 万 = **$191.5/年 ≈ ¥1,360/年**（更接近 Pro 档 + 部分企业）。
- **对标**：Cursor Pro $20/月 = $240/年（¥1,704）；Claude Code 按用量无固定 ARPPU。
- **结论**：Copilot ARPPU **$191–425/年（¥1,360–3,021/年）**，中值约 **$300/年（¥2,130/年）**。置信度**低**（收入本身是估算）。
- **敏感度**：收入 ±50% → ARPPU 在 $96–638 之间摆动。**这个区间跨度过大，说明"Copilot 到底赚多少钱"本身不可靠，任何基于它的估值论证都不稳。**

### B4. 使用率下滑的归因测算（-5.0pct 是否等于"用户流失"）

- **观测**：75.9%（2025，n>49,000）→ 70.9%（2026，n=13,193），**-5.0pct**。
- **候选解释**：① 真实流失到 Cursor/Zed；② 样本结构变化（2026 样本 30,903 vs 2025 的 49,000+，新人占比可能不同）；③ 多选题竞争项变多（2026 新增 Kiro、Antigravity、Trae 等选项，稀释了其他选项的勾选率）。
- **判别**：若为①，Cursor+Zed 的增量应约等于 VS Code 的减量。实际 Cursor 14.9% + Zed 11.4% = 26.3%，远大于 5.0pct → **说明主要是"并用"而非"替换"，且③的稀释效应存在。**
- **结论**：**-5.0pct 是"相对份额被稀释"，不是"用户绝对流失"。** 置信度**中**。这一条修正了多数媒体"VS Code 正在失去开发者"的解读。

## 附 D、开源依赖与许可清单

> 本节回答：**若你要基于 VS Code 做产品，哪些能用、哪些一碰就必须重做。**

| 组件 | 许可 | 可否闭源商用 | 用途/备注 |
