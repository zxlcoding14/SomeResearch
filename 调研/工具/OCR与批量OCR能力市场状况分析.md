# 纯 OCR / 批量 OCR 能力市场状况分析

> 分析日期：2026-09-29
> 分析对象：**「OCR 能力」本身作为商品的市场**（不是扫描 App 产品市场）
> 数据来源：Grand View Research、Coherent MI、灼识咨询（CIC）、Precedence Research、OmniDocBench / olmOCR-Bench / ParseBench / Dr.DocBench、各厂商公开定价页、开源仓库实测、中国政府采购平台
> 核心差异：**这一层的公开数据远比 C 端扫描 App 完整** —— 因为它是"按量计费的能力"，有公开单价、有统一基准、有独立厂商财报。

---

## 〇、结论先行（TL;DR）

1. **能分析，而且是整条链上数据最透明的一层。** 纯 OCR 有公开单价（¥0.009–0.0825/次）、有统一基准（OmniDocBench）、有第三方独立横评、有对比厂商财报。**这与 C 端扫描 App（财务黑箱）形成鲜明反差。**
2. **但"纯 OCR"这个词在 2026 年已经失去商业含义。** 它退化成了两种东西：**免费的公共品**（开源引擎）或**近乎零毛利的云 API 走量品**。OmniDocBench 上两个开源权重模型（GLM-OCR 94.62、PaddleOCR-VL 94.50）**已经压在 GPT-5（≈85.8）和 Gemini 3 Pro（≈84.2）之上**。
3. **护城河在 2025–2026 塌了，而且塌得很干净。** 自建方案 $0.04–0.10/千页 vs Google Document AI $30–65/千页 —— **成本比 333–722 倍，且精度更高**。行业定论一句话：**"OCR 是 2026 年商品化程度最高的 AI 任务"**。
4. **能收钱的只剩两层**：① 把 OCR 之后的结构化交付 + 责任做成产品（IDP / 文档智能，ABBYY 口径毛利 35–45%）；② 落到具体场景的批量工程（票据 / 档案 / 证照）。这两层的单价是纯 OCR 的 **10–50 倍**。
5. **批量 OCR 的真实市场不在"技术"，在"政务与金融的存量数字化预算"。** 因为它是项目制采购、有公开招标价可查（实例：北京市档案馆「纸质档案数字化成果 OCR 识别项目」预算 **¥80.3 万**）。**这是整条链上唯一价格不透明、还能维持毛利的口子。**
6. **中国市场的残酷结论**：垂直厂商（合合 / 汉王 / 文通 / 达观）合计份额约 **33.1%**，被云厂商（合计约 **48.6%**）持续挤压；而云厂商自己在打价格战（同一能力报价差 **9 倍**）。**纯 OCR 能力在中国已进入"零毛利 + 合规门槛"阶段。**

## 一、先立口径：OCR 不是"一个市场"，是五个

**这是本分析最重要的第一步。把五层混谈，任何规模数字都是错的。**

| 层 | 名称 | 计费单位 | 典型价格（2026-09） | 毛利率 | 护城河 | 2026 状态 |
|---|---|---|---|---|---|---|
| **L1** | **开源引擎** | 免费 | **$0** | n/a | 工程优化、硬件效率 | **免费公共品，精度已反超商业云** |
| **L2** | **云厂商通用 OCR API** | 元/次、$/千页 | **¥0.009–0.0825/次**；$1.5/千页（AWS/Azure/GCP 纯 OCR） | 极低（规模摊薄） | 云生态绑定、MSA | 商品化，价格战 |
| **L3** | **文档解析 / 版面还原 API** | $/千页 | **$1.25–$56.25**（LlamaParse 档差 **45×**）；Reducto $10–30 | 中 | 表格 / 版面 / 公式保真度 | 争夺中，分层明显 |
| **L4** | **IDP 智能文档处理** | 项目 + 年订阅 | $0.25–0.38/页；≈$199/月（SME）；$10k–$190k 项目制 | **35–45%**（ABBYY 口径） | 行业 Knowhow + 审计链 + 交付责任 | **唯一有系统溢价的一层** |
| **L5** | **场景批量工程**（票据 / 档案 / 证照） | 项目制 / 按票 | **招标制**（¥80.3 万/项目实例）；票据 ¥0.35–0.8/次 | 中高 | **资质 + 现场交付 + 兜底责任** | **中国唯一能维持毛利的口子** |

**读法**：L1 免费、L2 零毛利、L3 靠精度分层、L4 靠责任溢价、L5 靠资质与交付。**"纯 OCR"指的是 L1–L2，而这两层恰恰都不赚钱。**

## 四、核心结论：护城河塌方时间线

| 时期 | 状态 | 证据 |
|---|---|---|
| **2024 及以前** | **有护城河** | AWS Textract / Google Document AI / Azure Form Recognizer 靠"别人做不到的像素识别"每年赚数千万美元 |
| **2025–2026** | **护城河塌方** | 开源权重模型在 OmniDocBench 上**反超 GPT-5（85.8）与 Gemini 3 Pro（84.2）** |
| **成本坍塌** | 结构性 | 自建 $0.04/千页 vs Document AI $30–65/千页 = **333–722×**；"比商业视觉 API 便宜约 167×" |
| **商业后果 ①** | 被迫上移 | **ABBYY 2025 营收 $406–420M**，被逼从 OCR 转向 process intelligence；SaaS 占收入 88%；毛利仅 35–45% |
| **商业后果 ②** | 被弃用 | **UiPath 弃用 ABBYY 集成**，改自研 Generative Extraction |
| **商业后果 ③** | 客户自建 | **2025 年 48% 的 Fortune 500 在建内部文档 AI**，3 年 TCO 低 30–60% |
| **商业后果 ④** | 被 VLM 吞 | Claude / GPT / Gemini 一次调用完成"提取 + 理解 + 结构化"，"离删掉整个 OCR 管道只差一次 VLM 调用" |

**行业定论原话（CodeSOTA，2026）：** > *"OCR is the most commoditized AI task in 2026. For most of the last decade, document parsing was a moat... That moat collapsed in 2025–2026."*

**中短期仍存的三条反向力量（不能忽略）：**

1. **存量还没吃完**：全球 OCR 需求 2025 约 **1.87 万亿页当量**，同比 **+23.4%**；商业文档 40.5%、医疗文档 22.3%、税务政务 18.1%、教育出版 9.7%。
2. **合规与主权强制私有化**：欧盟 GDPR 下本地化部署占 **71%**（云原生 OCR 增速仅 9.7%）；中国 IDP 厂商受美国芯片/云出口限制反而受益。**这是纯 OCR 唯一还能守住的护城河——不是算法，是数据不出域。**
3. **传统结构仍在，但会被抽掉**：McKinsey 估算 **2028 年前 40% 的 B2B 文档流将被结构化 API 取代**（ISO 20022、GS1 JSON、SWIFT 已达 83% 高价值流量）。**API-to-API 是纯 OCR 的长期终局风险，ABBYY 口径的暴露敞口为 15–25%。**

## 五、批量 OCR：它与"纯 OCR"的本质区别

### 5.1 定义与五个真实场景

批量 OCR ≠ "一次一张"，而是 **"一次数十万到数亿页 + 必须工程化交付"**。

| 场景 | 批量规模 | 交付物 | 采购方式 | 价格锚点（实测） |
|---|---|---|---|---|
| **政务档案数字化** | 馆藏级（百万–千万页） | **双层 PDF / 双层 OFD / TXT** | **公开招标** | **¥80.3 万/项目**（北京市档案馆 2026-06 招标） |
| **金融票据（发票/结算单）** | 日万级–百万级 | 结构化字段 | API 按量 + 私有化 | ¥0.009–0.0825/次；医疗票据 ¥0.35–0.8/次 |
| **银行/保险单据** | 存量千万页 | 字段 + 审计链 | 项目制 | ABBYY Vantage $20–80/千页；项目 $40k–190k |
| **书籍/古籍数字化** | 百万页级 | 结构化全文 + 版面 | 项目制 | 与档案类似 |
| **RAG 语料构建** | 千万页级 | Markdown / JSON chunk | API 按量 | $1.25–$56.25/千页 |

### 5.2 批量 OCR 的四个经济学特征（**这是它区别于"纯 OCR"的关键**）

**① 单页价格被量摊薄到失效，价格锚点转向「QPS 并发」和「私有化许可」。**

> **真实案例**：某电商大促月调用 20 万次，**基础费仅 ¥800，但为应对瞬时并发的 QPS 叠加包花了 ¥3,600**（百度 QPS 包 ¥10/天/QPS、¥180/月/QPS）。**QPS 成本占总支出 82%。**

**② 总成本公式不是"调用量 × 单价"：**

```
月总成本 = 基础调用费
         + QPS 叠加包费用        ← 最容易漏，且可能占大头
         + 资源包过期损失        ← 强制买包、用不完作废
         + 人工校对成本          ← 98% 准确率 → 每万次仍有 200 张需人工修
```

**③ 计费细节的隐形差异**：失败是否计费、错误码是否计费（**腾讯云部分错误码也收费**）、页面复杂度是否计费、字符数是否计费、表单是否加收（LlamaParse 每页含表单 +10 信用卡）。**这些决定了"能不能用页数预测账单"。**

**④ 真正的付费点是「不用人看的比例」（straight-through processing），不是识别率。**

> 这是 IDP 厂商的定价逻辑，也是纯 OCR 永远无法触及的定价维度。行业共识指标：**"无人工干预通过率"才是预测真实成本的数字**。而这个指标**恰恰是所有厂商最不公开的**。

## 六、市场状况总判断（漏斗形收敛）

**第一层：这个市场有多大？**
宽口径 OCR 全球 2025 **$12.5–17.5B**、2026 **$14–20B**，CAGR **12.9–16.9%**；窄口径 IDP 2026 **$1.45B**，CAGR 仅 **4.9%**。中国智能文字识别 2027E **¥168.9 亿**（CAGR 27.3%）。

**第二层：钱在哪一层？**
**纯 OCR（L1–L2）不赚钱** —— 开源免费、云 API 近零毛利、同能力报价差 9 倍。**钱在 L4 IDP（毛利 35–45%）和 L5 场景批量项目。** 灼识数据早有预判：基础技术服务 CAGR 16.5%，只有总增速的 60%。

**第三层：为什么纯 OCR 不赚钱？**
三重挤压同时发生：**① 开源精度反超商业云**（GLM-OCR 94.62 vs GPT-5 85.8）；**② VLM 单次调用替代整条管道**；**③ 大客户自建**（48% 的 Fortune 500 已在内建，TCO 低 30–60%）。叠加价格战，能力层毛利被压到结构性接近零。

**第四层：还有什么结构性机会？**
只剩三条，且都不是"算法"：**① 数据主权与私有化**（欧盟本地部署 71%）—— 护城河是合规资质不是精度；**② 存量数字化的项目制预算**（政务档案、银行存量单据）—— 护城河是资质 + 现场交付 + 兜底责任；**③ 交付完整性溢价**（医疗票据 10–80 倍溢价来自"字段完整率"）。

**第五层：给 PM 的启示（四条）**

1. **不要做"更好的 OCR"，要做"OCR 之后的交付与责任"。** 能力层已是免费公共品；溢价全部来自"可核验的结构化输出 + 审计链 + 行业字段完整率 + 兜底责任"。
2. **批量 OCR 唯一的护城河是「资质 + 现场交付 + 兜底责任」，不是算法。** 政务档案与银行存量单据是唯一价格不透明、能维持毛利的口子（有公开招标价可锚）。
3. **如果一定要留在能力层，做「路由层」而不是「引擎层」。** 成熟管道的标准架构是：**便宜引擎跑简单多数 + 强引擎兜难例 + confidence gate 路由**，并且**把 extract 阶段做成可换后端的接口**（"接口才是产品，模型是可替换件"）。
4. **成本核算必须算 QPS 与人工校对，不能只算单价。** 单价差 9 倍听起来很大，但 QPS 叠加包能让总成本翻 4.5 倍 —— **真正决定成败的是"无人工干预通过率"。**

## 七、数据缺口清单（公开渠道无解）

1. **纯 OCR 单独的全球/中国规模** —— 所有市场报告都把 OCR 与 IDP 混在一起，没有一份纯能力层口径。
2. **开源 OCR 的实际部署量** —— 只有 GitHub stars（PaddleOCR 88.3k、Tesseract 75.7k、Surya 21.2k、Marker 38k），**无调用量、无企业渗透率**。
3. **中国批量 OCR 的年项目数与总额** —— 招投标平台分散，需逐个抓取（本次仅取到单项目实例）。
4. **云厂商 OCR 业务的独立收入与毛利** —— 从不单独披露，全部并入"云与 AI"。
5. **各厂商的「无人工干预通过率」（straight-through rate）** —— **最关键但最不公开的指标**，没有一家厂商公布。
6. **企业自建的替代率明细** —— 只有"48% 的 Fortune 500 在内建"这一个总数，无分层。
7. **各国政府采购中 OCR 专项的年度预算总额** —— 无统一口径。
