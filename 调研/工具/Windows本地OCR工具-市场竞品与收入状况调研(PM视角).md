## 〇、结论先行（TL;DR）

**1. 这道题在 Windows 上的第一答案是"已被官方免费覆盖"（L4），必须先判死再谈。**
Windows 自带本地 OCR 引擎 `Windows.Media.Ocr`；`Win+Shift+T` 唤起 **PowerToys Text Extractor**；Snipping Tool 自 24H2 起内置"文本操作"。**三者全部本地推理、全部免费、全部无需账号**（PowerToys 亦为微软官方免费、MIT）。按免费覆盖度五级判定，这是 **L4（被平台/官方覆盖）→ 按 SOP 应直接砍**。**"在 Windows 上做一个能截图识字的本地工具"，这一层已经没有位置。**

**2. 但 L4 只覆盖了「抓取」，没覆盖「交付」——这是唯一剩下的缝。**
微软官方文档与实测横评把边界写得很清楚：系统内置 OCR **只输出纯文本**——**无版面保留、无表格结构、无公式 LaTeX、无批量处理、无 PDF 加文字层、无手动纠正**。原文口径：*"It is designed for quick extraction, not document reconstruction."* **能收钱的全在"识别之后"。**

**3.【否定性结论】"本地/离线"这个限定词本身不构成商业模式，它反过来锁定天花板。**
本地 = 可脱离账号 = **无持续交付成本 = 订阅不成立 = 只能一次性买断**。国产独立客户端的定价锚点已塌到 **¥30–59 一次买断**（白描 ¥30/¥40、天若OCR ¥59、迅捷 ¥88 终身），**而这条线上功能最全的开源项目 ARPU = ¥0**（Umi-OCR 47,664★ / MIT / 免费）。

**4. 本地引擎的三条路已全部免费、许可全部宽松——"我自带引擎"已从壁垒变成成本包袱。**
① 微软系：`Windows.Media.Ocr`，随系统，**包体成本 = 0**；② 传统开源：Tesseract 5.x（Apache-2.0，**纯 CPU 可跑，<1GB**）；③ 深度学习开源：PaddleOCR / RapidOCR（均 Apache-2.0）。代价是**包体 100–440MB**（Umi-OCR 约 440MB）与**"本地 = 精度下降"**（用户实测结论）。

**5. 收入上限可算，而且很低。**
本轮自下而上测算（附 B）：一个独立开发者的 Windows 本地 OCR 买断工具，**年收入 P50 ≈ ¥3.5 万，画像区间 ¥0.6 万 – ¥7.1 万**；唯一公开真实数字的同赛道项目 **GhostText：3 个月 $196 / 200+ 用户，ARPU ≈ $0.98**，与本测算悲观档同量级——**两条路径互相印证，不是巧合。**

**6. 可进场位置只剩两条，都在"识别之后"；P1 起全部不值得做。**

| 优先级 | 位置 | 一句话 | 定价 |
|---|---|---|---|
| **P0** | **结构化交付层** | 表格→Excel、公式→LaTeX、竖排/日文断句、可搜索 PDF、代码保缩进 | ¥39–99 买断（对标 TextSniper/ZenOCR 的 $7.99–12.99） |
| **P0** | **薄壳 + 系统/本地引擎的极简形态** | 包体 5–15MB，把引擎成本转嫁给 OS（`Windows.Media.Ocr`） | 免费 + BYOK，或极低价买断 |
| P1 | 竖排/古籍/日文垂直包 | 开源零覆盖，但池子只够养一个独立开发者 | 买断，愿付溢价 |
| **✖** | **又一个"Windows 本地截图识字工具"** | 四重免费包夹，期望 ROI 结构性 < 1 | **不做** |

## 二、"Windows 本地 OCR"是什么：形态谱系与功能分层（L1）

### 2.1 一句话定义（不贴品类词）

> **它替用户做的事是：把"屏幕上或图片里看得见、但选不中的字"，变成"能编辑、能粘贴、能进下一个流程的字"——并且承诺这个过程不出本机。**

**注意**：上句里没有"OCR"这个品类词。一旦以"OCR 工具"开头，竞品集合就自动锁定成"其他 OCR 软件"，从而**漏掉最强的两个对手**：操作系统本身，和"忍着不做"。

### 2.2 六种形态谱系（按"引擎归属"切，不按功能切）

功能在这条线上高度同质化，**唯一有区分度的是"引擎从哪来"**。这个切法直接决定了成本结构与定价可行性。

| # | 形态 | 引擎归属 | 是否需要安装 | 是否本地 | 代表 |
|---|---|---|---|---|---|
| **①** | **OS 内置** | 微软（`Windows.Media.Ocr`） | **否 / 官方免费** | ✅ 完全本地 | PowerToys `Win+Shift+T`、Snipping Tool（24H2+）、Recall（Copilot+ PC） |
| **②** | **即时通讯内置** | 腾讯 / 阿里 / 字节 | 已有 | ❌ 上传云端 | 微信、QQ、钉钉、飞书截图识别 |
| **③** | **开源成品** | PaddleOCR / Tesseract / 系统引擎 | 需安装 | ✅ 多数本地 | Umi-OCR、Text-Grab、eSearch、NAPS2、NormCap、gImageReader |
| **④** | **国产商业客户端** | 自研 / 云 / 聚合 | 需安装 | 混合 | 白描、天若OCR、迅捷OCR、夸克扫描王 PC、扫描全能王 PC |
| **⑤** | **海外商业客户端** | Apple Vision / 自研 / 云 | 需安装 | 混合 | TextSniper（Mac）、OwlOCR（Mac）、ZenOCR（Mac）、ScreenSnap Pro（Win+Mac）、ABBYY FineReader（Win） |
| **⑥** | **2026 新形态：薄壳 + 系统引擎** | 借系统 / 借本地开源 | 需安装（极轻） | ✅ 本地 | Cheese! OCR（Mac）、ClariRec（Mac）、**HushSnap（Win）**、GhostText |

> **形态 ⑥ 是本轮最重要的变化**：它把"引擎成本"转嫁给 OS 厂商，从而可以做到**永久免费或极低价买断**。**它对形态 ③④ 是降维打击——③④ 自己背引擎（成本 + 包体），⑥ 不背。**

### 2.3 功能四层分层（T1–T4）

| 层 | 定义 | 具体能力 | 商业含义 |
|---|---|---|---|
| **T1 内核** | 去掉它产品不成立 | 快捷键截图 → 识别 → 剪贴板 | **定价地基，但已被免费全覆盖 → 定价 0** |
| **T2 增强** | 提效但可替代 | 多区域连续捕获、剪贴板图片直识别、识别历史、取色、屏幕放大镜 | 决定体验口碑，**通常不该单独收费** |
| **T3 差异化** | 只有它有 | **表格→Excel、公式→LaTeX、竖排/日文断句、可搜索 PDF、代码保缩进** | **卖点来源 → 唯一能收费的部分** |
| **T4 长尾** | 低频/边缘 | 翻译、TTS、图床上传、GIF 录制、二维码 | 常是"看起来很强"的装饰，**用户明确不要翻译**（*"不要翻译功能，翻译全用 AI 客户端工具了"*） |

**读法**：**厂商在 T1 投入最多功能，却在 T1 收不到钱；能收钱的 T3，投入最少、做得最晚。** 这是本条线最重要的产品结构错位。

### 2.4 Non-scope：它明确不做什么

- 不做企业级字段完整率与审计链（→ B 端 IDP 的事）
- 不做数十万页批量工程（→ 政务/金融项目的事）
- 不承担出错兜底责任（→ 这是免费工具与付费 IDP 的根本分野）

**范围边界 = 定位的负空间。这三条"不做"，恰好就是"为什么它收不到钱"的答案。**

| **合并取值** | **≈ ¥1.9 亿** | **≈ ¥3.3 亿 / 年** | **≈ ¥5.4 亿 / 年** |

> **置信度：低–中。** 三条假设（桌面占 5–10%、C 端占本地 10–20%、Windows 占 72%）**各自都有 ±50% 的不确定性**，其中**"C 端个人桌面工具占本地部署的比例"最脆弱**——它没有任何直接数据来源，是从"B 端私有化是本地主体"这一判断推出来的。

>
> **结论（可写进决策）**：**"Windows 本地 OCR 工具"是一个年规模**个位数亿人民币**、且被四重免费包夹的细分。它值得做产品，不值得做公司。**

### 6.2 自下而上测算：一个独立开发者的 Windows 本地 OCR 工具能收多少

**公式**（`c-end-pm-methodology` §7）：
```
年营收 = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
```

**基准情景（P50）**：
| 乘数 | 取值 | 依据 |
|---|---|---|
| 可触达人数 | **100 万 / 年** | 少数派 / 即刻 / B站 / V2EX / 小众软件论坛 / 知乎，一年内容复利累计曝光 |
| 触达转化率（点进产品页） | **3%** | 工具类软文点击率经验区间 1–5%，取中 |
| 激活率（下载并跑通一次） | **40%** | 桌面工具"下载即用"门槛低于 SaaS |
| 付费率（免费增值，功能墙） | **5%** | 对标白描免费版 5 次/天 → 付费转化经验区间 1–10% |
| 客单价 | **¥59** | 对标天若OCR ¥59 买断 |
| **年营收** | **100万 × 3% × 40% × 5% × ¥59 = ¥35,400** | |

**三档情景 + 敏感度**：

| 情景 | 可触达 | 付费率 | 客单价 | **年营收** | 说明 |
|---|---|---|---|---|---|
| **悲观 P10** | 30 万 | 3% | ¥59 | **¥6,372** | 与 GhostText 实测（≈¥5,600/年）**同量级** ✅ 交叉印证 |
| **基准 P50** | 100 万 | 5% | ¥59 | **¥35,400** | |
| **乐观 P90** | 300 万 | 10% | ¥99 | **¥1,188,000** | 需"表格/竖排"真差异化 + 强内容分发，**概率低** |

**敏感度检验（关键假设 ±50%）**：

| 变量 | -50% | 基准 | +50% | 结论是否翻转 |
|---|---|---|---|---|
| 可触达人数 | ¥17,700 | ¥35,400 | ¥53,100 | 否 |
| 付费率 | ¥17,700 | ¥35,400 | ¥53,100 | 否 |
| 客单价 | ¥17,700 | ¥35,400 | ¥53,100 | 否 |

> **置信度：中**（乘数各有依据，但均为经验区间，非本赛道实测）。
> **推翻条件**：出现一个 Windows 本地 OCR 工具公开年营收 > ¥50 万的实例（目前**零实例**）。
>

> - 一次性：研发工时折算（20–60 人日）+ 代码签名证书（¥1,000–3,000/年）+ 商标/软著
> - 每月固定：域名 + 官网 + 开发者账号

> **结论**：**P50 情景下（¥3.5 万/年营收），扣除全成本后净利润 ≈ 0 或为负。** 这是本份最重要的财务判断。

### 6.4 为什么这一层收不到钱：四条结构性原因

1. **引擎是借来的。** 系统引擎（`Windows.Media.Ocr`）免费、开源引擎（PaddleOCR / Tesseract）免费、大模型算力用户自付。**产品方在成本端没有任何议价空间，也就没有定价权。**
2. **本地 = 无账号 = 无法计费。** "本地/离线"排除了账号体系 → 排除订阅、云存储、续费管理 → **唯一可收的钱是一次性买断，而买断等于永久封印第二次收入。**
3. **免费替代 ≥ 8 条，其中 4 条是 OS / 官方。** 被 OS 内置 = 品类死亡判决（本项目第六次验证）。
4. **精度已无差异化，且"本地换精度"被用户实测确认。** 用户原话：*"只要模型转为本地，识别能力就会大大下降。"*

| 你方独占优势 | ×2 | **2** | 4 | 需靠"表格/竖排"建立，非天然独占 |
| 窗口期长度 | ×1 | **2** | 2 | 官方仍在加功能（Recall / NPU 模型），窗口在收窄 |
| 合规 / 平台风险 | ×1 | **4** | 4 | 无单一 API 依赖；本地处理反而降低隐私风险 |
| **收款可行性** | ×3 | **4** | 12 | 通道明确（买断、支付平台），资质门槛低 |
| **隐性成本可控性** | ×3 | **4** | 12 | 可完全自助，边际成本 ≈ 0 |
| **客体匹配度** | ×2 | **4** | 8 | 形态与个人开发者时间/资质匹配 |
| **合计** | — | — | **79 / 135 = 58.5%** | |

> **阈值判定**：≥70%（≈95）→ 进入证伪；**≤50%（≈68）→ 直接杀**；中间 → **只做最低成本补充采集，不投实验资源**。
> **本方向得分 79（58.5%），落在"中间区"** —— 意味着：**不杀，但也不投资源；只值得用最低成本（一个周末的假门测试）验证一次"表格/竖排"这一格。**

### 7.2 一票否决（8 条逐条对照）

| # | 否决项 | 命中？ | 判据 |
|---|---|---|---|
| 1 | **分发不可得** | ⚠️ 接近 | 有社区但**付费触达难**；不确定是否"完全不知道人在哪" |
| 2 | **频次 = 一次性，且无持续交付成本** | ⚠️ 部分 | 高频用户存在，但**无持续交付成本这一半已命中** |
| 3 | **依赖单一平台 / 一个版本就可能被内置** | 🔴 **命中** | **已被内置**（非"可能"）——`Windows.Media.Ocr` + PowerToys 是既成事实 |
| 4 | **触碰合规红线** | ✅ 未命中 | 本地处理反而是合规优势 |

| 6 | **收款路径不成立** | ✅ 未命中 | 买断通道成立 |
