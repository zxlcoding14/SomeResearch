> **分析对象**：Listary V7 Beta（v7.1.0.43，2026-10-12 更新）+ 其产品矩阵中的姊妹品 Gety
> **触发页面**：https://www.listary.net/v7（V7 官方发布页）
> **快照时间**：2026-10-15
> **分析目的**：学它 / 抄它 —— 一个运营 15 年的国产 Windows 效率工具如何在免费霸权夹缝中活到 V7，以及 V7 这一轮动作的战略含义
> **数据可信度分级**：① 审计财务（无）② API/页面实测（定价页、GitHub API、官网）③ 官方宣称（性能自测表、路线图）④ 第三方估算（营收/用户推算）⑤ 二手转载（评测站、百科）—— 全文逐条标注
> **本分析要回答的 3 个问题**：① Listary 真正的生存凭据是什么（不是搜索）；② ¥98 终身买断这个模式的天花板在哪；③ 对做桌面 mini-tool 的人有什么可抄 / 别碰

## 〇、结论先行（TL;DR）

1. **Listary 的真实身份不是「文件搜索工具」，而是「Windows 文件工作流粘合层」。** 文件名搜索层被 Everything（免费闭源）霸权锁死 15 年，Listary 靠三件免费替代做不了 / 不做的事活下来：**文件对话框集成 + Quick Switch（Ctrl+G 上下文跳转）+ 习惯学习排序**。V7 用 Rust 重写是工程表演兼借势营销（性能表拿 Everything 当参照系，把对手的强变成自己的论据），真正的战略动作是**推荐功能（数据飞轮）+ Gety 联动（双产品矩阵）**。

2. **商业模式是「个人免费 × 商用付费」的合规墙 + ¥98（$19.95）一次买断、终身升级。** 没有云成本、没有持续交付成本，买断是唯一诚实的计费（与方法论判定一致）；商用许可做付费墙是 C 端工具最难被骂的墙。但天花板低：测算显示 Listary 单品买断年收入仅 ¥14 万量级（P50，置信度低），**撑得起「养活自己」，撑不起现在 3–6 人团队 + 自研引擎的 Gety**——订阅制 Gety（$6/月）才是这个团队的第二曲线赌注，Listary 正在变成 Gety 的流量入口。

3. **【否定性】v6 时代的「更新不足」口碑已造成真实分流。** 小众软件社区出现开源替代 Lertaro（views 10,594 / replies 259，榜单最高级别需求讨论信号之一），用户原话痛点是「Listary 长期更新不足、付费/授权预期不确定」。V7 的公开路线图 + 3.5 个月 7 个 Beta 版的密集 changelog，本质是一场**信任修复工程**——但流失用户不会因为版本号 +1 自动回流。

4. **【否定性】纯文件名搜索赛道对新人已死，定价天花板 = 0。** Everything（免费）+ PowerToys Run（MIT，139,292★）+ Flow Launcher（MIT，15,783★，活跃）三层夹击。可进场位只剩两段：**「工作流粘合层」**（对话框 / 上下文感知集成，开源无成熟底座）和**「内容搜索的本地 AI 层」**（Gety 占的位置）。中间那段（文件名搜索、通用启动器）谁进场谁死。

5. **可迁移资产（抄什么）**：① 拿最强免费竞品做性能对照表的营销法；② 商用许可付费墙；③ 入口层产品（买断、老品牌、装 机量大）+ 内容层产品（订阅、AI、客单价高）双品牌矩阵互相导流；④ 公开路线图 + 密集更新日志修信任。**别碰**：文件名搜索本体、通用启动器、以及「深色主题收费」这类会被当成槽点的付费墙设计。

## 一、定位与口径

### 1.1 一句话定义（不贴品类词）

**「让 Windows 用户在打开 / 保存文件的对话框和资源管理器里，不用翻目录树。」**

它雇佣自己完成的任务是：把「找文件 → 跳到那个目录 → 打开 / 保存」这条每天重复几十次的链路，压缩成两次按键。搜索框只是这条链路的入口形态，不是产品本体。

### 1.2 品类归属与竞品集合

陌生用户会把它放上「Windows 效率 / 文件搜索」货架——这个货架的默认王者是 Everything，这决定了 Listary 永远被拿来和免费的 Everything 比较（V7 页面干脆自己先比了，见 §四）。

### 1.3 最小可用内核 & Non-scope

- **内核**：双击 Ctrl 唤起 → 输入 → 打开文件 / 应用 / 跳转目录。
- **Non-scope（明确不做）**：不替换开始菜单、不做文件管理器本体（不接管文件，只「送文件到眼前」）、不做内容全文搜索（这块明确切给了 Gety）、只做 Windows（拒绝跨平台诱惑——访谈原话「不被跨平台、移动化所引诱」）。

### 1.4 团队与主体（③ 官方宣称 + ⑤ 二手转载）

## 四、价值主张与需求硬度

### 4.1 官方性能对照表（③ 官方宣称·厂商自测，300 万文件，同机默认设置）

| 场景 | V5 | V6 | **V7** | Everything | 判读 |
|---|---|---|---|---|---|
| 打开启动器 | 0.034s | 0.044s | **0.027s** | 无此功能 | |
| 启动器出结果 | 0.196s | 0.181s | **0.060s** | 无此功能 | 启动器是差异化主场 |
| 打开文件搜索窗口 | — | 0.075s | **0.045s** | 0.143s | |
| 搜索窗口出结果 | — | 0.195s | **0.039s** | 0.040s | 基本打平 |
| 打开快速切换窗口 | 0.048s | 0.067s | **0.002s** | 无此功能 | Quick Switch 碾压级体验 |
| 建立索引 | 26s | 20s | **7s** | **5s** | **Everything 仍赢** |
| 内存（空闲，全部进程） | 87MB⁴ | 362MB | **245MB** | 277MB | V7 比 Everything 更省 |

**PM 读法**：这张表聪明在两点——① 拿公认王者当参照系，抢到「和 Everything 一个量级」的心智（此前心智是「Listary 慢」）；② **诚实列出输的项**（索引 7s vs 5s），可信度反而上升。V7 相对 V6 是数量级修复（内存 362→245MB，显卡共享内存 80→0MB），说明 v6 的臃肿是被社区骂过的真实痛点。

### 4.2 卖点真伪判定（对撞免费替代）

| 官方卖点 | 对撞免费替代 | 剩余价值 |
|---|---|---|
| 极速文件搜索 | Everything 免费且索引更快 | **≈ 0**（入场券，不可定价） |
| 双击 Ctrl 启动器 | PowerToys Run / Flow Launcher（MIT） | ≈ 0–20% |
| **对话框集成 + Quick Switch** | 开源无对应实现（Flow Launcher 不做对话框 hook） | **≈ 80–100%，定价地基** |
| 习惯学习排序 / 推荐 | 开源无 | ≈ 100%（且随使用时间增值 = 数据飞轮） |
| 第三方软件适配矩阵（WinRAR/WPS/AutoCAD/TC…） | 无开源等价物；这是脏活 know-how，逐个版本追着适配 | ≈ 100% |
| 高级搜索语法 | Everything 语法覆盖 ~80% | ≈ 20%（仍被做成 Pro 卖点） |
| Gety 联动内容搜索 | AnyTXT Searcher（免费）覆盖基础全文；语义 / 本地 AI 层开源无成熟品 | ≈ 60% |

**加权免费替代覆盖率 ≈ 60%（P50，±10%）【预估·逐功能对撞】**——即 Listary 六成功能生活在免费世界里，四成（工作流粘合层 + 习惯数据）是可定价部分。¥98 的定价全部落在那 40% 上，成立。

### 4.3 需求硬度

日频 × 真痛点（每次省 10–60 秒 × 每天几十次 = 每天省 10–30 分钟），属于「不做直接损失时间」的硬需求。但注意：**痛感是慢性的、低记忆度的**——用户习惯了忍受对话框翻目录，这类需求的教育成本高，靠口碑 / 必装清单渗透而非广告（Listary 15 年几乎零营销投放，符合其「朴实幸福」的运营哲学）。

| 边际成本 | ≈ 0 | ≈ 0（**纯本地**：自研索引引擎 + 本地 OCR + 端侧模型，MCP 开放） |
| 角色 | 流量入口 / 老品牌信任背书 | 第二曲线 / 订阅收入 / AI 叙事 |

**联动机制**（③ 官方更新日志 2026-07-08）：Gety 内容结果内联进 Listary 搜索流、预览面板显示内容摘要、未安装时 Listary 提供可关闭的「了解入口」——**Listary 正在把自己变成 Gety 的分发渠道**。这是本报告最重要的一条结构性判断：入口层老品（买断、低 ARPU、装机量大）给内容层新品（订阅、高 ARPU）导流。

> 顺带一个方法论检验：Gety 走纯本地推理 → 边际成本 ≈ 0 → 是 AI 类产品**唯一挂得起年费**的技术路径（方法论 §L4）。$6/月定价克制，未见云端 API 依赖，判定健康。但 ¥899「永久」与订阅制的并存（渠道页自述「永久为开发商单方面承诺」）是长期信任风险点。

## 六、竞争位势与免费替代

### 6.1 竞争四层

| 层 | 玩家 | 危险度 |
|---|---|---|
| 直接竞品 | Agent Ransack、Copernic、UltraSearch | 低（各有侧重，市场公认「Listary + Everything 双装」） |
| 间接竞品 | uTools / Quicker（国内效率平台）、Raycast（Mac，无 Windows 版） | 中（平台化吞噬单点工具的长期可能） |
| 免费替代 | **Everything（免费闭源，搜索层王者）**；Flow Launcher（15,783★/MIT/活跃）；PowerToys Run（139,292★/MIT） | **高但结构性受限**：均不做对话框 / Quick Switch 层 |
| 用户自己 | 忍受对话框翻目录 | 永恒基线 |

### 6.2 开源竞品雷达（覆盖度五级判定）

| 能力域 | 判定 | 依据 |
|---|---|---|
| 文件名搜索 + 通用启动器 | **L3（有活跃成品）** | Flow Launcher（MIT，pushed 2026-10-12）、PowerToys Run（MIT）——**这段对新入者已死，对 Listary 是「必须做到不输」的成本项** |
| 对话框 hook / Quick Switch / 上下文感知集成 | **L1–L2（无成熟开源成品）** | Flow Launcher / PowerToys 均未做；Lertaro 刚起步（259 回复但无成熟度证据）——**Listary 的护城河位** |
| 习惯数据 / 推荐排序 | L1 | 开源无对应（数据飞轮难开源复现） |
| 本地 AI 内容搜索 | L1–L2 | AnyTXT（免费闭源）覆盖基础全文；语义 / OCR / 端侧 AI 无活跃开源成品——**Gety 的赌注位** |

**许可核查（附 D 摘要）**：Flow Launcher = MIT、PowerToys = MIT，无传染风险；若进场做同类产品，启动器层可直接复用 MIT 底座，但对话框集成层**无现成开源底座，需自研**——这本身就是结论：护城河长在脏活上，不长在算法上。

### 6.3 系统内置威胁（C 端头号生死题）

- **短期（1–2 年）**：低。Windows 搜索 15 年没做好，V7 页面甚至拿「Windows Search just seems to get worse」的推文当广告。
- **中期（3–5 年）**：**中高**。OS 级 AI 语义搜索（Copilot 整合本地文件理解）一旦内置，「找文件」整条链路可能被系统层吞掉——**Gety 就是 Listary 对这个威胁的对冲**：与其被 OS 的 AI 搜索吃掉，不如自己先占住本地 AI 搜索位。
- 结构性安全垫：对话框 hook 这类「贴着 Win32 脏细节的集成」，恰恰是 OS 官方最懒得做的（做了反而和自家搜索产品打架）。

### 6.4 竞品盲区（机会所在）

- Everything：不做工作流、不做对话框、无推荐（官方对比表连自己都承认「无此功能」×3）。
- Flow Launcher / PowerToys Run：启动器纯度高，但**没有一家做「文件对话框」这个场景**——这是被所有竞品明确放弃的 30 年老痛点。
- 国内 uTools / Quicker：平台化路线，单点体验（0.002 秒开窗这种）打不过单点工具。

## 七、持续性与风险

| 维度 | 判断 | 依据 |
|---|---|---|
| 护城河类型 | **切换成本 + 适配 know-how + 习惯数据** | 15 年积累的第三方对话框适配矩阵是逐版本追出来的脏活；习惯排序随使用时间增值 |
| 护城河时间窗 | 对开源：长（无人愿意做脏活）；对 OS 内置 AI：3–5 年 | §6.3 |
| 平台依赖 | 单一 OS（Windows only）——**双刃剑**：放弃 Mac 保住深度 | 15 年战略定力（访谈原话） |
| 团队风险 | **单人 → 小团队的关键过渡期** | 历史单人开发 = 节奏脆弱（v6 时代已验证）；Gety 扩团是解法也是新成本压力 |
| 收入结构风险 | 单品买断收入撑不起团队（附 B），**依赖 Gety 订阅成功** | 测算冲突本身即证据 |
| 生命周期位置 | 成熟期二次出发（V7 = 成熟品的新一轮成长尝试） | 路线图密度 + Rust 重写的投入强度 |
| 信任风险 | 「终身免费升级」承诺 × 买断制 = 长期负债；深色主题收费的口碑税 | §5.2 |

## 八、可迁移结论与机会点

### 8.1 抄什么（可迁移清单）

| # | 机制 | 迁移方式 |
|---|---|---|
| 1 | **拿最强免费竞品做对照表的营销** | 官方性能表连输的项都列（索引 7s vs Everything 5s），可信度反升。做任何「免费霸权旁的付费品」都可复用 |
| 2 | **商用许可付费墙** | C 端个人免费 + 商用必须付费——口碑与收入兼得，比「限功能」「限次数」体面得多 |
| 3 | **买断 + 终身升级（无持续成本时）** | 方法论判定的正面样本：没有云成本就别装订阅 |
| 4 | **入口层老品 × 内容层新品双品牌矩阵** | 低 ARPU 大装机的老品给高 ARPG 订阅新品导流（Listary→Gety 内联） |
| 5 | **公开路线图 + 密集 changelog 修信任** | 针对「更新不足」骂声的精准回应；3.5 个月 7 版 |
| 6 | **把「用户呼声最高的功能」当版本主打** | 多选批量操作——官方自己标注「这是用户呼声最高的功能之一」 |

### 8.2 别做什么（反面清单）

1. **别做文件名搜索 / 通用启动器**——Everything + PowerToys Run + Flow Launcher 三层免费夹击，天花板 = 0（本报告第 4 条 TL;DR）。
2. **别把深色主题当付费点**——2026 年的舆论环境里这是负资产。
3. **别学它 15 年零营销**——那是 2010 年代的红利（必装清单时代），今天的新品没有这个免费分发环境。
4. **别在无持续成本时上订阅**——Listary 用 15 年证明了买断的口碑价值，也用测算暴露了买断的收入天花板：两者都要认。

### 8.3 若要进场（机会点 + 最小验证）

- **切入点 A：文件对话框 / 上下文感知的工作流粘合层**（Listary 的护城河位，开源 L1–L2）——但必须回答「Listary 已在那儿且只要 ¥98」，差异化只能来自 Listary 明确不做的段（跨平台？AI 原生？）。最小验证：定向下访谈 20 个 Listary 流失用户（Lertaro 帖 259 回复就是现成名单池）。
- **切入点 B：本地 AI 内容搜索**（Gety 的位置）——窗口开着但很窄：Gety 已卡位且背后是 15 年文件工具 know-how。更现实的是**给这条赛道做配套**（connector / MCP 数据源侧）。
- **对用户在研方向（桌面 AI mini-tool）的直接含义**：Listary×Gety 验证了「入口层 + 本地 AI 内容层」的组合是 Windows 效率赛道当前唯一被证明还留有空位的结构——**本地推理保住了订阅的毛利结构（边际成本 ≈ 0），这是 AI 桌面工具唯一挂得起年费的路径**。

## 附 B、测算过程（与实测分开排版；汇率假设 USD/CNY = 7.1【假设】）

### B1. 用户规模（自下而上 + 类比推算）

- **假设**：累计安装 P50 500 万（P10 200 万 / P90 2,000 万）；活跃率 20%。
- **依据**：运营约 15 年；Scott Hanselman 等国际 KOL 长期背书；志愿者多语言本地化（跨国用户基）；各大下载站长期分发；类比同赛道第一名 Everything 社区公认装机千万级。**反证：无任何官方数字。**
- **推算**：活跃用户 = 500 万 × 20% = 100 万。
- **结果**：**活跃用户 P50 ≈ 100 万（P10 40 万 / P90 400 万）**；置信度：低；推翻条件：官方或第三方（如遥测 / 下载站后台）数据出现。

### B2. 年营收（两条路径并列，冲突即结论）

**路径 A · 自下而上（买断收入）**
- 假设：历史累计付费用户 P50 1.5 万（按活跃 100 万 × 累计转化 0.3%–1.5% 区间取中低档——商用墙模式付费率天然低，类比 WinRAR 家用免费商用收费）；客单 $19.95（¥142）。
- 推算：累计买断收入 = 1.5 万 × $19.95 = **$29.93 万（¥212 万）**；按 15 年摊 → **年均 ≈ $2 万（¥14 万）/ 年**（P10–P90：¥5 万–¥50 万/年）。
- 结果：Listary 单品买断收入年均 **¥14 万量级**。置信度：低。

**路径 B · 锚点反推（团队成本）**
- 假设：团队 3–6 人（依据：Gety 招聘帖「小而精」「自给自足有稳定收入」+ Channing 单人开发史）；全成本 ¥25 万–¥50 万/人/年（中国一线，含社保场地）。
- 推算：年成本 ¥75 万–¥300 万；「自给自足」要求 Listary + Gety 合计年营收 ≥ 成本 → 取中 **P50 ≈ ¥300 万（$42 万）**（P10 ¥100 万 / P90 ¥800 万）。
- 结果：合计年营收 **¥300 万量级**。置信度：低。

**冲突处理（本节最有价值的发现）**：路径 A（¥14 万/年）与路径 B（¥300 万/年）相差 20 倍——**单靠 Listary 买断解释不了团队存续**。缺口由四块填补：① Gety 订阅（$6/月 × 未知订户数）；② 多许可批量授权（评测提及 multi-license packs，B 端采购）；③ 中国区 ¥98 特惠走量的转化率可能显著高于国际；④ Channing 个人在 AI 公司的积蓄/收入（招聘帖自述履历）。**这正是「买断老品 + 订阅新品」双产品矩阵存在的根本原因——不是产品战略，是收入结构逼出来的。**

**敏感度**：
| 变量 | 变动 | 结论是否翻转 |
|---|---|---|
| 付费转化率 | ±50% | 否（路径 A 在 ¥7 万–¥21 万/年波动，「单品撑不起团队」不变） |
| 团队人数 | ±50% | 否（路径 B 在 ¥150 万–¥450 万波动，量级判断不变） |
| 活跃用户 | ±50% | 否（ARPU 区间仍属「低 ARPU 买断形态」） |

### B3. ARPU

- 推算：ARPU = 合计年营收 ¥300 万 ÷ 活跃 100 万 = **¥3/活跃用户/年（$0.42）**。
- 对照方法论赛道基准：Raycast ≈ ¥75 vs uTools ≈ ¥2.1——**Listary 落在 uTools 一侧的低 ARPU 买断形态**，36 倍差距的归因四项（付费理由强度 × 计费结构 × 人群净值 × 计价货币）中，它输在计费结构（买断）这一项上，付费理由（商用合规）反而比 uTools 硬。
- 敏感度：营收 P10 × 活跃 P90 → ¥0.25；营收 P90 × 活跃 P10 → ¥20。区间内结论不变。

### B4. 免费替代覆盖率

- 方法：§4.2 逐功能对撞，按功能点加权。
- 结果：**≈ 60%（P50，区间 50%–70%）**；定价检验：¥98 全部落在未覆盖的 40%（工作流粘合层 + 习惯数据）→ 定价成立，天花板 ≠ 0。
