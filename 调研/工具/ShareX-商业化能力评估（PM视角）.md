# ShareX — 商业化能力评估（PM 视角）

> **分析对象**：ShareX（`ShareX/ShareX`，v21.0.0，Windows）
> **快照时间**：2026-10-26
> **分析目的**：判断这条赛道/这个标的**有没有收钱的可能**，以及「若我要在同类做商业化，钱从哪来」
> **数据分级**：见附 A；核心结论所用数据均为 `【实测】` / `【官方页面】`，唯一推算项单列附 B
> **关联文档**：`ShareX-功能点全景与工具清单（PM视角）.md`（能力清单、36 工具、许可与工作量，本篇不重复）

## 〇、结论先行（TL;DR）

1. **没有商业化能力。而且不是"还没做"，是四条结构锁锁死的 —— 换团队也做不了，除非换主体、换产品形态。**
2. **现价：¥0。全产品零付费点、零广告、零账号、零云服务分成。** Steam 版与 Microsoft Store 版同样是免费分发（Steam 页面明标 "免费开玩"），**渠道不产生任何收入，只省掉分发成本**。
3. **唯一收入是捐赠**：GitHub Sponsors（$5/$10/$20/$50/$100 五档）+ Patreon + 加密货币。公开可见的当前赞助人 **29 位**（历史累计 365 位）。按其档位结构推算，**月收入量级 $145–450（¥1,030–¥3,195 / 月），年 ¥1.24 万–¥3.83 万**【推算·低置信】。**这个数字与作者"我全职做了 15 年、捐赠是我唯一收入"的公开自述不自洽**（附 C 已列为反方证据）—— 要么公开列表不完整，要么存在未公开的收入来源。无论哪种，**量级都远低于任何可称为"商业化"的水平**。
4. **四道锁**：① **GPL-3.0 + 无 CLA** → 无法双许可、无法闭源卖 Pro；② **单人项目 + 无公司实体** → 无销售、无客服、无合同主体；③ **18 年免费把用户预期训练成 0** → 任何付费墙都等于自杀式口碑崩塌；④ **无云端 = 无持续交付成本 = 订阅不成立**（它的成本优势，正是它收不到钱的同一件事）。
5. **唯一有戏的方向是 B 端合规版**（强制水印 / 上传白名单 / 审计日志 / 静默部署 / 策略下发），而不是 C 端 Pro 买断。理由：C 端被自己免费版和 OS 内置功能双向夹死；B 端买的是**合规责任**，不是功能。

## 二、为什么收不到钱：四道结构锁（每道都有硬证据）

| # | 锁 | 证据 | 后果 | 能否解开 |
|---|---|---|---|---|
| 1 | **GPL-3.0 + 无 CLA** | 仓库 `license.spdx_id = GPL-3.0`；第三方核查机构确认"无 CLA / 无版权转让要求" | ① 闭源 Pro 版不可行（同代码必须开源）② 双许可不可行（拿不到全体贡献者授权）③ 任何人都可合法编译分发免费版 | ❌ **基本不可解**；只能"另起一个不共享代码的闭源产品"，等于重做 |
| 2 | **单人 + 无公司实体** | 维护者单一（Jaex）；无公司官网、无销售页、无发票/合同体系 | 收 B 端钱需要：合同主体、发票、SLA、安全问卷、采购流程对接 —— 一个都不具备 | ⚠️ 可解，但需要建团队，成本远高于潜在收入 |
| 3 | **18 年免费形成的用户预期** | 官网首页明写 "Completely free / No advertisements / Privacy first"，作为**核心卖点**在宣传 | 加付费墙 = 直接摧毁其唯一差异点；且立刻被自己的旧版本 + 社区 fork 惩罚（GPL 允许） | ❌ 不可解（一旦承诺"永久免费"，退路就没了） |
| 4 | **无云端 = 无持续交付成本** | 上传走各家 API 直连、凭据存本地；OCR 用系统 API；抠图在本地推理 | 没有"每月都在发生的成本"可挂订阅；用户会问"你凭什么按月收我钱" | ❌ 结构性的；要收订阅必须先造云，而造云就丢掉了它最大的成本优势 |

> **这一节最重要的一句**：ShareX 的**成本结构**（服务端为零）与它的**变现能力**（订阅不成立），是同一件事的两面。想靠它赚钱的人，第一步就得先破坏让它免费活下来的那个结构。

## 三、可商业化路径评估（5 条，逐条判死）

评分：可行性 = 在法律/结构上做得到；天花板 = 一年能收多少钱的量级。

| # | 路径 | 怎么做 | 可行性 | 天花板 | 关键障碍 | 判定 |
|---|---|---|---|---|---|---|
| A | **C 端 Pro 买断**（$15–30 一次） | 高级功能锁付费 | ⛔ 不可行 | $0 | GPL：付费版必须开源，任何人可免费重编译；旧版永久免费可用 | **直接砍** |
| B | **订阅制**（$3–5/月） | 云同步配置 / 团队图库 / 在线分享页 | ⚠️ 需先造云 | $50 万–$300 万/年（若做到 1–5 万付费用户） | 破坏零成本结构；对标物是"完全免费且功能更多的自己"；截图属低频工具，续费理由弱 | **不推荐**（对开源本体） |
| C | **企业合规版**（¥30–80/席/年） | 强制水印、上传目标白名单、审计日志、组策略/MSI 静默部署、DLP 对接 | ✅ 可做（另建闭源组件，不共享 GPL 代码） | $30 万–$150 万/年（10–50 家中型客户） | 需公司实体 + 销售 + 安全认证；决策链长（IT 安全部门） | **唯一推荐方向** |
| D | **OEM / 白标授权** | 把捕获引擎授权给 SaaS/录屏/客服厂商 | ⚠️ 受 GPL 限制 | $10 万–$50 万/年 | 双许可需版权统一（锁 1）；买方通常要求闭源 | 需重写闭源版本才成立 |
| E | **广告 / 捆绑安装** | 装机量变现 | ✅ 技术可行 | $20 万–$80 万/年（按 CPM/CPA 粗估） | **作者明确拒绝**；且会摧毁"无广告"这一核心信任资产 | **价值观否决** |

### 3.1 为什么 C 端买断在这条赛道"别人能收、ShareX 不能"

看同赛道真实定价：

| 产品 | 平台 | 定价 | 模式 | 数据级别 |
|---|---|---|---|---|
| **CleanShot X** | macOS | **$29 一次性**（¥206，含 1 年更新 + 1GB 云）；Cloud Pro **$8/用户/月**（年付，¥57/月）或 $10/月；团队 $8/用户/月 | 买断 + 云订阅 | `【官方定价页】2026-10-26` |
| Snagit | Win/Mac | 订阅制，$3.25/月起（年付口径） | 订阅 | `【二手·Toolradar，口径存疑】` |
| FireShot Pro | 浏览器扩展 | $99.95 终身（¥710） | 买断 | `【二手·2026 榜单】` |
| PicPick | Windows | 个人免费 / **商用一次性授权** | 免费 + 商用授权 | `【二手·2026 榜单】` |
| Greenshot / Lightshot / ShareX | Windows | 完全免费 | 无 | `【实测】` |

**差异不在功能。** CleanShot X 的功能集与 ShareX 高度重叠（滚动截图、Pin、OCR、录屏、标注、云链接），甚至更少 —— 但它能收 $29，因为它卖的是**打磨过的体验 + 开箱即用的云链接 + 售后**。ShareX 卖不出钱，是因为它把这三点分别换成了：**设置项密度**、**让用户自己配图床**、**无**。

> **可迁移结论**：截图/录屏这类工具，付费理由从来不是"能截"，而是「**不用配就能发出去**」和「**出问题有人管**」。ShareX 主动放弃了这两件收钱的事。

## 五、它真正的"商业化能力"在哪（换个问法）

如果问题不是"ShareX 能不能收钱"，而是"ShareX 这个资产值什么"，答案完全不同：

| 资产 | 可变现方式 | 现实性 |
|---|---|---|
| **40,417 Star / 3,400 万下载的品牌** | 引流到同团队的其他付费产品 | ⚠️ 可行，但作者无其他产品 |
| **89 个上传器的协议实现** | 抽成 SaaS 做"截图分享链接"服务 | ⚠️ 可行，但要做服务端、要运维、要合规 |
| **Avalonia + SkiaSharp 的编辑器架构** | 作为闭源产品的技术底座（**重写而非复制**） | ✅ 最高价值的一条（见附 D） |
| **"免费无广告 18 年"的信任** | 唯一能支撑"付费企业版"的道德资本 | ✅ 但仅限 B 端，且不得回收 C 端承诺 |
| 用户付费意愿本身 | —— | ❌ 不存在 |

**判断：它是一个"高价值资产、零现金流"的项目。** 当成竞品看，它是最难打的免费替代；当成生意看，它是一条已经证明走不通的路。

## 六、结论与可迁移判断

1. **对"ShareX 有没有商业化能力"**：没有。四条锁里两条（GPL + 永久免费承诺）是不可逆的，另外两条（无实体、无云）解开就等于换了一个产品。
2. **对赛道**：截图/录屏**能收钱**（CleanShot $29、FireShot $99.95、PicPick 商用授权、Snagit 订阅），但收的是「开箱即用的分享链路 + 售后」，不是功能数量。**任何以"功能比 ShareX 多"为卖点的方案，都会先被免费版打死。**
3. **对个人开发者（这是给你的直接结论）**：
   - **不要挑"ShareX 已经免费做全"的位置**。它的 36 个工具 + 89 个上传目标已经把 C 端需求吃干净，且边际成本为 0 —— 你收一分钱都是劣势。
   - **要挑它结构上做不到的位置**：需要服务端持续交付的（团队素材库、合规留痕、在线审阅），或需要承担责任的位置（企业 DLP、法务取证）。
   - **别把它当"低垂果实"**：4 万 Star、3,400 万下载、18 年、单人维护、收入靠赞助 —— 这是"高 Star ≠ 高收入"最干净的一个反例，比任何调研结论都硬。
4. **若真要做同类商业化，最小验证**（不是做产品，是验证付费）：
   - 拿 3 家 500 人以上的 Windows 企业 IT 安全负责人，问一个问题：*"你们现在怎么阻止员工把含客户数据的截图传到公网图床？"*
   - 如果他们已经在用 DLP 但覆盖不到截图 → 有需求；如果答"没考虑过" → **这条线也不成立，直接放弃**。

## 附 B、测算过程（假设 → 依据 → 推算 → 结果 + 敏感度）

### B.1 捐赠收入（唯一的可见现金流）

| 步骤 | 内容 |
|---|---|
| **假设 1** | 赞助档位分布：$5 占 60%、$10 占 25%、$20 占 10%、$50 占 4%、$100 占 1% |
| **依据** | 无公开分布数据。依据是 OSS 捐赠的通行规律（最低档占比最高）；**这是本测算最脆弱的一环** |
| **推算** | 29 人 × 上述比例 → 17.4×5 + 7.25×10 + 2.9×20 + 1.16×50 + 0.29×100 = 87 + 72.5 + 58 + 58 + 29 ≈ **$304/月** |
| **结果** | **$304/月 ≈ ¥2,158/月 → 年 $3,648 ≈ ¥2.59 万**（USD/CNY = 7.1 `【假设】`） |
| **敏感度** | 悲观（全部 $5）：$145/月 → 年 ¥1.24 万；乐观（20% 落在 $20 以上）：$450/月 → 年 ¥3.83 万。**结论不翻转**：量级始终在"万级人民币"，与"全职 18 年"不可能自洽 |
| **置信度** | **低**。推翻条件：拿到真实档位分布，或 Patreon/加密捐赠规模 |
| **未计入** | Patreon、加密捐赠、私有赞助。若三者合计与 Sponsors 同量级，年收入区间上移到 **¥2.5 万–¥7.7 万**，结论不变 |

### B.2 C 端买断天花板（"假装 GPL 不存在"的参照值）

| 步骤 | 内容 |
|---|---|
| **假设 2** | 年活跃用户 = 累计下载 × 1%/2%/3%；付费转化 0.5%/1.5%/3%；客单价 $19 |
| **依据** | 活跃率取"累计下载 → 年活跃"的常见衰减（工具类 1%–3%）；转化率取自工具类买断产品的常见区间（0.5%–3%），**无本品实测数据** |
| **推算** | 悲观 34 万 × 0.5% = 1,700 人 × $19 = $3.23 万；基准 68 万 × 1.5% = 10,200 × $19 = $19.4 万；乐观 102 万 × 3% = 30,600 × $29 = $88.7 万 |
| **结果** | **年 $3.23 万–$88.7 万（¥22.9 万–¥630 万）**，且**一次性、无续费** |
| **敏感度** | 活跃率 ±50% 与转化率 ±50% 同向叠加，结果在 $1.6 万–$200 万之间摆动 → **结论不稳，只能当量级参考，不可当预测** |
| **置信度** | **低**（三个假设均无本品实证） |

### B.3 企业路径（唯一推荐的账）

| 步骤 | 内容 |
|---|---|
| **假设 3** | ¥60/席/年；客户席位 200–2,000 |
| **依据** | 锚点反推：CleanShot Cloud Pro $8/用户/月 = 年 $96（¥682），企业批量授权通常为 C 端订阅价的 10%–20%；另参考国内企业工具 ¥50–100/席/年区间 |
| **推算** | 200 席 × ¥60 = ¥1.2 万/客户/年；2,000 席 × ¥60 = ¥12 万/客户/年 |
| **结果** | 覆盖 1 人团队年成本（¥60 万 `【假设：含社保与设备】`）需 **5–50 家客户**；做到 ¥500 万/年需 **80–400 家**，必须建销售团队 |
| **敏感度** | 客单价 ±50% → 所需客户数反向 ±50%，**结论不翻转**：单人或小团队做 B 端可行，做大必须组织化 |
