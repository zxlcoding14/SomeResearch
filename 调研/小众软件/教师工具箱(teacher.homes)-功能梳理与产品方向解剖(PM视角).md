# 教师工具箱（teacher.homes）— 论坛帖样例的功能梳理与产品方向解剖

> **分析对象**：小众软件官方论坛（meta.appinn.net）主题 77805《教师工具箱介绍》及其承载的产品 `teacher.homes` / GitHub `CrisXie4/teacher-website`
> **版本快照**：帖子 v1（2025-11-27 首发，2025-11-29 最后回复，共 24 楼）｜产品 README v2.1.0｜GitHub 数据采集日 2026-10-10
> **分析目的**：**学它**（拆设计师的决策与失误）+ **判方向**（这条赛道值不值得进场、在哪进场）
> **分析框架**：`产品分析框架`（七层提问法）→ `开源竞品与可复用能力`（先判死再省钱）→ `C端方向方法论` / `个人开发者方向方法论`（这一刀怎么切）→ 报告结构沿用 `研究报告规范`
> **数据可信度分级**：① 经审计 ② 页面/API 实测 ③ 官方宣称 ④ 第三方 ⑤ 二手转载
> **本分析要回答的 3 个问题**：① 这个"工具箱"到底做了什么、设计决策对不对？② 它踩中的是哪几条产品方向、每条方向的真实玩家与定价天花板在哪？③ 如果换成我要进场，闸门过不过、空位在哪？

## 〇、结论先行（TL;DR）

1. **【否定性结论】这不是一个产品样本，是一个作品集样本 —— 但它作为"方向样本"的价值极高，因为它把一个被三重免费覆盖的赛道用最干净的方式证伪了一遍。** 作者自述为**初中生开发者**（README「Cris Xie - 初中生开发者」），暑假期间开发，MIT 开源、完全免费、无广告、靠打赏页支撑。用它做商业可行性评估是维度错配；用它的**功能构成 + 竞品对撞结果**做方向判断，结论是干净的。

2. **13 个功能里，13 个都已被免费替代覆盖（覆盖率 100%），其中 11 个被"同一形态的直接免费竞品"覆盖。** 直接对撞者不是某家公司，而是四个零成本渠道：**酷课堂 kuketang.cn**（31 个工具、免注册免费，直接覆盖其中 9 个）· **Classroomscreen**（200 万教师，Basic 档 26 个 widget 全免费）· **班级优化大师**（380 万教师，永久免费）· **希沃白板**（教室预装，活跃教师 700 万）。按 CVD 框架的天花板公式：`定价天花板 ≈ min(竞品价, 人力替代成本, 损失规避额) × (1 − 免费替代覆盖率) = X × 0 = 0`。

3. **"工具箱 / 工具聚合"本身就是这套设计里最大的一个产品误判 —— 用功能数量冒充价值。** 13 个功能里 T1（内核级、去掉不成立）只有 **2 个**（随机点名器、课堂计时器），其余 11 个落 T4（低频/边缘/装饰）。而恰恰是这两个 T1，被免费替代覆盖得最彻底。工程完整度（PWA 离线、多语言、公告系统、共享学生名单库）做得比功能组合好得多。

4. **唯一做对的那件事是"共享学生名单数据库"——它是这个产品里唯一的切换成本来源，却没有被当成卖点来经营，也没有配套账号体系把它变成留存。** 点名器 / 分组器 / 表现记录器共用一份名单，一次 CSV 导入三处复用。这是可迁移的正确设计；但它仍是纯本地 localStorage，无账号 = 无跨设备 = 无网络效应 = 无数据飞轮。

5. **这个帖子的舆情走向本身就是一条产品教训，且是本文保留价值最高的一条：把工具发到"发现频道"，换来的不是用户反馈，是价值观审判。** 24 楼里 **15 楼（62.5%）**在争论"教室音量检测 = 监控学生 = 监狱"，**有效产品反馈 0 条**。触发点是"功能列表按开发顺序排列"，把最有争议的功能排到了第一位（作者原话：「这只是我第一个写出来的功能，我是按顺序写的，所以排到了第一个」）。结果：一个高危标签被搜索引擎与产品名永久绑定。

6. **对"想收钱的个人开发者"，这条方向在闸门 1（收得到钱）直接不过，不必进入后面的测算。** 教师是典型的"使用者 ≠ 付费者"人群：个人几乎无付费习惯，学校预算走招投标（个人结构性做不到）。四道闸门诊断：① 收得到钱 **✗** ｜ ② 扛得住成本 **✓（成本结构极好，纯前端边际成本≈0）** ｜ ③ 送得到人 **△（可达但留不住）** ｜ ④ 算得过账 **✗（免费 = 无账可算）**。

7. **可迁移的三条**：抄它的**交付形态**（纯前端 + PWA + 零依赖 = 个人交付成本最低的形态）、抄它的**名单复用设计**、抄它的**隐私叙事当信任资产**；别抄它的**功能堆叠**、别进"K12 教师课堂小工具"这个格子、**别让功能排序变成开发顺序**、别把"免费开源 + 打赏"当商业模式。

### 2.2 六组设计决策与 PM 判读

| # | 设计决策 | 具体做法 | PM 判读 |
|---|---|---|---|
| 1 | **形态：纯前端静态站 + PWA** | 无服务器、localStorage、可离线、可安装到桌面 | ✅ **个人交付成本最低的形态**（托管费≈0、无运维、无 SLA）。❌ 代价是**主动放弃了这个品类里唯一还能收费的部分**——凡需要服务端的能力（账号、云同步、学情报告、家校通知、AI 批改）一个都做不了。**形态选择即商业模式选择**，这一步就把上限锁死在 0 |
| 2 | **零依赖自研** | 除图表用 Chart.js，全部原生 | ✅ 包体小、无供应链风险、无许可风险。❌ 13 个工具 × 自研 = 维护面 = 一个人的全部业余时间（见 §六审计：作者是初中生，2026-05 后已无推送） |
| 3 | **隐私叙事** | 「所有数据本地存储，绝不上传云端」 | ✅ 是真差异点；❌ 但**教师不为隐私付费**——这条只有在"家长/学生数据"场景才有付费含义，而本地存储恰恰做不了家校互通 |
| 4 | **多语言** | 中/英/西/法四语 | ✅ 工程方向对（教师工具海外确有需求）；❌ **有产能没渠道**：没有对应海外分发动作，四语版本 ≈ 零增量 |
| 5 | **完全免费 + 打赏** | 无功能墙、无用量墙、无广告 | ❌ 直接删除收入路径。换来的是"口碑 + 分发"——而两者都没做成（★24、域名失效）。**"开源 + 赞助"已被方法论列为个人开发者头号反模式** |
| 6 | **工具箱式聚合 + 按开发顺序排序** | 13 个独立工具并列，音量检测排第一 | ❌❌ **双重误判**：① 工具箱 = 用功能数量冒充价值；② 功能排序 = 开发顺序而非用户价值顺序 → 把争议最大的功能推到门面位置，直接引发 15 楼舆情 |

### 2.3 唯一"做对了"的设计：共享学生名单库

| 设计 | 做法 | 为什么这是全场最有价值的一处 |
|---|---|---|
| **共享学生数据库** | 点名器 / 分组器 / 表现记录器共用一份名单；支持单个添加、CSV(学号,姓名) 批量导入、`.json/.csv/.txt` 文件导入 | 这是 13 个工具里**唯一的切换成本来源**（迁走要重新导入名单 + 重建分组）。它把一个"工具集合"往"工作台"方向拉了一步 |
| **但它没被兑现成资产** | 仍为纯 localStorage；无账号、无云同步（README 长期规划里"可选云同步"仍未勾选） | 切换成本极低（换个浏览器就没了），且**无法变成留存、无法跨设备、无法形成数据飞轮**。设计对了，经营没做 |

## 四、"涉及的产品方向"——5 个子方向 + 1 个元模式

> 这 13 个工具不是一个方向，而是**6 个不同方向的拼接**。分开看，每个方向的生死条件都不一样；拼在一起，等于同时打 6 场仗，而每一场都有一个已经赢了的对手。

### 4.1 方向归属表

| # | 方向 | 落在哪些功能 | 该方向的真实玩家（实测） | 该方向的死亡条件 | 本样本位置 |
|---|---|---|---|---|---|
| **A** | **课堂大屏 / 展示工具**（Classroomscreen 型） | 时钟、计时器、电子白板、音量检测 | **Classroomscreen**（200 万教师；Basic 全 26 widget 免费，Pro $3/月=$36/年）｜酷课堂｜`tinkertanker/classroom-widgets`（MIT，桌面悬浮窗） | **免费档已给满**：核心能力全免费，付费只买"保存/共享/组织" | 正面撞，无差异 |

## 五、逐层 PM 分析（L1–L6 收敛）

### 5.1 L1 · 一句话定义与替代谱系

- **一句话（不贴品类词）**：**它替教师在教室电脑上"当场"办好 13 件小事，让老师不用去翻手机、翻纸质表格、或临时找网站。**
- **最小可用内核**：**一节课里被反复调用 2 次以上的那两件事——随机点人和控制时间。** 删掉其余 11 个工具，产品依然成立（且体验更聚焦）。

**替代谱系六类（C 端尤其看第 2、3、6 类）**

| 类 | 具体替代 | 对本方向的杀伤力 |
|---|---|---|
| 手动做 | Excel 名单 + 心算 + 手机计时 | 低（更麻烦） |
| **系统内置** | Windows 时钟/画图/便签；**教室预装希沃白板** | **★★★★★** 教室里的默认软件就有白板与学科工具 |
| **免费开源** | classroom-widgets（MIT，活跃）、k12Tools（16 工具）、ClassyRoom | **★★★★** 功能同构、可商用、有人在维护 |
| 竞品（直接） | 酷课堂（9 个功能重合）、课堂有点酷、Classroomscreen Basic | **★★★★★** 同形态、免费、有用户 |
| 外包找人做 | — | — |
| **忍着不做** | 用纸质名单点名、用手机计时、什么都不用 | **★★★★** 成本 0，且教师已经这么干了十年 |

### 5.2 L2 · 谁用 / 何时用 / 多久一次 / 谁付钱

| 维度 | 结论 |
|---|---|
| 使用者 | 小学 / 初中 / 高中教师、培训机构教师（**帖子自称"适用场景"**：全学段） |
| **付费者** | **无。** 教师个人几乎不为此付费；学校预算走招投标（个人做不到）。**使用者 ≠ 付费者，且付费者不在个人开发者的可及范围内** |
| 触发场景（JTBD） | 「当我在上课、需要**当场公平选一个学生**／**控制一个活动的时间**时，我想要一个不用准备就能开的工具，这样我就不用打断课堂节奏。」 |
| 频次 | 点名/计时：**日频（每节课多次）**；分组：周频；字帖/出题：学期频；3D/元素表：偶发 |
| 切换成本 | **极低**（localStorage，换个浏览器就没了；工具间无依赖） |
| 用户在哪儿讨论 | 小众软件论坛、教师公众号/教研群、B 站教学号（本样本的传播渠道即在此） |

**频次 × 心理价位**：日频是"可订阅"的信号——**但心理价位锚点是 ¥0**（因为有四个免费渠道），频次再高也换不来付费。这正是 CVD 框架"频次决定商业模式"的例外条件：**频次只有在"免费替代不覆盖"时才转化为付费能力。**

### 5.3 L3 · 为什么成立（需求硬度）

| 判定 | 结论 |
|---|---|
| 痛点 / 痒点 / 爽点 | **痒点为主**：不点名也能上课（用纸质名单），不计时也能上课（手机）。**没有"不做就损失钱或触发合规"的痛点** |
| 卖点对撞免费替代 | 逐条对撞后**剩余价值 ≈ 0**（见 §3.2 矩阵，覆盖率 100%） |
| 可感知的 10 倍 | ❌ 无。每个功能都是"更方便一点"，不是"快 10 倍" |
| 需求真实性 | **需求是真的**（教师确实想要），但**"需求真" ≠ "能收钱"**——这是本样本最重要的区分：它证明了"真需求 + 100% 免费覆盖 = 商业价值 0" |

### 5.4 L4 · 商业模式与付费墙

| 项 | 结论 |
|---|---|
| 收费对象 | 无（免费） |
| 计费单位 | 无（打赏属自愿赠与，非计费） |
| 付费墙 | **四面墙一面都没建**（功能墙/用量墙/时间墙/体验墙全无） |
| 续费理由 | ❌ 不存在。**纯前端 = 无持续交付成本 → 订阅根本不成立，连买断都无处附着** |
| 价格锚点 | 无。竞品锚点全是 ¥0 / $0 |

> **本层最狠的一句话**：`无持续交付成本` 在方法论里是"只能买断、不能订阅"的理由；但在**竞争者全是免费**的赛道上，它进一步变成"连买断也没有意义"——因为用户没有理由为一次性交付付钱，当同一交付在四个地方免费可得。

### 5.5 L5 · 竞争位势与系统内置威胁

**开源竞品雷达（先判死，再省钱）**

| 步 | 结果 |
|---|---|
| ① 候选 | classroom-widgets、k12Tools、ClassyRoom、各类 Classroomscreen 复刻 |
| ② 一手数据 | classroom-widgets：MIT / ★3 / **pushed 2026-10-09（活跃）**；k12Tools：★0 / created 2026-01-04 / license 字段 null；ClassyRoom：MIT |
| ③ 三问 | 有活跃成品？**是**（classroom-widgets 在持续提交，且形态比本样本更完整：桌面版 + 常驻悬浮窗 + 实时互动）｜有同类商业免费？**是**（四个） |
| ④ 等级 | **L3 —— 有活跃开源成品 + 已存在的免费商业领导者**（接近 L4 的效果） |

**L3 的决策含义**：只做开源**明确不做**的那一段。开源明确不做的是什么？classroom-widgets 做了悬浮窗、k12Tools 做了座次表，唯独都没做——**服务端的结构化交付**（学情报告、成绩分析、家校通知）。而那一段，本样本因为"纯前端"做不了，个人开发者因为"需要资质 + 客服"也做不动。

**系统内置威胁（头号生死问题）**

| 威胁源 | 覆盖了什么 | 后果 |
|---|---|---|
| Windows 时钟 / 画图 / 便签 | 时钟、计时器、白板 | 三个功能的"必须装第三方"理由消失 |
| **希沃白板（教室预装）** | 白板 + 学科工具（几何/化学） | **目标用户在教室电脑上开机的第一屏就有一个免费竞品**，这是最硬的一条 |
| **国家中小学智慧教育平台**（basic.smartedu.cn） | 电子课本、教学资源 | 帖子里第 7 楼用户自己就在推荐它 |

**定价天花板公式**：`≈ min(Classroomscreen Pro $36/年, 班级优化大师 ¥0, 希沃白板 ¥0, 酷课堂 ¥0, 开源 ¥0) × (1 − 100%) = 0`。

### 5.6 L6 · 持续性与生命周期

| 项 | 结论 | 依据 |
|---|---|---|
| 护城河 | **无**：无网络效应、无数据飞轮、无切换成本、无生态 | localStorage + 无账号 |

## 六、若换成"我"要进场：四道闸门顺序否决

> 前提：假设一个在职/独立开发者看中了"教师工具"这个人群，想认真做。**顺序不可跳，前两道不过后面全废。**

| 闸门 | 判定 | 依据 | 死信号 |
|---|---|---|---|
| **1 · 收得到钱** | ❌ **不过** | 使用者（教师）≠ 付费者；教师个人无付费先例；学校预算 = 招投标 + 等保 + 私有化交付 → **个人结构性做不到**（方法论明确列为"结构性做不到"第 1、4 条） | 「钱从哪个口子进来」答不出 |
| **2 · 扛得住成本** | ✅ **过**（罕见的亮点） | 纯前端 → 边际成本 ≈ 0；月固定成本 ≈ 域名 ¥70/年 ÷ 12 ≈ ¥6；无模型调用、无服务器、无审核 | — |
| **3 · 送得到人** | △ **边际不过** | 教师社群可零预算触达（教研群/公众号/论坛），"2 周内让 20 个教师开口"能做到。**但触达之后留不住**——因为免费替代已够用 | 送得到人是必要条件，不是充分条件（免费竞品把它变成了不充分） |
| **4 · 算得过账** | ❌ **不过** | 免费 = 无营收 → 盈亏平衡公式无输入。若强行定价：天花板 = 0（见 §5.5） | 算不出盈亏平衡用户数 |

**一票否决命中**：第 1 条（收款路径不成立）、第 3 条（客服/合规面 vs 承载——13 个工具的支持面 = 1 个人的全部业余时间）、第 5 条（分发虽可得但价值为 0）。

> **结论：这道题不是"努力不够"，是"结构不成立"（§二 的四个结构性做不到命中 2 条）。**

## 七、可迁移结论：抄什么 / 别做什么 / 从哪进场

### 7.1 能抄什么（机制 / 形态 / 设计）

| 可抄项 | 具体 | 迁移到哪 |
|---|---|---|
| **交付形态** | 纯前端 + PWA + localStorage + 零依赖 = 个人交付成本最低的形态模板（托管免费、无运维、无许可风险） | 任何"单点能力型"个人项目 |
| **共享数据层设计** | 一份名单喂三个工具（一次导入、多处复用）→ 制造人工切换成本 | 任何工具集类产品（把"集合"往"工作台"拉） |
| **隐私叙事当信任资产** | 「数据不出本机」写进首屏卖点 | 面向敏感场景的本地工具 |
| **工程完整度** | 公告系统、404 页、PWA 缓存版本化、i18n 框架、README 的贡献规范 | 作品集 / 开源门面（这一层做得比很多商业项目好） |
| **打赏页 + 社群（QQ 群）** | 兴趣项目的收尾动作 | 非商业项目 |

### 7.2 别做什么（反面清单）

| 反模式 | 本样本的实证 |
|---|---|
| **别做"工具箱 / 功能聚合"** | 13 功能里 T1 只有 2 个；聚合本身不构成价值，反而放大了维护面 |
| **别进"K12 教师课堂小工具"这个格子** | 商业免费（4 家）+ 开源活跃（3 个）+ 系统预装（希沃）三重覆盖，定价天花板 = 0 |
| **别把功能排序变成开发顺序** | 作者自述「按顺序写的，所以排到了第一个」→ 把高危功能推到门面 → 15/24 楼舆情，负面标签与产品名在搜索里绑定 |
| **别做"教室音量检测"这类舆情高危功能** | 它是唯一有记忆点的功能，也是唯一让产品在论坛上被骂的功能。**争议功能不是流量，是负债** |
| **别把"免费开源 + 打赏"当商业模式** | 头号反模式；本项目为其提供了教科书级案例 |
| **别只用无埋点的纯前端做产品** | 无账号、无埋点 → **留存不可测 → 连"有没有人用"都答不出**，等于闭眼开车 |
| **别把"零依赖自研 13 个工具"当卖点** | 自研 13 个 = 13 份维护债，且每一个都撞一个免费成品 |

### 7.3 从哪进场（若一定要在这个大领域里找位置）

| 切入点 | 为什么可能成立 | 为什么本样本做不到 | 需先回答 |
|---|---|---|---|
| **① 服务端那一段（学情报告 / 成绩分析 / 家校通知）** | 这是"持续交付成本"所在，也是订阅唯一能挂的地方；开源与纯前端工具都明确不做 | 纯前端形态锁死；且需要资质 + 客服，个人承载不了 | 客单价？学校还是家长付？合规（未成年人数据）怎么办？ |
| **② 家长侧付费（孩子的练习/成长记录）** | **付费方从"教师"换成"家长"**，付费意愿显著更高（K12 家长付费习惯成熟） | 原作者从一开始就把人群定死在教师 | 触达家长的成本？未成年人数据合规底线？ |
| **③ 不做产品，做"素材/模板包"** | 零边际成本、可买断、无需客服（方法论列为个人形态之一） | 未做 | 教师群体的付费力仍是最大疑问 |
| **④ 只做平台不做产品：给教师工具做"分发 + 支付 + 更新"** | 避开功能竞争，赚通道钱 | 未做 | 冷启动双边市场，个人几乎必败 |

> **本节的诚实结论**：这个"大领域"里，**唯一对个人开发者友好的位置是"换付费方"（教师→家长）或"换形态"（工具→素材包）**；坚持"给教师做免费课堂小工具"，无论做得多好，都会重复本样本的结局。

## 附 B · 测算过程（与实测分开排版）

> **纪律**：以下全部为**推算 / 预估**，每项按「假设 → 依据 → 推算 → 结果」四段书写，并附置信度与推翻条件。**不可与附 A 的实测数据混读。**

### B1 · 免费替代覆盖率（判定性指标）

- **假设**：一种功能只要被"系统内置 / 免费商业 / 免费开源 / 手工可替代"任一渠道覆盖，即记"已覆盖"。
- **依据**：§3.2 矩阵逐格取证（官网功能页、README、GitHub 描述）。
- **推算**：13 个功能 × 5 类免费渠道 → 有覆盖的功能数 = 13 → `13 ÷ 13 = 100%`；其中被"同类形态直接竞品（酷课堂/Classroomscreen/班级优化大师）"覆盖 = 11 → `84.6%`。
- **结果**：**覆盖率 100%（宽口径）／84.6%（同形态窄口径）**。置信度 **高**（取证路径为官方页面与 API）。推翻条件：发现某功能在四类免费渠道中均无对应物（本次未发现）。

### B2 · 定价天花板

- **假设**：天花板 = `min(竞品价, 人力替代成本, 损失规避额) × (1 − 免费替代覆盖率)`。
- **依据**：Classroomscreen Pro $36/年；其余竞品与开源均为 ¥0/$0。
- **推算**：`min($36, ~¥0, ~¥0) × (1 − 100%) = $36 × 0 = 0`。
- **敏感度**：即便假设"覆盖率仅 80%"（乐观），天花板 = `$36 × 0.2 = $7.2/年/教师`。要覆盖一名开发者 ¥15 万/年的机会成本，需 `150,000 ÷ 7.2 ≈ 20,833` 名付费教师，且转化率按 1% 计需触达 **208 万教师**（≈ 与 Classroomscreen 全量教师数同量级）。
- **结果**：**天花板 ≈ ¥0；乐观情形下亦不可行。置信度 高；结论不翻转。**

### B3 · 打赏模型的收入上限（锚点反推）

- **假设**：月活 ∈ [500, 3000]；打赏转化率 ∈ [0.01%, 0.1%]；人均打赏 ∈ [¥5, ¥20]。
- **依据**：① 月活依据 —— ★24 是唯一公开热度锚点，"Star 数 → 活跃用户"的经验倍率取 20–125 倍（**该倍率为经验估计，未做样本量化**）；② 打赏转化率 —— 免费工具捐赠页的行业经验区间（**同为经验估计**）；③ 人均 —— 参照国内小额打赏常见区间。
- **推算**：
  - 悲观：`500 × 0.01% × ¥5 = ¥0.25/月`
  - 中位：`1,000 × 0.05% × ¥10 = ¥0.5/月`
  - 乐观：`3,000 × 0.1% × ¥20 = ¥6/月`
- **结果**：**月收入数量级 ¥0–¥10。置信度 低**（两个乘数均为经验估计，非实测）。**推翻条件**：拿到站点真实访问数据（现在已不可能，域名失效）。**但即使取最乐观值，也不足以覆盖任何形式的固定成本 —— 结论方向不翻转。**

### B4 · 个人开发者的生存线（"若别人来做这个方向"）

- **假设**：月固定成本逐项列。
- **依据**：静态托管（GitHub Pages / Cloudflare Pages）¥0；域名 `*.homes` 非常规 TLD，取值 ¥70–¥200/年；SSL 免费；无服务器、无 API 月费、无开发者证书。
- **推算**：`月固定成本 ≈ ¥6 ~ ¥17`。若客单价 ¥0（免费），则 `盈亏平衡付费用户数 = 6 ÷ 0 = 不可计算`。
- **结果**：**成本结构极好（闸门 2 通过），但生存线公式无输入 → 闸门 4 不过。** 这形成本样本最反直觉的一条结论：
  > **"做出来"从来不是这个方向的问题——问题全在"收钱"与"留存"。**
- **敏感度**：把域名换成 ¥1,000/年的短域名，或加上 OCR/AI 类 API（¥100–1,000/月），月固定成本上升到 ¥100–1,000 —— 仍然极低。**成本侧无论如何都不构成门槛，因此"降本"这条路对本方向毫无意义。**

### B5 · 分群留存的缺失（不可测算项的处理）

- **事实**：无账号、无埋点、无后台 → **次日/7 日/30 日留存、月流失率全部无法测算**。
- **处理**：按方法论，此处**不做估算**（无任何可用于类比的乘数），列为缺口并给出获取路径（见附 C）。
- **PM 含义**：**"留存不可测"本身即是本次分析中最致命的一条产品缺陷** —— 它使产品无法回答"有没有人在用"，也就无法迭代、无法证明价值、无法融资、无法出售。
