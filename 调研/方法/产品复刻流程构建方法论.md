## 〇、结论先行（TL;DR）

**通用的不是「步骤清单」，是「产物契约 + 可判定门禁」。步骤清单谁都能写，写出来也只是提示词合集——LLM 每次跑出来都不一样，不可复现。**

| # | 判断 |
|---|---|
| 1 | **先定契约，后定步骤。** 复刻流程的骨架是 `clone/` 目录下的产物文件格式，不是 skill 的提示词。产物格式定了，阶段才能独立替换、断点续跑、人工插检 |
| 2 | **门禁必须能被脚本判定。** Replica 真正值钱的不是 11 个 skill，是 `parity.py`（加权评分，缺 must-have 直接判"不可发布"）、`imgdiff.py`（边缘图比对，换色不影响分数）、`sweep.py`（扫原版残留）这三个**确定性工具**。它们把"感觉差不多"变成"78 分，不可发布"。没有这一步，规范等于没有 |
| 3 | **流程层与平台层必须解耦。** 阶段划分、产物契约、门禁逻辑是通用的；侦察手段、UI 提取、测试执行器、打包发布**不可通用**，必须做成可插拔 Adapter。Replica 的失败就在于把 Web 实现焊进了流程 |
| 4 | **通用性是可证伪的。** 判据：同一条流水线跑 3 个异构目标（原生 Win32 / Electron / 自绘），**如果只需要换 Adapter、流程层一行不改，才算通用**。跑不通就是没解耦 |
| 5 | **先手工跑一遍，再写 skill。** 顺序不能反。先用一个真实小目标人工走完全流程并记录产物，再把手工流程固化成 skill。一上来写 11 个 skill 是**最典型的失败路径** |
| 6 | **必须标出人工检查点。** 全自动复刻是幻想。法律评估、抄砍换决策、技术选型、品牌命名、法律终审——这 5 处必须人工拍板，写进流程 |
| 7 | **Windows 侧的核心难点不是"看不到"，是"定位不稳"。** 自绘 UI 只能像素兜底；DPI/主题/窗口尺寸会让 diff 全红。这两项要在设计阶段就当一等公民处理 |

## 一、设计目标与边界

### 1.1 什么叫"通用"

| 层次 | 是否通用 | 说明 |
|---|---|---|
| 阶段划分（做什么） | **通用** | 侦察→规格→需求→方案→实现→测试→验收→差异化→洗牌→上线，任何平台都这套 |
| 产物契约（产出什么格式） | **通用** | 文件路径、schema、字段语义固定 |
| 门禁逻辑（什么算过关） | **通用** | 判定条件与阈值机制固定，阈值数值可调 |
| 交付节奏与人工检查点 | **通用** | — |
| 侦察手段（怎么看到） | **不可通用** | 网页读 DOM、Android dump UI 树、Windows 走 UIA/控件树——**必须换** |
| UI 规格提取方式 | **不可通用** | 截图量 token vs 控件树反推布局参数 |
| 测试执行器 | **不可通用** | Playwright vs FlaUI/WinAppDriver/pywinauto |
| 打包与发布 | **不可通用** | 应用商店 vs 域名 vs 安装包签名 |

**结论**：目标是「**流程通用 + 执行器可插拔**」，不是"一套东西打天下"。

### 1.2 设计约束（承认边界）

- **不保证复刻质量**：流程只保证"过程可复现、缺口可见"，不保证结果一定像。像不像由 parity 分数说话
- **不解决合规问题**：只把合规变成流程里的**门禁**（不过不让上线），不给法律结论
- **不适用于"目标不可观测"**：全自绘 + 加固 + 无可见 UI 的目标，侦察段会失效，应尽早识别并退出
- **不是全自动**：5 个人工检查点是硬性的

```
┌──────────────────────────────────────────────────────┐
│ L0 元规范   artifact-contract.md · gate-criteria.md   │  ← 地基，最先写
│            legal-checklist.md · adapter-interface.md │
├──────────────────────────────────────────────────────┤
```

## 三、产物契约（地基）

所有阶段通过 `clone/` 目录通信，路径与格式固定。**先定这个，再写任何 skill。**

```
<工作区>/
└── clone/
    ├── _state.json              # 状态机：当前阶段、门禁结果、阻塞项
    ├── 00-brief.md              # 目标/目的/边界/法律前置结论           【人工必填】
    ├── 05-detect.md             # 平台与 UI 框架识别结论 + 侦察手段选择
    ├── 10-recon/
    │   ├── surfaces.md          # 界面清单（每项带 ID 与证据引用）
    │   ├── flows.md             # 流程清单（步骤级）
    │   ├── components.md        # 组件清单（含变体与状态）
    │   ├── controls.md          # 控件地图（定位器 + 优先级）※Windows 重点
    │   ├── datamodel.md         # 推断数据模型
    │   ├── behavior.md          # 行为清单（文件/注册表/网络/进程）
    │   └── evidence/            # 截图、资源、抓包原始件
    ├── 20-spec/
    │   ├── design-tokens.json   # 设计令牌（可被脚本校验）
    │   ├── page-blueprints.md   # 页面蓝图（布局分区/组件树/弹窗）
    │   └── interaction-spec.md  # 交互规格（状态机/动效/快捷键）
    ├── 30-prd/
    │   ├── scope.md             # 抄 / 砍 / 换 决策表                   【人工拍板】
    │   ├── features.csv         # 功能矩阵：id,tier(must|should|could),状态,验收标准
    │   └── nfr.md               # 非功能需求（性能/合规/安全/无障碍）
    ├── 40-arch/
    │   ├── stack.md             # 技术选型（含理由与被否方案）          【人工拍板】
    │   ├── schema.sql           # 数据模型
    │   └── risks.md             # 风险登记 + 兜底方案
    ├── 50-build/                # 实现产物指针（代码在 src/，这里只放映射与进度）
    ├── 60-test/
    │   ├── test-plan.md         # 测试计划（分层策略/范围/排除项）
    │   ├── cases/               # 用例（编号规范见 L0）
    │   ├── bugs.md              # 缺陷（严重度 S1–S4 + 复现步骤）
    │   └── evidence/            # 执行证据（截图/日志）
    ├── 70-parity/
    │   ├── parity.md            # 一致性报告（分数 + 缺口清单）
    │   └── diffs/               # 逐页 diff 图
    ├── 80-differentiate/
    │   ├── reviews.md           # 差评挖掘（引语必须带链接，禁编造）
    │   └── positioning.md       # 定位与修复计划
    └── 90-ship/
        ├── rebrand-sweep.md     # 清扫报告（零命中才过）
        ├── preflight.md         # 上线前检查清单
        └── legal.md             # 合规归档
```

**契约的三条硬规则**：
1. **每个产物必须有证据引用**：`surfaces.md` 里的每个界面要指向 `evidence/` 下的截图或 `controls.md` 的采集记录。无证据的条目视为未完成
2. **禁止空值与 TBD**：门禁脚本扫 `TBD` / `待补充` / `?` 直接判不通过
3. **机器可读的产物用结构化格式**（`features.csv` / `design-tokens.json` / `_state.json`），人读的用 md。**能被脚本判定的部分必须结构化**——这是门禁可执行的前提

## 四、阶段流水线（12 阶段）

`🧑` = 硬性人工检查点

| # | 阶段 | 输入 | 产出 | 门禁 | 需平台 Adapter |
|---|---|---|---|---|---|
| 0 | **立项与边界** 🧑 | 目标客户端、复刻目的（自用/商用） | `00-brief.md` | G0 | — |
| 1 | **平台识别** | brief | `05-detect.md` | G1 | `detect()` |
| 2 | **侦察** | detect | `10-recon/*` | G2 | `recon()` `locate()` |
| 3 | **规格提取** | recon | `20-spec/*` | G3 | `spec()` |
| 4 | **需求与决策** 🧑 | recon + spec | `30-prd/*` | G4 | — |
| 5 | **技术方案** 🧑 | prd | `40-arch/*` | G5 | — |
| 6 | **实现** | arch | `50-build/` + `src/` | — | — |
| 7 | **测试** | prd + 实现 | `60-test/*` | G6 | `test()` |
| 8 | **一致性验收** | 目标 + 实现 | `70-parity/*` | G7 | `verify()` |
| 9 | **差异化** | 公开差评 | `80-differentiate/*` | — | — |
| 10 | **洗牌与清场** 🧑 | 全部 | `90-ship/rebrand-sweep.md` | G8 | `sweep()` |
| 11 | **上线** 🧑 | 全部 | `90-ship/*` | G9 | `package()` |

**阶段设计要点**：

- **阶段 0 的法律前置不能后置**。`00-brief.md` 里就要写清：目的（自用 or 商用）、目标 EULA 是否禁止逆向、是否涉及授权绕过。**如果是商用 + EULA 禁逆向，G0 直接不通过，不进侦察**——省掉后面所有成本
- **阶段 1 是所有 Windows 复刻的关键分水岭**。同一句"复刻这个客户端"，目标 UI 框架不同，后面所有手段都不同：

  | 识别的框架 | 侦察路径 | 规格提取 | 定位器可靠性 |
  |---|---|---|---|
  | 原生 Win32 / MFC / VB6 | Spy++ 拿类名+控件 ID+消息流 | 控件矩形 + 资源尺寸反推 | **高**（HWND 稳定） |
  | WPF / WinForms / UWP | Inspect.exe / FlaUI 拿 UIA 树 | UIA 属性 + 视觉树 | **高**（AutomationId 稳定） |
  | Qt | GammaRay 导窗口结构 | 布局类反推 + 资源尺寸 | 中 |
  | Electron / Tauri / WebView2 | CDP 读 DOM（Playwright） | DOM + CSS 计算样式 | **高**（等同网页） |
  | Java Swing | Java Access Bridge | 组件树 | 中 |
  | **自绘 / 游戏化界面** | 只能像素 + OCR | **无结构化来源，全靠视觉反推** | **低**（只能图像匹配/坐标） |

  **自绘 UI 要在 G1 就识别出来并重估成本**——这是最容易低估的坑
- **阶段 8 与阶段 7 是两件事**：测试管"功能对不对"，一致性管"像不像"。分开做、分开判门禁
- **阶段 9 是所有版本里最容易被跳过、但最决定成败的一环**。复刻得再像，没有存在理由就是个没人要的副本

## 五、门禁体系（可脚本判定）

**门禁的核心要求：判定过程不能依赖 LLM 自评。** 阈值可以初始拍，但判定必须由脚本执行。

| 门禁 | 位置 | 判定条件 | 判定方式 | 不通过 |
|---|---|---|---|---|
| **G0** 立项 | 0→1 | 目的明确 + 法律前置结论非"禁止" + 边界（复刻什么/不复刻什么）非空 | 字段完整性 + 枚举值校验 | 停止 |
| **G1** 识别 | 1→2 | UI 框架有结论（"未识别"也算结论）+ 侦察手段已选定 + 若为自绘/加固则已完成成本重估 | 字段检查 | 重估或退出 |
| **G2** 侦察 | 2→3 | 界面覆盖率 ≥ 阈值；核心流程覆盖 = 100%；`controls.md` 可定位率 ≥ 阈值 | 脚本比对清单长度与 evidence 引用 | 补侦察 |
| **G3** 规格 | 3→4 | 所有 P0 页面有蓝图；token 无空值；对比度检查通过 | JSON schema + 对比度脚本 | 补齐 |
| **G4** 需求 | 4→5 | `features.csv` 无未决策项；每条 must-have 有可验证的验收标准 | 脚本扫空值/TBD | 冻结前不许开工 |
| **G5** 方案 | 5→6 | 每条 must-have 有实现路径；`risks.md` 非空 | 字段检查 | — |
| **G6** 测试 | 7→8 | P0 用例通过率 = 100%；`bugs.md` 无未关的 S1/S2 | 计数 | 修复 |
| **G7** 一致性 | 8→9 | parity ≥ 阈值（**建议初始 85**）；must-have 全绿 | `parity` 脚本 | **判定"不可发布"** |
| **G8** 洗牌 | 10→11 | 清扫零命中：原版名称/域名/配色/文案/资源/标识符残留 | `sweep` 脚本 | **拒绝上线** |
| **G9** 上线 | 11→done | preflight 清单全通过 | 清单脚本 | 拒绝 |

> **阈值（85 / 覆盖率 X%）为建议初始值，必须用真实项目校准后再固化。** 不要把它当权威数字用。

**三个必须做的确定性工具**（照 Replica 的思路，这是流程的牙齿）：

| 工具 | 做什么 | 关键设计 |
|---|---|---|
| `parity.py` | 一致性评分 | 加权：must=3 / should=2 / could=1；半成品计半分；**故意砍掉的不计分**；缺 must-have 直接输出"不可发布" |
| `imgdiff.py` | 视觉比对 | **转边缘图再比对**——只比布局位置，不比颜色，避免换色影响分数；补 DPI/主题归一化前置处理 |
| `sweep.py` | 合规清扫 | 扫原版名称、域名、配色值、文案、图片资源，**包括代码标识符里的残留**（如 `OriginalAppEmbed`）；零命中才放行 |

## 六、平台适配层设计

### 6.1 Adapter 接口（统一契约）

每个平台实现同一组接口，流程层只调接口、不碰实现：

| 接口 | 职责 | Windows 实现 |
|---|---|---|
| `detect()` | 识别 UI 框架/技术栈/是否加固 | 进程模块签名 + 窗口类名特征 + 包内容特征 + Detect It Easy |
| `recon()` | 产出统一格式的侦察产物 | 见 6.2 工具箱 |
| `spec()` | 产出 `design-tokens.json` + 页面蓝图 | screenpilot（首选）+ 控件矩形反推 + 截图像素兜底 |
| `locate()` | 控件定位，返回**带优先级的定位器** | HWND > UIA runtime_id > automation_id > 图像 > 坐标 |
| `test()` | 执行自动化测试 | FlaUI / WinApp MCP / pywinauto / winguictl |
| `verify()` | 一致性验证 | WinApp MCP 的 `screenshot_diff` + `imgdiff.py`（含 DPI/主题归一化） |
| `sweep()` | 残留扫描 | 通用逻辑，无需平台特性 |
| `package()` | 打包发布 | 安装包签名 / 商店上架检查 |

### 6.2 Windows 侦察工具箱（按框架分发）

| 用途 | 工具 |
|---|---|
| Win32 控件结构 | **Spy++**（类名/控件 ID/`WM_COMMAND` 消息流/窗口层级） |
| UIA 树（WPF/WinForms/UWP） | **Inspect.exe** / FlaUInspect / FlaUI |
| 设计规格批量提取 | **screenpilot**（token + 组件 + 页面蓝图，直接出 `design.md`/`design-tokens.json`） |
| UI 树快照（通用） | `@uipath/servo`（`servo snapshot`，Win32/WPF/UWP） |
| Qt 窗口结构 | **GammaRay** |
| Electron/WebView2 | CDP（Playwright 接 `--remote-debugging-port`） |
| 脚本化控件枚举 | pywinauto（`print_control_identifiers`） |
| 资源提取 | Resource Hacker（图标/字符串/对话框/清单） |
| 行为观测 | Process Monitor（文件/注册表/进程）、API Monitor、Fiddler/Charles（网络） |
| 二进制分析 | IDA / Ghidra / x64dbg；.NET 用 dnSpy / ILSpy |
| 加固识别 | Detect It Easy（壳/编译器/保护） |

### 6.3 Windows 专属规范（写进 L0，不是可选项）

1. **定位器优先级规范**：`HWND > UIA runtime_id > automation_id > 图像匹配 > 坐标`。低优先级定位器必须标注不稳定原因
2. **DPI 矩阵**：一致性验证必须在 100% / 125% / 150% / 200% 四档下跑，或先做归一化；否则 diff 全红
3. **主题矩阵**：浅色 / 深色必须分别验收（很多客户端两套配色）
4. **窗口尺寸**：最小尺寸 / 默认尺寸 / 最大化，三档
5. **自绘控件兜底策略**：图像匹配需固定 DPI 与主题 + 模板图版本管理；变更视觉即失效，需重录
6. **进程权限对齐**：目标以管理员运行时，侦察与自动化工具需同级权限，否则看不到窗口

## 七、跑起来的形态（skill 拆分）

## 八、构建路线（Phase 0–6，顺序不可颠倒）

| Phase | 做什么 | 产出 | 关键要求 |
|---|---|---|---|
| **0** | **定契约**：写 `artifact-contract.md` + `gate-criteria.md` + `legal-checklist.md` | L0 三份规范 | 这一步没做完，后面全是返工 |
| **1** | **手工跑通一遍**：选一个**小目标 + 单一核心流程**，人工走完 12 阶段，按契约落产物 | 一套真实产物 + 卡点清单 | **不许先写 skill**。手工阶段暴露的问题，写进 skill 就是防止复发 |
| **2** | **写三个确定性工具**：`parity.py` / `imgdiff.py` / `sweep.py` | 可执行脚本 | 先做工具，再做 skill。门禁的牙齿在这 |
| **3** | **固化成 skill**：把 Phase 1 的手工流程写成 `clone-orchestrator` + 3 个阶段 skill | 4 个 skill | 用 `skill-creator`；每个 skill 只做一件事 |
| **4** | **实现 Windows Adapter**：`detect/recon/spec/locate/test/verify` | `platform-win` | 按框架分支实现，自绘路径单独处理 |
| **5** | **异构回归**：换一个**不同 UI 框架**的目标再跑一遍 | 通用性验证报告 | **流程层改了几行？改一行以上说明没解耦** |
| **6** | **抽象多平台**：抽 P2 的 adapter 与其他平台 | `platform-*` | 在有第二个平台需求前不做 |

**Phase 1 的选目标标准**：小、单一核心流程、UI 非自绘、有公开差评可挖。**别拿一个复杂目标练手**——前面搜到的所有方案都提醒了这点。

## 九、验证与度量（怎么证明这套流程有用）

| 指标 | 怎么测 | 注意 |
|---|---|---|
| **通用性** | 异构目标跑通，流程层改动行数 = 0 | 这是**唯一可证伪的通用性判据** |
| **可复现性** | 同一目标跑两次，产物结构与门禁结论一致 | 用产物结构比对，不是文本比对 |
| **返工拦截率** | 门禁拦下的问题数 / 上线后发现的问题数 | 前者越高越好，后者越低越好 |
| **parity 收敛曲线** | 每轮迭代的 parity 分数 | 看是否收敛，而非绝对值 |
| **阶段耗时分布** | 各阶段实际耗时 | 找瓶颈；Windows 侧瓶颈通常在 recon 与 verify |

**禁止的度量方式**：用"效率提升 X%"这类自报数字。前面查到的 TRAE 方案自报"提升约 80%"，无第三方验证、无基线定义——这种数字没有决策价值。

## 十、反模式（这套流程会怎么失败）

| 反模式 | 症状 | 纠正 |
|---|---|---|
| **过度工程** | 一开始就写 11 个 skill，没人跑得完 | MVP 4 个 skill，先跑通 1 个目标 |
| **门禁虚设** | 阈值靠 LLM 自评"我觉得差不多了" | 门禁判定必须脚本化；阈值可拍，判定不可拍 |
| **平台泄漏** | 流程层出现"用 Spy++ 抓句柄"这类字眼 | 平台概念只能进 Adapter |
| **合规后置** | 上线前才发现要改品牌、要重画图标 | G0 法律前置 + G8 强制清扫 |
| **侦察过度** | 想把 100% 界面摸清才开工 | 首轮只摸一条核心流程；G2 的覆盖率阈值分轮次提高 |
| **自绘低估** | 开工后才发现 UI 全是自绘，像素兜底成本爆炸 | G1 强制识别 + 成本重估 |
| **契约漂移** | 各阶段产物格式随手改，下游全断 | 契约改动走版本号，老产物标记不兼容 |
| **丢证据** | `surfaces.md` 写着有某个界面，但找不到截图 | 契约硬规则①：无证据的条目视为未完成 |

## 十一、缺口与未决（诚实交代）

| 缺口 | 说明 |
|---|---|
| 门禁阈值无权威依据 | 85 分、覆盖率阈值均为**建议初始值**，需用 2–3 个真实项目校准；无公开基准 |
| 自绘 UI 路径无成熟方案 | 现有工具（screenpilot 等）在自绘场景都退化为像素兜底，准确率无公开评测 |
| 各现成件未实测 | screenpilot / WinApp MCP / cua_desktop_operator 在本机可用性未验证（依赖 Python / .NET 10 运行时） |
| Replica 设计仅取二手转述 | 未直接读 `github.com/Jakeschincariol/replica-skill` 的 SKILL.md 原文，其评分与清扫机制的具体实现细节可能有出入 |
| 跨平台抽象未验证 | `platform-mac` / `platform-web` 的接口是否真能被同一套 L1 复用，需在 Phase 6 验证；当前是设计假设 |

### 应查未查
- Replica 三个 Python 工具（`parity.py` / `imgdiff.py` / `sweep.py`）的源码实现
- 是否有 Windows 专属的「UI 规格提取准确率」第三方评测
- 本机是否具备 Python 3.10+ / .NET 10 运行时

## 附 · 最小可行版本（MVP）清单

要在一周内看到这套东西有没有用，只做这 6 件事：

- [ ] 1. 写 `artifact-contract.md`（第三节的目录结构 + 三条硬规则）
- [ ] 2. 写 `gate-criteria.md`（第五节表，先只做 G0 / G2 / G7 / G8 四道）
- [ ] 3. 选一个小目标，人工走完「侦察 → 规格 → 需求 → 实现 → 测试 → 一致性」六段，按契约落产物
- [ ] 4. 写 `parity.py`（加权评分 + 缺 must-have 判死）
- [ ] 5. 写 `sweep.py`（残留扫描，零命中才放行）
- [ ] 6. 把 3–5 步固化成 `clone-recon` / `clone-prd` / `clone-verify` 三个 skill

**不做**：全平台适配、11 个 skill、全自动编排。**先证明门禁能拦住东西**，再谈铺开。
