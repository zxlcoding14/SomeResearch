# 产品盈利可行性分析 · 补充提问域（C端 × B端 × 个人开发者）

> **文档类型**：方法论（提问清单 / 判据 / 决策树 / 打分卡），非具体产品分析
> **视角**：产品经理（PM）
> **适用对象**：个人开发者、独立开发者、小团队、内部创新小组
> **版本**：v1.0（2026-10-08）
> **文档性质**：**自包含独立文档** —— 不引用、不依赖、不摘编任何其他文档，单独取用即可执行全部判断。
> **本文要回答的 4 个问题**：① 已有分析框架**还缺哪些问题**？② 一条方向**怎么判断能不能盈利**（可算的模型是什么）？③ **C 端**与**B 端**两条路分别该怎么分析？④ **个人开发者**这条路在哪些环节会被卡死、怎么绕？
>
> **数据口径声明**：本文只给方法与判定标准，**不含任何市场规模、用户量、营收等外部数据**。文中出现的费率、比例、阈值为**行业常见区间**，一律标注「需核实」，**使用时必须回官方页重新核对，不得直接引用**。所有示例均为**填写格式示范**。

## 〇、结论先行（TL;DR）

1. **现有框架解决的是「这东西好不好、这方向值不值得试」，不解决「我靠它能不能养活自己」。** 这中间隔着四层现实约束：**钱怎么进来**（定价与收款）、**钱怎么花出去**（成本与现金流）、**人怎么进来**（获客与留存）、**出了事怎么办**（合规·税务·主体）。现有文档里只有 L4 一节碰到第一层的边缘。
2. **补 6 大模块 / 22 个必答域**（第二章），并从中抽出**盈利可行性 12 问快扫**（2.3）。其中 **4 个新增一票否决项**（2.4）是现有框架完全没有的。
3. **C 端与 B 端的判据不能通用。** 一句话区分：**C 端卖的是「省时间 / 爽」，B 端卖的是「不出事 / 可交代」**。C 端的分子是「可触达人数 × 付费率 × 客单价」，B 端的分子是「目标企业数 × 渗透率 × 席位 × 年单价 ÷ 销售周期」——两套公式的瓶颈位置完全不同（C 端瓶颈在分发，B 端瓶颈在决策链与销售人力）。
4. **个人开发者的第一约束不是需求，是「能不能合法收到钱」和「能不能长期承受隐性成本」。** 这两件事在写代码之前就该确认；否则做出来的东西再好，也收不到钱、或赚的钱被客服和合规吃光。
5. **【否定性结论】大多数「看起来能做」的方向，死在成本和分发上，而不是死在需求上。** 判断标准很硬：**如果一个方向必须先解决「谁来买」和「谁给我打钱」才能成立，它就不适合作为个人开发者的第一个项目。** 个人开发者的正确起点是「收钱路径明确 + 边际成本可控 + 分发渠道我自己就泡在里面」的三重交集，而不是「需求最有想象力」的那一个。
6. **落地方式**：把本文 22 个域接进现有五段式流水线的**第 ③ 段（快筛新增否决项）与第 ④ 段（证伪新增「付费 + 成本」双实验）**；在七层提问法里，**L4 之后新增 L4.5「盈利模型」与 L4.6「交付与合规」两层**（第七章）。

| **交付与运营** | ❌ 无 | 客服成本与承载上限、迭代节奏、稳定性/SLA、数据与隐私运营 | **上线即被客服和运维拖死（个人开发者头号死因）** |
| **法务·合规·税务·主体** | ❌ 无 | 主体选择、知识产权、开源许可、数据合规、内容合规、税务发票 | **做出产品但无法合法收费 / 被投诉下架 / 版权纠纷** |
| **B 端专属链路** | ❌ 无 | 决策链、预算科目、销售模式、采购流程、部署形态、安全合规门槛、续约 | **用 C 端的脑子做 B 端，最后发现"用户很喜欢但你签不下单"** |
| **个人开发者现实约束** | 🟡 弱：第 5 章"约束清单"提到时间/钱/技能/渠道 | 收款主体、时间预算的现实换算、支持能力上限、不可能三角 | **按大厂打法定计划，永远完不成** |

**一句话总结缺口**：现有框架把「**要不要做**」问到底了，但「**做出来之后靠什么活**」是空白。本文补的就是这一整层。

## 二、PM 还需要问的 22 个提问域（6 大模块）

> 使用方式：按 A→F 顺序过；**A/E 两个模块在动手写代码之前就必须有答案**（收不到钱、合不了规，后面全白干）；B/C/D 可以在 MVP 之后再补答案，但**不能晚于第一次收钱**。F 只在走 B 端路线时启用。

### 模块 A · 变现落地层（钱怎么进来）

#### A1 收款主体与通道

| 必答问题 | 追问 |
|---|---|
| 我以什么身份收钱？（自然人 / 个体工商户 / 有限公司 / 海外主体） | 有没有能力开对公账户？能不能开发票？ |
| 走哪个收款通道？（自有支付 / 第三方 Merchant of Record / 应用商店内购 / 线下转账） | 该通道**需要什么资质**、抽成多少、几天到账？ |
| 支付通道会不会因为我的品类被拒？（AI / 工具类 / 成人 / 金融相关） | 有没有备用通道？ |
| 收款通道与我的分发渠道是否绑定？（上架 App Store 必须用 IAP 吗？） | 平台 15%–30% 的抽成后，我的定价还成立吗？ |

> **死信号**：说不出「钱从哪个口子进来」；通道需要资质而我完全不具备。
> **好信号**：通道明确、费率已核算进定价、到账周期可接受。

**支付通道检查表（费率一律「需核实」，采集日 2026-10-08，使用时必须回官方页重核）**

| 通道类型 | 常见计费结构（参考区间·需核实） | 主要门槛 | 适合谁 |
|---|---|---|---|
| 国际卡收单（Stripe 类） | 约 2.9% + $0.30 / 笔 | 需可接收外币的主体；不代扣税 | 有海外主体或能接外币的开发者 |
| Merchant of Record（Paddle / Lemon Squeezy 类） | 约 5% + $0.50 / 笔 | 门槛低，**由平台代扣全球税** | **个人开发者首选**（省掉全球税务负担） |
| 应用商店内购 | 15% / 30%（小企业计划常见 15%） | 必须走平台 IAP；审核政策风险 | 纯 App 分发 |
| 国内聚合支付（微信 / 支付宝） | 约 0.6% / 笔 | **需商户资质**（个体户或公司） | 面向国内 C 端 / 小微 B 端 |
| 平台分成（市场 / 插件商店） | 视平台政策而定 | 依赖平台 | 插件 / 模板类 |
| 人工转账 / 对公汇款 | 0%（银行手续费另计） | 无法规模化，纯手工 | 早期 B 端验证 |

> ⚠️ **本表所有费率为行业公开常识的近似区间，未经官方页核实，禁止直接用于定价测算。** 正确做法：选定 1–2 个候选通道 → 打开其官方定价页 → 记录**采集日期 + 费率 + 是否有固定费 + 是否代扣税** → 写进成本模型。

#### A2 定价策略与结构

| 必答问题 | 追问 |
|---|---|
| 我用哪一种定价逻辑？（价值定价 / 竞品锚定 / 成本加成 / 损失规避） | 决定这个价，**用户能算清账吗**（"省我 10 小时/月"比"功能更强"好卖）？ |
| 是不是三档结构（够用 / 好用 / 全都要）？ | 中间那档是不是我真正想卖的？低价档是不是只为锚定？ |
| 计费单位选对了吗？（买断 / 订阅 / 按量 / 席位 / 混合） | 与**使用频次**匹配吗？（低频收订阅 = 必然流失） |
| 定价与**边际成本**的关系？ | 每多一个用户，我多花多少钱？定价能覆盖住吗？ |
| 要不要区域定价 / 学生价 / 年付折扣？ | 折扣会不会打穿价值感知？ |

> **死信号**：定价是"看着竞品随便定的"；客单价 < 单用户边际成本。
> **好信号**：能用一句话说清"为什么值这个价"，且价格 ≥ 边际成本 × 安全倍数。

#### A3 支付摩擦与税费

| 必答问题 | 追问 |
|---|---|
| 退款政策是什么？退款率预期多少？ | 有没有把退款率计入营收模型？ |
| 会不会遇到拒付（chargeback）？怎么处理？ | 拒付率过高的后果（通道封禁）知道吗？ |
| 要不要开发票？开票成本与人工成本谁承担？ | B 端客户**一定要发票**，这点常被 C 端出身的人忽略 |
| 跨境业务涉及哪几种税？（VAT / Sales Tax / 预提所得税） | 用 MoR 通道能不能把这块外包出去？ |

#### A4 ARPU 提升机制

| 必答问题 | 追问 |
|---|---|
| 怎么让老用户付更多？（席位扩容 / 用量阶梯 / 增值包 / 服务） | 有没有「越用越贵但越划得来」的结构？ |
| 有没有年付 / 多年付？ | 年付折扣换现金流，划算吗？ |
| 免费用户里有多少比例可能升级？ | 触发升级的那个"时刻"是什么？ |

> **C 端 vs B 端的关键差别**：C 端 ARPU 靠「**升级**」（个人版 → 专业版），B 端 ARPU 靠「**扩容 + 续约**」（5 席位 → 50 席位）。**C 端 ARPU 天花板明显低于 B 端，但 B 端的获客成本也高数倍。**

### 模块 B · 成本与现金流层（钱怎么花出去）

#### B1 全成本清单（必须逐条填数）

| 成本类别 | 具体项 | 性质 |
|---|---|---|
| **一次性投入** | 研发工时（折算机会成本）、设计、商标注册、软著登记、必要的设备 | 沉没 |
| **每月固定** | 服务器 / 云资源、域名、SSL、开发者证书（Apple ¥/年）、代码签名、第三方 API 月费、工具订阅（设计 / 监控 / 客服系统） | 固定 |
| **每单变动** | 支付手续费、模型调用费（AI 类**最大变量**）、带宽 / 存储、发票与税务成本、退款 | 变动 |
| **隐性（最常被漏）** | **客服与支持时间**、运维与故障处理、内容审核、合规维护、迭代维护、社区运营 | 隐性 |
| **时间的机会成本** | 我每周投 N 小时，若去做别的能挣多少 | 隐性（个人开发者的真实成本） |

> **纪律**：把「客服时间」按小时折算成钱写进去。个人开发者最常见的幻觉是"成本只有服务器那点钱"。

#### B2 盈亏平衡与回本周期

```
月毛利/单  = 客单价(月) − 单用户变动成本
盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单
回本周期(单用户)  = 单用户获取成本 ÷ 月毛利/单      ← 必须 < 12 个月，越短越好
```

| 必答问题 | 追问 |
|---|---|
| 我每月固定成本是多少？（写数字） | 有多少是"不赚钱也得付"的？ |
| 单用户月毛利是多少？ | 涨价 20% 或降本 20%，哪个更容易？ |
| 要多少付费用户才能不亏？ | 这个数，**按我的渠道能力，多久能到**？ |
| 多久能回本？ | 如果 24 个月才能回本，我撑得住吗？ |

> **个人开发者专用换算**：买断 ¥99 的产品，要覆盖每月 ¥500 的固定成本，**每月需卖出约 5 单以上**（未计手续费与退款，需自行代入实际费率）。先算这个数，再去想"怎么卖到 5 单"——比先想"做什么功能"重要得多。

#### B3 边际成本可控性（AI 类方向的头号杀手）

| 必答问题 | 追问 |
|---|---|
| 每多一个用户，我多花多少钱？ | 是**近似 0**（纯本地工具）还是**线性增长**（云端 / 模型调用）？ |
| 重度用户会不会把我的成本拖爆？ | 有没有用量上限 / 阶梯价 / 降级策略？ |
| 模型 / API 供应商涨价 30%，我还赚钱吗？ | 有没有可替换方案？ |
| 缓存 / 本地推理能不能降本？ | 降本后体验损失多少？ |

> **新增一票否决**：**边际成本 ≥ 定价的方向，直接杀**（或必须重做定价结构）。这是 AI 时代个人开发者最常踩的坑：免费用户把 API 额度吃光。

### 模块 C · 获客与留存层（人怎么进来）

#### C1 增长引擎与渠道选择

| 引擎类型 | 适用 | 特征 | 适合个人开发者？ |
|---|---|---|---|
| **内容 / SEO**（教程、对比评测、开源引流） | C 端工具、开发者工具 | 慢但复利，成本=时间 | ✅ 最匹配 |
| **社区运营**（垂直论坛、群、Discord） | 细分人群 | 深度但天花板低 | ✅ 匹配 |
| **应用商店 ASO / 榜单** | 移动端 / 插件市场 | 有平台红利也有政策风险 | ⚪ 可做，被动 |
| **产品自传播（PLG）** | 有分享/协作属性的产品 | 需要产品内嵌传播机制 | ✅ 若能设计 |
| **付费投放** | C 端规模化 | 需要预算 + 转化数据 | ❌ 个人慎入（除非 ROAS 已实测为正） |
| **KOL / 测评** | 消费级工具 | 一次性峰值，衰减快 | ⚪ 可小试 |
| **B 端销售（SLG）** | 企业客户 | 客单价高、周期长、需人力 | ❌ 一人公司极难 |

> **判定口径**：`我能不能在 2 周内、零预算、让 20 个目标用户开口说话？` 答不出 → 现有框架已判定为**一票否决**（分发不可得）。本模块只是把它**展开成渠道选择与执行路径**。

#### C2 首个 100 / 1000 用户的具体路径

| 必答问题 | 追问 |
|---|---|
| 前 100 个用户，**具体从哪来**？（指名到社群/名单/关键词） | 我能说出 3 个具体的群名或版块吗？ |
| 从 100 到 1000，靠什么机制放大？ | 是内容复利、口碑推荐，还是渠道投放？ |
| 获客成本（CAC）怎么实测？ | 有没有做过一次真实的获客动作（哪怕是发一个帖子）来测？ |
| 转化漏斗每一层的数字？ | 曝光 → 访问 → 试用 → 付费，哪一层最漏？ |

#### C3 激活与留存

| 必答问题 | 追问 |
|---|---|
| 用户第一次用，多久能感受到价值？（Aha moment 是什么） | 能不能压缩到 3 分钟内？ |
| 留存曲线长什么样？（次日 / 7 日 / 30 日） | 是"微笑曲线"（回升）还是持续下滑（= 没有真实价值）？ |
| 月流失率（churn）多少？ | 年付客户的续费率比月付高多少？ |
| 什么行为与留存强相关？ | 能不能主动把用户推向那个行为？ |

> **死信号**：只谈下载量 / 注册量，从不谈留存。**下载量是虚荣指标，留存才是命。**
> **审计口径**：留存必须按**自然日 / 自然周分群**看，不能只看总体平均（会被新增用户稀释）。

### 模块 D · 交付与运营层（怎么让它活下去）

#### D1 支持成本与承载能力

| 必答问题 | 追问 |
|---|---|
| 每天/每周大概多少支持请求？ | 一人能不能扛住？扛不住的临界点是多少用户？ |
| 支持渠道有哪些？（邮件 / 群 / 工单） | 有没有把常见问题做成文档来自助化？ |
| 有没有 SLA 承诺？ | 承诺了做不到，会不会引发差评/退款？ |

> **个人开发者的头号杀手不是竞品，是客服。** 200 个付费用户如果每人每月问一次，就是 10 次/工作日——这是一个人的全部业余时间。

#### D2 迭代节奏与稳定性

| 必答问题 | 追问 |
|---|---|
| 产品会退化吗？（依赖的 OS / API / 平台政策会变） | 每年要花多少时间做"维护性开发"而不是新功能？ |
| 出故障了怎么办？ | 有没有监控、备份、回滚方案？ |
| 版本节奏定多快？ | 一个人做得过来吗？ |

#### D3 数据与隐私运营

| 必答问题 | 追问 |
|---|---|
| 我收集哪些用户数据？ | 每一项都有必要性吗（最小必要原则）？ |
| 隐私政策、用户协议写了吗？ | 能不能通过应用商店审核？ |
| 遥测 / 崩溃上报怎么配？ | 能不能关掉？合规吗？ |
| 用户数据存在哪？出境吗？ | 出境要额外做什么合规动作？ |

### 模块 E · 法务·合规·税务·主体层（必须合法）

#### E1 主体与知识产权

| 必答问题 | 追问 |
|---|---|
| 用什么主体运营？ | 自然人（无法开票/难以收外币） / 个体户（低成本合规） / 有限公司（能开票、能签 B 端合同、可开对公户） |
| 软著登记要不要做？ | 上架国内应用商店、走政府/企业采购常需要 |
| 商标注册了吗？ | 名字被抢注怎么办？（先查再定名） |
| 代码版权归属清晰吗？ | ⚠️ **在职开发的作品可能属于职务作品**，需确认劳动合同约定 |
| 有没有竞业限制风险？ | 做的东西与原公司业务重合吗？ |

#### E2 开源与第三方授权合规

| 必答问题 | 追问 |
|---|---|
| 我用了哪些开源库？各自许可证是什么？ | GPL/AGPL 有**传染性**，会不会要求我开源整个产品？ |
| 商用是否被许可？ | 有些库（或字体、图标、素材）明确禁止商用 |
| 模型 / API 的 ToS 允许我把它包装成产品卖吗？ | 很多模型服务条款禁止"以本服务为卖点转售" |
| 有没有用到他人的素材（图片、音效、字体）？ | 授权范围覆盖我的使用方式吗？ |

#### E3 数据与内容合规

| 必答问题 | 追问 |
|---|---|
| 涉及个人信息处理吗？ | 需不需要隐私政策、单独同意、个人信息处理者告知？ |
| 面向境外用户吗？ | GDPR / CCPA 等适用吗？ |
| 有 AI 生成内容吗？ | 国内可能涉及**生成式 AI 服务备案 / 算法备案 / 深度合成标识**（需按最新规定核查） |
| 有 UGC 吗？ | 内容审核义务与成本能承担吗？ |
| 有未成年人用户吗？ | 触碰这块直接提高合规门槛 |

#### E4 税务与发票

| 必答问题 | 追问 |
|---|---|
| 收入怎么申报？ | 经营所得 / 劳务报酬口径不同（**须咨询专业人士，本文不给税务结论**） |
| 能不能开发票？ | B 端客户没发票不付款 |
| 跨境收入怎么处理？ | 用 MoR 通道能否代扣代缴？ |
| 有没有税负优化的合法路径？ | 只走合法路径，不碰灰色 |

#### E5 平台政策风险

| 必答问题 | 追问 |
|---|---|
| 我依赖哪些平台？（商店 / 云 / 模型 / 支付） | 任一个改政策，我会怎样？ |
| 有没有被封号 / 被下架的历史先例？ | 有没有申诉通道与备用方案？ |
| 平台自己要做了怎么办？ | 这是现有框架 L6「系统内置威胁」的延伸 |

### 模块 F · B 端专属层（只在走企业路线时启用）

#### F1 决策链与预算科目

| 必答问题 | 追问 |
|---|---|
| **使用者 / 影响者 / 决策者 / 付款者 / 合规**分别是谁？ | 是同一人吗？不是的话，我要说服几个角色？ |
| 这笔钱从哪个**预算科目**出？ | 有科目 = 有钱；没科目 = 要创造新预算（极难） |
| 采购流程是什么？ | 谁发起、谁审批、要不要走招标/比价？ |
| 会不会被 IT / 安全 / 法务一票否决？ | 我的产品能过安全审查吗？ |

> **B 端第一性原理**：**「使用者喜欢」和「能签单」是两件事。** 现有框架的 L2 只提到"使用者与决策者常不同"，本模块把它展开成完整的决策地图。

#### F2 销售模式与采购流程

| 模式 | 特征 | 个人开发者可行性 |
|---|---|---|
| 自助式（PLG + Self-serve） | 客户自己注册付费，无需销售 | ✅ **个人唯一可行路径** |
| 轻销售（Inside Sales） | 线上沟通、远程演示 | ⚪ 一人勉强可做，但极耗时间 |
| 现场销售（Field Sales） | 上门、招投标 | ❌ 需要团队 |
| 渠道 / 代理 | 靠伙伴卖 | ⚪ 需先有产品与伙伴网络 |
| 政府采购 / 集采 | 招标、资质、账期 | ❌ 个人基本无缘（无资质、账期长） |

#### F3 部署形态与安全合规门槛

| 必答问题 | 追问 |
|---|---|
| 交付形态选哪种？（公有 SaaS / 私有化 / 混合 / 内网离线） | 私有化的实施与运维成本是一个人扛得住的吗？ |
| 客户要求哪些合规资质？（等保 / 信息安全认证 / 信创适配） | 这些认证的**时间和费用**我承担得起吗？ |
| 数据能不能出客户内网？ | 不能 → 架构要重做 |

#### F4 客单价 · 销售成本 · 续约

| 必答问题 | 追问 |
|---|---|
| 年客单价多少？ | 目标客户愿付的价位在哪（对标他们的**人力成本**最有效） |
| 获取一个客户的成本（CAC）多少？周期多长？ | 是 1 周签单还是 6 个月？ |
| 一年后有多少客户续费？（续费率） | **净收入留存（NRR）= 续费 + 扩容 − 流失**，>100% 才是好生意 |
| 账期多久？ | 3 个月账期 + 一人公司 = 现金流断裂风险 |
| 会不会被客户自研替代？ | 客户 IT 说"我们自己做一个"是最大威胁 |

| # | 问题 | 答不出来的后果 |

| 6 | 前 100 个用户具体从哪来（指名到社群/名单）？ | 分发不可得 = 一票否决 |

| 12 | **（B端专用）** 使用者/决策者/付款者是谁？钱从哪个科目出？ | **用户喜欢但签不下单** |

### 2.4 新增一票否决项（4 条，触发即杀）

> 与现有框架的 5 条一票否决（分发不可得 / 一次性且无持续成本 / 单一平台依赖 / 触碰合规红线 / 答不出"去掉 AI 还剩什么"）并列使用。

| # | 否决项 | 为什么不可救 |
|---|---|---|
| 1 | **收款路径不成立** —— 通道需要我不具备的资质，或品类被通道明令禁止 | 产品再好也无法变现 |
| 2 | **边际成本 ≥ 定价** —— 每多一个用户就多亏一份钱 | 规模越大死得越快，商业模式本身不成立 |
| 3 | **客服/合规成本超出个人承载上限** —— 单用户需要人工介入，或触发的合规义务需要专职人力 | 收入增长会被成本同比吃掉 |
| 4 | **B 端方向要求我方不具备的资质或现场交付能力**（招投标资质、等保、私有化实施） | 个人开发者结构性做不到，不是努力问题 |

## 三、C 端方向分析框架（12 维）

> **C 端的第一性原理**：卖给**个人**，卖的是「**省时间 / 省钱 / 爽 / 身份感**」。决策链短（一个人就能决定），但**付费意愿弱、流失快、获客贵**。C 端的瓶颈几乎永远在**分发**。

| # | 维度 | 必答问题 | 死信号 |
|---|---|---|---|
| 1 | **人群与可触达规模** | 具体是谁？我能触达多少？ | 只说"办公族""年轻人" |
| 2 | **频次与场景** | 日/周/月/一次性？什么时刻想起它？ | 一次性需求还想收订阅 |
| 3 | **替代方案** | 系统内置 / 免费开源 / 手工 / **不做**，谁最危险？ | 系统已内置且够用 |
| 4 | **心理价位** | 用户觉得这事值多少钱？对标什么？（一杯咖啡 / 一个钟点工时薪） | 高于"冲动消费线"且无试用 |
| 5 | **定价与计费** | 买断 / 订阅 / 按量？和频次匹配吗？ | 低频硬收订阅 |
| 6 | **付费墙位置** | 功能墙 / 用量墙 / 时间墙 / 体验墙？ | 免费版够用 → 无人付费 |
| 7 | **转化漏斗** | 曝光→下载→激活→付费→复购，各层数字 | 只统计下载量 |
| 8 | **获客渠道与 CAC** | 具体渠道？CAC 实测多少？ | 只会说"靠口碑" |
| 9 | **留存与 churn** | 分群留存曲线？月流失率？ | 留存曲线持续下滑 |
| 10 | **边际成本** | 每用户成本？重度用户会不会拖爆？ | 云端 AI 无用量限制 |
| 11 | **成本结构与生存线** | 月固定成本？盈亏平衡用户数？ | 算不出 |
| 12 | **风险** | 系统内置 / 大厂免费版 / 商店政策 / 差评 | 未回答"它会被什么吃掉" |

**C 端盈利模型（可直接套）**

```
年营收 = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利 = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本
```

> **C 端最容易被忽略的一条**：**客单价的选择决定了你的分发难度。** ¥9 的产品需要海量分发才能养活自己；¥299 的产品只需少量高意向用户。个人开发者应**优先选高客单价 + 小规模高意向人群**，而不是"低价 + 大流量"。

## 四、B 端方向分析框架（12 维）

> **B 端的第一性原理**：卖给**组织**，卖的是「**降本、不出事、可交代、可审计**」。决策链长、周期长、客单价高、续约复购好，但**获客成本与交付成本极高**。B 端的瓶颈几乎永远在**决策链与销售人力**。

| # | 维度 | 必答问题 | 死信号 |
|---|---|---|---|
| 1 | **目标行业与企业数** | 哪个行业？多少家？每家多少席位？ | 只说"所有企业" |
| 2 | **决策链** | 使用者/影响者/决策者/付款者/合规分别是谁？ | 见不到决策者 |
| 3 | **预算科目** | 钱从哪个科目出？是存量预算还是新增？ | 需要创造新预算 = 极难 |
| 4 | **痛点类型** | 是"降本增效"还是"合规/风险规避"？ | 只省一点时间 = 优先级最低 |
| 5 | **替代方案** | 自研 / 外包 / Excel / 不做，哪个最危险？ | 客户 IT 说"我们自己做一个" |
| 6 | **销售模式** | 自助 / 轻销售 / 现场 / 渠道？ | 需要现场交付却只有一个人 |
| 7 | **采购流程与周期** | 谁审批？要不要比价/招标？多久签单？ | 要走招标 |
| 8 | **客单价与合同结构** | 年单价？席位还是用量？ | 单价低于销售成本 |
| 9 | **交付与实施成本** | 要不要实施/培训/对接？ | 每个客户都要定制 |
| 10 | **安全与合规门槛** | 需要什么认证/资质？（等保、信创、私有化） | 门槛需要团队与预算 |
| 11 | **续约与 NRR** | 续费率？扩容空间？ | 用完就走，无扩容 |
| 12 | **现金流** | 账期多久？坏账风险？ | 3 个月以上账期 + 一人公司 |

**B 端盈利模型（可直接套）**

```
年营收 = 新签客户数 × 年客单价 + 存量客户 × 年客单价 × 续费率 + 扩容收入
年毛利 = 年营收 − (销售人力 + 实施交付 + 支持服务 + 云成本)
可行条件 = 年毛利 > 固定成本，且 单客户 CAC 回收周期 < 12 个月
```

> **B 端最容易被忽略的一条**：**B 端买的是"不会出错"，不是"更爽"。** 所以 B 端的价值主张里，**承诺（SLA / 数据安全 / 合规 / 可审计日志）比功能清单更重要**。用 C 端的思路（做酷炫功能、拼用户体验）做 B 端，会做出"用户很喜欢但没人签单"的产品。

## 五、C 端 × B 端 对比矩阵

| 维度 | C 端 | B 端 |
|---|---|---|
| **购买主体** | 个人 | 组织 |
| **决策链** | 1 人（自己） | 5 类角色（使用者/影响者/决策者/付款者/合规） |
| **决策周期** | 分钟–天 | 周–半年 |
| **核心买点** | 省时间 / 爽 / 身份感 | 降本 / 不出事 / 可交代 / 可审计 |
| **客单价** | 低（¥9–¥999/年） | 高（¥千–¥百万/年） |
| **计费单位** | 买断 / 订阅 / 按次 | 席位 / 年框 / 用量 + 服务 |
| **付费墙** | 功能墙 / 体验墙为主 | 用量墙 / 功能墙 + 服务 |
| **获客方式** | 内容 / 社区 / ASO / 投放 | 销售 / 渠道 / 招投标 / 生态 |
| **CAC** | 低（¥几–¥几百） | 高（¥几千–¥几万） |
| **销售人力** | 几乎不需 | 必需（除自助型小微 B） |
| **增长瓶颈** | **分发** | **决策链 + 销售人力** |
| **留存/续费** | 靠习惯与价值，churn 高 | 靠切换成本与合同，NRR 可 >100% |
| **交付成本** | 近 0（自助） | 高（实施/培训/对接） |
| **合规门槛** | 较低（隐私、内容） | 高（等保/信创/私有化/审计） |
| **失败主因** | 无人知道 / 免费替代够用 | 用户喜欢但签不下单 / 交付拖垮 |
| **个人开发者可行性** | ✅ 主战场 | ⚠️ **仅"自助型小微 B"可行**；重 B 不可行 |
| **典型形态** | mini-tool / 插件 / 小 SaaS | 行业 SaaS / 工具 + 服务 / 私有化 |

> **一句话选路**：**C 端拼分发，B 端拼信任。** 个人开发者的天然优势在 C 端（无需销售团队）与技术型小微 B（无需现场交付）；天然劣势在需要人力与资质的一切环节。

## 六、个人开发者专项分析

> 这一节的立场是**唱反调**：个人开发者最容易犯的错，是**用"公司产品"的标准去评估"一个人的生意"**——于是永远在选择"市场最大"的方向，而不是"我这条命能跑通"的方向。

### 6.1 四道闸门（顺序否决，不可跳）

> 顺序不可颠倒。**前两道闸门不过，后面的分析全部作废**——这正是现有框架缺失的部分。

| 闸门 | 问题 | 不过则 |
|---|---|---|
| **闸门 1 · 收得到钱** | 我有合法主体与通道吗？品类被通道接受吗？ | 项目不成立，换方向（**不是努力问题，是结构问题**） |
| **闸门 2 · 扛得住成本** | 客服/运维/合规的隐性成本，我一个人的时间承受得住吗？ | 缩形态（自助化 / 降低支持面）或换方向 |
| **闸门 3 · 送得到人** | 前 100 个用户我能零预算触达吗？ | 现有框架已判一票否决 |
| **闸门 4 · 算得过账** | 盈亏平衡用户数 × 我的渠道能力，可达吗？ | 调客单价 / 调成本结构；不可调则杀 |

### 6.2 个人开发者的"时间预算"现实换算

| 现实 | 含义 |
|---|---|
| 每周可投入时间 ≈ 8–15 小时（在职副业） | 每月 ≈ 35–65 小时 |
| 一个可用 MVP 通常需要数月 | 意味着**必须选"最小形态"**（单点工具 > 套件 > 平台） |
| 上线后维护 / 客服 / 运营会吃掉 30%–50% 的可用时间 | 实际能用于"做新功能"的时间只剩一半 |
| 因此：**能做的产品数量 ≈ 1 个**（同时维护 2 个以上会全部做不好） | 选方向时必须一次选对，且必须能长期做（现有框架 §8.4 第 5 问已提到） |

> **结论**：个人开发者的约束不是"想不出好点子"，而是**每年只能认真做一件事**。所以「选错方向的机会成本」远高于「做得慢」。

### 6.3 个人开发者的不可能三角

> **同一时间只能占两角，第三角必然放弃：**

```
        高频迭代（快）
           /    \
          /      \
  深度销售 ────── 大规模投放
```

| 选择 | 意味着 | 适合的产品 |
|---|---|---|
| 高频迭代 + 大规模投放 | 需要全职 + 预算，**个人基本不可得** | — |
| 高频迭代 + 深度销售 | 需要销售时间，**产品做好但没人买** | 高客单价小 B |
| 深度销售 + 大规模投放 | 需要人力与预算 | — |
| **高频迭代 + 社区分发（放弃投放）** | ✅ **个人最优解** | C 端工具、开发者工具 |

### 6.4 个人开发者适合 / 不适合的形态

| 适合（起点） | 原因 | 不适合 | 原因 |
|---|---|---|---|
| **单点高频 mini-tool（买断）** | 卖点单一、支持面窄、边际成本≈0 | 需要现场实施的重行业 SaaS | 交付成本 = 团队级 |
| **浏览器插件 / 编辑器插件** | 自带分发渠道（商店），入口天然高频 | 需要资质的领域（金融/医疗/教育） | 牌照门槛 |
| **模板 / 预设 / 素材包** | 零边际成本、可买断 | 需要内容审核的 UGC 平台 | 审核成本与合规义务 |
| **轻量 SaaS（自助型）** | 无销售人力 | 依赖大规模 GPU 训练的方向 | 资本门槛 |
| **开发者工具 / API / 库** | 开发者是付费意愿最高、最不需要教育的人群 | 需要 7×24 SLA 的基础设施类 | 稳定性承诺个人扛不住 |
| **垂直小人群工具** | 竞品盲区、大厂看不上 | 通用大而全平台 | 冷启动几乎必败 |

### 6.5 个人开发者的合规底线清单（动手前先过）

- [ ] 主体：明确用什么身份收款；能不能开票（有 B 端客户就必须解决）
- [ ] 通道：确认通道接受我的品类、费率、到账周期
- [ ] 知识产权：产品名先查商标；软著按需登记；**确认在职作品归属与竞业限制**
- [ ] 开源许可：列出所有依赖及其许可证，排除 GPL/AGPL 传染风险与"禁商用"素材
- [ ] 模型/API ToS：确认允许我包装成产品对外售卖
- [ ] 数据合规：隐私政策、用户协议、最小必要采集；跨境数据传输
- [ ] 内容合规：AI 生成内容标识 / 备案（按最新规定核查）；UGC 审核能力
- [ ] 税务：合法申报口径（**咨询专业人士，本文不给结论**）

### 6.6 个人开发者的退出信号（什么时候该停）

| 信号 | 含义 |
|---|---|
| 上线 3 个月，付费用户 < 5 且无增长 | 不是分发问题，就是价值问题 → 复盘后停或换 |
| 客服时间 > 开发时间 | 形态错了（支持面太宽），不是努力不够 |
| 每月净收入 < 服务器成本 × 3 持续 6 个月 | 商业模型不成立 |
| 依赖的单一平台改政策导致分发腰斩 | 平台风险已实现，需重建渠道 |
| 自己已经不想做这件事了 | 现有框架 §8.4 第 5 问的答案变了 → 诚实退出 |

### 6.7 个人开发者高频反模式（对照自查）

| 反模式 | 为什么错 | 替代做法 |
|---|---|---|
| 把"开源 + 赞助"当商业模式 | 赞助收入极不稳定，且与"付费买断"互相掐死付费意愿 | 开源社区版 + 商业版双轨，或纯商业闭源 |
| 认为"上架就有人买" | 商店是渠道不是分发；无推广 = 零曝光 | 上架前先攒 100 个种子用户 |
| 用"功能多"当卖点 | 功能是成本；一个人维护不动 | 单点做到最好 |
| 拿"AI"当卖点 | 用户不为技术付钱，为结果付钱；模型能力下放会抹平 | 卖可感知的结果（快 N 倍 / 少做 N 步） |
| 定价过低求销量 | 低价需要海量分发，恰好是个人最缺的 | 提高客单价，缩小目标人群 |
| 免费额度给太大 | 边际成本失控 + 免费用户永不变现 | 免费版限功能，付费版限用量 |
| 同时开两个项目 | 时间切片导致两个都做不好 | 一次只做一个 |
| 只算服务器成本 | 漏掉客服、运维、机会成本 | 全成本清单逐条填数 |
| 先做产品再想收款 | 可能做了个收不到钱的东西 | **闸门 1 前置** |

## 七、把新提问域接进现有流水线（SOP 补丁）

### 7.1 补丁 1 · 五段式流水线

| 阶段 | 原动作 | 新增动作 |
|---|---|---|
| ① 定约束 | 时间/钱/技能/渠道/红线 | **+ 主体与收款通道、可承受的支持量上限** |
| ② 采信号 | 9 类信号源 | **+ 信号源 ⑩：竞品的定价页与付费墙结构**（看别人怎么收钱） |
| ③ 快筛 | 三问 + 九维打分卡 + 5 条一票否决 | **+ 本文 2.4 的 4 条新增否决项**；打分卡**新增 3 维**（↓↓） |
| ④ 证伪 | 付费/行为实验 | **+ 双实验：付费实验 × 成本实验**（真的交付一次，记录真实耗时与真实成本） |
| ⑤ 立项 | 最小可做形态 | **+ 盈利模型与生存线测算（B2 公式）+ 合规底线清单（6.5）** |

**打分卡新增 3 维（建议权重）**

| 新增维度 | 权重 | 5 分锚点 | 1 分锚点 |
|---|---|---|---|
| **收款可行性** | ×3 | 通道明确、资质具备、费率可接受 | 无合法收款路径 |
| **隐性成本可控性** | ×3 | 可完全自助，边际成本≈0 | 每单需人工介入 |
| **客体匹配度**（C/B 与我方能力） | ×2 | 形态与我的时间/资质完全匹配 | 需要团队或资质 |

> 新增后满分 = (3+3+3+2+2+2+2+1+1+3+3+2) × 5 = 135。**阈值比例不变**（≥70% 进证伪，≤50% 杀）。

## 附 · 口径说明与缺口声明

**口径说明**

- 本文全部内容为**方法框架与判定标准**，不含任何市场规模、用户量、营收等外部量化数据。
- 第二章 A1 支付费率表、以及各处出现的比例（15%/30% 抽成、0.6% 聚合支付、LTV:CAC > 3、回本周期 < 12 个月等）均为**行业常见区间或经验值**，**采集日 2026-10-08，未经官方页核实**。使用时必须回到对应官方页面重新确认，并记录采集日期与币种。**本文不对这些数值的准确性负责。**
- 第四章 B 端合规门槛（等保 / 信创 / 算法备案 / 生成式 AI 备案等）涉及**动态变化的法律法规**，本文只列"要知道有这件事"，**不提供合规结论**，具体须咨询专业人士并查最新规定。
- 本文提及的税务内容仅用于提示"这是一个必须提前确认的问题"，**不构成税务建议**。

**缺口声明**

- 【未实测】个人开发者的真实时间分配比例（"维护/客服吃掉 30%–50%"）为经验估计，未做样本量化的实测统计。建议自行记录 1 个月真实工时分布后修正。
- 【未实测】"200 个付费用户 → 每工作日约 10 次支持请求"为量级推演示例，非实测数据。
- 【未取得】各支付通道的**当期**费率与资质要求未逐一核对官方页；本文给出的仅为结构与量级，不可直接引用。
- 【推断】C 端与 B 端的对比矩阵为归纳产物，真实业务常出现混合形态（如自助型小 B 兼具两者特征）。矩阵用途是提示"该测什么"，不是分类学。
- 【未取得】本文未覆盖：融资与股权结构、并购与退出、多产品矩阵运营、团队组建与股权激励——这些超出"个人开发者做出可盈利产品"的范围，如需可另立文档。
