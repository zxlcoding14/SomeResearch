## 〇、结论先行（TL;DR）

**有半成品的端到端流水线，但没有一个覆盖「Windows 原生客户端黑盒复刻」。缺的不是零件，是编排层。**

| 判断 | 内容 |
|---|---|
| **端到端成品** | 只有 2 套。① **Replica**（11 个 skill 串联 recon→deploy，MIT，开源）② **app-replication-rebuild**（TRAE 社区个人作品，PDCA 五阶段） |
| **Replica 的硬缺口** | 面向 **Web / iOS / Android App**。侦察靠「公开页面 + 应用商店截图 + 你自己账号」，**不做二进制分析、不提取控件树、不覆盖 Win32/WPF/Qt 客户端**；测试环节是 Playwright（Web 向） |
| **app-replication-rebuild 的硬缺口** | 前提是**你已有项目路径**（源码级重构），不是黑盒复刻；个人参赛作品，无公开仓库、无版本维护、单文件 skill，工程可靠性不可托付 |
| **真正的空白** | 「Windows 原生客户端」这条线，**侦察 / UI 规格 / 需求 / 技术方案 / 测试验收** 五段没有串起来的成品；但**每一段都有成熟件**（见第三、四节），拼装成本低 |
| **最值钱的两个发现** | ① **screenpilot**（Gitee，Python）——专做 Windows 桌面应用的 design token + 组件目录 + 页面蓝图提取，正好补 Replica 的 Windows 侧缺口；② **qa-tester**（openclaw/skills）——测试金字塔 + 发布门禁 + 禁止编造结果的 QA 规范 skill |
| **可落地性** | **「Replica 骨架 + Windows 侦察件 + QA 规范件」三件套拼装**是当前最优解，但要自建编排层与 Windows 专属规范。工作量集中在「侦察→UI 规格→需求」这三段 |
| **红线** | Replica 用代码强制 clean-room（`sweep.py` 扫原版名称/域名/颜色，`deploy` 前拒绝上线）。逆向教程一致声明「仅限学习/研究/合法授权」。**复刻功能可行，复刻资产（代码/Logo/文案/商标/私有接口）违规** |

## 一、外部方案全景（按形态分三类）

### A 类 · 端到端复刻流水线

| 方案 | 形态 | 许可/成熟度 | 覆盖流程 | 关键事实 |
|---|---|---|---|---|
| **Replica**（`Jakeschincariol/replica-skill`） | 11 个 Claude skill + 6 个纯标准库 Python 工具 | MIT · 2026-10-03 发布，首日约 119 星，一周口径约 1900 星（口径冲突见附 A） | recon → architect → design → build → backend → test → diff → entrepreneur → brand → launch → deploy | 技能间靠 `replica/` 目录传递产物；`parity.py` 加权评分（must=3/should=2/could=1，半成品算一半，缺 must-have 直接判"不可发布"）；`imgdiff.py` 用**边缘图**比对布局，避免换色影响分数；`reviews.py` 只保留带链接的原始引语，不编评论 |

### B 类 · 逆向 / 侦察层（补黑盒能力）

| 方案 | 形态 | 覆盖 | 备注 |
|---|---|---|---|
| **haikow/claude-reverse-skills** | 5 个 Claude Code skill + IDA MCP | 通用逆向方法论（混淆/壳/字节码/反调试/固件）、`ida-reverse`（IDA Pro/idalib）、`apk-reverse`（APK 全流程+Frida）、`radare2`、前端 JS 逆向 | 跨平台含 Windows；**落点是"看懂"不是"复刻交付"**，无 UI 还原/需求/测试环节 |
| **screenpilot**（Gitee `leomen/screenpilot`） | Python 工具 + MCP server | **Windows 桌面应用设计智能提取**：design tokens（色/字/间距/阴影/圆角/透明度）+ 组件目录（含 default/hover/focus/disabled 变体）+ 页面蓝图（布局分区/组件树/弹窗/右键菜单/无障碍）+ `design.md`/`design-tokens.json` | 支持 **WPF / Qt / Electron / WebView2 / Tauri / Flutter / Java Swing**；三级分析深度；UIA 树 + WebView DOM（CDP）+ 截图像素兜底三条采集路径；**这是 Windows 侧 recon/design 的最强现成件** |

## 三、Windows 客户端专属缺口（为什么不能直接套 Replica）

| 环节 | Replica 的做法 | Windows 原生客户端的实际需求 | 差距性质 |
|---|---|---|---|
| 侦察 | 读公开帮助文档、定价页、商店截图、你自己的账号 | 需要 **Spy++ 拿类名/控件 ID、Inspect 拿 UIA 树、抓 `WM_COMMAND` 消息流、Resource Hacker 提资源、ProcMon 看文件/注册表行为** | 方法论级差异：从"读网页"变成"读进程" |
| UI 规格 | 从截图量 token | 需要 **控件树 + 布局参数反推**（Qt 可借 `QHBoxLayout` 等布局规则反推间距；WPF 走 UIA；自绘 UI 只能靠像素兜底） | 有现成件（screenpilot / servo），但**未与复刻流程串接** |
| 技术方案 | Next.js + Postgres + Stripe（Web 预设） | Win32/WPF/Qt/Electron/Tauri 选型、安装包与签名、注册表与文件系统行为、多语言资源、权限与 UAC | 完全重写 |
| 测试 | Playwright e2e | WinAppDriver / pywinauto / FlaUI / WinApp MCP；**控件定位稳定性**（HWND > UIA id > 图像 > 坐标）是核心难题 | 工具链全换 |
| 验收 | 网页截图 diff | 需处理 DPI 缩放、主题（浅/深）、窗口尺寸、自绘控件、动画帧 | 需补 DPI/主题矩阵 |
| 合规 | clean-room + 商标清扫 | **额外**：破解/绕过授权（如去广告、解锁付费）在多辖区涉法律风险；EULA 明确禁止逆向时要单独评估 | 风险更高，需单独一节红线 |

**一句话**：Replica 的**流程骨架可复用**（阶段划分、产物传递、评分/门禁机制），**平台实现层必须重写**。

## 四、拼装路线（三条，按投入递增）

### 路线 1｜直接用（1 天内可跑通，验证可行性）

```
Replica（11 skill）作为流程骨架
  + screenpilot（Windows UI 规格提取，替换 replica-design 的输入）
  + winguictl 或 cua_desktop_operator（替换 replica-test 的执行层）
  + qa-tester（替换/加强 test 规范）
```
- **适合**：先跑一个**小目标**（单一核心流程）验证这套东西对自己的项目是否真有用
- **风险**：Replica 的 recon 对 Windows 客户端会「问不出东西」——它不会自己开 Spy++。需要人工喂侦察产物
- **建议**：`/replica-entrepreneur` 单独先跑（读差评判断该不该做），成本最低、信息量最大

### 路线 2｜半拼装（1–2 周，推荐）

自建 3 个 skill，其余借用：
1. `win-recon`：编排 Spy++/Inspect/screenpilot/ProcMon，产出**控件地图 + 设计令牌 + 行为清单**（对应 Replica 的 `recon.md` 格式，保持下游兼容）
2. `win-test-spec`：以 qa-tester 为规范底座，补 Windows 专属章节（DPI/主题矩阵、控件定位优先级、自绘控件兜底策略）
3. `win-parity`：以 WinApp MCP 的 pixel-diff + Replica 的 `parity.py` 加权逻辑为内核，补 DPI/主题归一化
- 其余（architect/build/backend/brand/launch/deploy）继续用 Replica，只替换其中的平台预设
- **成本集中在**：控件定位稳定性调试（自绘 UI 是主要坑）、DPI/主题归一化

### 路线 3｜全自建（不建议现在做）

统一编排 + 全环节自研。**不建议**：Replica 的评分/门禁机制（`parity.py` 加权、`imgdiff.py` 边缘图、`sweep.py` 清扫）已成体系且经社区验证，重造是浪费。

**取舍建议**：先做路线 1 的小目标验证。**如果目标客户端的 UI 是自绘的（如很多国产工具、游戏化界面），路线 2 的 UI 段成本会显著上升**，此时应优先评估"是否只复刻功能不复刻像素"。

## 五、法律与合规红线（复刻类项目必读）

| 维度 | 高风险场景 | 控制措施 |
|---|---|---|
| 代码版权 | 直接使用 GPL 代码 / 反编译后照搬 | clean-room 重写；开源组件走 MIT/Apache；保留依赖许可清单 |
| 授权绕过 | 破解去广告、解锁付费功能、伪造授权校验 | **这是复刻与侵权之间的分水岭**；EULA 禁止逆向时单独法律评估 |
| 商标与视觉 | 沿用原名/图标/配色/文案 | Replica `sweep.py` 式清扫（连 `OriginalAppEmbed` 这类标识符也要扫）；上线前 legal check |
| 私有接口 | 复用对方私有 API / 扒 JS bundle 取 endpoint | 只读公开页面与自己的账号；接口一律重新实现 |
| 数据 | 搬运对方用户数据/内容库 | 完全自建数据 |

**Replica 的 enforce 机制值得抄**：`replica-deploy` 设 9 项 preflight，其中「rebrand sweep 干净」不通过就拒绝上线。**规范要能被工具强制执行，否则等于没有。**

## 六、缺口声明（外部方案本身的缺口）

| 缺口 | 说明 | 可能的补齐路径 |
|---|---|---|
| 无 Windows 专属端到端 skill | 未搜索到任何把「Windows 客户端侦察→UI 规格→需求→技术方案→测试→验收」串成一条流水线的公开成品 | 自建（路线 2） |
