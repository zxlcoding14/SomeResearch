# 产品分析报告工作流（PM 视角）

## 何时使用
用户给出某款工具（多为 Windows/Mac 效率软件、独立开发者小工具、AI mini-tool）的链接或名称，要求：
- 梳理页面/软件的功能点
- 产品分析、商业化分析、竞品对比
- 「落盘」「归档」到调研目录

> **上游框架**：动手前先过一遍姊妹 skill **`product-analysis-framework`**——它提供「分析任何产品该问什么、看哪些面」的七层提问法 + 八把判定尺子 + 数据口径陷阱清单。本 skill 负责「产出什么形态的报告 + 赛道基准数据」，那个负责「思考框架」。两者叠加使用。
> 完整提问手册：`..\产品分析框架\references\产品分析框架-提问手册.md`（相对本文件夹；也可经 `~/.workbuddy/skills/product-analysis-framework/references/产品分析框架-提问手册.md` 访问——同一份文件，junction 指过去）
> **本文件夹是自包含单元（2026-10-08 重构）**：本 SKILL 实际存于 `调研\方法\研究报告规范\SKILL.md`；`~/.workbuddy/skills\product-research-report` 只是 Windows 目录链接（junction）。**⚠️ 删链接只能用 `rmdir`，`rm -rf` 会穿透删掉本体。**
> **路径锚点（换机必读）**：本文所有 `调研\...` 路径都相对 **{调研根}**，默认 `D:\code\Test\SomeResearch\调研`。换了电脑后盘符 / 用户名 / 目录位置可能不同——若默认路径不可达：① 在 `D:\`、`C:\Users\<当前用户>\`、`文档`、`OneDrive` 下按目录名 `调研` 搜索；② 仍找不到就直接问用户新路径，拿到后把上句默认值改掉（这行是其他 skill 的锚点来源）。

## 硬性要求（用户偏好，必须满足）
1. **结论先行**：开篇 `〇、结论先行（TL;DR）`，用编号给出 3–5 条判断。
2. **漏斗形分层**：先总览 → 再按维度逐层收敛（功能枚举 → 对比 → 数据 → 商业化 → 建议）。
3. **必须含真实数据**：用户规模、活跃度、下载量、星标、定价、营收推算。数据不足要标注口径（如「官方宣称」）。
4. **表格化**：每个维度用 markdown 表格承载，避免长段落。
5. 文末附「数据来源与口径说明」表。

## 数据采集清单（按优先级）

| 目标 | 方法 | 已验证可用的写法 |
|---|---|---|
| GitHub 仓库指标 | WebFetch GitHub API | `https://api.github.com/repos/{owner}/{repo}` → 取 stargazers_count / forks_count / subscribers_count / open_issues_count / created_at / pushed_at / license / language |
| 版本与下载量 | WebFetch Releases API | `https://api.github.com/repos/{owner}/{repo}/releases` → 每个 asset 的 download_count 求和 |
| 论坛热度（Discourse） | WebFetch 加 `.json` | `https://meta.appinn.net/t/topic/{id}.json` → posts_count / views / like_count / participant_count / created_at |
| **论坛帖子全楼层正文（强推）** | managed Python urllib（见下「环境注意」） | `python -c` 请求 `/t/{id}.json` → `post_stream.posts[].cooked` 去标签即得全部楼层正文。⚠️ 逐页 WebFetch `/topic/{id}/{floor}` 会漏正文（Discourse 前端按需渲染，楼层标题会被吞），**只有 JSON 版是完整的** |
| 官方定位与功能 | WebFetch 官网、README、发布帖 | 小众软件论坛发现频道帖（meta.appinn.net）、appinn.com 专文 |
| 定价与会员政策 | WebFetch 官网定价页 + 官方 Guide/QA | 如 getquicker.net/Guides、listary.net/pro、raycast.com/pricing |
| 竞品与行业信号 | WebSearch | 中文关键词 + 年份；注意搜「官方是否在某方向发力」这类缺失信号 |
| 外部评测 | WebSearch | 少数派、什么值得买、小众软件周榜、下载站转载 |
| **多仓库批量指标**（开源调研必用） | WebFetch GitHub Search API | `https://api.github.com/search/repositories?q=user:A+user:B+user:C&per_page=100&sort=stars` —— `user:` 可多值 OR，一次拿几十个仓库的 stars/forks/license/pushed_at，比逐个 `/repos/*` 快一个数量级 |
| **npm 下载量（多包一次）** | WebFetch npm point API | `https://api.npmjs.org/downloads/point/last-month/p1,p2,p3` 支持逗号批量（上限百来个），**但不支持 scoped 包**（含 `@x/y` 会让整批报错，需剔除或单独查） |
| **包体积与依赖数** | WebFetch Bundlephobia | `https://bundlephobia.com/api/size?package={pkg}` → size / gzip / dependencyCount；判断"轻量"定位是否成立的关键证据 |
| Python 包下载量 | ⚠️ 受限 | pypistats.org 持续 429 限流；api.pepy.tech 需 API Key。暂无稳定免费通道，缺数据就在报告里标注缺口 |
| **输出压缩（省 context 关键）** | 提示词约束 | GitHub/Bundlephobia 类接口若写"Return the raw JSON values"，会倾倒全量 JSON（约 4k tokens/次）。改成 `Output ONLY one compact line: full_name \| stars \| forks \| license \| pushed_at. No prose.` 可压到 50 tokens 内 |
| **开源项目的权威功能清单（做到"所有功能点"级别穷举的必备三件套）** | curl raw 文件 | `curl -sL https://raw.githubusercontent.com/{owner}/{repo}/main/{CHANGELOG.md,USAGE.md,config.example.ini}`（当前环境 curl 直连 raw 可用）。**Release 说明只是摘要**——实证 PopDrop 的 Release 漏掉 v0.10 / v1.1.x / v2.0.1–2.0.12 等全部中间版本，而 CHANGELOG（91 条）+ USAGE（66 节手册）+ config 示例（85 个配置键）三份合计才能穷举出 210 条功能点。**配置示例文件信息密度最高**：它等于「产品功能的完整开关面」，还能暴露「配置可达但 UI 不可达」的隐性功能 |
| **Issues 列表** | ⚠️ 匿名 `/issues` API 会返回错误对象（非数组），`json.load` 后下标取字段报 `TypeError: string indices must be integers` | 改用 WebFetch 抓 `https://github.com/{owner}/{repo}/issues?q=is%3Aissue` 的 HTML，可一次拿全（含状态与日期）。活跃 issue = 真实用户诉求的一手素材 |

## 报告结构模板
```
# {产品} — 产品经理视角分析报告
> 元信息引用块：分析对象/版本/日期、分析视角、数据截至时间与来源
## 〇、结论先行（TL;DR）           ← 3–5 条编号判断
## 一、页面/需求功能点梳理          ← 若由论坛帖触发，先写触发页面
## 二、{产品}全功能点枚举          ← 按模块分层表格 + 版本演进时间线
## 三、需求覆盖度对比              ← 逐项判定 ✅/⚠️/❌
## 四、真实数据（API 实测）        ← GitHub / 论坛 / 分发渠道
## 五、产品分析                    ← 定位、用户场景、优势、劣势风险、竞争位势
## 六、商业化分析（漏斗形收敛）     ← 第一层现状→第二层为何不可行→第三层可行路径→第四层启示
## 七、产品改进建议                ← P0/P1/P2 优先级表
## 附：数据来源与口径说明
```

## 论坛帖整理类（appinn「我最喜爱」/求推荐帖）的轻量产出模式
用户常直接甩一个小众软件论坛帖子链接说「提取工具」「整理这个页面」「按上述要求处理」。此类**不要套单产品长模板**，用：
```
# {主题}整理 / {产品}功能点文档
> 信息源：帖子标题 + 全部 N 层楼层 + 链接
## 一、原始需求（提问者场景）        ← 求推荐类帖
## 二、帖子推荐的工具清单            ← 每款：定位 / 平台 / 同步或核心机制 / 真实定价
## 三、能力对比表                    ← 维度取帖内分歧点（如图片支持、跨外网、Android 实时性）
## 四、PM 视角速读                  ← 3–5 条：解法分类 → 价格锚点 → 设计巧思 → 竞品盲区
## 五、相关链接
```
要点：
- 定价务必去官网/下载站/吾爱破解等**核实真实数字**（帖内只写「免费/付费」的信息量极低）
- 帖内真实用户吐槽（卡死、误删、Win7 兼容差、耗电）是最高价值素材，必须保留原话
- 若同一作者有多款工具（如 appinn 的 dog），记录其「产品矩阵 + 变现模式」

## 量化对比框架（营收 / 规模 / 活跃 / ROI）——凡涉及商业化必做
用户常在拿到初版对比后要求补「营收、用户规模、商业化、ROI、活跃量、年度收入」维度。按以下五组指标建表：

| 组 | 指标 | 算法 |
|---|---|---|
| 规模 | 用户数 / DAU / MAU / 下载量 | 官网宣称需标「宣称」；第三方统计需标「估算」 |
| 收入 | 年营收、ARPU（单活跃用户年收入）、人均产出 | ARPU = 年营收 ÷ 活跃用户；人均产出 = 年营收 ÷ 团队人数 |
| 资本 | 累计融资、轮次、领投方 | GitHub/公开报道/官网 Jobs 页时间线 |
| 效率 | 融资额 ÷ 年营收（= 多少年营收覆盖融资） | 判断"当期 ROI 是否成立" |
| ROI | 三视角：资本 ROI / 运营 ROI / 用户 ROI | 用户 ROI = 时间收益 ÷ 订阅成本 |

**最有信息量的两个派生指标**：
1. **ARPU 断层**——同赛道产品的 ARPU 差异几乎总由「付费理由强度 × 计费结构 × 人群净值 × 计价货币」四项决定，**不由功能数量决定**。实证：Raycast ≈¥75 vs uTools ≈¥2.1（36 倍），后者用户多 10 倍但营收更低。
2. **人均产出**——反映模式效率，常常颠覆"谁更成功"的直觉（实证：Raycast ¥94 万/人/年 vs uTools ¥61–78 万，但**单人 + 网络效应的 Quicker 才是 ROI 最优形态**）。
3. **下载/Star 比**（开源调研专用）——`包月下载量 ÷ GitHub Stars`。>5,000 = 真·基础设施（marked 7,321、markdown-it 5,113）；50–5,000 = 正常组件；**<50 = 高星但极少被真正集成**（vditor 14、cherry-markdown 5）。**低比值 ≠ 差代码，而是"未被大厂占位的机会区"**，是开源选型里信息量最高的单一指标。

**ROI 测算必做的三情景**（用于独立开发者/小工具决策）：
| 情景 | 假设 | 结论形态 |
|---|---|---|
| A 个人兴趣 | 免费+打赏 | ROI < 1，仅作品/简历价值 |
| B 垂直高 ARPU | 高客单价 × 低转化率 | 反推所需付费用户数 → 反推所需活跃规模 → 判断是否可达 |
| C 被吸收/合作 | 一次性出售 | 期望 ROI 最高但不可控 |

> 落地经验：**独立 mini-tool 的期望 ROI 常低于 1**，除非拿到规模、走 B 端或出海。这个"负结论"本身往往是对用户最有价值的输出，要敢于直接给。

## 单产品「功能点全景分析」法（用户说"分析所有功能点 / 所有功能点分析一下"时使用）

和「产品分析报告」不同：报告回答"这产品怎么样"，全景分析回答"**它到底有哪些能力，以及这些能力值不值钱**"。产出独立文件 `{产品}-功能点全景分析.md`，不必与报告合并。

### 1. 先立口径，再数数
必须显式声明计数口径，否则数字无法复用。验证有效的双层口径：
- **最小能力单元**（可独立描述、可独立触发或在配置中独立开关）= 主口径；
- **用户可感知独立功能**（合并参数类，如"缩略图 4 个参数算 1 项"）= 辅口径。
实证：PopDrop 210 条 / 约 90–110 项，两者都写出来比只写一个更可信。

### 2. 模块化 + 四层分层（核心方法）
把功能点归入 8–12 个模块，再按「删掉它产品定义会不会变」划四层：

| 层 | 判据 | 商业含义 |
|---|---|---|
| **T1 主干范式** | 删掉它产品就不是这个产品了 | 获客功能点，**必须永久免费** |
| **T2 场景能力** | 决定"能不能真用起来" | 留存功能点，与竞品重合度最高 |
| **T3 界面细节** | 决定"顺不顺手" | 口碑功能点（极客投票的来源） |
| **T4 工程保障** | 用户看不见，删掉产品就崩 | **成本中心：不可感知、不可计价** |

实证占比：PopDrop T1 20% / T2 53% / T3 9% / T4 18%。**T4 超过 10% 即属"单人项目里的罕见工程投入"**，是要点出的异常信号。

### 3. 商业可提取性映射（本方法最有价值的一步）
给每个模块打三档「商业可提取性」：**无**（基础体验/参数/纯工程）、**弱**（有真实边际成本或可做增强包）、**强**（能撑订阅）。做成「用户价值感知 × 商业可提取性」气泡象限图（气泡直径 = 功能点数）。

**由此得出的通用规律（已实证，可直接复用）**：
> **功能点的投入强度与商业可提取性呈负相关。** 最花功夫的层（工程保障、界面细节）用户感知不到也无法收费；唯一能撑订阅的那一层，往往是工程量最轻、开发者最晚才做的一层。
> 落地表达：**"这个产品 95% 的工作量都在为那 5% 的可能性铺路，但作者从未把那 5% 做出来。"**

### 4. 三条必须做的静态检查
1. **AI 功能点计数**——显式在全文检索"AI / 大模型 / 提示词 / 语义"，给出确切条数（常为 0）。这是判断"窗口是否还开着"的硬指标。
2. **出站网络功能点计数**——区分「入站接收」（URL 下载）与「出站」（同步/账号/遥测）。**出站为 0 = 隐私卖点同时是商业化死角**：无账号则无法计费、无法运营用户。
3. **配置键数量**——配置键数 ÷ 模块数 > 7，说明大量功能点「配置可达、UI 不可达」，是认知负担与产品定位漂移的证据。

### 5. 缺失功能点对照清单（比功能清单更有信息量）
逐条对照「同价位/同赛道竞品普遍具备而该产品没有」的能力，每条必须给：**影响等级（🔴/🟡/🟢）+ 依据**（Issue 编号、论坛帖号、API 字段）。🟢 要区分"真缺失"与"主动取舍"——后者不算缺点（如 PopDrop 不做全盘检索）。

### 6. 功能点 × 竞品覆盖矩阵
行 = 模块，列 = 竞品，值 = ✅/⚠️/❌。**读法不是"谁功能多"，而是找独占区与缺席区**：独占区 = 差异化立足点，缺席区 = 被复刻风险。
实证：PopDrop 独占区仅 M6 拖放投递 + M7 外部内容接收（34 条，16%），而 Quicker/uTools/Listary/Raycast 在这两块全为空 → 产出结论「**用 A 的投递层 + B 的 AI 层 = 最清晰的产品空位**」，这类跨产品拼接结论比单产品评价有用得多。

### 7. 因果链归因（解释"为什么是这些功能点"）
把版本演进按**驱动力**而非时间重新切片：自身痛点 → 工程完备性 → 社区反馈 → 确定性焦虑 → 场景外扩。实证 insight：**前四阶段都是"把已有的做对"，只有最后一个阶段是主动扩张，而那恰好是唯一商业出口**——说明作者走对了方向但没继续（用 `pushed_at` 距今天数佐证）。

## 护城河的"时间窗"判断法
不要轻易写「架构性护城河」。判定步骤：
1. 找出竞品架构**逻辑上做不到**的能力（如"启动器拿不到当前输入框上下文"）；
2. **再验证竞品最新版本日志**——若其近期已上线相关能力（实证：Raycast 0.71 / 2026-08-12 上线 Screen Awareness，"启动器拿不到上下文"的判断立即被证伪）；
3. 若被证伪，降级表述为「时间窗优势（估 6–18 个月）」，并给出窗口内必须完成的动作。
4. 更稳的壁垒排序：**场景壁垒（中文 IM 生态/垂直行业贴合度）> 技术壁垒（会被追平）**。

## 单品「付费墙位置」判定法 + 「商业模式类型」快速识别（2026-09 新增，实证：迅捷OCR）

### 1. 把付费墙按位置分三类，第一眼先判类型
| 墙位 | 做法 | 典型产品 | 后果 |
|---|---|---|---|
| **用量墙** | 限次/限页，但完整可用 | 白描（5 次/天）、扫描全能王 | 口碑最好，转化靠"用上瘾" |
| **功能墙** | 限输出格式 / 精度档位 | ABBYY、福昕 | 中性，须在价格页讲清楚 |
| **交付墙** | **能识别、不能导出/复制** | 迅捷OCR | **转化最优、口碑最差** |

> **判定规则**：付费墙设在"交付"环节 = 「流量型产品」的第一特征。墙位越靠后（越接近用户完成劳动的那一刻），转化越高、信任损耗越大。凡希望做复购或做品牌的产品，都不应把墙放在交付环节。**差评措辞会直接暴露墙位**——搜"说免费实际收费""收费不提前标出"这类原话，命中即交付墙。

### 2. 「包体差 = 架构证据」
同一产品在不同渠道的安装包大小若差一个数量级，直接判定为「**下载器外壳 + 云端处理**」架构，并由此**推导三件事**：① 必有次数限制（云端有按次成本）② 必然存在"终身无限次"的负毛利敞口 ③ 客户端只是壳，差异化不可能来自端侧。
- 实证：迅捷OCR 联想渠道 **3.65MB** vs 360 宝库 **120.61MB**（差 **33 倍**）；官网下载按钮指向第三方域。
- 配套检查：渠道页的"收费 / 有弹窗 / 捆绑"标注；用户协议里是否有"捆绑软件视为同意"条款。

### 3. T4 层要再看构成：技术工程 vs 商业化工程
T4 占比高**不等于**工程投入高。拆两类：**技术工程**（兼容性/性能/崩溃处理/跨平台，见于技术型产品如 PopDrop）vs **商业化工程**（广告弹窗/限次/设备限制/下载器壳/EULA 捆绑/合规文档，见于流量型产品）。
- 实证：迅捷OCR 的 T4 共 24 条，其中 **10 条属商业化工程（42%）**——"工程很多"是假象。

### 4. 内容农场污染检测（交叉比对法）
第三方"评测/推荐文章"的价格与功能若与官网不符，即判为 SEO 铺稿，**不可作数据源**，且应本身作为"该品牌获客手段"的发现写入报告。
- 实证：多篇软文称迅捷OCR"日卡 5 元 / 月卡 39 / 年卡 199"（官网实为 ¥48/¥68/¥88）、称"支持公式识别转 LaTeX"（官网功能列表无此项）。

### 5. OCR / 文档工具类赛道的必查免费替代清单（不逐项过会把已免费的能力误判为差异化）

### 7. 可迁移结论（OCR / 文档工具类赛道）
1. **"免费能识别、不能导出"是最有效的付费墙，也是最贵的一刀**——短期最大化转化，长期把品牌打成"骗人"。
2. **本地引擎与账号云不可兼得，最优解是分层**：本地引擎做免费体验层，云端/服务层做付费层。纯本地（PopDrop 型）收不到钱，纯云端（迅捷型）有成本敞口与口碑风险。
3. **不要做"又一个能识别文字的软件"**。N1（图变字）已被六类免费来源覆盖，N2（批量）被开源覆盖；唯一还有护城河的是 **N3 结构化交付（表格/公式/竖排/多栏）与 N6 嵌入工作流（文件夹监听 / API / 私有化）**。
4. **¥88 终身 + 无限次云端识别 = 结构性负毛利敞口**，且无公平使用条款兜底。规则：有持续交付成本的产品不能卖终身无限次；无持续成本的产品不应挂年费。

## 赛道/生态类调研（非单一产品）的专用框架

当用户说"调研某个开源项目/某个品类"，而非某一个具体产品时，改用**五层漏斗 + 许可证矩阵**，不要套单产品模板：

1. **先分层再分析**。典型分层（以 Markdown 为例）：L0 解析内核 → L1 可嵌入组件 → L2 增强链 → L3 端应用 → L4 发布/团队工具。**混层分析必然得出错误结论**（例：markdown-it 有 2.19 万★但 npm 月下载 1.12 亿，两个数字说的不是同一件事）。
2. **许可证风险矩阵是复用决策的第一优先级**，比技术优劣更早筛。按传染性排序：MIT/BSD/Apache（✅ 闭源可用）→ MPL-2.0（🟡 文件级）→ LGPL（🟡 动态链接）→ GPL（❌）→ **AGPL-3.0（❌ 含网络服务，绝对不能代码级复用）**。⚠️ GitHub 的 `NOASSERTION` ≠ 无许可证，只是无法自动识别，**必须人工读 LICENSE 原文**。
3. **"停更/归档"是最该突出的风险信号**。用 `archived` 字段 + `pushed_at` 双指标，分 🟢活跃 / 🟡半停滞（>6 个月无提交）/ 🔴停更三档。实证：一轮调研中 11 个高星项目已死。
4. **变现点几乎总在"产品之外"**。开源编辑器/工具的付费墙 100% 落在**同步 / 发布 / 协作**三件事上，功能本身定价为 0。写建议时必须把变现锚点从"功能"挪到"服务"。
5. **许可证开放度与商业化成反比**（已验证规律）：高星且高收入的端应用多为 AGPL（防白嫖换维护者收入）；被全行业复用的内核多为 MIT（换生态位、放弃直接变现）。

## 平台级/基础设施类赛道的分层调研法（虚拟桌面、云办公这类"品类"调研）

当调研对象是"某个系统级品类"而不是单个软件时，**分层要按「付费主体 + 距系统内核的远近」，不要按功能分类**。实证分层（Windows 虚拟桌面）：

L0 系统内核（Task View / Windows Sandbox / Hyper-V，免费）→ L1 本地增强（Dexpot / VirtuaWin / 国产小工具）→ L2 工作区窗口管理（PowerToys Workspaces / DisplayFusion / komorebi / GlazeWM / Seelen-UI）→ L3 沙箱隔离（Sandboxie-Plus）→ L4 企业 DaaS（Windows 365 / AVD / Citrix / Omnissa / 华为云桌面 / 无影企业版 / 深信服 aDesk / 麒麟信安）→ L5 消费云电脑 + 云手机（无影个人版 / ToDesk 云电脑 / 顺网 / 红手指）→ L6 Agent 执行环境（Windows 365 for Agents / 无影 AgentBay / E2B / Daytona / Blaxel）→ L7 相邻高 ARPU 赛道（指纹浏览器 AdsPower / 比特 / 云登 / VMLogin）

四条硬结论（可直接迁移到任何"系统内置能力"型赛道）：
1. **"被操作系统内置"= 品类死亡判决。** 判定证据链优先级：官网新闻页最后更新日期 > 功能版本号年份 > 第三方站 Discontinued 标记 > 同类产品下架公告里的原话。实证：Dexpot 官网停在 2016-02 被标 Discontinued；VirtuaWin 功能版本 4.5 停在 2012；Rainmeter 2016 年下架 VirtualDesktops 插件，官方原话"Win10 内置后两工具都不再相关"。
2. **商业价值曲线是 U 型，不是递减**：贴内核那层归零、中间层天花板低、两端（服务化 DaaS / Agent 执行环境）价值最高。混层分析必错——PowerToys 的 138,843★ 说的是 30+ 工具套件，不是虚拟桌面。
3. **算 ARPU 断层比算功能对比有用得多**：同一赛道年化单用户收入可从 ¥48（DisplayFusion $34 买断摊 5 年）跨到 ¥11,988（AgentBay Pro ¥999/月），差约 250 倍。决定因素是「付费理由强度（成本中心 vs 收入中心）× 计费结构（买断 vs 按席位月付）× 人群净值 × 计价货币」，**与功能数量无关**。
4. **找空位的方法：看巨头只做了哪一半。** 微软只在**云端**做了 Windows 365 for Agents，**本地**"让 Agent 在可编程沙箱里操作 Windows"没有成熟方案（Windows Sandbox 免费但不可编程、不可持久化）→ 这就是空位。

**B 端真实成交价的唯一可靠渠道（新验证，价值极高）**：中国政府采购网 / 省级公共资源交易信息网的中标（成交）结果公告与合同公告，会**逐项列出品牌、型号、数量、单价**。
- 搜索式：WebSearch「{品类} 中标 成交 结果公告 单价 {年份}」，如「云桌面 中标 成交 单价 2026」
- 实证收获：深信服云桌面终端 aDesk-STD-200H-s **¥1,460–1,605/台**；云桌面平台软件 V5.0 **¥162,000/90 终端**（≈¥1,800/终端一次性）；超融合一体机 ¥70,000–99,800/套。据此反推出"硬件 40–50% + 软件授权 15–20% + 终端 30–40%"的三段式 CapEx 结构。
- 结论：**行业报告说"市场多大"，中标公告说"钱怎么赚"**——后者对决策更有价值，赛道路演务必去捞。

**赛道路演必备两张图**：① N 层产品形态 × 商业价值指数横向条形图（灰=已被系统厂商消灭，绿=仍可捕获的价值）；② 各形态「年化单用户收入」横向条形图（买断按 5 年摊销 vs 订阅按月×12）。第二张图能直接说服决策层"该选哪种计费结构"。

## 商业模式分析的通用结论（已沉淀，可直接复用）
- 国内效率工具**定价锚点 ≈ ¥50–100/年**（Quicker ¥57.6/年）；高于 ¥100/年将直面比价压力

**五条可迁移的赛道结论（系统工具类通用）**：

1. **ARPU 断层可达 1,000 倍以上**（效率源 B 端 ≈¥2.9 万/客户/年 vs 消费级 ≈¥20–300/用户/年），决定因素仍是「付费理由强度 × 计费结构 × 人群净值 × 计价货币」，**与功能数量无关**。数据恢复之所以能卖 $69.95/月，唯一原因是用户处在**损失厌恶峰值**。

2. **市场规模口径陷阱**：同一"数据恢复软件"品类，2025 年规模在不同报告里能从 **$23.6 亿到 $375.6 亿（差 16 倍）**——因为"消费级软件订阅"与"企业备份/容灾服务"被混在同一标题下。**必须分层后才可引用**（可用的那层：PC 系统工具软件 = 个人 $99.09 亿 + 中小企业 $50.94 亿 + 大企业 $21.23 亿）。

3. **"被 OS 内置"= 品类死亡判决**（已在虚拟桌面、磁盘清理两条赛道双重验证）。判定信号：微软 PC Manager 版本迭代日志 + Windows File Recovery 存在 + 开源免费工具（Dism++）权限高于所有商业工具。

4. **同赛道内「产品线宽度」与「商业可提取性」呈负相关**（易我↔傲梅对照，2026-09 第二次验证）。易我 30 SKU，独占区全是消费级一次性低价品（PDF/录屏/擦除/修复/AI）→ 只能靠买量转化；傲梅 14–15 SKU，独占区全是订阅制 B 端品（AnyViewer/MultCloud/Cyber Backup）→ 自然流量 + 大单。
   > 落地表达：**当一个工具公司开始快速横向铺 SKU，通常不是扩张信号，而是「主产品付费理由变弱」的信号**——它在用宽度掩盖单 SKU 的 ARPU 衰减。**宽度不是护城河，是可提取性低的证据。**

5. **评估同类公司时，先算「人均产出 × 费用率」，再看营收规模**（易我↔傲梅对照，2026-09）。实证：傲梅用易我 **44%** 的人（129 vs 291）拿到 **57%** 的营收（¥1.7 亿 vs ¥3.0 亿）→ 人均产出 ¥131.8 万 vs ¥103.1 万，**高 27.8%**；主站月访问仅易我 **1/14**（544.1K vs 7.8M）→ **每万次访问收入 ¥260,200 vs ¥32,100，差 8.1 倍**。
   > 三条补缺口的机制：① **终身买断首年收满**；② **不买量 → 无广告折损**（易我估广告费占营收 ~45%，傲梅估 15–25%）；③ **B 端大单不走网站点击漏斗**。
   > **衍生决策规则**：a) **不做「年费 + 终身」双轨** —— 价差 <2 年回本时年费 SKU 纯属价格锚点道具，且永久封印续费收入（傲梅 PA $49.95年/$69.95终身 = **1.40 年回本**）；b) **捆绑包折扣是 ARPU 毒药** —— 傲梅 $89.95 买 6 个终身 = 单线仅 **$15**，对标易我 8 应用 $199 = 单线 $24.9（后者折扣更浅反而更健康）；c) 如果产品**没有持续交付成本**（纯本地工具），**不要做年费**，正确做法是只卖终身并把年费从价格页拿掉（傲梅只做了半个，年费仍挂着当锚点，反而自曝终身制更划算）。

**克隆赛道的三次判死（可直接引用的历史证据）**

1. **Symantec Ghost 消费版 2013-04-30 停止销售**。官方理由：不支持 UEFI/GPT 且不会重写；非官方理由：消费级 PC 备份已转向云，"本地磁盘镜像市场已停止增长"。企业版 Ghost Solution Suite 存续于 Broadcom，社区判为僵尸产品。技术死因（可迁移）：扇区级克隆 → **SID 重复**（域灾难）、**0x0000007B 蓝屏**（存储控制器驱动不匹配）；而官方 Sysprep 就是为 SID 而生的。
2. **Macrium Reflect Free 2024-01-01 退役 → 2024-10 Reflect X 全线转订阅**（取消独立/永久授权）。官方论坛原声：*"Macrium has gone 'Full Adobe' on us... I'm already shopping around for alternatives... I can't do the subscription thing."*、*"one of the main reasons I became an ex-Acronis customer to Macrium is that they offered a reasonable, clear and fair way to lease their software. Pay once and you're done."* → **用户流向 Hasleo Free 与傲梅 Backupper Standard**（Hasleo 官方直接把产品页做成 "Best Free Alternative to Macrium Reflect" 落地页）。
3. **OEM 白送**：三星/美光/西数/希捷/Intel/金士顿全部免费送克隆工具 → **克隆是 SSD 厂商的销售辅助工具，不是独立商品**。

**可迁移的品类规律（三条，已交叉验证）**

1. **「绕开 OS 官方机制」的工具，一旦 OS 提供"官方格式+官方工具链+免费"，该层商业价值归零而不是变小。** 克隆的"配置与执行"层已被 WIM/DISM/Sysprep 归零；只剩"引导修复（EFI/BCD/MBR↔GPT/SID）"仍活着，因为官方工具链（ADK）要求用户理解它。**失败点即收费点，但只能收一次钱。**
2. **在"功能无持续交付成本"的本地工具上强推订阅 = 把用户名单送给免费竞品。** 正确做法：本地能力永久免费，订阅只挂**有持续成本的那一层**（云存储 / 不可变仓库 / 恢复验证服务 / 终端数量）。分层模板参考 Hasleo：**免费版只砍"企业才需要的那刀"（商业授权 + 命令行 + 服务器支持），不砍普通用户核心体验**。
3. **备份赛道真正的钱不在"备份"，在"恢复"和"证明能恢复"。** 92% 有备份但 31% 恢复失败、33% 从不测恢复 → **「恢复验证 / 恢复演练 / 不可变第二副本」是从备份软件里长出来的新付费层，目前只有托管服务商（BCP Group / Trace3 / 11:11 Systems / 四大）在做，工具层几乎空白。** 这是本赛道最清晰的产品空位。

**ARPU 断层（本赛道实测，约 1,000 倍）**：免费层/OEM 克隆 **¥0** → 消费级买断摊 5 年 **¥57–65** → 克隆专业工具 **¥180** → 消费级订阅 **¥360** → SMB **¥100（ABB 摊薄）–¥6,640** → MSP **¥1,800–51,600** → 企业项目级 **¥23 万–150 万/套**。**断层由「付费主体」决定，与功能数量无关。**

**备份需求五层（按"愿意付费比例"排序：N5 > N4 > N3 > N2 > N1 —— 与功能投入强度完全相反）**
N1 对象（备什么）→ N2 触发（何时备）→ N3 落点（备到哪：含不可变 WORM / 离线气隙）→ N4 恢复（含 Universal Restore / **恢复验证**）→ N5 治理（加密/保留策略/去重/审计证据/集中管理/批量部署）。**厂商在 N1/N2 投最多功能，在 N5 收最多钱。**
**克隆需求四层**：M1 配置 → M2 执行 → **M3 引导（EFI/BCD/MBR↔GPT/SID，80% 失败在此，且免费工具最弱）** → M4 验收（可引导验证 / 激活保持）。

**三条新沉淀的可迁移规律**

1. **克隆/迁移赛道的可收费面 = 官方免费工具的能力边界。** PC 端个人换盘被 OS 内置（WIM/DISM/Sysprep）+ 6 家存储厂商 OEM 白送完全覆盖 → UBackit 归零；手机端厂商换机工具只能做同生态搬运 → **MobileTrans 靠「跨生态 iOS↔Android」+「有状态应用数据（WhatsApp/LINE/Kik/Viber）」活下来，并拆出 Wutsapper 单卖 $18.99/月，App 月收入 $80k**。**落地：做迁移工具先画「官方免费工具覆盖矩阵」，只投空白格。**
2. **买量驱动型公司做不了信任驱动型工具——是基因问题不是投入问题。** UBackit 产品合格（覆盖克隆 M1–M4 全层 + 备份 N1–N3）、价格有竞争力（$15.99/月 + 2 设备授权，比易我便宜 47%）、有母公司服务器与研发 → **总下载 2 次**。**落地：销售费用率 >40% 的公司，不要进「高决策成本 + 低冲动 + 靠口碑传播」的工具品类。**
3. **「数据」品类的抗周期性优于「创作」品类。** 万兴 2026H1 视频创意 **-9.78%** vs 实用工具 **+10.45%**；同期 Backblaze 消费备份 +3% vs 企业云 +26%。**落地：增长焦虑期数据类产品是可依靠的「扛损业务」，但天花板明确（Backblaze 消费级仅 3% 增速），不要指望它救公司。**

### 方法论：把「场景」切成格子再投放，而不是按厂商罗列产品

当用户问"某批厂商在某类场景下还有哪些产品"时，**不要按厂商逐个罗列**（会变成无边界清单）。做法：

1. **先按场景的工作流位置切 5–6 格**（本次用的办公六格：A 文档生产 / B 屏幕与音视频 / C 迁移与云盘 / D 终端与 IT 运维 / E 数据合规 / F AI 智能体）。
2. **建「厂商 × 格子」矩阵总表**，每格用 ★★★/★★/★/— 标强度 + 标该格"谁在付钱"。**矩阵的稀疏位置就是结论**——本次结论是"厂商扎堆 A/B/C，真收大钱的 D/E 入场者最少（E 格只有 Ontrack 与效率源真正做成）"。
3. **识别"接法"而不是"产品"**：把厂商的动作归成 3–4 种可复用路径（本次：换收款口径 / 邻能力顺移 / 升维到 B 端 / 跳 AI Agent），做成**「能力复用度 × 客户付费能力」象限图**——**右上象限（高复用 + 高付费）= 唯一被验证的路径**。
4. **必须找 2–3 个"反向样本"**（本次：名科国际直接做 B 端 IT 服务一年亏 HK$557 万、MacPaw 跳通用 AI Agent 导致首次亏损 >$1,000 万 + 裁员 20%、易数软件 Eassos 干脆不做矩阵）——**负样本的说服力高于正样本**。
5. **交付前把"格子级成交金额"做成对数刻度图**：本次实测格间差约 300 倍（E ≈¥2.9 万/客户/年 vs A ≈¥128 一次性）。

## 开源项目调研专用：GitHub 数据采集的三条禁令与两条替代通路（2026-09 实证，czkawka）

### 三条禁令
1. **禁止直接比较不同版本的累计下载量。** GitHub Release 的 `download_count` 是**自发布起的累计值**，老版本天然更高。**必须 ÷ 在架天数得到「日均下载」才可比**。实证反例：若不归一化，czkawka 10.0.0（224,480）看起来是 12.0.1（99,659）的 2.3 倍"更受欢迎"；归一化后真相相反（553 次/天 vs 1,634 次/天，差 3 倍）。
   > **日均下载速度 = 累计下载 ÷ 在架天数**，这是评估开源端应用"是否还在增长"的唯一正确指标。
2. **禁止把「仓库语言字段」当技术栈。** 本地化文件多时 GitHub 会把语言识别为 `Fluent`（czkawka 实测结果），真实工程代码在子目录里。必须结合目录结构 + crates.io/npm 判断。
3. **禁止把 `NOASSERTION` 当"无许可证"。** 多许可证或自定义许可证都会落到 `NOASSERTION`。**必须逐个组件查**：czkawka 的 `czkawka_core` / `czkawka_cli` 实测为 **MIT**（crates.io 的 version 对象里有 `license` 字段，比读仓库 LICENSE 文件更可靠）。

### 两条替代通路（GitHub core API 匿名配额 60 次/小时、全 IP 共享，调研中极易耗尽）
| 通路 | 端点 | 能拿到什么 | 备注 |
|---|---|---|---|
| **WebFetch 走独立出口** | `https://api.github.com/repos/{o}/{r}` | 不受本地 IP 限流影响 | ⚠️ 大 JSON 会被截断。**含 52 个资产的 release 对象会吃掉整个返回** → 改用 `https://api.github.com/repos/{o}/{r}/releases/tags/{tag}` 单版本查询，每次返回小且完整 |
| **第三方无鉴权 API** | `flathub.org/api/v2/stats/{app_id}` | **Linux 真实装机量 + 逐日曲线 + 逐国家分布** | 端应用调研的**最高价值单一数据源**（czkawka 实测：累计 200,542 / 近 30 天 5,302 / 含 190+ 国家明细） |
| | `community.chocolatey.org/api/v2/Packages()?$filter=Id%20eq%20'{id}'` | Windows 包下载量（OData XML） | ⚠️ 每个 version 返回的是**包级累计值（所有版本同值）**，取一次即可，不要逐版本累加 |
| | `crates.io/api/v1/crates/{name}` | 累计下载 / 近 90 天下载 / 版本数 / **license** | 判断"核心库被多少项目真正嵌入" |
| | `api.npmjs.org/downloads/point/last-month/{p1,p2}` | npm 批量下载量 | 不支持 scoped 包 |

### 「畸形下载面」检查项（开源 GUI 项目通用）
单版本资产数 > 20 即判定为**分发设计缺陷**。实证：czkawka 单版本 **52 个资产**（平台 × 渲染后端 femtovg/skia × 图形后端 opengl/vulkan/wgpu 的组合爆炸），导致中文社区出现专文《54个下载文件！所以，我到底该下哪个？》，官方只能回复"先找关键词 heif/avif/raw，不太重要 femto/skia"。**这是纯免费开源项目最容易被忽视、也最容易修的用户流失点。**

### 开源项目的商业化硬度判定（两条一眼定论）
1. **看 `.github/FUNDING.yml`**：若只有 `github: <user>` 一行 = 变现能力为 0（czkawka 实测），全部价值沉淀在声誉。
2. **查品牌域名是否被抢注**：czkawka 实测 czkawka.com/.net/.org/**.cn 四个后缀全部被抢注为恶意站点**，Issue #1583 挂了 13 个月无人处理，第三方评测站仍把 czkawka.com 当官方链接。**结论：面向普通消费者的开源项目，不注册官方域名 = 把品牌流量全部送给钓鱼站。**

## 「功能同质化赛道」的价值锚点分析法（2026-09 新增，实证：Mac 清理 / 磁盘优化套件）

**何时用**：调研对象所在的品类里，竞品功能高度重合（如本赛道 11 个主体里 9 个的「垃圾清理+应用卸载+大文件+重复文件」四项全占），此时**数功能清单没有信息量**。

### 1. 先问锚点，再数功能
> **功能同质化赛道的唯一差异化维度是「价值锚点」，不是功能清单。做竞品分析时先问"它把价值锚在哪个焦虑上"，再数功能。**

五类价值锚点（可直接复用）：

| 锚点 | 用户真实诉求 | 代表 | 商业可提取性 | 收入形态 |
|---|---|---|---|---|
| **V1 认知卸载** | "我该删什么？"→"点一下" | CleanMyMac Smart Care、BuhoCleaner Flash Clean、柠檬清理一键 | 中 | 订阅（套件） |
| **V2 可视化** | "空间去哪了？" | **DaisyDisk**、GrandPerspective、Space Lens、Disk Map | 中（**撑不起订阅**） | 一次性买断 |
| **V3 安全感** | "删了会不会坏 / 有没有病毒" | **MacKeeper / Intego / MacBooster**（AV+VPN+ID） | **强**（有持续成本项） | 高价订阅 |
| **V4 可量化省空间** | "给我一个 GB 数字" | 所有产品的宣传页 | **弱**（无持续理由） | 免费 / 极低价 |
| **V5 掌控感 / 身份** | "我要自己决定" | **OnyX**、CLI 工具、Pearcleaner | 弱（换忠诚度） | donation / 免费 |

> **判别法：同一款产品里，价值锚点越靠 V1/V2/V3，ARPU 越高；越靠 V4，越接近免费。功能数量与 ARPU 无关。**
> 极端实证：DaisyDisk **1 个功能** ARPU ¥13；CleanMyMac **25+ 个功能** ARPU ¥268（20 倍）。CleanMyMac 的 25 个功能里 20 个属 V4，溢价来自把 V1/V2/V3 打包进一个按钮。
> 交付形态：把五锚点做成「用户价值感知 × 商业可提取性」**气泡象限图**（气泡大小 = 该锚点在竞品中的覆盖广度），比功能矩阵更能一眼说清结论。

### 2. 定价铁律：功能被"三方夹击"时，定价天花板 = 0
> **只做「清理」（或任何单一可被免费替代的核心动作）的产品，定价天花板 = ¥0。** 三股力量同时清零中间层：
> ① **OS 自愈**；② **免费 + 本地化**；③ **收益可再生 / 无持续交付成本**。
> 要越过 ¥0，必须**在核心动作之外至少迁移到一个有持续成本或强感知的锚点**（安全 / 可视化 / 云盘 / 多设备 / 垂直场景专项）。

**验证法**：逐个问"它的付费理由是核心动作本身吗？"——本赛道 11 个付费主体**没有一个的付费理由是"清理得更干净"**。

### 3. 收订阅的唯一正当理由 = 有一层真实持续交付成本
> 能收 ¥300–500/年的三家（MacKeeper / Intego / Gen Digital）全靠 **病毒库 + VPN 带宽 + ID 监控数据源**；纯本地工具（DaisyDisk / BuhoCleaner / Sensei）**全部只能买断**。
> **这不是营销选择，是成本结构决定的。** 评估任何"要不要做订阅"的产品时，先问"我的持续交付成本是什么"。

### 4. 口碑公式（本赛道实测）
> **口碑与"功能多少"无关，与"付费墙位置 + 是否强制订阅"强相关。**
> 实证排序：BuhoCleaner **4.8**（最激进买断，终身/年费 1.15 年回本）> CleanMyMac 4.7（用量墙）> DaisyDisk 4.7（买断）> MacKeeper 4.3（无免费可用层）> Cleaner One 3.5（功能墙）。
> 与既有「付费墙三分类」的联动：**墙位越靠后（越接近交付环节），转化越高、口碑越差**；墙位越靠前或不设墙，口碑越好、转化越依赖"用上瘾"。

### 六条可迁移结论
1. **差异化不在功能清单，在「付费墙位置 × 价值锚点 × 交付形态」。** 免费开源 ShareX 功能最多、ARPU=¥0；CleanShot X 只 50+ 功能、ARPU 最高。
2. **无持续交付成本 → 只卖买断，不要挂年费。** 截图是纯本地动作；挂年费会被用户一眼看穿"收第二次钱但没交付第二次价值"。
3. **付费墙用"功能墙 + 商用墙"，绝不用"交付墙"。** 墙位越靠后（越接近用户完成劳动那一刻），转化越高、信任损耗越大。
4. **不要在"识别精度"上投入。** OS 免费、微信免费、Umi-OCR 47K★ 免费开源，纯识别已是负数资产。护城河已迁移到**结构化交付**（表格/公式/界面元素→代码）→ 再迁移到**批量的确定性 + 责任承担**。
5. **出海是被严重低估的杠杆。** 同功能美元定价 = 国内 5–10 倍；而**云层是唯一有真实持续成本、因而能正当收订阅的部分**。国内两强（Snipaste $19.99 与 ¥99 同价、PixPin 无国际支付）都白白放弃了这个空间。
6. **坦率的负结论：做"用户端截图工具"的期望 ROI 结构性 < 1。** 本赛道所有赚钱形态都证明：**钱不在"截"这一侧，在"交付"与"责任"这一侧。**

## 「单品收入还原法」+「水印双引擎模型」（2026-09 新增，实证：扫描全能王 CamScanner）

> 适用场景：分析上市公司旗下**单一旗舰产品**（公司不单独披露单品收入），要求回答"这款产品到底赚多少钱"。
> 实证对象：合合信息（688615.SH）→ 扫描全能王。已用两套独立口径交叉验证，误差为 0。

### 1. 单品收入还原法（三步，可复制到任何"公司只披露占比"的场景）

已知条件：① 港股/A 股招股书或年报里常披露**单品收入占比**（如"某产品贡献收入占比 72.3%/76.2%/77.3%/80.6%"）；② 公司总营收必须来自**法定披露**（不能用第三方估算）。

| 步骤 | 操作 | 扫描全能王实例 |
|---|---|---|
| **Step 1 占比 × 总营收** | 年份 → 占比 × 该年总营收 | 2022 9.88×72.3%=7.15 亿；2023 11.87×76.2%=9.05 亿；2024 14.38×77.3%=11.12 亿 |
| **Step 2 用 Q4 反推全年** | 若只有前三季占比，用 `全年总营收 − 前三季营收 = Q4`，按同比例摊 Q4 | Q4=18.10−13.03=5.07 亿 → ×80% ≈ 4.06 亿 → 全年 ≈ 14.57 亿 |
| **Step 3 用「分产品明细」交叉验证** | 找更细的分产品披露（C 端/B 端分列），反算单品 | 2025 智能文字识别 C 端 14.86 亿 − 名片全能王（占比 1.7%→0.31 亿）= **14.55 亿** ✅ 与 Step 2 一致 |

**🔑 结论性事实（2025 年，可直接引用）**：扫描全能王单品收入 ≈ **¥14.5 亿**，占公司营收 **80.1%**，占公司 C 端收入 **93.9%**。
→ **方法论价值**：**"B+C 双轮""多产品矩阵"这类叙事，在单品还原表面前会立刻瓦解。凡是看到公司在讲"第二曲线"，先做这张还原表。**

### 2. 「水印双引擎模型」（C 端 Freemium 工具最被低估的商业设计）

免费版强制水印 = 同时具备三重功能，**不只是一个付费闸门**：

| 引擎 | 机制 | 实证证据 |
|---|---|---|
| **① 付费驱动** | 正式文件不能带水印 → 为「交付件专业度」付费 | 免费版导出全带 "Scanned with CamScanner"，是其最强付费动机 |
| **② 病毒式分发** | 17 亿+ 次下载分发出的文件都携带品牌水印 = 零成本全球曝光 | 印度 2020 封禁后，财政部/地方政府/德里警察局的文件上 4 年间持续出现其水印（Rest of World 查出 30 份政府文件） |
| **③ 政治豁免** | 水印本身成为"禁令无效"的证据链，反向证明产品不可替代 | 印度封禁只禁下载与更新，已安装设备照用，且离线可用 |

**判定规则（可迁移）**：评估任何 Freemium 工具时，问一句——**"免费版留下的痕迹能否替我传播？"** 若答案是"能"（水印/署名/页脚/链接），则免费层的用户价值回收效率远高于单纯广告；若"不能"，则免费层是纯成本。**该模型是扫描全能王 17 亿下载能变现 14.5 亿的核心机制。**

→ **≥5 条时，纯"扫描 + 取字"的 ARPU 结构性趋零；护城河只能建在「扫描之后」**（去反光、鉴伪、大尺寸、学习场景、无水印交付、多端归档）。

### 4. 本赛道四条可迁移结论

1. **钱不在"能不能扫"，在"交付出去的文件够不够专业/安全/完整"。** 付费痛点三特征：**后果不可逆 + 时间成本可量化 + 有持续成本**（云存储/风险监控/持续同步）；收不到钱的全是「一次性动作 + 结果可自验」。
2. **免费通道 ≥5 条时，不要打"功能战"，要打"交付战"和"责任战"。** 合合的独占能力（大尺寸扫描、跨模态鉴伪、学习场景、200+ 国家覆盖）**没有一项是"扫描本身"，全部是"扫描之后"**——这正是它没被 7 条免费通道打死的原因。
3. **单品依赖是本赛道最隐蔽的雷。** 合合财报上写着"B+C 双轮"，还原后是单品占 80.1%、C 端占 93.9%。**分析任何工具类上市公司，第一步先做单品收入还原表。**
4. **AI 能力若 100% 打包进现有产品，就没有第二曲线。** 合合的大模型能力全部用于功能升级，**没有任何独立 AI 收入**；教育是唯一跑通"把免费场景变付费"的方向（蜜蜂 AI 用一体机进校园采购，B 端变现）。

## 「披露颗粒度收窄识别法」+「口径歧义破解法」（2026-09 新增，实证：扫描全能王功能/入口级数据核查）

**触发场景**：用户问"某个入口/某个功能的收入占比或使用量是多少""有没有按功能拆的收入数据"。这类问题在上市公司身上 99% 的答案是"公开渠道为零"，**但直接答"没有"是浪费了一次高价值分析机会**——正确做法是给「可得性光谱 + 收窄轨迹 + 逼近代偿数据 + 代理指标」。

### 1. 先做「数据可得性光谱」（七档，L0–L5）

把颗粒度从上往下排，标出每档是否有数据、来源、覆盖期：

| 层级 | 内容 | 典型可得性 |
|---|---|---|
| L0 | 公司整体（营收/净利/毛利率） | ✅ 年报，完整 |
| L1 | 业务线（赛道 × C/B） | ✅ 年报，完整 |
| L2 | 单品 | ⚠️ 仅港股招股书，且常只覆盖 1 款主力产品 |
| L3 | 收入类型（会员/单次付费/广告/技术授权） | ⚠️ 只有招股书时代有，上市后被合并 |
| L4 | 付费结构（月/季/半年/年费订单占比 + 续购率 + ARPPU） | ✅ **港股招股书"主要经营指标"表** |
| L5 | 功能级 / 入口级 | ❌ **零** |

**规律（可直接复用）**：**L2–L4 只在港股招股书里存在**。A 股年报只到 L1。所以分析任何"已在港股递表 / A+H"的公司，**第一步先去翻港股招股书的"主要经营指标"表**，那里有 A 股年报永远不会给的东西（订单结构比率、分档续购率、ARPPU、B 端净收入留存率）。

### 2. 「披露颗粒度收窄识别法」（本次最有效的发现手法）

**做法**：把该公司不同年份的"按产品收入拆分"表并排放，数维度的条数。

合合实证：**8 条（2018–2022 招股书，广告与技术授权单列）→ 6 条（2023–2024，两者被并入）→ 4 条（2024 年报起，"赛道 × 客户类型"矩阵）→ 4 条（2026 中报，C/B 再合并）。**

**三条判断规则**：
1. **维度数在减 = 公司在藏东西，不是"口径优化"。** 每次收窄都值得当负面信号读。
2. **去机构调研纪要里找口径变更的"公司原话"**（合合在 2025-04-18 的 32 家机构调研里被问到"问题 13：按产品收入披露口径发生了变化"，公司回答了"广告非主要盈利来源、为更清晰体现收入与产品相关性"）。**有原话就能引用，没有原话就只是猜测。**
3. **收窄后要问一句"外部失去了什么判断能力"**：合合并广告后，外部再也看不出"广告变现是在增强还是衰减"，也无法识别"付费转化吃力、靠广告补量"这一风险信号。

### 3. 「口径歧义破解法」（找到别人漏掉的错）

**症状**：同一指标在不同来源差 10–15%，且不是四舍五入能解释的。

合合实证：2024 年扫描全能王收入，招股书写 **¥11.12 亿（77.3%）**，券商研报写 **¥9.82 亿（68.31%）**。差额 ¥1.30 亿。

**破解三步**：
1. **列出所有候选口径**（本例：含广告 / 不含广告）。
2. **找第三个数做加法校验**——本例用"互联网广告推广收入"当年值（2023 年 ¥0.96 亿、2024 年 ¥1.30 亿）去补差额。
3. **回溯验证至少 3 年**，全部吻合才能定论。本例：2022 (6.33+0.82=7.15 ✓)、2023 (8.09+0.96=9.05 ✓)、2024 (9.82+1.30=11.12 ✓)，**三年误差为 0**。

**结论**：**招股书口径的"单品收入"= 该产品会员收入 + 分配给它的广告收入；券商/年报口径 = 仅会员收入。** 派生警告：**2024 年起用"单品收入 ÷ 付费用户数"算 ARPPU 会系统性偏高超 10%。**

### 4. 「功能级数据」的四条结构性障碍（用于说服用户"这数据不存在，不是我没找到"）

1. **归因不可能**：一份文档穿过「相机→增强→OCR→转格式→签名→存储→分享」，收入无法切分到任一环。
2. **销售单元是"会员身份"不是"功能"**：用户买打包 VIP，不是按功能计次。
3. **核心经营机密**：功能级使用分布 = 产品路线图，公开即被抄。
4. **监管未强制 + 公司在主动收窄**（见第 2 条）。

### 5. 「付费墙倍数差 = 功能价值权重」代理指标（拿不到数据时的标准替代方案）

**做法**：把免费版额度与会员版额度做成对照表，算倍数，并判定墙体类型。

- **「独占墙」**（免费版完全没有，如转 Word/PPT、证件模式、拼图、电子签名、去水印、加密、长图）→ **定价骨架**，用户只有买或不买。
- **「配额墙」**（免费给一点、用一次就卡住，如 OCR 10 次/月 vs 1,000 次/月 = 100×，拍题 3 次 vs 不限 = ∞，转 Excel 1 次/月 vs 不限 = ∞）→ **转化诱饵**。**配额倍数越大的功能，越不靠它赚钱，越靠它促转化。**
- **「容量墙 / 时长墙」**（云空间 1GB vs 10GB = 10×，回收站 7 天 vs 30 天 = 4.3×）→ 制造"持续成本"以正当化订阅。

**三条铁律**：① 必须标注为"推断，非披露"；② 它给排序不给百分比；③ "入口"通常 100% 免费、收费动作全在"输出侧"——所以**按入口拆收入在商业上无意义，入口是获客成本中心**。

### 6. 该场景的交付结构（漏斗形，四层）

① 结论先行（明确"零"，别绕）→ ② 七档可得性光谱 → ③ 收窄轨迹 + 公司原话 → ④ **能还原到多细的替代数据**（三层还原表 + 订单结构比率 + 付费墙倍数表）→ ⑤ 数据缺口清单（逐条列"公开渠道无解"，用于防止后续被不可信来源误导）。

**关键提醒**：这类问题的价值不在"回答有没有"，而在**把"没有"变成"这是我能给的最接近的东西"**。

## 「能力市场」五层切分法 + 「商品化塌方」检测（2026-09 新增，实证：纯 OCR / 批量 OCR）

**触发场景**：用户问"单纯某种技术能力（OCR / 语音 / 翻译 / 向量检索 / 视频转码…）的市场状况"。**注意：这是"能力市场"（按量计费），不是"产品市场"（订阅）——两者的分析方法完全不同，切勿套用产品分析框架。**

**关键前提判断**：**能力市场的公开数据通常比产品市场完整得多。** 因为它有 ① 公开单价（云厂商定价页）② 统一基准（benchmark 排行榜）③ 独立厂商财报（对比标的）④ 开源替代品（免费锚点）。**先去查这四项，不要一上来就找"市场规模报告"。**

### 1. 五层切分法（第一件事，不做这步任何规模数字都是错的）

能力市场几乎都能切成这五层，**每层的毛利结构完全不同**：

| 层 | 内容 | 计费单位 | 典型毛利 | 2026 状态规律 |
|---|---|---|---|---|
| **L1** | 开源引擎 | 免费 | n/a | 免费公共品，**精度已常反超商业云** |
| **L2** | 云厂商通用 API | 元/次、$/千页 | 近零（规模摊薄） | 商品化、价格战、同能力报价差 5–10 倍 |
| **L3** | 增强型托管 API（精度/结构分层） | $/千页 | 中 | 按"交付物形态"分层，不按精度 |
| **L4** | 行业解决方案（IDP / 工作流） | 项目 + 年订阅 | 35–45% | **唯一有系统性溢价的一层** |
| **L5** | 场景工程（项目制 / 招标制） | 项目 | 中高 | **唯一价格不透明、能维持毛利的口子** |

**判据**：**"纯某能力"（L1–L2）几乎必然不赚钱**，因为开源免费 + 云 API 价格战。**溢价全部在 L3 以上，且溢价来源不是精度，是"交付物形态 + 责任"。**

### 2. 「商品化塌方」四条检测指标（判断这个能力市场还值不值得进）

1. **开源精度是否已反超闭源旗舰？** 查 OmniDocBench / ParseBench / Dr.DocBench 一类统一基准（OCR 场景）。OCR 实证：GLM-OCR 94.62 / PaddleOCR-VL 94.50 **已反超 GPT-5（85.8）与 Gemini 3 Pro（84.2）**。
2. **自建 vs 商业云的成本比是多少？** OCR 实证：**$0.04–0.09/千页 vs $30–65/千页 = 333–722×**。**成本比 >100× 即判定为"护城河已塌"。**
3. **宽口径与窄口径的 CAGR 差多少？** **这是最容易被忽略、信息量最大的一招。** OCR 实证：宽口径"OCR 整体"CAGR 12.9–16.9%，窄口径"IDP"仅 **4.9%** —— **差 3.5 倍。这个差就是"能力本身在贬值"的财务证据**（价格下行的跌幅抵消了量的增长）。
4. **老牌厂商的应对动作是什么？** 被迫上移 = 塌方确认。OCR 实证：ABBYY（2025 营收 $406–420M）被逼从 OCR 转向 process intelligence、SaaS 占收入 88%、毛利仅 35–45%；**UiPath 弃用 ABBYY 集成改自研**；48% 的 Fortune 500 在内建。

### 3. 「细拆 CAGR 对比法」（找出真正在萎缩的那一档）

拿到行业咨询机构（灼识 / IDC / Gartner）的**细分 CAGR 拆分表**，把每一档除以总增速。OCR 实证（灼识，2022–2027E）：

| 细分 | CAGR | ÷ 总增速 27.3% |
|---|---|---|
| 场景化解决方案 | 31.6% | 1.16× |
| 标准化产品（B 端） | 30.0% | 1.10× |
| 标准化产品（C 端） | 22.4% | 0.82× |
| **基础技术服务（≈纯能力）** | **16.5%** | **0.60×** |

**规律：最末一档"基础技术服务"永远是最低的。** 这个 0.60× 在 2022 年就预言了 2026 年的塌方。**做能力市场分析，先找这张表，再除以总增速。**

### 4. 批量场景的四个经济学特征（"批量"≠"能力"）

批量业务（批量 OCR / 批量转码 / 批量翻译）与纯能力的本质区别：

1. **单页价格被量摊薄到失效，价格锚点转向「并发」和「私有化许可」。** 实证：某电商月调用 20 万次，**基础费 ¥800，QPS 叠加包 ¥3,600（占 82%）**。百度 QPS 包 ¥10/天/QPS、¥180/月/QPS。
2. **总成本公式 ≠ 调用量 × 单价**：`基础调用费 + QPS 叠加包 + 资源包过期损失 + 人工校对成本`（98% 准确率 → 每万次仍有 200 张需人工修）。
3. **计费细节是隐形战场**：失败是否计费、错误码是否计费（腾讯云部分错误码也收费）、按页还是按字符、表单是否加收。
4. **真正的付费点是「无人工干预通过率」（straight-through rate），不是识别率。** 而这个指标**恰恰是所有厂商最不公开的** —— 报告里应把它列为头号数据缺口。

**定价实证（OCR 票据）**：通用 OCR ¥0.009–0.0825/次 vs **医疗票据 ¥0.35–0.8/次（10–80 倍）**。溢价来自**字段完整率**（漏掉"医保类型""医院等级"会导致二次人工录入），**不是识别精度**。

### 5. 该赛道的三条可迁移结论

1. **能力不是护城河，"交付完整性 + 兜底责任"才是。** 所有溢价（医疗票据 10–80 倍、IDP 毛利 35–45%、政务档案招标制）都来自"交付出去的东西能不能直接用、出错谁负责"。
2. **唯一能守住的能力层护城河是「数据主权 / 私有化合规」**，不是算法。实证：欧盟 GDPR 下本地部署占 **71%**，而云原生 OCR 增速仅 **9.7%**。
3. **如果必须留在能力层，做「路由层」而不是「引擎层」。** 成熟管道标准架构：便宜引擎跑简单多数 + 强引擎兜难例 + confidence gate 路由；**把 extract 做成可换后端的接口——"接口才是产品，模型是可替换件"。**

### 6. 该场景的交付结构（漏斗形，七段）

① 结论先行 → ② **五层切分表**（价格 × 毛利 × 状态）→ ③ **规模口径对照表 + 可信度分级**（★–★★★★，明示哪些不可引用）→ ④ **商品化塌方证据链**（开源精度 + 成本比 + CAGR 差 + 老牌厂商动作）→ ⑤ 竞品分层对照（开源 / 托管 API / 中国厂商）→ ⑥ 批量场景的四个经济学特征 → ⑦ 五层漏斗收敛 + 数据缺口清单。

### 7. 市场规模来源的可信度分级（能力市场必备，直接复用）

| 级别 | 类型 | 用法 |
|---|---|---|
| ★★★★ | Grand View Research、灼识咨询（CIC）、Gartner/IDC、统一 benchmark（OmniDocBench 等） | 可直接引用为主锚点 |
| ★★★ | Coherent MI、Precedence Research、厂商官方定价页、GitHub 实测 | 可引用，需注明口径 |
| ★★ | 厂商立场横评站（idp-software.com / anyformat.ai 一类）、券商研报二手引用 | 交叉验证用，不单独引用 |
| ★ | SEO 型市场报告（pmarketresearch / marketlensiq / IIM 信息 / 博研咨询） | **仅作区间参考；同一赛道常自相矛盾（实测出现过同文两处数字差 1.75 倍）** |
| ★★★★（一手） | **政府采购 / 招投标平台** | **能力市场唯一的原始一手价格证据，务必去查** |

## 「客户端独立使用」场景的三条判定法 + 一手机型基准数据（2026-09 新增，实证：C 端桌面 OCR）

**触发场景**：用户问"C 端用户 / 个人用户在**独立客户端**上使用某能力（OCR、翻译、压缩、取词…）是否可做分析、市场如何"。**注意：这既不是"能力市场"（按量计费）也不是"产品市场"（订阅 SaaS），而是介于两者之间的"单机客户端"层——它的商业化规律与前两者都不同。**

### 0. 先立口径：三个限定词各砍掉一半市场

```
"C 端" → 排除 B 端采购与 API 计费
"客户端" → 排除网页一次性工具、移动 App、SaaS 尾巴
"独立使用" → 排除账号绑定型订阅
```
**「独立使用」= 桌面客户端能脱离账号与云端独立完成主任务。这条定义直接决定商业化后果：独立 = 无法计费到账号 = 无持续交付成本 = 只能一次性买断 = 收不到第二次钱。** 与 PopDrop、虚拟桌面、磁盘清理结构同构。

### 1. 「包体撕裂」判定法（本条线最强的单一结构证据）

同一赛道内比较各产品的**安装包体积**，会出现两个极端，**两个极端都不赚钱**：

| 包体 | 架构 | 后果 |
|---|---|---|
| **极小包（1–5 MB）** | 下载器壳 + 云端处理 | 有按次云成本 → 必设次数限制 → 交付墙 → **口碑最差** |
| **极大包（100–500 MB）** | 端侧引擎（打包模型） | 无持续成本 → 只能免费或买断 → **收不到钱**，且对标免费开源 |
| **中间量级（薄壳 + 系统引擎）** | **调 OS 自带能力**（Apple Vision / Windows OCR API） | **唯一跑通**：引擎成本转嫁给 OS 厂商，可永久免费或极低价买断 |

- 实证（桌面 OCR）：夸克扫描王 PC **2.44MB** / 迅捷OCR 联想渠道 **3.65MB** ↔ 扫描全能王 PC **149MB** / Umi-OCR **约 440MB**（**差 120 倍**）；而 TextSniper（$11.99 无限设备）、Cheese! OCR（$0）、ClariRec（¥36）全部是第三种。
- **判定规则**：看到极小包，直接推三件事（必有次数限制 / 必有终身无限次的负毛利敞口 / 差异化不可能来自端侧）；看到极大包，直接问"凭什么比免费的 Umi-OCR 贵"。

### 2. 「形态替换」检测（新入局者换的是"层"不是"功能"）

当赛道内出现一批新入局者时，**先看它们的引擎从哪来、包体多大、定价多少**，而不是看功能：
- 桌面 OCR 实证（2026 年全部新入局者）：Cheese! OCR（Apple Vision，无网络权限，$0）、ClariRec（Vision + 本地 GLM-OCR，¥36）、HushSnap / ImgPeel（本地，$0）、GhostText（云端 API，$4.99 终身）——**无一例外是"薄壳 + 免费引擎"，定价 $0–9.99。**

### 8. 四条可迁移结论（客户端独立使用层通用）

1. **"独立"这个词在商业上是减分项。** 独立 = 无账号 = 无持续交付 = 只能买断 = 封死第二次收入。任何"独立客户端"类产品，第一步先问：**我的持续交付成本是什么？没有，就只卖终身，不要挂年费。**
2. **星标与收入反比，活跃度优先于星标。** 判断这条线的项目健康度只看 `pushed_at`；判断商业健康度只看"有没有持续交付成本"。
3. **不要投"识别精度"。** 开源已反超商业云（PaddleOCR-VL 94.5 / GLM-OCR 94.62 vs GPT-5 ≈85.8），且用户实测确认**"只要模型转为本地，识别能力就会大大下降"**——「本地 + 隐私 + 高精度」三者不可兼得，必须选二。
4. **唯一还值钱的方向是"能力之后的交付"。** 本层能收钱的格子只有：结构化交付（表格/公式/竖排/代码）、隐私、懒（一步到剪贴板），外加新出现的「大模型客户端极简壳」。**落地表达："全行业只做到'输出文本'，没有一家做到'输出可直接用'。"**

## 「免费单品工具」四通道变现解剖法 + 「赞助位零成交」判据（2026-09 新增，实证：CrystalDiskInfo）

### 2. 「赞助位零成交」判据（本次最有信息量的负结果）
> **看赞助位是最省力的单品商业化体检**：2,000 万次/年下载 + 3,366★ + 4.7 分，**换不来一个 $1,000/月的企业赞助席位** → 说明**该品类对 B 端品牌方没有赞助价值**，捐赠只能停在个人情感层（$10–100）。
> 派生决策规则：**若赞助位空白而单品已成名，正确动作是做深"一个可维护的判定能力"，不是"继续加功能"。**

### 3. 「全量下载归一化」三件套（比 stars 重要一个数量级）
1. **SourceForge 统计 API 是免费单品唯一可量化渠道**：`sourceforge.net/projects/{p}/files/stats/timeline` → 给"区间内全量下载"（实证：90 天 5,156,766 次）；项目页给"周下载"；子目录页给**逐文件周下载**（逐文件数据是"渠道结构分析"的唯一入口）。
2. **渠道结构比总量更有信息量**：标准 exe 45.7% / ZIP 21.3% / **Ads 20.3%** / 主题版 12.6% / 源码 0.05%。**源码占比 0.05% = 开源是信任背书而非生态共建**；**Ads 占比 20% = 变现规模可直接算出年化安装量**。
3. **必须声明"下限"**：官网 redirect、Store、PortableApps、Chocolatey、各国下载站均不在 SourceForge 计数内 → 写"仅单渠道，实际为下限"，且"次 ≠ 台 ≠ 人"。

### 4. 三条可迁移结论（与既有赛道结论同构）
1. **「行业约定格式」是无法定价的资产。** 当一款工具成了"大家都用它截图/发帖/举证"的默认格式（CDI 三色灯之于二手盘交易），护城河是真的，但价值只能被捐赠——**上移所需的梯子（商用授权 / 主动动作）往往被它自己用 MIT 与"只读"主动砍掉了**。
2. **广告捆绑 = 一次性卖品牌，不是商业模式。** 用 20% 流量换现金，对价是官网被安全厂商与英文社区公开质疑"还安全吗"。**有口碑的免费工具宁可只做买断/联名。**
3. **空位永远在能力边界外一厘米处。** CDI 用户原话：*"只能被动读 SMART，清零盘的 CDI 表面反而漂亮"* → **"判定（真假/真伪/是否还能用）+ 可举证验证（带时间戳、防篡改）"是与备份赛道「恢复验证」、清理赛道「可回滚验证」结构完全同构的第三个实例**。凡"读数据型"工具，都去查它的能力边界，边界外那一步就是付费点。

### 5. 老牌免费工具必查的五项现场取证（缺任何一项都写不出商业化结论）
`Ads.exe` 内嵌子安装器的签名方与落地注册表键（Tom's Hardware/F5 Forums 一类逆向帖）｜官方 support 页是否**自述**捆绑（CDI 官网有「About bundling advertisements with installers」小节，这是最硬的一手证据）｜**版权方/代码签名变更日志**（CDI 9.7.0「Added CrystalMark Inc. as copyright holder」= 个人作者法人化的信号）｜第三方冒名站点（中文 SEO 站 `crystaldiskinfo.org` 自称"中文网"）｜下载站标注冲突（华军同产品一处标"共享软件"一处标"免费软件"）。
