## 0. 使用方式：三个档位

分析不是越长越好。先确定档位，避免用 3 小时的深度去做 10 分钟的判断。

| 档位 | 耗时 | 做什么 | 产出 |
|---|---|---|---|
| **速判** | 15 分钟 | 只答 [10 问快扫](#2-10-问快扫15-分钟版) | 10 行表格 |
| **标准** | 1–2 小时 | 七层扫描 + 判定工具箱关键几把尺子 | 一页纸结论 + 分层表格 |
| **深度** | 半天以上 | 七层全扫 + API 实测 + 交叉验证 + 缺口声明 | 完整报告（走 `product-research-report` 模板） |

**档位选择规则**：目的是「判断要不要投入」→ 速判；「决定做什么」→ 标准；「落盘归档、对外输出」→ 深度。

## 1. 六条核心原则

这六条比任何清单都重要，它们决定你会不会问出正确的问题。

### ① 先问口径，再问结论
「用户 100 万」这句话在不知道口径时信息量为 0。是注册数、下载数、月活、还是累计？不知道口径的数字无法横向比较，也无法验证。

### ② 价值不由功能数量决定
功能是**成本**，不是价值。一个 200 功能的产品可能不如一个 3 功能的产品值钱。
正确的问法是：**用户为哪一件事付钱？** 而不是「它有多少功能」。

### ③ 永远把「免费替代」与「什么都不做」放进竞品格
绝大多数产品的真实竞争对手不是同类商业产品，而是：
- 系统内置的免费功能
- 开源免费工具
- 用户自己用 Excel / 脚本凑合
- **用户忍着不做**（成本为 0，且极难被击败）

忽略这两格的竞品分析，结论必然乐观失真。

### ④ 频次决定商业模式
- 日频 → 可以订阅、可以养成习惯
- 周频 → 可以订阅，但需要强价值
- 月频 / 一次性 → 只能买断或按次，**收订阅会引发反感**

### ⑤ 看趋势不看快照
任何产品分析都必须包含一句：「它会被什么吃掉？」
- 会被 OS 内置功能吃掉？
- 会被大模型能力下放吃掉？
- 会被免费开源替代吃掉？
- 会被平台政策（如应用商店抽成/API 涨价）吃掉？

### ⑥ 结论必须可执行
「这个产品有前景」「市场竞争激烈」——这类结论无价值。
必须落到：**该抄什么 / 别做什么 / 从哪进场 / 需要什么验证**。

## 2. 10 问快扫（15 分钟版）

时间紧时的最小可用分析。每问限 60 字以内。

| # | 问题 | 回答的是 | 答不出来意味着 |
|---|---|---|---|
| 1 | 它替谁完成了什么任务？（一句话，**不用品类词**） | 定位 | 你还没看懂它 |
| 2 | 用户不用它会怎样？替代方案谱系（含「忍着不做」） | 需求硬度 | 你高估了需求的必要性 |
| 3 | 谁付钱、付多少、为什么**现在**付、会付多久？ | 商业模式 | 它的收入是偶然 |
| 4 | 付费墙卡在哪一层？有没有真实的持续交付成本？ | 订阅正当性 | 订阅是硬收的，会流失 |
| 5 | 差异点是真差异化还是包装？（拿去和免费替代对撞） | 竞争力 | 可能是伪卖点 |
| 6 | 用户量 / 营收的真实数字？口径是什么？ | 规模 | 你在凭感觉判断 |
| 7 | 竞争四层里谁最危险？系统 / 大厂做了会怎样？ | 生存风险 | 你可能在分析一个会消失的产品 |
| 8 | 护城河是什么？还能守多久？ | 持续性 | 它随时可被复制 |
| 9 | ARPU / 人均产出说明它的模式效率如何？ | 效率 | 你看不出它的商业模式质量 |
| 10 | 结论：抄什么 / 别做什么 / 从哪进场？ | 行动 | 分析没有产出价值 |

> **填写示范（形式示范，数字处一律留占位，禁止凭空填数）**

| # | 示范答法 |
|---|---|
| 1 | 「想给文件改个名，但不想学正则/脚本，用一句话描述就完成批量重命名」——注意：这里没有出现「AI 工具」这类品类词 |
| 2 | 替代谱系：手动一个个改 / Excel 拼公式 / 写脚本 / 系统自带重命名 / 免费开源批量改名工具 / **忍着不改** |
| 3 | 收费对象=个人用户；价格=【待实测官网定价页】；现在付的理由=【待验证：是一次性需求还是周期性需求】；付多久=【取决于是否有持续交付】 |
| 4 | 墙型=【待判定：功能墙 / 用量墙 / 时间墙 / 体验墙】；持续交付成本=【待验证：是否有云/模型/内容层】 |
| 5 | 卖点拿去和免费开源替代对撞后剩余价值=【待实测】 |
| 6 | 活跃/下载量=【API 实测】；营收=【官方宣称/推算，需标注】 |
| … | 其余同理，**先搭骨架，数字后补，缺口单列** |

## 3. 七层提问法（完整版）

顺序不可颠倒：**先定口径 → 再说是什么 → 再定给谁 → 再问为什么成立 → 再问怎么赚钱 → 再看竞争 → 再判持续性 → 最后收敛**。
颠倒顺序最常见的后果是：还没搞清「给谁用」，就开始算营收，然后在错误的人群上算出一堆正确但无用的数字。

### L0 · 口径与边界

> **一句话目标**：把「这次分析是什么、要回答什么、数据算什么」钉死。

| 要素 | 必答内容 | 追问 |
|---|---|---|
| 分析对象粒度 | 单品 / 产品矩阵 / 赛道 | 是分析「这一个」还是「这一家」还是「这一品类」？ |
| 快照时间与版本 | 软件版本号 + 数据日期 | 结论多久会过期？ |
| 分析目的 | 抄它 / 投它 / 打它 / 学它 / 替代它 | 目的是什么？目的决定维度权重 |
| 计数口径 | 功能怎么数 | 最小能力单元 vs 用户可感知功能？两个数都写吗？ |
| 数据可信度分级 | 逐条标注等级 | ①经审计 ②API 实测 ③官方宣称 ④第三方估算 ⑤二手转载 |

**产出**：6 行元信息引用块 + 一句「本分析要回答的 3 个问题」。

### L1 · 是什么（What）

> **一句话目标**：在不贴品类标签的前提下，说清它替用户做了什么。

**必答 5 问**
1. **一句话定义**：先说它替用户做了什么，不要先贴品类标签。
   - ❌ 「这是一个 AI 桌面助手」——品类词会把竞品集合锁死，且掩盖真实价值。
   - ✅ 「它在任意窗口里按快捷键就能把当前内容喂给模型并就地给出结果」。
2. **品类归属**：陌生用户会把它放到哪个货架？——货架决定竞品集合与定价参照。
3. **最小可用内核**：删掉所有包装，用户为哪**一件事**安装 / 付费？
4. **Non-scope**：它明确不做什么？（范围边界 = 定位的负空间，也是它与竞品的真正分界）
5. **功能全景**：按模块切分 → 再按四层分层。

**四层功能分层（核心工具）**

| 层 | 定义 | 判定话术 | 商业含义 |
|---|---|---|---|
| **T1 内核** | 去掉它产品不成立 | 「删掉这个功能，还有人来用吗？」 | 定价地基，必须做到最好 |
| **T2 增强** | 提效但可替代 | 「没有它，用户还能完成任务吗？」 | 决定体验口碑，通常不该单独收费 |
| **T3 差异化** | 只有它有 | 「竞品有这个吗？免费替代有这个吗？」 | 卖点来源，但要验证是否被免费替代覆盖 |
| **T4 长尾** | 低频 / 边缘 | 「有多少用户真的会用到？」 | 常是「看起来很强」的装饰，警惕拿它当卖点 |

**取证**：官网功能页 / 定价页 / 官方文档 / CHANGELOG / 用户手册 / 配置文件示例（配置项 = 完整开关面，信息密度最高）。

### L2 · 给谁用、什么时候用（Who & When）

> **一句话目标**：找到「谁在用、谁在付、在什么时刻想起它」。

**必答 6 问**
1. **用户分层**：核心用户 / 边缘用户 / **付费方**——三者常不同（B 端尤其），必须分开写。
   - 追问：「使用者」和「决策者」是同一个人吗？
2. **触发场景（JTBD）**：什么时刻会想起它？
   - 标准句式：**「当我在 ___ 的时候，我想要 ___，这样我就能 ___」**
3. **使用频次**：日 / 周 / 月 / 一次性 —— **频次决定能否收订阅**。
4. **替代方案谱系（必须列全 6 类）**：

| 类别 | 它是谁 | 威胁度 |
|---|---|---|
| 手动做 | Excel / 脚本 / 手工操作 | 中（费力但免费） |
| 系统内置 | OS / 平台自带功能 | **高**（零成本、零学习） |
| 免费开源 | 开源工具 | **高**（多数场景够用） |
| 竞品 | 直接 / 间接竞品 | 视情况 |
| 外包或找人做 | 请人代做 | 低 |
| **忍着不做** | 用户接受现状 | **最高**（成本为 0，无法被击败） |

5. **切换成本**：迁移数据 / 重新学习 / 团队习惯 / 集成改造 / 沉没成本。
6. **用户在哪讨论它？最常出现的褒贬词？**
   - 取证：论坛 / 社区 / 应用商店评论 / 社交媒体。
   - ⚠️ **不可编造用户声音**。没有一手素材就写「未见一手用户反馈，建议补充访谈」。

### L3 · 为什么成立（Why / 价值主张）

> **一句话目标**：验证它的需求是「真需求」还是「看起来像需求」。

**必答 5 问**
1. **痛点 / 痒点 / 爽点**——只有痛点才好收钱。

| 类型 | 特征 | 付费意愿 |
|---|---|---|
| 痛点 | 不做会有明确损失（时间/钱/风险） | **强** |
| 痒点 | 做了更爽，不做也无妨 | 弱 |
| 爽点 | 情绪价值、身份认同 | 中（波动大） |

2. **卖点真伪判定**：把每条卖点拿去和「免费替代」对撞，对撞后还剩多少？
3. **可感知的 10 倍**：提升是可感知的，还是需要教育？
   - **需要教育才被理解的卖点 ≈ 不存在。**
4. **刚需还是可选**：没有它，用户的损失是什么（时间 / 钱 / 风险）？能否量化？
5. **天花板**：TAM / SAM / SOM 粗算，**必须标口径**——三口径常差 2–3 倍。

### L4 · 怎么赚钱（How Money）

> **一句话目标**：说清「谁付钱、为什么现在付、能付多久」。

**必答 9 问**

1. **收费对象**：C 个人 / C 专业 / B 团队 / 企业采购 / 平台分成 / 广告 / 数据变现。
2. **计费单位**：买断 / 订阅 / 按量 / 按席位 / 免费增值 / 打赏 / 一次性授权。
3. **付费墙位置**（四种墙）——墙的位置直接决定商业模式类型：

| 墙型 | 机制 | 对应的商业类型 | 典型流失原因 |
|---|---|---|---|
| **功能墙** | 部分功能锁付费 | 工具型 | 用户只用免费功能 |
| **用量墙** | 免费额度用尽 | 服务型 | 用户量小、额度用不完 |
| **时间墙** | 试用期结束 | 习惯转化型 | 试用期内没养成习惯 |
| **体验墙** | 去水印 / 去广告 / 去限制 | 打扰变现型 | 用户忍受打扰也不付 |

4. **续费理由**：是否存在「一层真实的持续交付成本」？
   - 云资源 / 模型调用 / 内容持续更新 / 合规与安全 / 人工服务。
   - **没有 → 订阅不成立，只能买断。** 硬收订阅 = 一次性流失。
5. **价格锚点**：它相对什么定价？（竞品 / 人力成本 / 损失规避 / 心理价位）
6. **ARPU 与断层**：
   ```
   ARPU = 年营收 ÷ 活跃用户        人均产出 = 年营收 ÷ 团队人数
   ```
   同赛道 ARPU 差异由 **付费理由强度 × 计费结构 × 人群净值 × 计价货币** 四项决定，
   **不由功能数量决定**。看到 10 倍以上的 ARPU 断层，先查这四项，不要归因于功能。
7. **转化漏斗反推**：
   ```
   付费用户数 ← 转化率 ← 活跃规模 ← 获客渠道
   ```
   例：目标年营收 ¥500 万、客单价 ¥300/年 → 需 1.67 万付费用户；若转化率 1% → 需 167 万活跃。**判断这个量级是否可达。**
8. **单位经济**：CAC / LTV（LTV:CAC 应 > 3）/ 毛利率 / 退款率 / 渠道分成（应用商店 15–30%）。
9. **定价天花板**：当功能被「系统内置 + 开源免费 + 大厂免费版」三方夹击时，天花**趋近 0**。
   - 追问：它的某个功能是否已经能在别处免费拿到？如果是，这个功能不能定价。

### L5 · 竞争位势（Where）

> **一句话目标**：搞清它在四层竞争结构里的位置，以及谁最可能杀死它。

**必答 6 问**

1. **竞争四层**：直接竞品 / 间接竞品 / 免费替代（开源 + 系统内置）/ 用户自己动手。
2. **对比矩阵维度**：功能覆盖 · 定价 · 平台 · 目标人群 · 渠道 · 生态与插件 · 数据迁移成本。
3. **差异点层级**——越靠后越难被抄：

| 层级 | 举例 | 可复制难度 |
|---|---|---|
| 功能 | 多一个导出格式 | 极低 |
| 体验 | 交互更顺、速度更快 | 低 |
| 价格 | 更便宜 | 低 |
| 人群 | 只服务设计师 | 中 |
| 渠道 | 只在小红书做增长 | 中高 |
| 品牌 | 成为某类用户的心智默认 | **高** |

4. **竞品盲区**：对手「明确不做什么」？——**本层信息量最高，机会常在这里。**
   - 追问话术：这个头部产品为什么不做 X？是做不到、不划算，还是看不上？
5. **谁在攻击它**：新入场者 / 大厂功能下放 / 开源替代 / 平台政策变化。
6. **系统内置威胁**：如果 OS 或平台方把它做成系统功能，它还活吗？
   - 这是桌面 / 效率工具类产品的**头号生死问题**，必答。

---

### L6 · 能不能持续（Sustainability）

> **一句话目标**：判断它「强」是暂时的还是可持续的。

**必答 7 问**

| # | 问题 | 判定要点 |
|---|---|---|
| 1 | **护城河类型** | 网络效应 / 数据飞轮 / 切换成本 / 生态与插件 / 品牌 / 成本结构 / 补贴 |
| 2 | **护城河时间窗** | 还能守多久？**给出时间估计 + 依据**（越具体越好） |
| 3 | **团队与资源** | 人数 / 融资轮次与金额 / 人均产出 / 现金流正负 |
| 4 | **平台依赖** | 单一分发渠道 / 单一 API / 单一 OS 政策 / 单一模型供应商 |
| 5 | **技术风险** | AI 是否把它降维成「一个 prompt」？模型能力下放是否吞掉它？ |
| 6 | **合规风险** | 数据隐私 / GDPR / 个人信息保护法 / 版权 / 内容安全 |
| 7 | **生命周期位置** | 萌芽 / 成长 / 成熟 / 衰退——依据是什么 |

**生命周期判定信号表**

| 阶段 | 正信号 | 负信号 |
|---|---|---|
| 萌芽 | 功能少但尖锐、用户讨论在增长 | 无付费、无留存验证 |
| 成长 | 用户量与营收同步增长、渠道扩张 | 竞品开始模仿 |
| 成熟 | 品牌确立、涨价仍留存 | 增长停滞、功能堆砌（转向内卷） |
| 衰退 | 靠涨价维持营收 | 停更、系统内置替代出现、团队流失 |

---

### L7 · So What（结论与行动）

> **一句话目标**：把分析转成决策。**这一层没写，前面全白干。**

**必答 5 问**
1. **结论先行**：3–5 条编号判断——**全文最重要，放最前**。
2. **可迁移清单**：能抄什么（机制 / 定价 / 增长手法 / 交互设计）。
3. **反面清单**：别做什么（它踩的坑 / 它的伪需求 / 它的过度设计）。
4. **机会点**：若我要进场，切入点在哪？最小验证是什么（MVP 验证方案）？
5. **数据与测算**：附 A 明细 + 附 B 测算过程（含敏感度）+ 附 C 缺口声明与应查未查清单。

## 4. 判定工具箱（九把尺子）

七层解决「问什么」，九把尺子解决「怎么下判断」。每把尺子都是可操作的快速判定法。

### 尺子 1 · 差异化真伪四步判定
1. 列出它自称的差异点。
2. 对每个差异点，找**免费**替代实现（开源 / 系统内置 / 大厂免费版）。
3. 若免费方案已能覆盖 80% → 判定为 **「包装」**。
4. 剩余真正无法被免费替代的差异点，才是它的定价依据。

### 尺子 2 · 订阅正当性三问
1. 用户的使用是**周期性**的吗？（一次性需求收订阅 = 必然流失）
2. 产品方有**持续交付成本**吗？（云 / 模型 / 内容 / 合规 / 人工）
3. 续费时，用户是否**获得了新价值**？
> 三问全「是」→ 订阅成立；任一为「否」→ 应改买断或按量。

### 尺子 3 · 付费墙位置 → 模式类型映射
见 [L4 表格](#l4--怎么赚钱how-money)。判定顺序：先找墙在哪，再看持续交付成本，最后定模式名称。
> 加固证据：**包体差 / 价格档差异**常能反推架构与墙的位置。

### 尺子 4 · 护城河时间窗评分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 可复制性 | 纯功能，一周可抄 | 需数月工程 | 需多年数据 / 网络效应 |
| 迁移成本 | 无数据沉淀 | 有配置/习惯 | 有团队级数据资产 |
| 生态位 | 无插件无集成 | 有部分集成 | 有开发者生态 |
| 平台风险 | 完全依赖单一平台 | 多平台 | 自建渠道 |

总分 0–3：护城河 < 6 个月；4–5：6–18 个月；6–8：18 个月以上。
**必须写依据，不要只给分数。**

### 尺子 5 · 定价天花板公式
```
定价天花板 ≈ min(竞品价格, 用户人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)
```
免费替代覆盖率越高，天花板越低；覆盖率达 100% 时天花板 = 0。

### 尺子 6 · 需求硬度矩阵

|  | 低频 | 高频 |
|---|---|---|
| **痛感强** | 一次性买断，高价可接受 | **最佳赛道**，订阅成立 |
| **痛感弱** | **不做**（无法变现） | 免费功能 / 引流品 |

### 尺子 7 · 机会点四象限

|  | 赛道拥挤 | 赛道空位 |
|---|---|---|
| **我有优势** | 差异化切入，靠体验/人群细分 | **优先做**（最佳） |
| **我无优势** | 不做 | 需先补齐能力，谨慎观察 |

### 尺子 8 · 生命周期判定信号表
见 [L6 表格](#l6--能不能持续sustainability)。用「正信号 vs 负信号」数量对比定位阶段。

### 尺子 9 · 开源覆盖度五级判定（2026-10-08 新增，本手册最省力的一把）

**为什么单独成尺**：开源是免费替代里**功能最全、最难打、也最容易被漏查**的一档。只凭"有开源但不成熟"就放行，是分析里最常见的一次性致命误判。**这把尺子 5 分钟能跑完，却经常直接决定要不要做。**

| 等级 | 判据 | 决策 |
|---|---|---|
| **L0 未被覆盖** | 搜不到 Star > 1k 的同功能项目，或只有 CLI 无 GUI | 可继续 |
| **L1 有库无产品** | 有成熟**库/引擎**，但没有可直接给终端用户的**成品** | ✅ **最佳位置**：复用它的库，做它没做的产品层 |
| **L2 有成品但不活跃** | 有开源 GUI 成品，但 `pushed_at` > 6 个月，或体验差 / 无中文 | ⚠️ 可进场，须回答「为什么是现在、为什么是我」 |
| **L3 有活跃成品** | Star > 10k + 30 天内仍有提交 + 功能高度重叠 | 🔴 只做它**明确不做**的那一段，否则别做 |
| **L4 被 OS / 官方免费覆盖** | 开源之外，OS 内置或大厂官方免费工具已做同一件事 | ⛔ **直接砍**，别再谈 AI 增强 |

**四个必查动作（缺一项即视为没查）**：
1. `Stars` + `pushed_at` **一起看**——高 Star + 停更久 = **空位，不是威胁**。
2. 查 **License**——AGPL 一票否决、GPL 传染、`NOASSERTION` 必须逐组件核（四档矩阵见公共文档 §4.1）。
3. 区分「**开源竞品**」（抢用户 → 记威胁）与「**开源底座**」（省成本 → 记杠杆）——同一项目在不同用途下结论相反。
4. 中英关键词**各搜一遍**（`duplicate file finder` / `重复文件查找`），否则会漏掉 libvips、pdfcpu 这类中文圈零讨论的主流项目。

> **实证校准（2026-10-08 实测）**：重复文件查找 = **L3**（czkawka 34,057★）｜批量重命名（Windows）= **L4**（PowerToys/PowerRename 139,292★、MIT）｜图像底层处理 = **L1**（libvips 11,711★）｜本地大模型推理 = **L1**（llama.cpp / Ollama 是运行时不是产品）。
> 细则、29 个项目的一手数据、「先判死再省钱」的两套动作，见 `调研\方法\开源竞品与可复用能力.md`。

## 5. 数据口径陷阱清单

**本手册最值钱的一节**。同一个数字，口径不同可以差 10 倍以上。

| 指标 | 常见陷阱 | 正确处理 |
|---|---|---|
| 用户量 | 「注册用户」≠ 活跃；下载量含重复下载、爬虫、预装 | 优先 MAU / 付费用户数；一律标口径 |
| 营收 | 「服务 X 万客户」是累计数、非年化 | 找经审计财报；否则标「官方宣称」 |
| 融资额 | 累计融资 ≠ 当期现金；估值 ≠ 融资额 | 标轮次 + 时间 + 领投方 |
| GitHub Star | Star ≠ 使用量，可能只是「收藏了再说」 | 用「包下载量 ÷ Star」判真实集成度；**Star 高 + 停更久 = 空位不是威胁** |
| **开源许可**（2026-10-08 新增） | 把 `NOASSERTION` 当"无许可"；忽略 **AGPL 的 SaaS 传染**（直接触发整线开源义务）；把 **open-core / fair-code** 当"全免费可复用" | 逐组件查（`crates.io` / `package.json` 的 `license` 字段比仓库 LICENSE 更准）；过四档矩阵 |
| **开源"竞品"与"底座"混淆** | 同一开源项目，按用途结论相反 | 分开记账：抢用户的记**威胁**，能复用的记**杠杆** |
| 定价 | 促销价冒充标准价；未含税；未计汇率 | 记录采集日期 + 币种 + 是否含税 |
| 市场规模 | 不同机构口径差 2–3 倍 | 必须切层（TAM/SAM/SOM）+ 标来源 |
| 口碑 / 评论 | 内容农场灌水、刷好评、竞品黑稿 | 多源交叉；**重点读差评与中评** |
| 独立开发者产品 | 营收数字多为自述，缺乏审计 | 区分「自述 / 推算 / 审计」三级 |
| 活跃度代理指标 | 论坛发帖量 ≠ 用户活跃 | 需与下载量 / 留存交叉验证 |

> **核心纪律（2026-10-08 修正）**
> 1. 二手数据必须标注口径与可信度等级。
> 2. **禁止的是「无依据的数字」，不是「估算」本身。** 拿不到的数据不许只写缺口了事：先给获取路径；确实取不到，就按「合理预估五法」（自上而下 / 自下而上 / 类比推算 / 锚点反推 / 区间优先）给出有依据的推算，写成 **假设 → 依据 → 推算 → 结果** 四段，并附**置信度**与**敏感度**（关键假设 ±50% 后结论是否翻转）。
> 3. 每个数字带标签：`【实测】/【审计】/【官方宣称】/【推算·方法】/【预估·依据】/【未取得】`；【未取得】只进缺口清单，且必须附获取路径。
> 4. **预估与实测在版面上分开**（单列「测算过程」节），不许混进同一张表冒充实测。
> 5. 完整方法（源分级 / 完整性三问 / 三角印证与反方证据 / 可复算规范 / 标注规范）见 `SKILL.md` §四「数据获取与测算方法论」。

## 6. 取证路径表：每条结论去哪儿找证据

| 要证明什么 | 一手取证路径 |
|---|---|
| 功能清单（做到穷举级） | 官网功能页 + 官方文档 + CHANGELOG + 用户手册 + **配置文件示例**（配置项 = 完整开关面） |
| 定价与付费墙 | 官网定价页 + 官方 Guide/FAQ + 应用商店内购页 |
| 开源项目热度与状态 | GitHub API：`/repos/{owner}/{repo}` 取 stars / forks / license / pushed_at（**走 WebFetch 打 `api.github.com`，绕开匿名配额**） |
| 开源项目真实使用度 | `flathub.org/api/v2/stats/{app_id}`（Linux 真实装机 + 逐日曲线，**端应用最高价值源**）；`crates.io/api/v1/crates/{name}`（库的真实嵌入量 **+ license**）；`api.npmjs.org/downloads/point/last-month/{pkg}`；SourceForge files stats（老牌免费单品） |
| **开源可否复用**（2026-10-08 新增） | 逐组件查许可（`crates.io` / `package.json` / 项目内分模块 LICENSE）；判断是 open-core 还是全开源；确认有无 GPL / AGPL 传染 |
| **上游维护状态** | `pushed_at` + Issue 关闭速度；**停更 > 6 个月 = 接手机会，也是依赖风险** |
| 包体积 / 轻量定位是否成立 | Bundlephobia API：size / gzip / dependencyCount |
| 用户真实诉求 | GitHub Issues 列表；论坛帖子全楼层；应用商店评论 |
| 团队与融资 | 官网 About/Jobs 页；公开报道；GitHub 组织成员 |
| 公司层财务（唯一可审计的一档） | 上市公司财报 / 年报 |
| 市场规模 | 行业研究机构报告（**必须标口径与年份**） |
| 竞品动态 | 竞品官网更新日志 + 招聘页面（招什么人在做什么） |

**取证优先级**：API 实测 > 官网官方信息 > 平台官方数据 > 用户一手评论 > 二手报道。

> **开源采集三禁令（必须遵守，否则数据必错）**：① Release 的 `download_count` 是**自发布起累计值**，比较前必须 **÷ 在架天数**换算成"日均下载"；② 仓库 `language` 字段**不是技术栈**（本地化文件多时会被误判为 `Fluent` 等）；③ `NOASSERTION` **不等于**无许可证，必须逐组件查。
> 完整细则（含两条替代通路、被限流时的应对）见 `调研\方法\开源竞品与可复用能力.md` §7.2。

## 7. 常见误判（反面模式）

出结论前逐条自查。

1. **把功能数量当价值**——数功能 = 数成本。功能多往往是定位不清的表现。
2. **把技术亮点当用户价值**——「用了自研模型」不是卖点，「快 3 倍」才是。
3. **用「我认为有用」替代「用户真的在用」**——PM 最容易犯的错。
4. **忽略免费替代与「忍着不做」**——导致严重高估市场。
5. **累计数据当年化数据**——把「累计服务 100 万用户」当「100 万活跃」。
6. **只看现状，不看「会被什么吃掉」**——系统内置 / 大模型下放 / 开源是三大吞食者。
7. **结论模糊**——只说「有前景」，不给可执行判断。
8. **用「品类繁荣」推导「单品能赚钱」**——赛道大 ≠ 你能切到份额。
9. **拿融资额当成功证据**——融资是负债与预期，不是收入。
10. **把「用户吐槽多」当负面**——吐槽多是使用深度的证据，无人讨论才是真危险。

## 8. 产出模板与填写示范

### 8.1 标准产出模板（结论先行 + 漏斗分层）

```
# {产品} — 产品分析
> 分析对象 / 版本 / 快照时间 | 分析目的 | 数据来源与可信度分级

## 〇、结论先行（TL;DR）        ← 3–5 条编号判断（最重要，放最前）

## 二、功能全景（四层分层表）    ← L1：T1 内核 / T2 增强 / T3 差异化 / T4 长尾
## 三、用户与场景               ← L2：用户分层 / JTBD / 频次 / 替代谱系 / 切换成本
## 四、价值主张与需求硬度        ← L3：痛痒爽 / 卖点对撞 / 需求强度 / 天花板

## 六、竞争位势与免费替代        ← L5：四层竞争 / 对比矩阵 / 差异层级 / 竞品盲区 / 系统威胁

## 八、可迁移结论与机会点        ← L7：抄什么 / 别做什么 / 从哪进场 / 最小验证
## 附 A、数据明细表         ← 指标 / 数值 / 口径 / 来源级别 / 采集日
## 附 B、测算过程与敏感度    ← 假设 → 依据 → 推算 → 结果（与实测分开排版）
## 附 C、缺口声明与应查未查清单
```

**漏斗结构说明**：总览（TL;DR）→ 逐层收敛 → 行动建议。
**每层用表格承载，不写长段落。** 表格化 = 可对比 = 可复用。

### 8.2 结论先行的写法示范

❌ 差的写法：
> 「该产品功能丰富，市场竞争激烈，但仍有发展空间。」

✅ 好的写法（编号 + 判断 + 依据）：
> 1. **它的真内核是 X，其余 90% 功能属 T4 长尾，不构成付费理由。**
> 2. **订阅模式与需求频次错配**——需求为一次性，续费率必然崩塌，应改买断。
> 3. **头号风险是系统内置**：2027 年前若 OS 原生支持该能力，其定价天花板趋近 0。
> 4. **可抄的是它的上手路径设计**，不可抄的是它的功能堆砌。
> 5. **若进场，切入点是对手的盲区 Y**（对手明确不做，且不划算做）。

> 三条硬要求：① 每条都是**判断**不是描述；② 每条都带**依据或时间估计**；③ 至少一条是**否定性结论**（敢说不行）。

### 8.3 缺口声明的写法示范

```
## 附、缺口声明
- 【未取得】MAU 数据：官网仅披露累计注册数，无活跃口径 → 本报告中的"活跃规模"为推算值
- 【口径存疑】营收 ¥X 万：来源为创始人对媒体自述，未经审计
- 【推断】护城河时间窗 12–18 个月：基于功能复杂度与竞品迭代速度推断，非实测
- 【建议补充】10 份核心用户访谈，用于验证 L3 的痛点假设
```

## 9. 执行 SOP 与自查清单

### 9.1 执行流程

1. **定档位**（速判 / 标准 / 深度）
2. **写 L0**——目的、口径、数据分级，30 秒内完成
3. **采数**——一手优先：API 实测 > 官网/定价页 > 用户评论 > 二手报道
4. **七层扫描填表**——缺失即标「缺口」，**不跳过、不编造**
5. **交叉验证**——每条关键结论至少两条独立证据
6. **跑判定工具箱**——至少跑尺子 1（差异化真伪）、2（订阅正当性）、5（定价天花板）、6（需求硬度）
7. **收敛写 TL;DR**——先写结论，再倒推章节
8. **落盘**——`.md` 格式（用户铁律），归档到 `D:\code\Test\SomeResearch\调研`
