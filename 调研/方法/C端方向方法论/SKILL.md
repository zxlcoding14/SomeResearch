# C 端方向 · PM 方法论（方向专用 · 可执行流程）

> **一句话定位**：把通用产品分析框架切成 **C 端专用** 的那一刀 —— 卖的对象是「个人」，瓶颈在「分发」，头号生死问题在「系统内置」。

## 一、六条不可让步的先验（先背这 6 条，再谈流程）

1. **C 端卖的是「省时间 / 省钱 / 爽 / 身份感」，不卖功能、不卖技术。** 分野口诀：**C 端卖「省时间 / 爽」，B 端卖「不出事 / 可交代」。** 判据混用，结论必错。
2. **C 端的瓶颈几乎永远是「分发」。** 需求好 ≠ 你能拿到。**分发不可得 = 一票否决**，不必进入打分环节。
3. **客单价的选择直接决定分发难度。** ¥9 需海量分发；¥299 只需少量高意向用户。个人/小团队应**优先「高客单价 + 小规模高意向人群」**，而不是「低价 + 大流量」。
4. **头号生死问题是「系统内置」。** 截图 / 窗口管理 / 文件批处理 / 录屏 / AI 摘要 —— OS 或平台一原生支持，定价天花板趋近 0。**每题必答。**
5. **免费替代是最强对手**：系统内置 + 开源免费 + 用户自己凑合 + **忍着不做**（成本 0）。每条卖点拿去和这四者对撞，对撞后剩下的才是可定价部分。
6. **C 端进入门槛低，生存门槛高。** 正确起点 = 「**收钱路径明确 + 边际成本可控 + 分发渠道我自己就泡在里面**」的三重交集，不是「需求最有想象力」的那一个。

## 二、C 端高发三死法（判之前先拿这三条筛）

| # | 死法 | 前置可查信号 |
|---|---|---|
| 1 | 做完了没人知道 | 说不出「前 100 个用户从哪来（**指名到社群 / 名单**）」 |
| 2 | 免费替代已经够用 | 卖点拿去和免费替代对撞后，剩余价值 ≈ 0 |
| 3 | 边际成本 ≥ 定价 | 答不出「每多一个用户我多花多少钱」（云端 AI 高发） |

## 三、执行流程 SOP

**默认动作**：只要产出了判断 / 清单 / 对比 / 评估，就落盘为 `.md`（用户铁律，不产 docx/pdf/pptx/xlsx）。不必等用户说「归档」。

1. **定口径（L0）** —— 分析对象粒度、快照时间与版本、分析目的（抄/学/替代/投）、计数口径、数据可信度五级（① 经审计 ② API 实测 ③ 官方宣称 ④ 第三方估算 ⑤ 二手转载）。**不做这层，后面全是废话。**
2. **三问快筛**（§5.1）—— 时间紧就只答这 3 个；第 3 问是**一票否决项**。
3. **九层扫描**（§4）—— 逐层填表，**任一层出现「死信号」即停手**，不往下走。
4. **打分卡 + 一票否决**（§6）—— 12 维 / 满分 135；再逐个对否决项。
5. **算账与测算**（§7）—— 生存线、回本周期、边际成本红线、漏斗反推，逐条给数。**缺失数据不许跳过**：按下方 §十二 的推算规范补（假设 → 依据 → 推算 → 结果 + 敏感度）。
6. **收敛（L7 So What）** —— 先写 TL;DR（3–5 条编号判断，**至少一条否定性结论**），再倒推章节。
7. **落盘** —— `调研\工具\{产品名}-产品分析报告.md`；若属小众独立单品 → `调研\小众`。
8. **呈现** —— `present_files`，回复中说明路径 + 「文档比对话多出什么」。

## 四、九层地图（一页判定表）

> 用法：从左到右扫，**任一层命中死信号即停手**。

| 层 | 核心问题 | C 端专用判据 | 死信号 |
|---|---|---|---|
| **L0 口径与边界** | 这次分析是什么、数据算什么 | 目的 · 快照时间 · 数据可信度五级 | 数字无口径 |
| **L1 是什么 + 替代谱系** | 它替用户做了什么；不用它会怎样 | 一句话定义（**不贴品类词**）· 六类替代谱系 · 四层功能分层（T1 内核 / T2 增强 / T3 差异化 / T4 长尾） | 品类词开头；替代谱系缺「系统内置」与「忍着不做」 |
| **L2 谁在用 / 何时 / 多久一次** | 谁在用、谁在付、什么时刻想起它 | 用户分层 · JTBD 句式「当我在 ___ 的时候，我想要 ___，这样我就能 ___」· **频次** · 切换成本 | 只说「办公族 / 年轻人」；一次性需求收订阅 |
| **L3 为什么成立** | 真需求还是「看起来像需求」 | 痛点 / 痒点 / 爽点（**只有痛点好收钱**）· 卖点对撞免费替代 · 可感知 10 倍 | 卖点需要教育才被理解 |
| **L4 怎么赚钱** | 谁付、为什么现在付、能付多久 | 收费对象（C 个人 vs C 专业）· 计费单位 · **四种付费墙** · 续费理由 · 价格锚点 | 付费墙与频次错配；免费版够用 |
| **L4.5 盈利模型与生存线** | 卖多少单才不亏 | 全成本清单 · 盈亏平衡 · 回本周期 · **边际成本** | 算不出生存线；边际成本 ≥ 定价 |
| **L4.6 交付与合规（C 端最小集）** | 能不能合法、可持续地交付 | 主体与通道 · 隐私与内容合规 · **客服承载上限** | 说不出钱从哪个口子进来 |
| **L5 竞争位势与系统内置威胁** | 谁最可能杀死它 | 竞争四层 · 差异点层级 · 竞品盲区 · **系统内置威胁** | 未回答「它会被什么吃掉」 |
| **L6 能不能持续** | 强是暂时的还是可持续的 | 护城河时间窗 · 平台依赖 · **留存与 churn** · 生命周期 | 只看下载量 / 注册量，从不看留存 |
| **L7 So What** | 抄什么 / 别做什么 / 从哪进场 | 结论先行 3–5 条 + **至少一条否定性结论** | 结论只说「有前景」 |

**L1 替代谱系六类（C 端尤其看第 2、3、6 类）**：手动做 · **系统内置（头号对手）** · **免费开源** · 竞品 · 外包找人做 · **忍着不做（最强，成本 0）**。

**L2 频次 × 心理价位（决定能否收订阅）**

| 频次 | 价位锚点（示例，需实测） | 模式含义 |
|---|---|---|
| 日频 | 对标「每天省 N 分钟的时薪价值」 | 可订阅，能养成习惯 |
| 周频 | 对标「一杯咖啡 / 一顿饭」 | 可订阅，需强价值 |
| 月频 | 对标「一次打车」 | 订阅勉强，应偏买断 |
| 一次性 | 对标「一次外包报价」 | **只能买断 / 按次，硬收订阅必流失** |

**L4 四种付费墙（C 端以功能墙 / 体验墙为主）**：功能墙（工具型）· 用量墙（服务型）· 时间墙（习惯转化）· 体验墙（打扰变现）。
> **续费理由**：有没有「一层真实的持续交付成本」？**没有 → 订阅不成立，只能买断。**

**L5 差异化真伪四步**：① 列它自称的差异点 → ② 每个差异点找**免费**替代实现 → ③ 免费方案已覆盖 80% 即判「**包装**」→ ④ 剩下无法被免费替代的，才是定价依据。
**定价天花板**：`≈ min(竞品价格, 人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)`；覆盖率 100% → 天花板 = 0。

**L6 死信号**：只谈下载量 / 注册量。**下载量是虚荣指标，留存才是命**；留存必须按自然日 / 自然周**分群**看。

## 六、打分卡与一票否决

### 6.1 打分卡（C 端加固版 · 12 维 · 满分 135）

| 维度 | 权重 | 5 分锚点 | 1 分锚点 |
|---|---|---|---|
| 使用频次 | ×3 | 每天 / 每周多次 | 一次性 |
| 痛点硬度 | ×3 | 不做直接损失钱或触发合规风险 | 只是「更方便」 |
| **分发可得性** | ×3 | 能直接触达并让 20 人开口 | 完全不知道人在哪 |
| 现有替代糟糕度 | ×2 | 只能手工或付费买别扭的老工具 | 系统内置已够用 |
| 付费方明确度 | ×2 | 有预算科目 / 有付费先例 | 无任何付费先例 |
| 持续交付成本 | ×2 | 有真实云 / 模型 / 内容成本 → 订阅成立 | 纯一次性交付 → 只能买断 |
| 你方独占优势 | ×2 | 有数据 / 身份 / 渠道别人没有 | 无 |
| 窗口期长度 | ×1 | 大厂 2 年内不会做 | 下个系统版本就被内置 |
| 合规 / 平台风险 | ×1 | 无单一 API 依赖 | 依赖单一平台政策 |
| **收款可行性** | ×3 | 通道明确、资质具备、费率可接受 | 无合法收款路径 |
| **隐性成本可控性** | ×3 | 可完全自助，边际成本 ≈ 0 | 每单需人工介入 |
| **客体匹配度** | ×2 | 形态与我的时间 / 资质完全匹配 | 需要团队或资质 |

**计分**：满分 = (3+3+3+2+2+2+2+1+1+3+3+2) × 5 = **135**。
**阈值**：≥ 70%（≈95）→ 进入证伪；≤ 50%（≈68）→ 直接杀；中间 → 只做**最低成本**补充采集，不投实验资源。

### 6.2 一票否决（不论总分多高，触发即杀）

| # | 否决项 | C 端高发度 |
|---|---|---|
| 1 | **分发不可得** | ★★★ |
| 2 | **使用频次 = 一次性，且无持续交付成本** | ★★★ |
| 3 | **依赖单一平台 / 单一 API，一个版本更新就可能被内置** | ★★★ |
| 4 | **触碰合规红线**（金融 / 医疗 / 未成年人 / 爬虫 / 版权 / 隐私数据） | ★★ |
| 5 | **答不出「去掉 AI 之后还剩多少价值」**（AI 类专用） | ★★★ |
| 6 | **收款路径不成立** | ★★ |
| 7 | **边际成本 ≥ 定价** | ★★★ |
| 8 | **客服 / 合规成本超出个人承载上限** | ★★ |

### 6.3 盈利可行性 11 问（C 端适用）

钱从哪进来 + 我有资质吗 · 定价多少 + 依据 · **每多一个用户多花多少钱** · 每月固定成本 + 盈亏平衡用户数 · 回本周期 · **前 100 个用户具体从哪来** · 转化漏斗每层数字 · 次日/7 日/30 日留存 + 月流失率 · 谁提供客服 + 我扛得住多少用户 · 开源库 / API 许可证允许商用吗 · 涉及个人信息 / AI 生成内容要做什么合规动作。

## 七、盈利模型（三个公式 + 一张关键决策表）

```
年营收   = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利   = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本

月毛利/单         = 客单价(月) − 单用户变动成本
盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单
回本周期(单用户)   = 单用户获取成本 ÷ 月毛利/单     ← 必须 < 12 个月

可行条件（AI 类加固）：定价 > 单次模型调用成本 × 单人月均调用次数 × 安全倍数
```

**全成本清单（「隐性」一栏最常被漏）**：一次性投入（研发工时折算机会成本 / 设计 / 商标 / 软著）· 每月固定（服务器 / 域名 / SSL / 开发者证书 / 代码签名 / API 月费 / 工具订阅）· 每单变动（支付手续费 / **模型调用费** / 带宽 / 发票与税务 / 退款）· **隐性（客服与支持时间 / 运维 / 内容审核 / 合规维护 / 迭代维护 / 社区运营）** · 时间的机会成本。
> **纪律**：把「客服时间」按小时折算成钱写进去。C 端最常见的幻觉是「成本只有服务器那点钱」。

**客单价 × 分发难度匹配表（本方向最关键的一张表；价格档为结构示意，非市场数据）**

| 客单价档 | 大致模式 | 所需用户量级 | 对分发能力的要求 | 个人可行性 |
|---|---|---|---|---|
| ¥9 级 | 冲动型工具 / 内购解锁 | 需要海量 | 必须有规模化渠道 | ⚠️ 个人最难 |
| ¥99 级 | 买断型单点工具 | 中量 | 垂直社区 + 内容复利 | ✅ 可行 |
| ¥299 级 | 专业工具 / 年订阅 | 少量高意向 | 精准人群 + 高信任内容 | ✅ **个人最优区间** |
| ¥999+ 级 | 专业级工具 / 小团队 | 更少 | 靠专业信任与口碑 | ✅ 但市场有限 |

> **核心结论**：**客单价的选择决定了你的分发难度。**

**边际成本红线（AI 类）**：免费版**限功能**，付费版**限用量**——不要反过来。必设用量上限 / 阶梯价 / 降级策略 / 缓存或本地推理。必答「供应商涨价 30% 后我还赚钱吗」。

## 八、从哪进场 / 最小验证

**正面画像**：有一群**具体的、我能零预算触达的**人 · 高频 + 痛感强 · 替代品是「还在收钱但体验陈旧」的老工具 · 免费替代覆盖率 < 80% · **边际成本 ≈ 0** · 支持面窄可自助 · 客单价 ¥99–¥999 · 高频**入口**（快捷唤起 / 右键菜单 / 拖拽即用）。
**负面画像**：需求真但我不知道人在哪 · 系统/平台已内置且够用 · 一次性需求却想收订阅 · 云端 AI 无限用量 · 需海量分发才能养活（¥9 级） · 需密集人工介入 · 触碰合规红线 · 依赖单一平台政策 · 需教育市场的卖点。

**证据强度阶梯（只认行为，不认口头）**：问未来意愿（几乎无效）→ 落地页点击 → 留邮箱/预约 → **人肉代做观察 → 直接收钱 / 预售（唯一强信号）**。

**判定门槛（写死，不许临场放宽）**

| 结论 | 条件 |
|---|---|
| **立项** | ≥5 个真实用户持续使用（非一次性）；或 ≥3 个明确付费信号（含预付 / 定金 / 书面意向） |
| **待观察** | 有使用但无付费信号 → 补做收费实验，2 周内无改善则杀 |
| **杀掉** | 无人持续使用；或用户明确表示「免费可以，付费不要」 |

**形态选择**：从**单点高频工具（mini-tool）**起步，而非工作流套件或平台。
**判定口诀**：`低频 + 无持续成本 → 只做买断单点工具；高频 + 有持续成本 → 可做订阅；需要教育市场 → 不做。`

## 十一、反模式（出结论前拿这张表对一遍）

**C 端专属陷阱 6 条**：只统计下载量/注册量 · 定价过低求销量 · 免费额度给太大 · 认为「上架就有人买」 · 拿「AI」当卖点 · 把「开源 + 赞助」当商业模式。
**通用误判（C 端高发 10 条）**：把功能数量当价值 · 把技术亮点当用户价值 · 用「我认为有用」替代「用户真的在用」 · 忽略免费替代与「忍着不做」 · 累计数据当年化数据用 · 只看现状不问「会被什么吃掉」 · 结论模糊 · 用「品类繁荣」推导「单品能赚钱」 · 把「用户吐槽多」当负面 · 把「我认识的人都说需要」当市场验证。

## 十二、数据与测算要求（不可让步）

> **立场（2026-10-08 修正）**：C 端分析的价值 = 数据的 **完整性 × 有效性 × 全面性**。
> **「拿不到」不是免责理由。** 拿不到 → 给获取路径；确实取不到 → 给**有依据的推算 / 预估**，标方法与置信度。
> **禁止的是「无依据的数字」，不是「估算」本身。** 只写缺口不做测算 = 分析没做完。
> 数据方法论的完整版（源分级 / 完整性三问 / 三角印证 / 五种预估法 / 可复算规范 / 标注规范）见 `product-analysis-framework` §四。

### 12.1 C 端专用测算清单（逐条给数，不许空着）

| # | 测什么 | 怎么算 | 缺失时怎么推 |
|---|---|---|---|
| 1 | **漏斗反推** | 目标年营收 ÷ 客单价 = 需多少付费用户 → ÷ 付费率 = 需多少激活 → ÷ 激活率 = 需多少曝光 | 用竞品公开转化率或同类目基准作类比，标「类比推算」 |
| 2 | **分发能力对照** | 我现有渠道能覆盖多少曝光 / 2 周能触达多少人 → 与上一步所需量级对撞 | 自下而上：可触达社群人数 × 转化率 |
| 3 | **ARPU 断层归因** | ARPU = 年营收 ÷ 活跃用户；10 倍断层先查四项：付费理由强度 × 计费结构 × 人群净值 × 计价货币 | 逐项给分档，不给总分 |
| 4 | **留存与 churn 推演** | 分群留存（次日 / 7 日 / 30 日）→ 月流失率 → 年存活率；年付 vs 月付续费差 | 无实测就用同类目区间（标「类比」+ 区间） |
| 5 | **边际成本对撞** | 单次模型 / API 成本 × 单人月均调用次数 × 安全倍数，与定价比较 | 用官方 API 价目页（【实测·官方页】）反算 |
| 6 | **免费替代覆盖率** | 逐功能对撞（系统内置 / 开源 / 手工 / 忍着不做），算被覆盖功能占比 % | 覆盖率是判断量，必须给数，不许写「较高」 |
| 7 | **生存线与回本** | 盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单；回本 = CAC ÷ 月毛利/单 | 固定成本逐项列，不许只算服务器 |

### 12.2 三条版式纪律

1. **估算必须写成四段**：假设 → 依据 → 推算 → 结果，缺一不可。
2. **必须做敏感度**：客单价 ±50%、付费率 ±50% 后，结论是否翻转？翻转就要明说「结论不稳」。
3. **预估与实测分开排版**（单列「测算过程」节），不许混进同一张表冒充实测。

### 12.3 标注规范（每个数字必带标签）

`【实测·API】` `【审计】` `【官方宣称】` `【推算·方法X】` `【预估·依据Y】` `【未取得】`
→ **前四种都能进结论**；【未取得】只进缺口清单，且必须附获取路径。

### 12.4 「文档层」与「产出层」的区别（务必分清）

- **文档层**：本 skill 与**同目录**的 `C端方向-PM方法论集成.md` 是**方法文档，本身不含市场数据**；其中费率、比例为**行业常见区间（采集日 2026-10-08）**，使用时须回官方页重核。
- **产出层**：用它们做出来的**分析报告必须包含数据与测算**——附 A 数据明细 / 附 B 测算过程与敏感度 / 附 C 缺口声明，**三附齐全才算交付完整**。
- 涉及合规与税务的内容**不构成法律或税务建议**。
