## 〇、结论先行（TL;DR）

1. **C 端卖的是「省时间 / 省钱 / 爽 / 身份感」，不卖「功能」也不卖「技术」。** 一句话记住与 B 端的分野：**C 端卖「省时间 / 爽」，B 端卖「不出事 / 可交代」。** 用 B 端的判据评 C 端产品、或用 C 端的判据评 B 端产品，结论必然错。
2. **C 端的瓶颈几乎永远在「分发」。** 需求好 ≠ 你能拿到。分配不可得是**一票否决**，不必进入打分环节。
3. **客单价的选择直接决定你的分发难度，这是 C 端最容易被忽略、也最致命的一条。** ¥9 的产品需要海量分发才养得活；¥299 的产品只需少量高意向用户。个人/小团队应**优先选高客单价 + 小规模高意向人群**，而不是「低价 + 大流量」。
4. **C 端的头号生死问题是「系统内置」**：截图、窗口管理、文件批处理、录屏、AI 摘要——一旦 OS 或平台方原生支持，定价天花板趋近 0。这一条必须每题必答。
5. **C 端的付费墙以「功能墙 / 体验墙」为主**（B 端以用量墙 / 功能墙 + 服务为主）。墙的位置必须与使用频次匹配：**低频需求硬收订阅 = 必然流失**。
6. **C 端的免费替代是最强对手**：系统内置 + 开源免费 + 用户自己凑合 + **忍着不做**（成本 0）。每条卖点都必须拿去和这四者对撞，对撞后还剩多少才是可定价的部分。
7. **C 端高发的三种死法**（按发生频次）：① 做完了没人知道（无分发）；② 免费替代已经够用（无定价空间）；③ 云端 AI 无用量限制 → **边际成本 ≥ 定价**，越赚越亏。
8. **【否定性结论】C 端不是「低门槛」赛道。** 它的进入门槛低（无需资质、无需销售团队），但**生存门槛高**（分发贵、付费意愿弱、流失快、系统内置随时抹平）。个人做 C 端的正确起点是「**收钱路径明确 + 边际成本可控 + 分发渠道我自己就泡在里面**」的三重交集，而不是「需求最有想象力」的那一个。

## 一、方向定义：C 端到底在卖什么

### 1.1 一句话定义（先不贴品类词）

> **它替一个具体的个人，在一个具体的时刻，省掉了什么，或换来了什么感觉。**

反面写法提醒：**先说「它替用户做了什么」，不要先说「这是一个 XX 工具」。** 品类词会把竞品集合锁死，也会掩盖真实价值。

| 写法 | 例子 | 后果 |
|---|---|---|
| ❌ 品类词开头 | 「这是一个 AI 桌面助手」 | 竞品集合被锁死，真实价值被掩盖 |
| ✅ 任务开头 | 「它在任意窗口按快捷键就能把当前内容喂给模型并就地给出结果」 | 定位清晰，替代谱系随之浮现 |

### 1.2 C 端 vs B 端：判据不能通用

> **C 端第一性原理**：卖给**个人**，卖的是「省时间 / 省钱 / 爽 / 身份感」。决策链短（一个人就能决定），但**付费意愿弱、流失快、获客贵**。
> **C 端瓶颈 = 分发**；**B 端瓶颈 = 决策链 + 销售人力**。

| 维度 | C 端 | B 端（对照，只作参照） |
|---|---|---|
| 购买主体 | 个人 | 组织 |
| 决策链 | 1 人（自己） | 5 类角色（使用者 / 影响者 / 决策者 / 付款者 / 合规） |
| 决策周期 | 分钟–天 | 周–半年 |
| 核心买点 | 省时间 / 省钱 / 爽 / 身份感 | 降本 / 不出事 / 可交代 / 可审计 |
| 客单价 | 低（¥9–¥999/年，需按标的实测） | 高（¥千–¥百万/年） |
| 计费单位 | 买断 / 订阅 / 按次 | 席位 / 年框 / 用量 + 服务 |
| 付费墙 | **功能墙 / 体验墙为主** | 用量墙 / 功能墙 + 服务 |
| 获客方式 | 内容 / 社区 / ASO / 投放 | 销售 / 渠道 / 招投标 / 生态 |
| CAC | 低（¥几–¥几百） | 高（¥几千–¥几万） |
| 销售人力 | 几乎不需 | 必需（除自助型小微 B） |
| **增长瓶颈** | **分发** | **决策链 + 销售人力** |
| 留存 / 续费 | 靠习惯与价值，**churn 高** | 靠切换成本与合同，NRR 可 >100% |
| 交付成本 | 近 0（自助） | 高（实施 / 培训 / 对接） |
| 合规门槛 | 较低（隐私、内容） | 高（等保 / 信创 / 私有化 / 审计） |
| 失败主因 | **无人知道 / 免费替代够用** | 用户喜欢但签不下单 / 交付拖垮 |

### 1.3 C 端的四个结构性特征（决定了它所有的难）

| # | 特征 | 直接后果 |
|---|---|---|
| 1 | 决策链极短，但**决策权重极轻** | 转化快，但用户随时可弃；不构成护城河 |
| 2 | **付费意愿弱、价格锚点靠心理价位** | 定价受「冲动消费线」压制；无试用难以破线 |
| 3 | **流失快（churn 高）** | 留存曲线是生死线；下载量是虚荣指标 |
| 4 | **获客贵（相对客单价）** | 低频 / 低客单 → 回收不了 CAC，模型不成立 |

### 1.4 一个必须先破除的错觉

> 「C 端靠产品体验好、口碑自然来」——**错**。口碑是**分发的结果**，不是分发的原因。
> C 端产品在「无人知道」和「免费替代够用」之间死掉的数量，远多于「做得不够好」。

### 1.5 【否定性结论】C 端方向最常见的三种死法

| # | 死法 | 机制 | 前置可查信号 |
|---|---|---|---|
| 1 | **做完了没人知道** | 无分发渠道，上架 ≠ 曝光 | 说不出「前 100 个用户从哪来（指名到社群 / 名单）」 |
| 2 | **免费替代已经够用** | 系统内置 / 开源 / 忍着不做，成本为 0 | 卖点拿去和免费替代对撞后剩余价值 ≈ 0 |
| 3 | **边际成本 ≥ 定价** | 云端 AI 无限用量、重度用户拖爆额度 | 答不出「每多一个用户我多花多少钱」 |

> 判断标准很硬：**如果一个 C 端方向必须先解决「谁来买」和「谁给我打钱」才能成立，它就不适合作为个人/小团队的第一个项目。**

## 二、分层概览：C 端 PM 要看的 9 层（一页地图）

> 用法：从左到右扫一遍，任一层出现「死信号」即停手，不必往下走。

|---|---|---|---|---|
| **L0 口径与边界** | 这次分析是什么、要回答什么、数据算什么 | 目的（抄/学/替代/投）· 快照时间 · 数据可信度五级 | 数字无口径 | §3.0 |

| **L2 谁在用 / 何时用 / 多久一次** | 谁在用、谁在付、什么时刻想起它 | 用户分层 · JTBD 句式 · **频次** · 切换成本 | 只说「办公族 / 年轻人」；一次性需求收订阅 | §3.2 |

| **L7 So What** | 抄什么 / 别做什么 / 从哪进场 | 结论先行 3–5 条 + 至少一条否定性结论 | 结论只说「有前景」 | §3.9 |

## 三、逐层收敛

### 3.0 L0 · 口径与边界（不写这层，后面全是废话）

| 要素 | 必答内容 | 追问 |
|---|---|---|
| 分析对象粒度 | 单品 / 产品矩阵 / 赛道 | 分析「这一个」「这一家」还是「这一品类」？ |
| 快照时间与版本 | 版本号 + 数据日期 | 结论多久会过期？ |
| 分析目的 | 抄它 / 投它 / 打它 / 学它 / 替代它 | 目的决定维度权重 |
| 计数口径 | 最小能力单元 vs 用户可感知功能 | 两个数都写吗？ |
| 数据可信度分级 | ①经审计 ②API 实测 ③官方宣称 ④第三方估算 ⑤二手转载 | 逐条标注 |

**C 端高频口径陷阱（优先查这几条）**

| 指标 | 常见陷阱 | 正确处理 |
|---|---|---|
| 用户量 | 「注册用户」≠ 活跃；**下载量含重复下载、爬虫、预装**；App Store 畅销榜排名 ≠ 营收 | 优先 MAU / 付费用户数；一律标口径 |
| 营收 | 「服务 X 万客户」是累计数、非年化 | 找经审计财报；否则标「官方宣称」 |
| 定价 | **促销价冒充标准价；未含税；未计汇率** | 记录采集日期 + 币种 + 是否含税 |
| 口碑 / 评论 | 内容农场灌水、刷好评、竞品黑稿 | 多源交叉；**重点读差评与中评** |
| 独立开发者产品 | 营收数字多为自述，缺乏审计 | 区分「自述 / 推算 / 审计」三级 |

### 3.1 L1 · 是什么 + 替代谱系（C 端：系统内置与免费开源是头号对手）

**必答 5 问**

1. **一句话定义**：先说它替用户做了什么，不贴品类标签。
2. **品类归属**：陌生用户会把它放到哪个货架？——货架决定竞品集合与定价参照。
3. **最小可用内核**：删掉所有包装，用户为哪**一件事**安装 / 付费？
4. **Non-scope**：它明确不做什么？（范围边界 = 定位的负空间，也是它与竞品的真正分界）
5. **功能全景**：按模块切分 → 再按四层分层。

**四层功能分层（核心工具）**

| 层 | 定义 | 判定话术 | 商业含义 |
|---|---|---|---|
| **T1 内核** | 去掉它产品不成立 | 「删掉这个功能，还有人来用吗？」 | 定价地基，必须做到最好 |
| **T2 增强** | 提效但可替代 | 「没有它，用户还能完成任务吗？」 | 决定体验口碑，通常**不该单独收费** |
| **T3 差异化** | 只有它有 | 「竞品有这个吗？免费替代有这个吗？」 | 卖点来源，但要验证是否被免费替代覆盖 |
| **T4 长尾** | 低频 / 边缘 | 「有多少用户真的会用到？」 | 常是「看起来很强」的装饰，**警惕拿它当卖点** |

**替代方案谱系（必须列全 6 类；C 端尤其看前两类和后一类）**

| 类别 | 它是谁 | 对 C 端的威胁度 |
|---|---|---|
| 手动做 | Excel / 脚本 / 手工操作 | 中（费力但免费） |
| **系统内置** | OS / 平台自带功能 | **高（零成本、零学习）→ C 端头号对手** |
| **免费开源** | 开源工具 | **高（多数场景够用）** |
| 竞品 | 直接 / 间接竞品 | 视情况 |
| 外包或找人做 | 请人代做 | 低（C 端少见） |
| **忍着不做** | 用户接受现状 | **最高（成本为 0，无法被击败）** |

> **C 端取证的特别提醒**：桌面 / 移动端产品极易被 OS 原生功能吞掉（截图、窗口管理、文件批处理、录屏、AI 摘要）。**评估任何 C 端工具，替代谱系里如果没有认真列出「系统内置」和「忍着不做」，结论必然乐观失真。**

### 3.2 L2 · 谁在用、什么时候用、多久用一次

**必答 6 问**

1. **用户分层**：核心用户 / 边缘用户 / **付费方**——C 端常是同一人，但要做付费的与爱用的是同一个人吗？
2. **触发场景（JTBD）**：标准句式 **「当我在 ___ 的时候，我想要 ___，这样我就能 ___」**
3. **使用频次**：日 / 周 / 月 / 一次性 —— **频次决定能否收订阅**。
4. **替代方案谱系**（见 §3.1，列全 6 类）。
5. **切换成本**：迁移数据 / 重新学习 / 团队习惯 / 集成改造 / 沉没成本。
6. **用户在哪讨论它？最常出现的褒贬词？** ⚠️ **不可编造用户声音**；没有一手素材就写「未见一手用户反馈，建议补充访谈」。

**C 端专用：心理价位与频次的组合判定**

| 频次 | 心理价位锚点（示例，需实测） | 模式含义 |
|---|---|---|
| 日频 | 对标「每天省 N 分钟的时薪价值」 | 可订阅，能养成习惯 |
| 周频 | 对标「一杯咖啡 / 一顿饭」 | 可订阅，但需要强价值 |
| 月频 | 对标「一次打车」 | 订阅勉强，应偏买断 |
| 一次性 | 对标「一次外包报价」 | **只能买断 / 按次，硬收订阅必流失** |

> **冲动消费线**：C 端存在一条「不用想就会买」的价格线（量级需按目标人群实测）。**高于这条线且无试用 = 转化断崖。**

### 3.3 L3 · 为什么成立（价值主张与需求硬度）

**必答 5 问**

1. **痛点 / 痒点 / 爽点**——**只有痛点才好收钱。**

| 类型 | 特征 | C 端付费意愿 |
|---|---|---|
| 痛点 | 不做会有明确损失（时间 / 钱 / 风险） | **强** |
| 痒点 | 做了更爽，不做也无妨 | 弱 |
| 爽点 | 情绪价值、身份认同 | 中（波动大） |

2. **卖点真伪判定**：把每条卖点拿去和**免费替代**对撞，对撞后还剩多少？——剩余部分才是可定价的。
3. **可感知的 10 倍**：提升是可感知的，还是需要教育？——**需要教育才被理解的卖点 ≈ 不存在。**
4. **刚需还是可选**：没有它，用户的损失是什么（时间 / 钱 / 风险）？能否量化？
5. **天花板**：TAM / SAM / SOM 粗算，**必须标口径**——三口径常差 2–3 倍。C 端尤其要问：**这个人群的增长本身在涨还是在萎缩？**

### 3.4 L4 · 怎么赚钱（C 端专版）

**必答 9 问**

1. **收费对象**：C 个人 / C 专业（愿意为效率付费的人） / 平台分成 / 广告 / 数据变现。
   > C 端的现实是：**「个人用户」与「C 专业用户」是两个完全不同的生意。** 前者靠规模，后者靠价值密度。
2. **计费单位**：买断 / 订阅 / 按量 / 免费增值 / 打赏 / 一次性授权。
3. **付费墙位置（四种墙）**——C 端以功能墙 / 体验墙为主：

| 墙型 | 机制 | 对应的商业类型 | C 端典型流失原因 |
|---|---|---|---|
| **功能墙** | 部分功能锁付费 | 工具型 | 用户只用免费功能 |
| **用量墙** | 免费额度用尽 | 服务型 | 用户量小、额度用不完 |
| **时间墙** | 试用期结束 | 习惯转化型 | 试用期内没养成习惯 |
| **体验墙** | 去水印 / 去广告 / 去限制 | 打扰变现型 | 用户忍受打扰也不付 |

4. **续费理由**：是否存在「一层真实的持续交付成本」（云资源 / 模型调用 / 内容更新 / 合规 / 人工）？——**没有 → 订阅不成立，只能买断。硬收订阅 = 一次性流失。**
5. **价格锚点**：它相对什么定价？（竞品 / 人力替代成本 / 损失规避 / 心理价位）
6. **ARPU 与断层**：
   ```
   ARPU = 年营收 ÷ 活跃用户          人均产出 = 年营收 ÷ 团队人数
   ```
   同赛道 ARPU 差异由 **付费理由强度 × 计费结构 × 人群净值 × 计价货币** 四项决定，**不由功能数量决定**。看到 10 倍以上 ARPU 断层，先查这四项，不要归因于功能。
7. **转化漏斗反推**：
   ```
   付费用户数 ← 付费转化率 ← 激活规模 ← 触达 / 曝光
   ```
   例：目标年营收 ¥500 万、客单价 ¥300/年 → 需 1.67 万付费用户；若付费转化率 1% → 需 167 万激活用户。**判断这个量级在你的分发能力下是否可达。**
8. **单位经济**：CAC / LTV（LTV:CAC 应 > 3）/ 毛利率 / 退款率 / 渠道分成（应用商店常见 15%–30%，**需核实**）。
9. **定价天花板**：当功能被「**系统内置 + 开源免费 + 大厂免费版**」三方夹击时，天花板**趋近 0**。
   - 追问：它的某个功能是否已能在别处免费拿到？如果是，这个功能**不能定价**。

> **C 端 ARPU 提升靠「升级」**（免费 → 个人版 → 专业版），而 B 端靠「扩容 + 续约」（5 席位 → 50 席位）。**C 端 ARPU 天花板明显低于 B 端。** 这是 C 端必须有心理准备的结构性限制。

### 3.5 L4.5 · 盈利模型与生存线（C 端公式）

```
年营收 = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利 = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本
```

```
月毛利/单        = 客单价(月) − 单用户变动成本
盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单
回本周期(单用户)  = 单用户获取成本 ÷ 月毛利/单      ← 必须 < 12 个月，越短越好
```

**全成本清单（逐条填数，C 端「隐性」一栏最常被漏）**

| 成本类别 | 具体项 | 性质 |
|---|---|---|
| 一次性投入 | 研发工时（折算机会成本）、设计、商标注册、软著登记、必要设备 | 沉没 |
| 每月固定 | 服务器 / 云资源、域名、SSL、开发者证书（如 Apple 年费）、代码签名、第三方 API 月费、工具订阅 | 固定 |
| 每单变动 | 支付手续费、**模型调用费（AI 类最大变量）**、带宽 / 存储、发票与税务成本、退款 | 变动 |
| **隐性（最常被漏）** | **客服与支持时间**、运维与故障处理、内容审核、合规维护、迭代维护、社区运营 | 隐性 |
| 时间的机会成本 | 每周投 N 小时，若去做别的能挣多少 | 隐性（真实成本） |

> **纪律**：把「客服时间」按小时折算成钱写进去。C 端最常见的幻觉是「成本只有服务器那点钱」。

**边际成本可控性（C 端 / AI 类头号杀手）**

| 必答问题 | 追问 |
|---|---|
| 每多一个用户，我多花多少钱？ | 是**近似 0**（纯本地工具）还是**线性增长**（云端 / 模型调用）？ |
| 重度用户会不会把我的成本拖爆？ | 有没有用量上限 / 阶梯价 / 降级策略？ |
| 模型 / API 供应商涨价 30%，我还赚钱吗？ | 有没有可替换方案？ |
| 缓存 / 本地推理能不能降本？ | 降本后体验损失多少？ |

> **新增一票否决**：**边际成本 ≥ 定价的方向，直接杀**（或必须重做定价结构）。这是 C 端 AI 类最常踩的坑：**免费用户把 API 额度吃光。**

### 3.6 L4.6 · 交付与合规（C 端最小集）

> C 端的合规门槛低于 B 端，但**有两件事在写代码之前就必须有答案**：**收得到钱**、**不违规**。

**A. 收款主体与通道（动手前定）**

| 必答问题 | 追问 |
|---|---|
| 我以什么身份收钱？（自然人 / 个体工商户 / 有限公司 / 海外主体） | 有没有能力开对公账户？能不能开发票？ |
| 走哪个收款通道？（自有支付 / Merchant of Record / 应用商店内购 / 线下转账） | 该通道**需要什么资质**、抽成多少、几天到账？ |
| 支付通道会不会因为我的品类被拒？（AI / 工具类等） | 有没有备用通道？ |
| 收款通道与分发渠道是否绑定？（上架 App Store 是否必须走 IAP？） | 平台抽成后，我的定价还成立吗？ |

**通道类型对照（费率一律「需核实」，采集日 2026-10-08，使用时必须回官方页重核）**

| 通道类型 | 常见计费结构（参考区间·需核实） | 主要门槛 | 适合谁 |
|---|---|---|---|
| 国际卡收单（Stripe 类） | 约 2.9% + $0.30 / 笔 | 需可接收外币的主体；不代扣税 | 有海外主体或能接外币的开发者 |
| Merchant of Record（Paddle / Lemon Squeezy 类） | 约 5% + $0.50 / 笔 | 门槛低，**由平台代扣全球税** | **个人开发者面向海外 C 端首选** |
| 应用商店内购 | 15% / 30%（小企业计划常见 15%） | 必须走平台 IAP；审核政策风险 | 纯 App 分发 |
| 国内聚合支付（微信 / 支付宝） | 约 0.6% / 笔 | **需商户资质**（个体户或公司） | 面向国内 C 端 |
| 平台分成（市场 / 插件商店） | 视平台政策而定 | 依赖平台 | 插件 / 模板类 |
| 人工转账 / 对公汇款 | 0%（银行手续费另计） | 无法规模化 | 早期验证 |

**B. 支付摩擦与税费**

| 必答问题 | 追问 |
|---|---|
| 退款政策是什么？退款率预期多少？ | 有没有把退款率计入营收模型？ |
| 会不会遇到拒付（chargeback）？怎么处理？ | 拒付率过高的后果（通道封禁）知道吗？ |
| 跨境业务涉及哪几种税？（VAT / Sales Tax 等） | 用 MoR 通道能不能把这块外包出去？ |

**C. 数据与内容合规**

| 必答问题 | 追问 |
|---|---|
| 我收集哪些用户数据？ | 每一项都有必要性吗（最小必要原则）？ |
| 隐私政策、用户协议写了吗？ | 能不能通过应用商店审核？ |
| 遥测 / 崩溃上报怎么配？ | 能不能关掉？合规吗？ |
| 有 AI 生成内容吗？ | 国内可能涉及**生成式 AI 服务备案 / 算法备案 / 深度合成标识**（须知有此事，具体按最新规定核查） |
| 有 UGC 吗？ | 内容审核义务与成本能承担吗？ |
| 开源库与模型 ToS 允许我商用 / 转售吗？ | GPL/AGPL 有传染性；有些素材明确禁商用 |

**D. 支持成本与承载能力（C 端头号杀手不是竞品，是客服）**

| 必答问题 | 追问 |
|---|---|
| 每天 / 每周大概多少支持请求？ | 一人能不能扛住？临界点是多少用户？ |
| 支持渠道有哪些？（邮件 / 群 / 工单） | 有没有把常见问题做成文档来自助化？ |
| 有没有 SLA 承诺？ | 承诺了做不到，会不会引发差评 / 退款？ |

> 量级推演示例（**非实测，需自行修正**）：200 个付费用户，若每人每月问一次 ≈ 每工作日约 10 次支持请求——这已是一个人的全部业余时间。

### 3.7 L5 · 竞争位势与系统内置威胁（C 端头号生死问题）

**必答 6 问**

1. **竞争四层**：直接竞品 / 间接竞品 / 免费替代（开源 + 系统内置）/ 用户自己动手。
2. **对比矩阵维度**：功能覆盖 · 定价 · 平台 · 目标人群 · 渠道 · 生态与插件 · 数据迁移成本。
3. **差异点层级**——越靠后越难被抄：

| 层级 | 举例 | 可复制难度 |
|---|---|---|
| 功能 | 多一个导出格式 | 极低 |
| 体验 | 交互更顺、速度更快 | 低 |
| 价格 | 更便宜 | 低 |
| 人群 | 只服务设计师 | 中 |
| 渠道 | 只在小红书做增长 | 中高 |
| 品牌 | 成为某类用户的心智默认 | **高** |

4. **竞品盲区**：对手「明确不做什么」？——**本层信息量最高，机会常在这里。** 追问话术：这个头部产品为什么不做 X？是做不到、不划算，还是看不上？
5. **谁在攻击它**：新入场者 / 大厂功能下放 / 开源替代 / 平台政策变化。
6. **系统内置威胁**：如果 OS 或平台方把它做成系统功能，它还活吗？——**桌面 / 效率 / 移动工具类产品的头号生死问题，必答。**

**差异化真伪四步判定（尺子）**

1. 列出它自称的差异点。
2. 对每个差异点，找**免费**替代实现（开源 / 系统内置 / 大厂免费版）。
3. 若免费方案已能覆盖 80% → 判定为 **「包装」**。
4. 剩余真正无法被免费替代的差异点，才是它的定价依据。

**定价天花板公式（尺子）**

```
定价天花板 ≈ min(竞品价格, 用户人力替代成本, 损失规避金额) × (1 − 免费替代覆盖率)
```

免费替代覆盖率越高，天花板越低；覆盖率达 100% 时天花板 = 0。

### 3.8 L6 · 能不能持续（C 端的核心是留存）

**必答 7 问**

| # | 问题 | 判定要点 |
|---|---|---|
| 1 | **护城河类型** | 网络效应 / 数据飞轮 / 切换成本 / 生态与插件 / 品牌 / 成本结构 / 补贴 |
| 2 | **护城河时间窗** | 还能守多久？**给出时间估计 + 依据** |
| 3 | **团队与资源** | 人数 / 融资 / 人均产出 / 现金流正负 |
| 4 | **平台依赖** | 单一分发渠道 / 单一 API / 单一 OS 政策 / 单一模型供应商 |
| 5 | **技术风险** | AI 是否把它降维成「一个 prompt」？模型能力下放是否吞掉它？ |
| 6 | **合规风险** | 数据隐私 / 个人信息保护法 / 版权 / 内容安全 |
| 7 | **生命周期位置** | 萌芽 / 成长 / 成熟 / 衰退——依据是什么 |

**C 端专用：激活与留存**

| 必答问题 | 追问 |
|---|---|
| 用户第一次用，多久能感受到价值？（Aha moment 是什么） | 能不能压缩到 3 分钟内？ |
| 留存曲线长什么样？（次日 / 7 日 / 30 日） | 是「微笑曲线」（回升）还是持续下滑（= 没有真实价值）？ |
| 月流失率（churn）多少？ | 年付客户的续费率比月付高多少？ |
| 什么行为与留存强相关？ | 能不能主动把用户推向那个行为？ |

> **死信号**：只谈下载量 / 注册量，从不谈留存。**下载量是虚荣指标，留存才是命。**
> **审计口径**：留存必须按**自然日 / 自然周分群**看，不能只看总体平均（会被新增用户稀释）。

**护城河时间窗评分（尺子）**

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 可复制性 | 纯功能，一周可抄 | 需数月工程 | 需多年数据 / 网络效应 |
| 迁移成本 | 无数据沉淀 | 有配置 / 习惯 | 有团队级数据资产 |
| 生态位 | 无插件无集成 | 有部分集成 | 有开发者生态 |
| 平台风险 | 完全依赖单一平台 | 多平台 | 自建渠道 |

总分 0–3：护城河 < 6 个月；4–5：6–18 个月；6–8：18 个月以上。**必须写依据，不要只给分数。**

### 3.9 L7 · So What（结论与行动）

**必答 5 问**

1. **结论先行**：3–5 条编号判断——**全文最重要，放最前**。
2. **可迁移清单**：能抄什么（机制 / 定价 / 增长手法 / 交互设计）。
3. **反面清单**：别做什么（它踩的坑 / 它的伪需求 / 它的过度设计）。
4. **机会点**：若我要进场，切入点在哪？最小验证是什么（MVP 验证方案）？
5. **缺口声明**：哪些数据没拿到、哪些是推断、可信度如何。

**写法三条硬要求**：① 每条都是**判断**不是描述；② 每条都带**依据或时间估计**；③ **至少一条是否定性结论**（敢说不行）。

## 五、C 端专用筛具与一票否决

### 5.1 三问快筛（时间紧就只答这 3 个）

| # | 问题 | 死信号 | 好信号 |
|---|---|---|---|
| 1 | 谁现在因为这件事在难受？（具体人群 + 具体时刻） | 回答是「所有人」「所有办公族」 | 能说出具体场景、具体频次 |
| 2 | 他现在怎么解决的？为此付过钱吗？ | 已有零成本且体验不错的免费替代 | 只能手工做 / 正在付费买别扭的老工具 |
| 3 | 我能 2 周内低成本触达 20 个这样的人吗？ | 完全不知道人在哪 | 有现成社群、名单、渠道 |

> 第 3 问是**一票否决项**。分发不可得，直接杀，不必进入打分环节。

### 5.2 打分卡（C 端加固版 · 12 维，满分 135）

| 维度 | 权重 | 5 分锚点 | 1 分锚点 |
|---|---|---|---|
| 使用频次 | ×3 | 每天 / 每周多次 | 一次性 |
| 痛点硬度 | ×3 | 不做直接损失钱或触发合规风险 | 只是「更方便」 |
| **分发可得性** | ×3 | 能直接触达并让 20 人开口 | 完全不知道人在哪 |
| 现有替代糟糕度 | ×2 | 只能手工或付费买别扭的老工具 | 系统内置已够用 |
| 付费方明确度 | ×2 | 有预算科目 / 有付费先例 | 无任何付费先例 |
| 持续交付成本 | ×2 | 有真实云 / 模型 / 内容成本 → 订阅成立 | 纯一次性交付 → 只能买断 |
| 你方独占优势 | ×2 | 有数据 / 身份 / 渠道别人没有 | 无 |
| 窗口期长度 | ×1 | 大厂 2 年内不会做 | 下个系统版本就被内置 |
| 合规 / 平台风险 | ×1 | 无单一 API 依赖 | 依赖单一平台政策 |
| **收款可行性**（新增） | ×3 | 通道明确、资质具备、费率可接受 | 无合法收款路径 |
| **隐性成本可控性**（新增） | ×3 | 可完全自助，边际成本 ≈ 0 | 每单需人工介入 |
| **客体匹配度**（新增） | ×2 | 形态与我的时间 / 资质完全匹配 | 需要团队或资质 |

**计分**：满分 = (3+3+3+2+2+2+2+1+1+3+3+2) × 5 = **135**。
**阈值**：≥ 70%（≈95 分）→ 进入证伪环节；≤ 50%（≈68 分）→ 直接杀；中间区间 → 只做**最低成本**的补充采集，不投入实验资源。

### 5.3 一票否决（不论总分多高，触发即杀）

| # | 否决项 | 为什么不可救 | C 端高发度 |
|---|---|---|---|
| 1 | **分发不可得** | 需求再好也不属于你 | ★★★ |
| 2 | **使用频次 = 一次性，且无持续交付成本** | 订阅不成立，只能买断，天花板极低 | ★★★ |
| 3 | **依赖单一平台 / 单一 API，且一个版本更新就可能被内置** | 生命周期不可控 | ★★★ |
| 4 | **触碰合规红线**（金融 / 医疗 / 未成年人 / 爬虫 / 版权 / 隐私数据） | 直接排除整类方向 | ★★ |
| 5 | **答不出「去掉 AI 之后还剩多少价值」**（AI 类专用） | 大概率只是 prompt 包装 | ★★★ |
| 6 | **收款路径不成立** | 通道需要我不具备的资质，或品类被通道明令禁止 → 产品再好也无法变现 | ★★ |
| 7 | **边际成本 ≥ 定价** | 每多一个用户就多亏一份钱，规模越大死得越快 | ★★★ |
| 8 | **客服 / 合规成本超出个人承载上限** | 单用户需要人工介入 → 收入增长被成本同比吃掉 | ★★ |
| 9 | **B 端方向要求我方不具备的资质或现场交付能力** | 结构性做不到，不是努力问题 | C 端不适用（列出以保持完整） |

### 5.4 盈利可行性 12 问（C 端适用前 11 问）

| # | 问题 | 答不出来的后果 |
|---|---|---|
| 1 | 钱从哪个通道进来？我具备资质吗？ | 做出来也收不到钱 |
| 2 | 定价多少？依据是什么（价值 / 竞品 / 人力替代成本）？ | 定价靠猜 |
| 3 | 每多一个用户我多花多少钱？定价覆盖得住吗？ | 越赚越亏（AI 类高发） |
| 4 | 每月固定成本多少？要多少付费用户才不亏？ | 算不出生存线 |
| 5 | 单用户回本周期多长？ | 不知道能不能撑到盈利 |
| 6 | 前 100 个用户具体从哪来（指名到社群 / 名单）？ | 分发不可得 = 一票否决 |
| 7 | 转化漏斗每层的数字？（曝光→访问→试用→付费） | 不知道瓶颈在哪 |
| 8 | 次日 / 7 日 / 30 日留存多少？月流失率多少？ | 看不清产品是否真有价值 |
| 9 | 谁来提供客服？我一个人扛得住多少用户？ | 上线即被支持拖死 |
| 10 | 用了哪些开源库 / 第三方 API？许可证允许我商用吗？ | 法律风险 |
| 11 | 涉及个人信息 / AI 生成内容吗？要做什么合规动作？ | 被下架或被投诉 |

## 六、C 端盈利模型与「客单价 × 分发难度」匹配表

### 6.1 三个公式

```
年营收   = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利   = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本
```

### 6.2 生存线速算（个人开发者专用换算）

> 买断 ¥99 的产品，要覆盖每月 ¥500 的固定成本 → **每月需卖出约 5 单以上**（未计手续费与退款，需自行代入实际费率）。
> **先算这个数，再去想「怎么卖到 5 单」——比先想「做什么功能」重要得多。**

### 6.3 客单价分档与所需分发量级（关键决策工具）

> ⚠️ 下表价格档为**示例分档**，用于说明结构关系，**不是市场数据**。实际使用须代入自己标的的实测客单价与转化率。

| 客单价档（示例） | 大致模式 | 所需用户量级 | 对分发能力的要求 | 个人可行性 |
|---|---|---|---|---|
| ¥9 级 | 冲动型工具 / 内购解锁 | 需要海量 | 必须有规模化渠道（商店红利 / 病毒传播） | ⚠️ 个人最难：海量分发恰好是个人最缺的 |
| ¥99 级 | 买断型单点工具 | 中量 | 垂直社区 + 内容复利可支撑 | ✅ 可行（前提：单点做到最好） |
| ¥299 级 | 专业工具 / 年订阅 | 少量高意向 | 精准人群 + 高信任内容 | ✅ **个人最优区间** |
| ¥999+ 级 | 专业级工具 / 小团队 | 更少 | 靠专业信任与口碑 | ✅ 可行，但市场规模有限，需确认人群付费力 |

> **核心结论**：**客单价的选择决定了你的分发难度。** 个人 / 小团队应**优先选高客单价 + 小规模高意向人群**，而不是「低价 + 大流量」。

### 6.4 边际成本红线（AI 类方向专用）

```
可行条件（AI 类加固）：定价 > 单次调用的模型成本 × 单人月均调用次数 × 安全倍数
```

- 免费版**限功能**，付费版**限用量**——不要反过来。
- 必须设：用量上限 / 阶梯价 / 降级策略 / 缓存或本地推理方案。
- 必须答：**供应商涨价 30% 后，我还赚钱吗？**

## 七、C 端常见死因与反模式（穷举）

### 7.1 无效探索的根因（C 端相关的 8 条）

| # | 常见做法 | 无效根因 | 后果 |
|---|---|---|---|
| 1 | 刷 Product Hunt / 新品榜 / 热搜找灵感 | 拿到的是**别人的答案**，且是滞后信号 | 只能抄形态，抄不到需求 |
| 2 | 从技术能力倒推场景 | 供给驱动，需求缺位 | 做出没人要的东西 |
| 3 | 凭空头脑风暴 | 产出的是**品类名**（「做个 AI 笔记」） | 无法验证，无法定价 |
| 4 | 先算 TAM / 研究赛道规模 | 大市场 ≠ 你能拿到 | 用宏大叙事替代可行性判断 |
| 5 | 一上来做竞品全量功能对比 | 需求尚未证伪，对比无意义 | 抄一堆用不上的功能 |
| 6 | 忽略「免费替代」与「什么都不做」 | 这两者成本为 0，是最强竞品 | 定价一上市就被击穿 |
| 7 | 一次只深挖 1 个想法 | 时间沉没成本高 → 自我说服 | 把「舍不得」当成「有前景」 |
| 8 | 用「未来意愿」当验证（「你会用吗？」） | 口头意愿与实际行为几乎不相关 | 拿到虚高信心 |

### 7.2 误判 / 反模式（C 端高发的 10 条）

| # | 误判 | 为什么错 | 替代做法 |
|---|---|---|---|
| 1 | 把功能数量当价值 | 数功能 = 数成本；功能多常是定位不清 | 只问「用户为哪一件事付钱」 |
| 2 | 把技术亮点当用户价值 | 「用了自研模型」不是卖点，「快 3 倍」才是 | 换成用户可感知的表述 |
| 3 | 用「我认为有用」替代「用户真的在用」 | PM 最容易犯的错 | 找真实使用行为证据 |
| 4 | 忽略免费替代与「忍着不做」 | 导致严重高估市场 | 每条卖点拿去和零成本方案对撞 |
| 5 | 累计数据当年化数据用 | 「累计服务 100 万用户」≠ 100 万活跃 | 一律标口径与时间窗 |
| 6 | 只看现状，不问「会被什么吃掉」 | 系统内置 / 大模型下放 / 开源是三大吞食者 | 必答趋势问题 |
| 7 | 结论模糊 | 只说「有前景」不可执行 | 落到抄什么 / 别做什么 / 从哪进场 |
| 8 | 用「品类繁荣」推导「单品能赚钱」 | 赛道大 ≠ 你能切到份额 | 拆到单品与人群层级 |
| 9 | 把「用户吐槽多」当负面 | 吐槽多是使用深度的证据 | 无人讨论才是真危险 |
| 10 | 把「我认识的人都说需要」当成市场验证 | 同质化样本偏差 | 换异质人群 + 直接收钱 |

### 7.3 C 端专属陷阱（补充 6 条）

| # | 陷阱 | 为什么致命 | 应对 |
|---|---|---|---|
| 1 | **只统计下载量 / 注册量** | 虚荣指标，掩盖留存崩塌 | 只看分群留存与付费转化 |
| 2 | **定价过低求销量** | 低价需要海量分发，恰好是个人最缺的 | 提高客单价，缩小目标人群 |
| 3 | **免费额度给太大** | 边际成本失控 + 免费用户永不变现 | 免费版限功能，付费版限用量 |
| 4 | **认为「上架就有人买」** | 商店是渠道不是分发；无推广 = 零曝光 | 上架前先攒 100 个种子用户 |
| 5 | **拿「AI」当卖点** | 用户不为技术付钱，为结果付钱；模型能力下放会抹平 | 卖可感知的结果（快 N 倍 / 少做 N 步） |
| 6 | **把「开源 + 赞助」当商业模式** | 赞助收入极不稳定，且与买断付费意愿互相掐死 | 开源社区版 + 商业版双轨，或纯商业闭源 |

## 八、可执行位置判断（收敛）

### 8.1 值得做的 C 端方向画像（正面清单）

| # | 特征 | 为什么 |
|---|---|---|
| 1 | 有一群**具体的、我能零预算触达的**人 | 分发可得 = 唯一不可替代的前提 |
| 2 | **高频 + 痛感强**（最佳象限） | 订阅成立、复购好 |
| 3 | 替代品是「**还在收钱但体验陈旧**」的老工具 | 付费意愿已被验证（原型 ① 替代升级型） |
| 4 | 免费替代覆盖率 < 80% | 才有定价空间 |
| 5 | **边际成本 ≈ 0**（本地优先 / 缓存 / 限额） | 规模越大越赚，而不是越亏 |
| 6 | 支持面窄（单点工具），客服可自助化 | 一个人扛得住 |
| 7 | 客单价落在 ¥99–¥999 区间 | 少量高意向用户即可养活 |
| 8 | 高频**入口**（快捷唤起 / 右键菜单 / 拖拽即用）而非高频功能 | 入口决定使用频次，频次决定能否收订阅 |

### 8.2 不要碰的 C 端方向画像（负面清单）

| # | 特征 | 为什么 |
|---|---|---|
| 1 | 需求真实但**我完全不知道人在哪** | 分发不可得，一票否决 |
| 2 | 系统 / 平台**已经内置且够用** | 定价天花板 ≈ 0 |
| 3 | 一次性需求 + 无持续交付成本，却想收订阅 | 必然流失 |
| 4 | 云端 AI 无限用量、无任何限额 | 边际成本失控 |
| 5 | 需要海量分发才能养活（¥9 级低客单） | 个人最缺的恰好是海量分发 |
| 6 | 需要密集人工介入（审核 / 客服 / 定制） | 一个人扛不住 |
| 7 | 触碰合规红线（金融 / 医疗 / 未成年人 / 爬虫 / 版权 / 隐私数据） | 直接排除 |
| 8 | 依赖单一平台政策且该能力随时可能被内置 | 生命周期不可控 |
| 9 | 需要教育市场才被理解的卖点 | 需要教育才被理解的卖点 ≈ 不存在 |

### 8.3 从哪进场 / 最小验证

| # | 问题 | 判定 |
|---|---|---|
| 1 | 用户装它只为做**哪一件事**？ | 说不出来 = 还没想清楚，别开工 |
| 2 | 它明确**不做什么**？（Non-scope） | 防止功能蔓延 |
| 3 | 变现的**付费墙**卡在哪一层？与频次匹配吗？ | 位置决定商业模式类型 |
| 4 | 是否有**真实的持续交付成本**？ | 没有 → 只能买断 |

**形态选择原则**：从**单点高频工具**起步，而非工作流套件或平台。

| 形态 | 启动成本 | 适合谁 | 风险 |
|---|---|---|---|
| 单点工具（mini-tool） | 低 | 个人开发者、无销售团队 | 天花板有限，易被内置 |
| 工作流套件 | 中 | 有产品组合经验的小团队 | 功能蔓延，定位模糊 |
| 平台 / 生态 | 高 | 有资金、渠道、BD 能力 | 冷启动极难 |

**判定口诀**：`低频 + 无持续成本 → 只做买断单点工具；高频 + 有持续成本 → 可做订阅；需要教育市场 → 不做。`

**最小验证：证据强度阶梯（只认行为，不认口头）**

| 强度 | 实验 | 做法 | 测的是 | 成本 |
|---|---|---|---|---|
| 弱 | 问未来意愿 | 问「你会用吗 / 你觉得有用吗」 | 意愿（**几乎无效**） | 极低 |
| ↓ | 落地页点击 | 一页落地页，看点击率 | 兴趣强度（非付费） | 低 |
| ↓ | 留邮箱 / 预约 | 「留下邮箱第一时间通知」 | 明确意向 | 低 |
| ↓ | 人肉代做观察 | 手工交付 5 个用户，观察是否持续使用 | **真实使用行为** | 中 |
| **强** | 直接收钱 / 预售 | 明码标价，要求现在付款或付定金 | **付费意愿（唯一强信号）** | 中 |

**判定门槛（写死，不许临场放宽）**

| 结论 | 条件 |
|---|---|
| **立项** | ≥5 个真实用户持续使用（非一次性）；或 ≥3 个明确的付费信号（含预付、定金、书面意向） |
| **待观察** | 有使用但无付费信号 → 补做收费实验，2 周内无改善则杀 |
| **杀掉** | 无人持续使用；或用户明确表示「免费可以，付费不要」 |

## 附 · 口径说明与缺口声明

**口径说明**

- **【2026-10-08 口径修正】本文不含外部数据，是「文档层的边界」，不是「产出的限制」。** 用本文做**产品分析**时，产出**必须包含数据与测算**：拿不到的数不许只写缺口——先给获取路径；确实取不到，就按「合理预估五法」（自上而下 / 自下而上 / 类比推算 / 锚点反推 / 区间优先）给出有依据的推算，写成 **假设 → 依据 → 推算 → 结果** 四段，附**置信度**与**敏感度**（关键假设 ±50% 后结论是否翻转）。**禁止的是「无依据的数字」，不是「估算」本身。** 交付须含附录三件套：A 数据明细（指标 / 数值 / 口径 / 来源级别 / 采集日）、B 测算过程与敏感度、C 缺口声明与应查未查清单。完整方法见 skill `product-analysis-framework` §四，以及本文 §3.4 / §3.5 / §6 的 C 端专用测算式。
- 本文全部内容为**方法框架与判定标准**，不含任何市场规模、用户量、营收等外部量化数据。
- §3.6 支付费率表、以及各处出现的比例（15%/30% 抽成、约 0.6% 聚合支付、LTV:CAC > 3、回本周期 < 12 个月等）均为**行业常见区间或经验值**，采集日 2026-10-08，**未经官方页核实**。使用时必须回到对应官方页面重新确认，并记录采集日期与币种。
- §6.3 的「客单价分档 ↔ 所需用户量级」为**结构示意**，价格档不是市场数据，须代入自己标的的实测客单价与转化率重算。
- 涉及合规与税务的内容仅用于提示「这是一个必须提前确认的问题」，**不构成法律或税务建议**，具体须咨询专业人士并查最新规定。

**缺口声明**

- 【未实测】§3.6 D 中「200 个付费用户 → 每工作日约 10 次支持请求」为量级推演示例，非实测数据。

- 【推断】§2 的九层地图为归纳产物：真实分析中 L4.5 / L4.6 常需与 L4 同时完成，层序是提问顺序而非流程阶段。
- 【未覆盖】本文不含：C 端的大规模投放实操（ROAS 测算细节）、应用商店 ASO 具体手法、移动端特有的推送与召回策略——如需可另立文档。
