## 〇、结论先行（TL;DR）

**可行，但不是"照抄"，是"观察后重建"。你的三个输入信息带宽差了一个数量级，不能平等对待。**

| # | 判断 |
|---|---|
| 1 | **三份输入的信息量排序：exe ≫ 官网 > 功能简介。** exe 是唯一的一手来源，但要靠工具"解锁"；官网是营销口径，只能当校验；**功能简介只能当覆盖率检查表，绝不能当需求来源** |
| 2 | **最大的错误是从官网抄功能列表当 PRD。** 那做出来是个空壳——功能名字都有，交互细节全不对。UI 规格、交互逻辑、数据模型**只能从 exe 里挖** |
| 3 | **第一步必须做「技术栈识别」，它决定后面全部手段。** 同一个 exe，是 Qt 还是 Electron 还是自绘，侦察路径完全不同。**不开程序先做这一步**（Detect It Easy + 安装目录 + 依赖 DLL），30 分钟内能出结论 |
| 4 | **决定项目生死的是三个问题**：① 有壳/加固吗？② UI 是自绘吗？③ 网络能不能抓？这三个答案决定了这活儿是 2 周还是 2 个月 |
| 5 | **官网的最佳用法不是抄功能，是读更新日志和 FAQ。** 更新日志能反推功能演进优先级（先做什么后做什么），FAQ/帮助文档藏着交互细节——这两样比功能简介值钱得多 |
| 6 | **黑盒拿不到的东西要提前认**：服务端业务规则、加密/签名算法、私有 API 契约、内部数据模型。能观察行为，不能还原实现。**后端大概率要自建，不是"复刻"** |
| 7 | **法律前置比白盒更严。** 反编译的合规风险 > 读公开页面。先读 EULA 再说其他 |

## 一、输入 → 产物的精确映射

**你的三个输入，各自只能喂给流程的特定段落：**

| 输入 | 信息带宽 | 能支撑的阶段 | 实际产出 | **不能**支撑 |
|---|---|---|---|---|
| **原始 exe** | 一手 · 最强 | 阶段 1 识别、2 侦察、3 规格、8 一致性验收 | `05-detect.md`、`10-recon/*`、`20-spec/*`、`70-parity/*` | 服务端逻辑、算法实现、内部数据模型（只能推断） |
| **官方网站** | 二手 · 营销口径 | 阶段 0 边界、4 需求校验、9 差异化 | 定价结构、目标用户表述、卖点、**更新日志→功能演进优先级**、FAQ→交互细节 | UI 规格、交互细节、数据结构 |
| **功能简介** | 三手 · 最弱 | 阶段 4 **覆盖率检查** | `features.csv` 的**遗漏核对清单** | 几乎所有细节 |

### 1.1 功能简介的正确用法（反常识）

**错误用法**：把它当需求来源 → 逐条实现 → 做出来的东西功能名字都有、用起来完全不一样。

**正确用法**：把它**倒过来当验收清单**。侦察完成后，拿它的每一条去反查侦察产物：
- 这条功能在 `flows.md` 里有对应流程吗？→ 没有 = 侦察有遗漏
- 有流程，但 `controls.md` 里找不到对应控件？→ 覆盖不全
- 有控件，但没有 evidence 截图？→ 未完成

**它是防漏网的工具，不是需求文档。**

### 1.2 官网的隐藏价值（比功能简介高一个数量级）

| 官网板块 | 能推什么 | 怎么用 |
|---|---|---|
| **更新日志 / Release Notes** | **功能演进优先级** | 看它半年内加了什么——那就是真实用户最想要的；也能判断产品的方向 |
| **帮助文档 / FAQ** | **交互细节** | "支持哪些格式""如何批量""快捷键是什么"——这些官网写得比功能简介细得多 |
| **定价页** | 商业化结构与付费墙位置 | 直接对应 `30-prd` 的抄砍换决策：哪些功能是收费的、收费点在哪 |
| **用户评价 / 案例** | 目标用户与场景 | 喂给阶段 9 差异化 |
| 功能简介 | 功能模块名称 | **仅当检查表** |

## 二、黑盒侦察执行手册（四层推进）

每一层都有明确工具、采集对象、产出文件。**按顺序做，不要跳。**

### L1 · 静态侦察（不开程序，30 分钟出结论）

| 采集对象 | 工具 | 判断什么 |
|---|---|---|
| 壳 / 保护 | **Detect It Easy**、PEiD | 是否加壳、什么编译器、有无混淆 → **有壳则静态侦察基本失效，只能纯动态** |
| 安装目录结构 | 文件管理器 | `resources/app.asar` = Electron；`Qt5Core.dll/qwindows.dll` = Qt；`*.dll` + `mscorlib` = .NET；`python3x.dll` = 打包 Python |
| 依赖 DLL | Dependencies / `dumpbin` | 判定技术栈与第三方库 |
| 资源 | **Resource Hacker** | 图标/位图/字符串表/对话框模板/版本信息/清单文件 → 拿到的资源**不能直接用**（版权），只作**尺寸与结构参考** |
| 字符串 | `strings`、Resource Hacker 字符串表 | URL、API 端点、配置键名、正则、错误提示原文 |
| 配置文件 | 安装目录 + `%AppData%` | 默认配置结构 → **推断内部数据模型的捷径** |

**产出**：`05-detect.md` —— 技术栈结论 + 侦察手段选择 + **自绘/加固判定**

**这一步的判定直接决定路线**：

| 识别结果 | 后续代价 | 说明 |
|---|---|---|
| Win32 / MFC / VB6 | **低** | Spy++ 全掌握，控件可定位 |
| WPF / WinForms / UWP | **低** | UIA 树完整 |
| Qt | 中 | GammaRay + 布局反推 |
| Electron / WebView2 / Tauri | **低**（若未加密打包） | CDP 直接读 DOM，等同网页 |
| **自绘 UI（DirectUI/自研渲染）** | **高** | UIA 树为空、Spy++ 只见一个空窗口 → **只能像素级还原 + 图像匹配** |
| **有壳 / 加固** | **高** | 静态全废，只能动态观察 |

### L2 · 动态结构侦察（开程序，读界面结构）

| 框架 | 工具 | 采集 |
|---|---|---|
| Win32/MFC | **Spy++**（准星拖拽） | 类名、控件 ID、窗口层级、样式位、`WM_COMMAND` 消息流 |
| WPF/WinForms/UWP | **Inspect.exe** / FlaUI / FlaUInspect | UIA 树：ControlType / Name / AutomationId / 支持的 Pattern |
| Qt | **GammaRay** | 窗口对象结构与布局层级 |
| Electron/WebView2 | **CDP**（Playwright 接 `--remote-debugging-port`） | DOM + 计算样式（**最理想的情况**） |
| 通用快照 | `@uipath/servo`（`servo snapshot`）、pywinauto（`print_control_identifiers`） | UI 树快照 |
| 批量规格提取 | **screenpilot** | design tokens + 组件目录（含 hover/focus/disabled）+ 页面蓝图 |

**产出**：`10-recon/surfaces.md`、`controls.md`、`components.md` → `20-spec/design-tokens.json`、`page-blueprints.md`

**`controls.md` 必须多一个字段：定位器可用性**（黑盒场景下这是最大不确定性）：

```markdown
| 控件ID | 界面 | 定位器 | 类型 | 优先级 | 可用性 |
|---|---|---|---|---|---|
| C-001 | 主界面/工具栏 | HWND/类名=Button/ID=0x101 | Win32 | 高 | ✅ 稳定 |
| C-014 | 主界面/文件列表 | UIA/AutomationId=FileList | UIA | 高 | ✅ 稳定 |
| C-027 | 预览面板 | 图像匹配/preview_btn.png | 自绘 | 低 | ⚠️ 依赖DPI与主题，需重录 |
```

### L3 · 行为侦察（读它做了什么）

| 采集对象 | 工具 | 产出 |
|---|---|---|
| 文件读写 / 注册表 / 进程 / 句柄 | **Process Monitor** | 它把配置、缓存、日志写在哪；是否依赖外部组件 |
| API 调用 | **API Monitor**、Frida | 关键系统调用与第三方库调用 |
| 网络请求 | **Fiddler / Charles / mitmproxy** | 接口清单、请求/响应结构 |
| 剪贴板 / 拖放 / 文件关联 / 开机启动 / 右键菜单 | 手工触发 + 注册表 | 系统集成清单 |

**产出**：`behavior.md` + `datamodel.md`（**从网络响应的字段反推数据模型**——这是黑盒下最接近"真实数据结构"的来源）

### L4 · 交互与状态侦察（读它怎么表现）

| 采集对象 | 做法 | 产出 |
|---|---|---|
| 核心流程 | 逐流程走查 + 录屏 + **分 DPI（100/125/150/200%）× 分主题（浅/深）截图** | `flows.md` + `evidence/screens/` |
| 交互状态 | hover / focus / disabled / loading / 空态 / 错误态 | `interaction-spec.md` |
| 边界与异常 | 断网、错误输入、权限不足、并发操作、大文件/大批量 | 错误处理清单（**复刻质量差异最大的地方**） |
| 快捷键 | 遍历菜单项 + 常见组合 + 菜单里的助记符 | 快捷键全表 |
| 动效 | 录屏逐帧 | 时长/缓动/触发条件 |

**产出**：`flows.md`、`interaction-spec.md`、`60-test/cases/`（**从控制流直接生成测试用例**——官网流程描述不能当用例来源）

## 三、拿不到什么（黑盒的硬边界）

| 拿不到 | 影响 | 替代方案 |
|---|---|---|
| 服务端业务规则 / 校验逻辑 | 无法 1:1 还原规则 | 黑盒观察输入输出，**推断规则并写成假设**，标注置信度；或自研更简单规则 |
| 加密 / 签名算法 | 无法复用其协议 | 抓包分析前后文；**自建协议**（不要解壳抄算法，合规风险高） |
| 私有 API 契约 | 接口不稳定、易变 | **重新设计自己的后端**，不依赖对方接口 |
| 内部数据模型 | 只能推断 | 从网络响应字段 + 配置文件结构 + 界面字段三方交叉推断 |
| 授权 / 付费校验逻辑 | — | **绝对不要绕过**（法律红线，见第六节） |
| 性能实现细节 | 无法复刻同等性能 | 自行优化 |

**一句话**：**黑盒复刻只能复刻"做什么"和"看起来怎样"，不能复刻"怎么做的"。** 后端与算法层大概率是自建，工期要按自建算，不是按"抄"算。

## 四、三个决定生死的检查（做完才谈排期）

**在这三件事有答案之前，任何工期估算都是猜。**

| # | 检查 | 怎么做 | 结果含义 |
|---|---|---|---|
| 1 | **有壳 / 加固吗？** | Detect It Easy 拖进 exe | 无壳 → 静态侦察可用，能提资源/字符串；有壳 → 只能纯动态观察，成本 ×1.5–2 |
| 2 | **UI 是自绘吗？** | 开程序，Spy++ 准星拖到主界面**按钮**上。看到有意义的类名/控件 ID → 非自绘；只看到一个占满窗口的空白容器 → **自绘** | 自绘 → `controls.md` 基本建不起来，只能图像匹配 + 像素还原。**这是最容易被低估的坑** |
| 3 | **网络能抓吗？** | Fiddler/Charles 挂代理，跑一遍核心流程 | 能看到明文/可解 JSON → 数据模型可推断；**抓不到（TLS 固定/自研协议）** → 后端必须完全自建，且拿不到字段线索 |

**三种结果的组合，决定项目量级**：

| 组合 | 量级 | 说明 |
|---|---|---|
| 无壳 + 非自绘 + 能抓包 | **最理想** | 结构可读、规格可提、数据模型可推 |
| 无壳 + 非自绘 + 抓不到包 | 中 | 前端可高保真复刻，后端自建 |
| 有壳 / 自绘 | **高** | 侦察靠像素与行为观察，规格靠人工量，工期显著拉长 |
| 自绘 + 抓不到包 | 最难 | 只剩"看着像 + 行为等价"，建议重新评估是否值得做 |

## 六、法律前置（黑盒场景风险更高）

| 维度 | 黑盒场景的特殊风险 | 控制 |
|---|---|---|
| **EULA** | 绝大多数商业软件 EULA **明确禁止逆向工程**。先读，读完再决定 | 商用前必须法律评估 |
| 反编译 | 合规风险 > 读公开页面。**有壳产品的解壳行为风险更高** | 静态侦察限于"识别与观测"，不解壳、不 patch |
| 资源使用 | 图标/位图/字符串**直接提取使用 = 侵权** | 提取仅作尺寸/结构参考，视觉元素全部重绘 |
| 授权绕过 | 去广告、解锁付费、绕过校验 | **红线，不做**。这不是复刻，是破解 |
| 私有接口 | 复用对方 API 不利于合规也不稳定 | 接口全部重新实现 |
| 数据 | 不得搬运对方用户数据/内容库 | 自建 |

**自用与商用的差别是决定性的。** 同一套技术动作，自用学习研究多数的风险可控，商用则要过 EULA、商标、专利三道关。**这个判断必须在阶段 0 做，不能推迟到上线前。**

## 七、对流程契约的补充（黑盒专属）

在第二篇的 `clone/` 目录契约基础上，黑盒场景需要增加：

```
clone/
├── 00-brief.md                  # 增加：EULA 结论 / 自用or商用 / 法律前置结论
├── 05-detect.md                 # 新增：技术栈 + 壳判定 + 自绘判定 + 侦察手段选择
├── 10-recon/
│   ├── controls.md              # 增加：定位器可用性字段（高/中/低 + 不稳定原因）
│   └── evidence/
│       ├── static/              # 静态侦察原始件（PE 信息/资源清单/字符串）
│       └── screens/             # 分 DPI × 分主题截图

│   └── assumptions.md           # 新增：黑盒推断的规则假设（含置信度）
└── 30-prd/
    ├── features.csv             # 由可观测行为生成，非官网抄录
```

**新增硬规则**：**凡是推断出来的东西，必须标置信度并写进 `assumptions.md`**。黑盒下"看起来是这样"和"确认是这样"必须分开——这是数据纪律在黑盒场景的落地。

## 八、缺口与未决

| 缺口 | 说明 |
|---|---|
| 具体目标未知 | 本文为通用细则，未针对某个具体 exe。技术栈、壳、自绘、抓包四项判定需在真实目标上执行 |
| 自绘 UI 还原准确率无公开基准 | 像素级还原的误差范围无行业数据，需实测 |
| 抓包对抗手段演进快 | 证书固定、双向认证、自研协议普遍化，Fiddler 成功率在下降，需按目标实测 |
| 工具可用性未验证 | Detect It Easy / Spy++ / Inspect / screenpilot / WinApp MCP 在本机的可用性未验证 |
| 工期量级为主观判断 | 第四节"量级"列基于工具能力推断，**非实测数据**，需用真实目标校准 |

### 应查未查
- 目标产品的 EULA 原文
- 目标产品的隐私政策（判断其数据流向，辅助推断架构）
- 是否有同类开源实现可直接复用（**先搜开源，能省则省**）
