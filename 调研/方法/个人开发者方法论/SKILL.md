# 个人开发者方向 · PM 方法论（方向专用 · 可执行流程）

> **一句话定位**：个人开发者不是「小号的公司」——公司的约束是**资源**，个人的约束是**时间、资质与承受力**。用公司标准评估一个人的生意，会永远选到「市场最大」而不是「我这条命能跑通」的方向。
> **与 `product-analysis-framework` 的关系**：那个是产品分析框架（七层提问法）；本 skill 把 **L4.6 交付与合规** 与 **L4.5 盈利模型** 前置成两道**闸门**，因为对个人来说这两条不过，后面全废。
> **与 `product-research-report` 的关系**：那个提供报告模板与赛道基准数据；本 skill 决定 **哪四道闸门、按什么顺序否决、什么时候该停**。
> **权威详版（长尾细则）**：**与本文件同目录** —— `个人开发者方向-PM方法论集成.md`（629 行，自包含）。本 SKILL 承载**决策关键路径**；需要通道费率表、合规 13 条逐条追问、原型→验证映射时，读**同目录**文档（§3.1 / §5 / §10.3）。

## 一、六条不可让步的先验

1. **第一约束不是需求，是「能不能合法收到钱」和「能不能长期承受隐性成本」。** 这两件事在**写代码之前**就该确认。
2. **四道闸门，顺序否决，不可跳**：① 收得到钱 → ② 扛得住成本 → ③ 送得到人 → ④ 算得过账。**前两道不过，后面的分析全部作废。**
3. **时间预算决定「每年只能认真做一件事」。** 在职副业每周 8–15 小时，其中 **30%–50% 会被上线后的维护 / 客服 / 运营吃掉**。所以**选错方向的机会成本，远高于做得慢**。
4. **不可能三角**：高频迭代 / 深度销售 / 大规模投放，同一时间只能占两角。个人的最优解是「**高频迭代 + 社区分发（放弃投放）**」。
5. **头号杀手不是竞品，是客服。** 200 个付费用户若每人每月问一次 ≈ 每工作日约 10 次支持请求 = 一个人的全部业余时间。
6. **天然优势在 C 端与「自助型小微 B」**（无需销售团队、无需现场交付）；**天然劣势在需要人力与资质的一切环节**（招投标、等保、私有化实施、7×24 SLA）。

## 二、四个「结构性做不到」（不是努力问题）

| # | 结构性做不到 | 为什么 |
|---|---|---|
| 1 | 需要现场交付 / 招投标 / 私有化实施 | 需要团队、资质与账期承受力 |
| 2 | 需要 7×24 SLA 的基础设施类产品 | 稳定性承诺需要轮值与备份人力 |
| 3 | 需要持续人工介入（审核 / 定制 / 深度服务） | 收入增长被人力成本同比吃掉 |
| 4 | 需要我不具备的资质（金融 / 医疗 / 教育牌照、等保） | 门槛即天花板 |

> **三个最容易犯的元错误**：用公司标准评估一个人的生意 · 把「我能不能做出来」当主要问题 · 把「成本」等同于「服务器那点钱」。

## 三、执行流程 SOP

**默认动作**：只要产出了判断 / 清单 / 对比 / 评估，就落盘为 `.md`（用户铁律，不产 docx/pdf/pptx/xlsx）。不必等用户说「归档」。

1. **过闸门 1 · 收得到钱** —— 主体与通道、定价结构、支付摩擦与税费、ARPU 提升机制。**不过 = 换方向，不是努力问题。**
2. **过闸门 2 · 扛得住成本** —— 全成本清单逐条填数、盈亏平衡与回本、边际成本、客服承载上限、迭代节奏。
3. **过闸门 3 · 送得到人** —— 增长引擎选择、首个 100/1000 路径、激活与留存。
4. **过闸门 4 · 算得过账** —— 生存线公式、时间换钱的账、**退出信号提前写死**。**缺数按 §十三 推算规范补，不许跳过。**
5. **打分卡 + 一票否决**（§6）。
6. **形态选择 + 三重交集收敛**（§7 / §9）。
7. **落盘** —— `调研\方法\{方向}\` 或 `调研\工具\{产品名}-产品分析报告.md`。
8. **呈现** —— `present_files`，回复中说明路径。

## 四、闸门判定表（顺序否决）

| 闸门 | 要回答的问题 | 不过则 | 死信号 |
|---|---|---|---|
| **1 · 收得到钱** | 我有合法主体与通道吗？品类被通道接受吗？ | 项目不成立，换方向（**结构问题**） | 说不出「钱从哪个口子进来」；通道需资质而我不具备 |
| **2 · 扛得住成本** | 客服 / 运维 / 合规的隐性成本，我一个人的时间承受得住吗？ | 缩形态（自助化 / 降支持面）或换方向 | 客单价 < 单用户边际成本；算不出客服临界点 |
| **3 · 送得到人** | 前 100 个用户我能零预算触达吗？ | 通用框架已判**一票否决** | 答不出「2 周内零预算让 20 个目标用户开口」 |
| **4 · 算得过账** | 盈亏平衡用户数 × 我的渠道能力，可达吗？ | 调客单价 / 调成本结构；不可调则杀 | 回本周期 > 24 个月；算不出盈亏平衡用户数 |

**与「七层提问法 / 五段式流水线」的映射**

| 四道闸门 | 对应七层提问法 | 对应五段式流水线 |
|---|---|---|
| 1 收得到钱 | L4 + 新增 L4.6 | ① 定约束（**动手前**） |
| 2 扛得住成本 | 新增 L4.5 + L4.6 | ③ 快筛否决 + ④ 证伪（成本实验） |
| 3 送得到人 | L2 + L5 | ③ 快筛（一票否决） |
| 4 算得过账 | 新增 L4.5 | ⑤ 立项（生存线测算） |

### 4.1 闸门 1 · 收得到钱（动手前必须有答案）

**主体与通道**：以什么身份收钱（自然人 / 个体户 / 有限公司 / 海外主体）？走哪个通道？该通道需要什么资质、抽成多少、几天到账？品类会不会被拒？通道与分发渠道是否绑定（上架商店是否必须走 IAP）？

**通道对照（费率一律「需核实」，采集日 2026-10-08）**

| 通道类型 | 常见计费结构（参考·需核实） | 主要门槛 | 适合谁 |
|---|---|---|---|
| 国际卡收单（Stripe 类） | 约 2.9% + $0.30 / 笔 | 需可接收外币的主体；不代扣税 | 有海外主体 |
| Merchant of Record（Paddle / Lemon Squeezy 类） | 约 5% + $0.50 / 笔 | 门槛低，**由平台代扣全球税** | **个人开发者首选** |
| 应用商店内购 | 15% / 30% | 必须走平台 IAP；审核政策风险 | 纯 App 分发 |
| 国内聚合支付（微信 / 支付宝） | 约 0.6% / 笔 | **需商户资质** | 面向国内 C 端 / 小微 B |
| 平台分成（市场 / 插件商店） | 视政策 | 依赖平台 | 插件 / 模板类 |
| 人工转账 / 对公汇款 | 0%（银行手续费另计） | 无法规模化 | 早期验证 |

**定价结构**：哪种定价逻辑（价值 / 竞品锚定 / 成本加成 / 损失规避）？是不是三档（够用 / 好用 / 全都要），中间那档才是我真正想卖的？计费单位与**使用频次**匹配吗（低频收订阅 = 必然流失）？定价与**边际成本**的关系？
**支付摩擦与税费**：退款率进模型了吗？拒付（chargeback）怎么办？**B 端客户一定要发票**（C 端出身的人常忽略）。跨境 VAT / Sales Tax 用 MoR 外包？
**ARPU 提升**：C 端靠**升级**（个人版 → 专业版），B 端靠**扩容 + 续约**（5 席位 → 50 席位）。C 端 ARPU 天花板明显低于 B 端。

### 4.2 闸门 2 · 扛得住成本

**全成本清单（逐条填数，「隐性」一栏最常被漏）**：一次性投入（研发工时折算机会成本 / 设计 / 商标 / 软著 / 设备）· 每月固定（服务器 / 域名 / SSL / 开发者证书 / 代码签名 / API 月费 / 工具订阅）· 每单变动（支付手续费 / **模型调用费** / 带宽 / 发票与税务 / 退款）· **隐性（客服与支持时间 / 运维 / 内容审核 / 合规维护 / 迭代维护 / 社区运营）** · 时间的机会成本。
> **纪律**：把「客服时间」按小时折算成钱写进去。个人开发者最常见的幻觉是「成本只有服务器那点钱」。

```
月毛利/单         = 客单价(月) − 单用户变动成本
盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单
回本周期(单用户)   = 单用户获取成本 ÷ 月毛利/单     ← 必须 < 12 个月
```

**个人专用换算**：买断 ¥99 的产品，要覆盖每月 ¥500 固定成本 → **每月需卖出约 5 单以上**（未计手续费与退款）。**先算这个数，再去想「怎么卖到 5 单」——比先想「做什么功能」重要得多。**

**边际成本可控性（AI 类头号杀手）**：每多一个用户多花多少钱（近似 0 还是线性增长）？重度用户会拖爆吗（用量上限 / 阶梯价 / 降级策略）？供应商涨价 30% 还赚钱吗？缓存 / 本地推理能降本吗？
> **一票否决**：**边际成本 ≥ 定价的方向，直接杀。**

**客服承载上限**：每天/周多少支持请求？一人扛住的临界点是多少用户？常见问题做成文档自助化了吗？

### 4.3 闸门 3 · 送得到人

**增长引擎选择**

| 引擎 | 适合个人？ |
|---|---|
| **内容 / SEO**（教程、对比评测、开源引流） | ✅ **最匹配**（慢但复利，成本 = 时间） |
| **社区运营**（垂直论坛、群、Discord） | ✅ 匹配（深度但天花板低） |
| 应用商店 ASO / 榜单 | ⚪ 可做，被动 |
| 产品自传播（PLG） | ✅ 若能设计传播机制 |
| 付费投放 | ❌ 个人慎入（除非 ROAS 已实测为正） |
| KOL / 测评 | ⚪ 可小试（一次性峰值） |
| B 端销售（SLG） | ❌ 一人公司极难 |

**判定口径**：`我能不能在 2 周内、零预算、让 20 个目标用户开口说话？` 答不出 → **一票否决**。
**首个 100 / 1000 路径**：前 100 个用户**具体从哪来**（能说出 3 个具体群名 / 版块吗）？100 → 1000 靠什么机制放大？CAC 怎么实测？漏斗哪层最漏？
**激活与留存**：Aha moment 能压到 3 分钟内吗？留存曲线是「微笑曲线」还是持续下滑？月流失率？**下载量是虚荣指标，留存才是命**（留存须按自然日/周**分群**看）。

### 4.4 闸门 4 · 算得过账

```
【C 端路线】
年营收   = 可触达人数 × 触达转化率 × 激活率 × 付费率 × 客单价
年毛利   = 年营收 × (1 − 支付费率) − 变动成本合计
可行条件 = 年毛利 > 年固定成本 + 时间机会成本

【B 端路线（仅限自助型小微 B）】
年营收   = 新签客户数 × 年客单价 + 存量客户 × 年客单价 × 续费率 + 扩容收入
年毛利   = 年营收 − (销售人力 + 实施交付 + 支持服务 + 云成本)
可行条件 = 年毛利 > 固定成本，且 单客户 CAC 回收周期 < 12 个月
```

**关键判定**：回本周期必须 < 12 个月（> 24 个月基本不可承受）· 涨价 20% 还是降本 20% 更容易（个人优先降本，客单价受心理价位压制）· **「时间换钱」的账算清了吗**（每月净收入是否显著高于投入时间的机会成本）。

## 五、退出机制（必须在开工前写死，否则无限期投入）

| 信号 | 含义 | 动作 |
|---|---|---|
| 上线 3 个月，付费用户 < 5 且无增长 | 不是分发问题，就是价值问题 | 复盘后停或换 |
| **客服时间 > 开发时间** | 形态错了（支持面太宽） | 缩形态或停 |
| 每月净收入 < 服务器成本 × 3，持续 6 个月 | 商业模型不成立 | 停 |
| 依赖的单一平台改政策导致分发腰斩 | 平台风险已实现 | 重建渠道，或停 |
| 自己已经不想做这件事了 | 「愿不愿意做 2 年」的答案变了 | 诚实退出 |

> **「愿不愿意做 2 年」这一问为什么关键**：它不靠新鲜感，靠兴趣与客户关系。比「我能不能做出来」更常被忽略，但决定能否活到收钱那天。

## 六、打分卡与一票否决

### 6.1 打分卡（个人开发者加固版 · 12 维 · 满分 135）

| 维度 | 权重 | 5 分锚点 | 1 分锚点 |
|---|---|---|---|
| 使用频次 | ×3 | 每天 / 每周多次 | 一次性 |
| 痛点硬度 | ×3 | 不做直接损失钱或触发合规风险 | 只是「更方便」 |
| **分发可得性** | ×3 | 能直接触达并让 20 人开口 | 完全不知道人在哪 |
| 现有替代糟糕度 | ×2 | 只能手工或付费买别扭的老工具 | 系统内置已够用 |
| 付费方明确度 | ×2 | 有预算科目 / 决策人清晰 | 无任何付费先例 |
| 持续交付成本 | ×2 | 有真实云 / 模型 / 内容成本 → 订阅成立 | 纯一次性交付 → 只能买断 |
| 你方独占优势 | ×2 | 有数据 / 身份 / 渠道别人没有 | 无 |
| 窗口期长度 | ×1 | 大厂 2 年内不会做 | 下个系统版本就被内置 |
| 合规 / 平台风险 | ×1 | 无单一 API 依赖 | 依赖单一平台政策 |
| **收款可行性** | ×3 | 通道明确、资质具备、费率可接受 | 无合法收款路径 |
| **隐性成本可控性** | ×3 | 可完全自助，边际成本 ≈ 0 | 每单需人工介入 |
| **客体匹配度** | ×2 | 形态与我的时间 / 资质完全匹配 | 需要团队或资质 |

**计分**：满分 = **135**。**阈值**：≥ 70%（≈95）→ 进入证伪；≤ 50%（≈68）→ 直接杀；中间 → 只做**最低成本**补充采集。

### 6.2 一票否决（不论总分多高，触发即杀）

| # | 否决项 | 对个人的致命度 |
|---|---|---|
| 1 | **收款路径不成立** | ★★★（**个人最高发**） |
| 2 | **边际成本 ≥ 定价** | ★★★ |
| 3 | **客服 / 合规成本超出个人承载上限** | ★★★ |
| 4 | **要求我不具备的资质或现场交付能力**（招投标 / 等保 / 私有化） | ★★★ |
| 5 | **分发不可得** | ★★★ |
| 6 | 使用频次 = 一次性，且无持续交付成本 | ★★ |
| 7 | 依赖单一平台 / API，一个版本更新就可能被内置 | ★★★ |
| 8 | 触碰合规红线（金融 / 医疗 / 未成年人 / 爬虫 / 版权 / 隐私数据） | ★★ |
| 9 | 答不出「去掉 AI 之后还剩多少价值」（AI 类专用） | ★★★ |

> 前 4 条是**个人开发者专项新增**（通用框架原本只有后 5 条）。

### 6.3 盈利可行性 12 问

钱从哪进来 + 资质 · 定价 + 依据 · **每多一个用户多花多少钱** · 每月固定成本 + 盈亏平衡用户数 · 回本周期 · 前 100 个用户具体从哪来 · 漏斗每层数字 · 留存 + 月流失率 · 谁提供客服 + 扛得住多少用户 · 开源库 / API 许可证允许商用吗 · 个人信息 / AI 生成内容要做什么合规动作 · **（走 B 端时）使用者 / 决策者 / 付款者是谁？钱从哪个科目出？**

## 七、形态选择（个人做 / 不做对照）

| 适合（起点） | 原因 | 不适合 | 原因 |
|---|---|---|---|
| **单点高频 mini-tool（买断）** | 卖点单一、支持面窄、边际成本 ≈ 0 | 需现场实施的重行业 SaaS | 交付成本 = 团队级 |
| **浏览器 / 编辑器插件** | 自带分发渠道，入口天然高频 | 需资质的领域（金融 / 医疗 / 教育） | 牌照门槛 |
| **模板 / 预设 / 素材包** | 零边际成本、可买断 | 需内容审核的 UGC 平台 | 审核成本与合规义务 |
| **轻量 SaaS（自助型）** | 无销售人力 | 依赖大规模 GPU 训练的方向 | 资本门槛 |
| **开发者工具 / API / 库** | 付费意愿最高、最不需教育 | 需 7×24 SLA 的基础设施类 | 稳定性承诺扛不住 |
| **垂直小人群工具** | 竞品盲区、大厂看不上 | 通用大而全平台 | 冷启动几乎必败 |

**形态阶梯**：单点工具（低）→ 工作流套件（中）→ 平台 / 生态（高，个人几乎必败）。
**判定口诀**：`低频 + 无持续成本 → 只做买断单点工具；高频 + 有持续成本 → 可做订阅；需要教育市场 → 不做。`

## 八、合规底线清单（动手前先过）

**主体**（自然人无法开票 / 个体户低成本合规 / 有限公司能开票能签 B 端合同）· **通道**（接受我的品类、费率、到账周期）· **知识产权**（产品名先查商标；软著按需登记；**确认在职作品归属与竞业限制**）· **开源许可**（列出所有依赖及许可证，排除 GPL/AGPL 传染与「禁商用」素材）· **模型 / API ToS**（允许包装成产品对外售卖吗）· **数据合规**（隐私政策、用户协议、最小必要采集；跨境传输）· **内容合规**（AI 生成内容标识 / 备案；UGC 审核能力）· **平台政策**（依赖哪些平台？任一改政策我会怎样？有备用方案吗）· **税务**（合法申报口径，**咨询专业人士，本 skill 不给结论**）。

> ⚠️ **在职开发必查两条**：① 作品可能属**职务作品**（看劳动合同约定）；② 与原公司业务重合可能存在**竞业限制**风险。

## 九、三重交集收敛（可执行位置判断）

**值得做的画像**：**收钱路径明确** × **边际成本可控** × **分发渠道我自己就泡在里面**，再加三条加固：形态匹配（单点工具 / 插件 / 模板 / 轻量自助 SaaS）· 支持面窄可自助 · **我愿意做 2 年**。
**不要碰的画像**：需现场实施 / 招投标 / 私有化 · 需 7×24 SLA · 需持续人工介入 · 需我不具备的资质 · 收款通道明确拒绝我的品类 · 云端 AI 无限用量 · **客户账期 ≥ 3 个月** · 需求真但我不知道人在哪 · 需大额前期投入 · 需教育市场的卖点。

**选路**：**C 端拼分发，B 端拼信任。** 个人主战场在 C 端；B 端**仅「自助型小微 B」（PLG + Self-serve）可行**，重 B（现场销售 / 招投标 / 集采）不可行。

**最小验证：证据强度阶梯（只认行为，不认口头）**

| 强度 | 实验 | 适用原型 |
|---|---|---|
| 弱 | 问未来意愿 | — |
| ↓ | 假门测试（Fake Door） | ③ 能力窗口型（注意伦理） |
| ↓ | 留邮箱 / 预约 | — |
| ↓ | 人肉代做（Concierge） | ② 手工自动化型 |
| **强** | **预售 / 直接收钱** | ①② 替代升级 / 手工自动化 |
| 补充 | 定向下访谈 20 人（**只问过去行为**） | ④ 细分人群型 |

**四种机会原型 → 验证方式**：① 替代升级型（存在还在收钱但体验陈旧的老工具）→ 测「愿不愿迁移」；② 手工自动化型（大量教程 / 脏脚本 / 外包代做）→ 人肉代做测复用；③ 能力窗口型（新模型 / API / OS 能力出现）→ 假门 + 48 小时 Demo（**窗口极短**）；④ 细分人群型（大厂通用产品不适配）→ 深访 20 人 + 小规模付费测试。

**判定门槛（写死）**：立项 = ≥5 个真实用户持续使用，或 ≥3 个明确付费信号 · 待观察 = 有使用无付费 → 2 周内无改善则杀 · 杀掉 = 无人持续使用，或「免费可以，付费不要」。

**时间盒**：W1 前 定约束（含主体通道 + 支持量上限）0.5h · W1 后 采信号（**只采不判**）4h · W2 前 快筛 + 打分卡 1h · W2–W3 三方向并行各跑 1 个证伪实验（付费 × 成本）各 ≤6h · W4 留 1 个 + 生存线测算 2h。
> 「成本实验」= **真的交付一次**，记录真实耗时与真实成本——个人开发者最该做、却最少做的实验。

## 十三、数据与测算要求（不可让步）

> **立场（2026-10-08 修正）**：个人做可行性判断，**账算不出来就等于没判**。
> **「拿不到」不是免责理由。** 拿不到 → 给获取路径；确实取不到 → 给**有依据的推算 / 预估**，标方法与置信度。
> **禁止的是「无依据的数字」，不是「估算」本身。** 只写缺口不做测算 = 分析没做完。
> 数据方法论的完整版（源分级 / 完整性三问 / 三角印证 / 五种预估法 / 可复算规范 / 标注规范）见 `product-analysis-framework` §四。

### 13.1 个人开发者专用测算清单（逐条给数，不许空着）

| # | 测什么 | 怎么算 | 缺失时怎么推 |
|---|---|---|---|
| 1 | **生存线** | 盈亏平衡付费用户数 = 月固定成本 ÷ 月毛利/单（月毛利/单 = 客单价 − 单用户变动成本） | 固定成本逐项列（服务器 / 域名 / 证书 / API 月费 / 工具订阅）；不许只算服务器 |
| 2 | **回本周期** | CAC ÷ 月毛利/单，**必须 < 12 个月** | 无实测 CAC 就用一次真实获客动作的成本（发帖耗时折算） |
| 3 | **全成本折算** | 客服时间 × 我的小时机会成本（= 我的市场时薪）× 月支持次数 | 月支持次数按「付费用户数 × 人均月提问次数」推，人均值标类比依据 |
| 4 | **工时分布自测** | 记录 1 个月真实工时 → 算出维护 / 客服 / 新功能各占 % | 无记录时用经验值 30%–50%（**必须标「经验估计·未实测」**，并建议补记录） |
| 5 | **时间换钱** | 月净收入 vs（月投入小时 × 机会成本时薪）——不高出就是亏 | 机会成本时薪用本人当前时薪或行业同岗折算 |
| 6 | **渠道到量推演** | 所需付费用户数 ÷ 我的月获客能力 = 需几个月 → 与我的耐心 / 现金流对比 | 自下而上：可触达社群人数 × 转化率 |
| 7 | **三重敏感度** | 定价 ±20% / 模型成本 ±30% / churn ±50% 三档，看是否还成立 | 每档给出结论翻转与否 |

### 13.2 三条版式纪律

1. **估算必须写成四段**：假设 → 依据 → 推算 → 结果，缺一不可。
2. **必须做敏感度**：上面第 7 条三档必算，翻转就明说「结论不稳」。
3. **预估与实测分开排版**（单列「测算过程」节），不许混进同一张表冒充实测。

### 13.3 标注规范（每个数字必带标签）

`【实测·API】` `【审计】` `【官方宣称】` `【推算·方法X】` `【预估·依据Y】` `【未取得】`
→ **前四种都能进结论**；【未取得】只进缺口清单，且必须附获取路径。

### 13.4 「文档层」与「产出层」的区别（务必分清）

- **文档层**：本 skill 与**同目录**的 `个人开发者方向-PM方法论集成.md` 是**方法文档，本身不含市场数据**；其中费率、比例为**行业常见区间（采集日 2026-10-08）**，使用时须回官方页重核。
- **产出层**：用它们做出来的**可行性判断必须包含测算**——附 A 数据明细 / 附 B 测算过程与敏感度 / 附 C 缺口声明，**三附齐全才算交付完整**。
- 「维护 / 客服吃掉 30%–50% 时间」是**经验估计、未做样本量化实测**——按第 4 条自测后修正，别当既成数据用。
- 涉及合规与税务的内容**不构成法律或税务建议**。

**维护提醒**：权威详版 `个人开发者方向-PM方法论集成.md` **就在本文件夹内**——改一处即两处生效，不存在跨目录副本漂移。但仍需人工核对：该文档是**详版**、本 SKILL 是**执行版**，两类表述（通道费率表 / 合规 13 条 / 原型映射 vs 四道闸门 / 否决项 / SOP）必须口径一致；文档更新后（映射表在 §12）按行核对。
